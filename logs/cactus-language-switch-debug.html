Cactus 언어 전환 실패 — 모델 문제인가, 프레임워크 문제인가

cactus run 에서 1턴을 일본어로 물어본 뒤 “한국어로 이야기해줘” 라고 하면 계속 일본어로 답하는 현상. 체계적 디버깅으로 원인을 분리하고, 모든 실험을 재현 가능한 형태로 기록한다.

2026-07-30

한 줄 결론

모델 능력의 문제가 아니라 프레임워크(엔진)의 문제다. 똑같은 대화를 한 번에 프리필하면 한국어 전환이 5/5 성공하지만, cactus run 이 2턴째부터 타는 KV 캐시 증분 재사용 경로로 넣으면 0/5 실패한다. 토큰 열은 동일하고 캐시 재사용 여부만 다르다.

이 결함은 언어와 무관하다. 순수 영어 대화를 그리디(argmax)로 돌리면 warm 과 cold 의 출력이 6개 중 5개에서 서로 다르다 — 같은 토큰 열, 같은 argmax인데 결과가 갈린다(§7.2). 일본어→한국어는 그 차이가 눈에 보이는 실패로 넘어간 지점일 뿐이다.

부수적으로, cactus serve/Python 바인딩에는 모든 비-ASCII 입력이 깨지는 별개의 확정 버그가 있다.

2. 증상 재현

cactus run 은 표준입력에서 한 줄씩 턴을 받으므로, 파일로 파이프하면 그대로 자동 재현된다.

  '日本語で「東京」について3文で説明してください。' \

You: 이제부터 한국어로 이야기해줘.        ← 이번엔 한국어로 답한다 (5/5)

이 3단계 비교의 한계. cactus run 과 cactus serve 는 클라이언트가 달라 1턴 응답 문자열까지 완전히 통제되지는 않는다(엄밀한 단일변수 A/B 는 아니다). 손으로 빠르게 확인하는 용도로는 충분하지만, 엄밀한 증명은 같은 핸들에서 cactus_reset() 하나만 토글한 §4·§7.2 쪽을 봐야 한다.

한국어로는 3단계를 할 수 없다. cactus serve 는 비-ASCII 입력을 파괴하므로(§8) cold 대조군을 한국어로 만들 수 없다. 그래서 이 단계만 영어로 한다.

관찰 포인트 — CLI 가 매 턴 찍어 주는 confidence

cactus run 은 턴마다 confidence: NN% 를 출력한다. 이 값은 첫 생성 토큰의 top-1/top-2 로짓 마진에서 나오는 결정론적 값이라, 대화가 진행되며 어떻게 움직이는지 볼 만하다. 재현 세션에서는 98.6% → 72.5% → 50.4% 로 떨어지며 3턴째에 같은 문단을 반복하는 붕괴가 시작됐다.

다만 confidence 는 프롬프트마다 자연히 달라지므로 이 숫자 하나만으로는 증거가 되지 않는다. 증거가 되는 건 같은 토큰 열에 대해 경로별로 값이 다른 경우다(§7).

4. 결정적 실험 — warm(캐시 재사용) vs cold(재프리필)

4.1 계측 도구를 바꾼다

CLI 는 옵션을 하드코딩하고 대화 상태를 프로세스 안에 가둬서, 변수를 하나씩 통제하기 어렵다. 그래서 같은 엔진 .dylib 를 Python 바인딩으로 직접 호출한다. 두 가지를 지켜야 CLI 와 등가다.

  • 샘플링 옵션을 CLI 와 바이트 단위로 동일하게 — run.cpp:1093-1100 에서 그대로 옮겼다 (temperature 0.7 / top_p 0.95 / top_k 40, stop sequences 포함).
  • 메시지 JSON 을 ensure_ascii=False 로 직접 직렬화 — 바인딩의 기본 경로에는 비-ASCII 를 파괴하는 별개 버그가 있다(8장). 그 버그를 우회해야 CLI 와 같은 조건이 된다.
# evidence/lang_probe.py — 공통 설정
OPTS = {"temperature": 0.7, "top_p": 0.95, "top_k": 40, "max_tokens": 200,
        "enable_thinking_if_supported": False, "auto_handoff": False,
        "confidence_threshold": -1.0, "cloud_timeout_ms": 15000, "tool_rag_top_k": 0,
        "stop_sequences": ["<|im_end|>", "<end_of_turn>", "<turn|>"]}

out = cactus_complete(h, json.dumps(msgs, ensure_ascii=False), OPTS)

판정은 눈대중이 아니라 유니코드 스크립트 카운트로 한다. 한글 음절/자모는 ko, 가나는 일본어 확정 신호, 한자는 한글이 없을 때만 일본어 쪽으로 계산한다.

4.2 실험 — 같은 대화, 캐시 재사용 여부만 다르게

# evidence/warm_vs_cold.py 의 핵심
def trial(h, q1, warm):
    cactus_reset(h)
    m1 = [{"role": "user", "content": q1}]
    reply1, _ = send(h, m1)                       # 1턴을 실제로 생성
    m2 = m1 + [{"role": "assistant", "content": reply1},
               {"role": "user", "content": "이제부터 한국어로 이야기해줘."}]
    if not warm:
        cactus_reset(h)                           # ← 유일한 차이: 캐시를 버린다
    return send(h, m2)

7. 수치 비등가성 — 같은 프롬프트인데 로짓이 다르다

confidence 는 첫 생성 토큰의 top-1 / top-2 로짓 마진에서 나온다 (confidence = 1 − entropy, sample_component_logits). 즉 샘플링과 무관한 결정론적 양이다. 같은 토큰 열을 넣었는데 이 값이 달라지면, 계산 자체가 다르다는 뜻이다.

멀티턴을 배제하고, 단일 프롬프트를 A(fused)와 B(chunked) 두 경로로만 통과시켜 비교했다.

7.2 영어로도 재현된다 — 그리디 결정성 테스트

이 절이 필요한 이유. §4 의 표에서 영어 대조군이 warm 에서도 성공했기 때문에 “결함이 일본어에서만 생긴다”로 읽힐 여지가 있었다. 그건 틀린 독해다. 결함은 언어와 무관하고, 앞 절들이 보여준 것은 증상이 일본어에서 임계를 넘었다는 사실뿐이다. 여기서 한국어·일본어를 전혀 쓰지 않고 결함 자체를 증명한다.

가장 깔끔한 증명은 그리디(argmax) 결정성이다. warm 과 cold 는 완전히 같은 토큰 열을 보고, argmax 는 확률적 요소가 없다. 두 경로가 등가라면 출력이 바이트 단위로 같아야 한다. 다르면 그 자체로 비등가의 증거다 — 샘플링 운을 따질 여지가 없다.

영어에서 결함이 어떻게 “보이는가”

영어에서는 하드 실패 대신 2턴 응답 품질 저하로 나타난다. 위 표에서 warm 쪽은 반복적으로 과제를 수행하는 대신 과제에 대해 논평하거나(“This request requires a slight shift in tone…”), 지시를 왜곡해서 받는다(“three uses that require different types of use”). 샘플링(N=5)으로 측정한 형식 전환 준수율은 두 갈래가 비슷했지만, 내용의 정확도에서 갈렸다:

편집자 주 — 여기부터는 해석이다. 위 관측(경로별 로짓 차이, 패딩 플래그의 영향)은 측정값이지만, “어느 쪽이 수학적으로 옳은 구현인가” 는 이 실험만으로 단정할 수 없다. 커널 레벨에서 참조 구현과 로짓을 대조해야 한다. 확실한 것은 세 경로가 서로 등가가 아니며, 그 차이가 사용자에게 보이는 동작을 바꿀 만큼 크다는 사실이다. cactus run 의 1턴은 A 경로, 2턴 이후는 C 경로를 타므로 — 대화가 길어질수록 사용자는 계속 다른(그리고 확신도가 낮은) 계산 경로에 머문다.

8.3 A/B 증명

같은 핸들, 같은 옵션, 같은 메시지. 다른 것은 JSON 인코딩 한 가지뿐이다.

# evidence/ab_ensure_ascii.py
("A", MSGS)                                    # list → _to_json 이 ensure_ascii=True
("B", json.dumps(MSGS, ensure_ascii=False))    # str  → 그대로 통과 (raw UTF-8)

A wire bytes: [{"role": "user", "content": "한국어로 서울에 …
B wire bytes: [{"role": "user", "content": "한국어로 서울에 대해 세 문장으로 설명해줘."}]

########## A  ensure_ascii=True   (현재 cactus serve / python 바인딩)
죄송하지만, 제시하신 문장이 어떤 언어인지 명확하지 않아 정확한 번역을 제공하기 어렵습니다. …

########## B  ensure_ascii=False  (raw UTF-8, C++ CLI 와 동일)
서울은 한국의 중심지로서, 역동적인 도시의 상징입니다. 이곳은 서울역사 박물관과 같은 …
영향 범위. cactus serve(OpenAI 호환 서버)와 Python 바인딩을 쓰는 모든 비영어 입력. 한국어·일본어·중국어·이모지·악센트 문자 전부. C++ CLI(cactus run)와 모바일 바인딩은 영향 없다.
고칠 곳은 한 줄이다 — json.dumps(obj, ensure_ascii=False).encode(). (근본적으로는 엔진의 parse_messages_json 이 \uXXXX 를 처리하도록 고치는 게 맞다.)
지금 당장의 우회: 바인딩 호출 시 메시지를 json.dumps(msgs, ensure_ascii=False) 문자열로 직접 넘기면 정상 동작한다.

9. 판정과 워크어라운드

9.1 모델인가 프레임워크인가

가설판정근거
모델이 한국어를 못한다기각 한국어 단독 질문에 완벽히 답함 (confidence 99.3%). 토크나이저/디토크나이저 정상.
모델이 언어 전환 지시를 못 따른다기각 같은 대화를 콜드 프리필하면 JA→KO 전환 5/5 성공 (§4). 영어 컨텍스트에선 warm 에서도 성공.
프레임워크가 히스토리를 흘린다 / 템플릿이 틀렸다기각 매 턴 전체 배열 재전송 확인, 공식 chat_template.jinja2 와 대조 일치 (§3).
KV 캐시가 손상된다 (위치·내용 유실)기각 warm 경로에서도 이전 턴 정보 회수 8/8. KV 압축·슬라이딩 윈도우 미발동 (§6).
증분 KV 재사용 경로가 콜드 경로와 수치적으로 등가가 아니다 채택 동일 토큰 열에 대해 경로별 confidence 상이(0.84 / 0.66), 동작 결과 상이(5/5 vs 0/5), prefill_tokens 로 경로 확정 (§5·§7).
이 결함은 일본어(또는 다국어) 상황에서만 생긴다기각 순수 영어 그리디 테스트에서 warm≠cold 가 6개 중 5개. 영어에서도 2턴 응답 품질이 떨어지고 “chlorophyll 색” 질문에 warm 5/5 오답 · cold 5/5 정답 (§7.2).
(별건) serve/바인딩이 비-ASCII 를 파괴한다확정 ensure_ascii=True ↔ \uXXXX 미처리 파서. 인코딩만 바꾼 A/B 로 증명 (§8).

그래서 답은

프레임워크 문제다. 다만 “프레임워크가 대화를 잃어버린다” 같은 단순한 결함이 아니라, 엔진의 프리필 구현 세 갈래가 서로 등가가 아니고, cactus run 의 2턴 이후가 그중 품질이 떨어지는 갈래에 고정된다는 형태다.

모델(Gemma 4 E2B, CQ4 4-bit)의 기여가 0 은 아니다. 이 모델은 언어 전환 판단의 마진이 작아서 수치가 조금만 틀어져도 결과가 뒤집힌다. 더 큰/덜 양자화된 모델이라면 같은 결함이 있어도 증상이 안 보였을 것이다. 결함은 프레임워크에 있고, 모델은 그 결함을 드러낸 리트머스지에 가깝다.

영향 범위는 “일본어 대화”가 아니라 “모든 멀티턴 대화”다. 언어와 무관하게 cactus run·cactus serve 의 2턴 이후 모든 응답이 1턴과 다른 계산 경로에서 나온다. 영어에서는 하드 실패 대신 조용한 품질 저하로 나타나므로(§7.2) 오히려 발견하기 더 어렵다. 사용자가 일본어로 시작한 덕분에 눈에 띄는 형태로 드러난 셈이다.

OPTS = {"temperature": 0.7, "top_p": 0.95, "top_k": 40, "max_tokens": 200,
        "enable_thinking_if_supported": False, "auto_handoff": False,
        "confidence_threshold": -1.0, "cloud_timeout_ms": 15000, "tool_rag_top_k": 0,
        "stop_sequences": ["<|im_end|>", "<end_of_turn>", "<turn|>"]}

JA_Q = "日本語で「東京」について3文で説明してください。"
EN_Q = "Explain Tokyo in three sentences."
KO_REQ = "이제부터 한국어로 이야기해줘."

def script_of(ch):
    o = ord(ch)
    if 0xAC00 <= o <= 0xD7A3 or 0x1100 <= o <= 0x11FF or 0x3130 <= o <= 0x318F: return "ko"
    if 0x3040 <= o <= 0x309F or 0x30A0 <= o <= 0x30FF: return "ja"    # 가나 = 일본어 확정
    if 0x4E00 <= o <= 0x9FFF: return "han"                            # 한자 = 공유
    if ("a" <= ch <= "z") or ("A" <= ch <= "Z"): return "en"
    return None

def classify(text):
    c = collections.Counter(filter(None, (script_of(ch) for ch in text)))
    ko, ja, han, en = c["ko"], c["ja"], c["han"], c["en"]
    if ko + ja + han + en == 0: return "empty", c
    ja_score = ja + (han if ko == 0 else 0)
    if ko > ja_score and ko > en:      return "KO", c
    if ja_score > ko and ja_score > en: return "JA", c
    if en >= ko and en >= ja_score:     return "EN", c
    return "MIX", c

10.2 warm_vs_cold.py — 핵심 A/B (§4)

import json, collections
from cactus.bindings.cactus import cactus_init, cactus_complete, cactus_reset, cactus_destroy
from lang_probe import MODEL, OPTS, classify, JA_Q, EN_Q, KO_REQ
N = 5

def send(h, msgs):
    out = cactus_complete(h, json.dumps(msgs, ensure_ascii=False), OPTS)
    return out.get("response") or "", out.get("confidence")

def trial(h, q1, warm):
    cactus_reset(h)
    m1 = [{"role": "user", "content": q1}]
    reply1, _ = send(h, m1)                     # 1턴을 실제로 생성
    m2 = m1 + [{"role": "assistant", "content": reply1},
               {"role": "user", "content": KO_REQ}]
    if not warm:
        cactus_reset(h)                         # ← 유일한 차이
    return send(h, m2)

h = cactus_init(MODEL)
try:
    for q1, qlabel in ((JA_Q, "JA first turn"), (EN_Q, "EN first turn")):
        for warm in (True, False):
            rows = []
            for _ in range(N):
                t2, conf = trial(h, q1, warm)
                rows.append((classify(t2)[0], conf, t2))
            tally = collections.Counter(r[0] for r in rows)
            mode = "WARM (KV reuse, = cactus run)" if warm else "COLD (full reprefill)"
            print(f"### {qlabel} | {mode}  ->  {dict(tally)}")
            for lang, conf, txt in rows:
                print(f"   [{lang}] conf={conf:.2f}  {txt[:120]}")
finally:
    cactus_destroy(h)

def send(h, msgs, opts):
    out = cactus_complete(h, json.dumps(msgs, ensure_ascii=False), opts)
    return (out.get("response") or "", out.get("confidence"), out.get("prefill_tokens"))

def warm_cold(h, q1, q2, opts):
    """두 갈래가 받는 m2 는 완전히 동일. 다른 것은 캐시 상태뿐."""
    cactus_reset(h)
    m1 = [{"role": "user", "content": q1}]
    r1, _, _ = send(h, m1, opts)
    m2 = m1 + [{"role": "assistant", "content": r1}, {"role": "user", "content": q2}]
    warm = send(h, m2, opts)        # 접두사 재사용 (prefill_tokens 17~19)
    cactus_reset(h)
    cold = send(h, m2, opts)        # 전체 재프리필 (prefill_tokens 42~147)
    return warm, cold
