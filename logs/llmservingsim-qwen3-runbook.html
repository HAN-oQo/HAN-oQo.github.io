2Pull Docker image + launch containerDocker 이미지 pull + 컨테이너 띄우기

The repo's 레포의 scripts/docker-sim.sh is designed to run interactively, but for automation/reproducibility it's easier to launch in 는 인터랙티브로 띄우게 돼 있는데, 자동화/재현성을 위해 detached modedetached 모드 and send commands via 로 띄우고 docker exec.로 명령 보내는 게 편함.

# 베이스 이미지 (linux/amd64)
docker pull astrasim/tutorial-micro2024

# detached 컨테이너 (sleep infinity로 살려둠)
docker run -d --name servingsim_docker \
  -v ~/Desktop/LLMServingSim:/app/LLMServingSim \
  -w /app/LLMServingSim \
  astrasim/tutorial-micro2024 \
  sleep infinity

# 살아있는지 확인
docker ps --filter "name=servingsim_docker"
Issue 2 (harmless):이슈 2 (무해): On Apple Silicon you'll see Apple Silicon에서 WARNING: The requested image's platform (linux/amd64) does not match the detected host platform (linux/arm64/v8). Ignore — it works fine under Rosetta emulation. Every command runs as-is. 메시지가 뜸. Rosetta 에뮬로 정상 동작하므로 무시. 모든 명령이 그대로 작동함.

Fix the dtype above and rerun:위 dtype을 고치고 다시 돌리면:

...

The summary lines all print, but the final throughput-per-window output dies because 요약 줄까지는 다 찍히는데, 마지막 throughput-per-window 출력에서 RATIO=0. 이라 죽음. CSV doesn't get written!CSV가 안 적힘!

Root cause — 원인 추적 — serving/__main__.py:436:

FREQ = 1_000_000_000      # 1 GHz

For --log-interval 5.0, 이면 INTERVAL=5e9, , RATIO = 1e9 // 5e9 = 0. This is a bug that always produces 0 whenever . log_interval ≥ 2.면 항상 0이 되는 버그.

Worth reporting upstream:업스트림에 보고할 만함: patching with RATIO = max(1, FREQ // INTERVAL) or float division would clean this up. 또는 float 나눗셈으로 패치하면 깔끔.

7-1. Custom cluster config

There's no dedicated cluster config for Qwen3-32B in the repo, so write one. Based on 레포에 Qwen3-32B용 cluster config가 따로 없어서 직접 작성. single_node_single_instance.json, change only the model name and TP:을 기반으로 모델명과 TP만 변경:

cat > configs/cluster/qwen3_32b_single.json <<'EOF'
{
    "num_nodes": 1,
    "link_bw": 16,
    "link_latency": 20000,
    "nodes": [{
        "num_instances": 1,
        "cpu_mem": {"mem_size": 512, "mem_bw": 256, "mem_latency": 0},
        "instances": [{
            "model_name": "Qwen/Qwen3-32B",
            "hardware": "RTXPRO6000",
            "npu_mem": {"mem_size": 96, "mem_bw": 1597, "mem_latency": 0},
            "num_npus": 2,
            "tp_size": 2,
            "pd_type": null
        }]
    }]
}
EOF

The 32B model doesn't fit in a single 96GB (one RTX PRO 6000's VRAM), so TP=2 (split across 2 GPUs). The repo's profiles include both tp1 and tp2.32B 모델은 96GB(RTX PRO 6000 한 장 VRAM) 한 대로 안 들어가서 TP=2 (GPU 2장으로 분할). 레포의 프로파일도 tp1·tp2 두 종류 다 있음.

B vs C — prefix cache on/off (same 100 requests):B vs C — prefix cache on/off (같은 100 요청): ShareGPT traces share almost no prefix across requests, so cache impact is marginal — TTFT mean 4,256 vs 4,416 (3.6% better), throughput 2,274 vs 2,253 (1% better). For chatbot-style workloads with shared system prompts, the gap would be much largersystem prompt를 공유하는 챗봇 같은 워크로드라면 차이가 훨씬 크게 날 것..
