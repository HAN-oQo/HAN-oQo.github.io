1. 왜 이 비교가 의미 있나

LLMServingSim은 "프로파일 1회 + sim 영원히 무료" 아키텍처 (자세한 건 Frontier 노트 §3-1). 핵심 가정:

  • vLLM이 측정한 op latency CSV를 룩업으로 재사용
  • 스케줄링/큐잉/comm은 시뮬레이터가 자체 모델로 처리

이 가정이 얼마나 잘 맞는지 검증하려면 실제 vLLM 측정값과 시뮬레이터 예측값을 같은 워크로드에 대해 직접 비교해야 함. LLMServingSim 논문은 sim 오차 <10% 클레임하지만 그건 그쪽 검증 셋. 우리 케이스에서도 그런지가 진짜 질문.

비교 결과로 얻고 싶은 것:

  • 절대 오차: TTFT / TPOT / latency p50/p95/p99 의 실측 vs 예측 (% 단위)
  • 발산 패턴: 어떤 요청에서 가장 많이 빗나가는가 (긴 input? 높은 concurrency? KV 압박 구간?)
  • 실용성 판단: 시뮬 결과를 어디까지 신뢰할 수 있나 — 절대값? 상대 비교? 트렌드만?

2. 설정 — 모델, 워크로드, HW 가정

2-1. 모델

항목값이유

dtypebfloat16shipped 프로파일이 bf16
TP1single GPU 시나리오 — 가장 noise 적음

2-2. 워크로드

항목값
JSONLworkloads/sharegpt-llama-3.1-8b-300-sps10.jsonl (LLMServingSim shipped)
요청 수300
도착률10 samples / sec (Poisson)
스키마{input_toks, output_toks, arrival_time_ns, input_tok_ids}
핵심: JSONL에 input_tok_ids (실제 토큰 ID 리스트) 가 들어있음 → 같은 토크나이저로 디토큰화해서 vLLM에 prompt로 보내면 완전히 동일한 입력 사용 가능. 두 sim 모두 같은 토큰 시퀀스로 동작 보장.

2-3. HW

항목값비고
HW label (sim)RTXPRO6000shipped profile
실제 GPU (vLLM)NVIDIA RTX PRO 6000 Blackwell Server Edition요 동일 HW 확보가 핵심 변수. 다른 GPU면 그 GPU용 프로파일 새로 만들어야 함 (프로파일링 가이드 참고)

대역폭1597 GB/scluster config의 mem_bw 와 일치
HW 매칭 못 하면: 보유 GPU (H100 등) 로 한 번 profiler/profile.sh 돌려서 새 프로파일 만들고, cluster config의 hardware 라벨만 그 새 라벨로 바꾸면 됨. 추가 시간 ~1-2h + GPU 비용.

docker exec servingsim_docker bash -c "

4. 실 vLLM 측 (진행 중)

4-1. JSONL replay 클라이언트

일반 LMeterX는 random prompt를 던지는 방식이라 JSONL의 정확한 arrival timing 재생 못 함. 그래서 전용 replay 스크립트 작성: tools/replay_jsonl.py (이 레포에 같이 커밋).

역할:

  • JSONL을 한 줄씩 읽음
  • input_tok_ids → 토크나이저로 디토큰화 → prompt 문자열
  • arrival_time_ns 만큼 기다린 후 vLLM /v1/completions 에 stream 요청 발사
  • per-token 응답으로 TTFT / ITL / TPOT 측정
  • LLMServingSim CSV와 동일한 12 컬럼 스키마로 결과 저장 → 직접 diff 가능

4-2. vLLM 서빙 명령

# GPU 머신에서
docker run --gpus all --rm -p 8000:8000 \
  -e HF_TOKEN=$HF_TOKEN \
  vllm/vllm-openai:latest \
    --model meta-llama/Llama-3.1-8B \
    --dtype bfloat16 \
    --block-size 16 \
    --tensor-parallel-size 1 \
    --max-model-len 4096

4-3. Replay 실행

python tools/replay_jsonl.py \
  --workload ~/LLMServingSim/workloads/sharegpt-llama-3.1-8b-300-sps10.jsonl \
  --endpoint http://<gpu-host>:8000/v1/completions \
  --model meta-llama/Llama-3.1-8B \
  --output outputs/llama8b_real_300.csv \
  --tokenizer meta-llama/Llama-3.1-8B

5. 비교 메트릭 정의

두 CSV가 같은 스키마이므로 request_id로 1:1 매칭 후 메트릭별 비교:

메트릭정의판단 기준
per-request TTFT 오차|sim - real| / real중앙값 < 15% 이면 sim 신뢰 가능
per-request TPOT 오차동일중앙값 < 10% 이면 좋음
per-request latency 오차동일TTFT + TPOT × N 의 누적 — 분산 큼
throughput (전체)req/s 단위 비교±5% 이내면 시뮬이 정상
p95/p99 latency분포의 꼬리 비교여기서 큰 차이 나면 큐잉/eviction 모델이 부정확
발산 요청 분석오차 상위 10개 요청의 (input_len, output_len, arrival_time) 패턴긴 input? 혼잡 시점? 특정 KV size?

비교 스크립트 (tools/compare_csv.py) 가 위 표 자동 출력 + matplotlib으로 scatter plot 2개 (TTFT sim vs real, TPOT sim vs real) 생성. 다음 푸시에 포함 예정.

6. 재현 명령어 모음

# --- LLMServingSim 측 (GPU 없음) ---
git clone --recurse-submodules https://github.com/casys-kaist/LLMServingSim.git
cd LLMServingSim
docker pull astrasim/tutorial-micro2024
docker run -d --name servingsim_docker \
  -v $(pwd):/app/LLMServingSim -w /app/LLMServingSim \
  astrasim/tutorial-micro2024 sleep infinity
docker exec servingsim_docker pip3 install pyyaml pyinstrument transformers datasets \
  msgspec scikit-learn xgboost==3.1.2 matplotlib==3.5.3 pandas==1.5.3 numpy==1.23.5
docker exec servingsim_docker bash scripts/compile.sh

docker exec servingsim_docker bash -c "
  cd /app/LLMServingSim && python -m serving \
    --cluster-config configs/cluster/single_node_single_instance.json \
    --dtype bfloat16 --block-size 16 \
    --dataset workloads/sharegpt-llama-3.1-8b-300-sps10.jsonl \
    --output outputs/llama8b_baseline_300.csv --log-interval 1.0
"

# --- 실 vLLM 측 (GPU 필요) ---
# (GPU 머신에서)
docker run --gpus all --rm -p 8000:8000 \
  -e HF_TOKEN=$HF_TOKEN \
  vllm/vllm-openai:latest \
    --model meta-llama/Llama-3.1-8B --dtype bfloat16 \
    --block-size 16 --tensor-parallel-size 1 --max-model-len 4096

# (별도 터미널)
python tools/replay_jsonl.py \
  --workload ~/LLMServingSim/workloads/sharegpt-llama-3.1-8b-300-sps10.jsonl \
  --endpoint http://localhost:8000/v1/completions \
  --model meta-llama/Llama-3.1-8B \
  --tokenizer meta-llama/Llama-3.1-8B \
  --output outputs/llama8b_real_300.csv

# --- 비교 ---
python tools/compare_csv.py \
  --sim outputs/llama8b_baseline_300.csv \
  --real outputs/llama8b_real_300.csv \
  --out comparison-report.html
