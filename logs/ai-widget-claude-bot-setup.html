The widget supports BYO-key multi-provider (Groq free / Claude / OpenAI / Gemini) plus a "My Claude bot" mode. The bot runs via two paths — I use both.봇은 두 경로로 돈다 — 둘 다 쓴다.

2. How it was deployed2. 어떻게 배포했나

2-1. Widget — auto-injected into every page2-1. 위젯 — 모든 페이지에 자동 주입

assets/ask.js is the widget itself (floating button + panel, asks using the current page's .wrap body as context, EN/KO, theme tokens). On most pages assets/i18n.js auto-loads the ask.js in the same folder. To attach it unconditionally even to pages that miss it (briefings, etc.), the deploy job in the deploy workflow runs an injection script right before upload:assets/ask.js가 위젯 본체다(플로팅 버튼 + 패널, 현재 페이지 .wrap 본문을 컨텍스트로 질문, EN/KO, 테마 토큰). 대부분 페이지는 assets/i18n.js가 같은 폴더의 ask.js를 자동 로드한다. 빠지는 페이지(briefings 등)까지 무조건 붙이려고, 배포 워크플로의 deploy 잡에서 업로드 직전 주입 스크립트를 돌린다:

# .github/workflows/pages.yml (deploy 잡)
- uses: actions/checkout@v4
- name: Inject Ask-AI widget into every page
  run: python3 tools/inject_ask_widget.py   # 소스 미수정, 배포 artifact에만 주입
- uses: actions/configure-pages@v5
- uses: actions/upload-pages-artifact@v3

tools/inject_ask_widget.py inserts the ask.js loader before </body> in every *.html (skips files that already have ask.js/i18n.js, StatiCrypt-locked pages, and *.unencrypted). So no matter who builds and pushes HTML from where, the live site gets the widget unconditionally.tools/inject_ask_widget.py는 모든 *.html의 </body> 앞에 ask.js 로더를 넣는다(이미 ask.js/i18n.js 있으면·StatiCrypt 잠금·*.unencrypted 은 건너뜀). 그래서 누가 어디서 HTML을 만들어 push해도 라이브엔 위젯이 무조건 붙는다.

2-3. My Claude bot — via subscription (no API billing)2-3. 내 Claude 봇 — 구독으로 (API 결제 없음)

assets/ask-bot-server/server.py is a small HTTP server (/ask) wrapping the Claude Agent SDK (claude-agent-sdk). It runs on the subscription by reusing the local claude login (= claude setup-token) (no separate ANTHROPIC_API_KEY needed). Same official SDK path as ce_slack_bot — not a workaround that injects a token into the raw API. Options: WebSearch, CORS, ACCESS_TOKEN gate, edit mode.assets/ask-bot-server/server.py는 Claude Agent SDK(claude-agent-sdk)를 감싼 작은 HTTP 서버(/ask)다. 로컬 claude 로그인(=claude setup-token)을 그대로 써서 구독으로 돈다(별도 ANTHROPIC_API_KEY 불필요). ce_slack_bot과 같은 공식 SDK 경로 — raw API에 토큰을 꽂는 우회가 아니다. 옵션: WebSearch, CORS, ACCESS_TOKEN 게이트, 편집 모드.

2-4. To use it on the live site — https tunnel2-4. 라이브에서 쓰려면 — https 터널

The live site is https, so it can't call http://127.0.0.1 (the bot) directly (mixed-content block). So a cloudflared tunnel puts a public https URL in front of the bot. For security, tunnel mode forces read-only (edit OFF).라이브 사이트는 https라 http://127.0.0.1(봇)을 직접 못 부른다(mixed-content 차단). 그래서 cloudflared 터널로 봇 앞에 공개 https URL을 씌운다. 보안상 터널 모드는 읽기전용 강제(편집 OFF).

3. How to inspect info (what's running · URL · token)3. 정보 보는 법 (어디 떠있나 · URL · 토큰)

cat ~/.askbot/askbot-pub.txt  # 공개 터널 봇: URL + 토큰

# 3) 포트 · 프로세스
lsof -nP -iTCP -sTCP:LISTEN | grep -E ':8787|:8788|:8000'
pgrep -fl 'server.py|cloudflared|http.server'

# 4) 토큰 — 실행 중 프로세스 env 에서 직접
ps eww $(pgrep -f 'ask-bot-server/server.py') | tr ' ' '\n' | grep ACCESS_TOKEN=

First launch on another Mac (new machine). Just two more things on top of the setup above:
① Clone the repo — git clone https://github.com/HAN-oQo/HAN-oQo.github.io.git && cd HAN-oQo.github.io
② The bot runs on that Mac's claude subscription → a claude login on that Mac is required (running without SKIP_TOKEN does a one-time setup-token browser auth).
③ To push in edit mode, that Mac needs GitHub push credentials (this repo uses a gh-token credential helper). Without them the bot can commit but push fails → run gh auth login on that Mac. Without push rights, that Mac is limited to "local edit · preview" and nothing reaches the live site.
After that it's the same as this Mac: SKIP_TOKEN=1 PYTHON=~/ask-bot-venv/bin/python bash assets/ask-bot-server/launch.sh (or TUNNEL=1 …). Info: cat ~/.askbot/*.txt.다른 맥(새 머신)에서 처음 띄울 때. 위 준비에 두 가지만 더:
① 레포 클론 — git clone https://github.com/HAN-oQo/HAN-oQo.github.io.git && cd HAN-oQo.github.io
② 봇은 그 맥의 claude 구독으로 돈다 → 그 맥에서 claude 로그인 필수(SKIP_TOKEN 없이 실행하면 setup-token 브라우저 인증 1회).
③ 편집 모드로 push까지 하려면 그 맥에 GitHub push 자격증명이 있어야 한다(이 레포는 gh 토큰 credential helper). 없으면 봇이 commit은 해도 push는 실패 → 그 맥에서 gh auth login. push 권한이 없으면 그 맥에선 "로컬 편집·프리뷰"까지만 가능하고 라이브 반영은 안 된다.
그 뒤는 이 맥과 동일: SKIP_TOKEN=1 PYTHON=~/ask-bot-venv/bin/python bash assets/ask-bot-server/launch.sh (또는 TUNNEL=1 …). 정보는 cat ~/.askbot/*.txt.

6. Security model (why only I can do it)6. 보안 모델 (왜 나만 가능한가)

  • The edit bot binds only to 127.0.0.1. From someone else's browser, 127.0.0.1:8787 is their own PC, so it can't reach my bot. If the server is in edit mode and you try to launch it on an external address, it refuses to start (with a FORCE_REMOTE_EDIT exception).편집 봇은 127.0.0.1에만 바인딩. 남의 브라우저에서 127.0.0.1:8787은 그 사람 PC라 내 봇엔 못 닿는다. 서버는 편집 모드인데 외부 주소로 띄우려 하면 기동 거부(FORCE_REMOTE_EDIT 예외).
  • URL·token live only in my browser localStorage / home directory. Visitors default to Groq, so they don't even know the bot exists.URL·토큰은 내 브라우저 localStorage·홈 디렉터리에만. 방문자는 기본 Groq라 봇 존재 자체를 모른다.
  • The real lock = GitHub push rights. The bot just calls git on my Mac; a push only goes through with my credentials. Even if someone clones the repo and runs the bot, it only affects their own fork — they can't push to my site.실제 잠금 = GitHub push 권한. 봇은 그냥 내 맥에서 git을 호출할 뿐, push는 내 자격증명이 있어야 통과한다. 남이 레포를 클론해 봇을 띄워도 자기 fork에만 영향, 내 사이트엔 push 불가.
  • The tunnel (public) forces read-only. Exposing a file-edit + shell + git bot on public https would be RCE, so tunnel mode has edit OFF.터널(공개)은 읽기전용 강제. 공개 https에 파일편집+셸+git 봇을 노출하면 RCE라서, 터널 모드는 편집 OFF.
The reality of the public tunnel — honestly. The askbot-pub tunnel is reachable from the internet. Anyone who knows both the URL and the ACCESS_TOKEN can call it — i.e. burn my subscription on Q&A (no edit/push; being read-only limits the damage to "quota consumption + arbitrary questions"). The only lock is the token. ALLOW_ORIGIN (CORS) only blocks cross-origin requests from a browser — it can't stop curl or scripts, so it's not a security boundary. The URL is random and ephemeral so it's hard to guess, but it's not secret-grade (it can leak via logs).공개 터널의 현실 — 솔직히. askbot-pub 터널은 인터넷에서 접근 가능하다. 그 URL과 ACCESS_TOKEN을 둘 다 아는 사람은 누구나 호출할 수 있다 — 즉 내 구독을 소모해 Q&A를 시킬 수 있다(편집·push는 불가, 읽기전용이라 피해는 "쿼터 소모 + 임의 질문"으로 한정). 유일한 잠금은 토큰이다. ALLOW_ORIGIN(CORS)은 브라우저의 타 출처 요청만 막을 뿐 curl·스크립트는 못 막는다 — 보안 경계가 아니다. URL은 랜덤·일회성이라 추측은 어렵지만 비밀급은 아니다(로그로 샐 수 있음).
  • How to lock it down. ① When not in use, kill it with tmux kill-session -t askbot-pub (zero public exposure). ② To revoke, restart the tunnel (new URL) + a new ACCESS_TOKEN. ③ If you need real authentication, put a named Cloudflare Tunnel + Cloudflare Access (login) in front. ④ If you don't want external access at all, use the local bot (localhost) only and use Groq / your own key on the live site.잠그는 법. ① 안 쓸 땐 tmux kill-session -t askbot-pub 로 끈다(공개 노출 0). ② 회수하려면 터널 재시작(새 URL) + 새 ACCESS_TOKEN. ③ 진짜 인증이 필요하면 named Cloudflare Tunnel + Cloudflare Access(로그인) 를 앞에 둔다. ④ 외부 접근이 아예 싫으면 로컬 봇(localhost)만 쓰고 라이브에선 Groq/본인 키 사용.
  • Live https → local http bot is blocked by mixed-content. That's why live uses the tunnel (https) and editing uses local (http localhost).라이브 https → 로컬 http 봇은 mixed-content로 차단. 그래서 라이브는 터널(https), 편집은 로컬(http localhost).
What I don't do. Injecting the claude setup-token OAuth token directly into the raw API (= impersonating Claude Code) is outside the terms, so I didn't implement it. The subscription is used only via the official Agent SDK path.하지 않는 것. claude setup-token의 OAuth 토큰을 raw API에 직접 꽂는 우회(=Claude Code인 척 위장)는 약관 밖이라 구현하지 않았다. 구독은 공식 Agent SDK 경로로만 쓴다.

Common issues흔한 문제

  • "Unexpected token '<'" → wrong URL. Exactly http://127.0.0.1:8787/ask (// and /ask required).URL이 틀림. 정확히 http://127.0.0.1:8787/ask (//와 /ask 필수).
  • Bot won't connect on the live site → mixed-content. Use the local preview or the tunnel (https).라이브에서 봇 연결 안 됨 → mixed-content. 로컬 프리뷰에서 쓰거나 터널(https) 사용.
  • Edit mode doesn't work on the live site → intended behavior (tunnel = read-only).편집 모드가 라이브에서 안 됨 → 의도된 동작(터널=읽기전용).
  • Gemini limit: 0 → that account/region doesn't support the free tier. Use free Groq or pay.그 계정/지역 무료티어 미지원. Groq 무료 또는 결제.
  • "Failed to fetch" → it's the browser side, not the server (dead URL·mixed-content·CORS). In the console, localStorage.removeItem("ask-ai-url-bot"); location.reload() clears the old URL and falls back to the default (askbot.ce.moreh.dev/ask). For a new domain, add the Origin per §8.서버가 아니라 브라우저 쪽(죽은 URL·mixed-content·CORS). 콘솔에서 localStorage.removeItem("ask-ai-url-bot"); location.reload() 로 옛 URL 비우면 기본값(askbot.ce.moreh.dev/ask) 사용. 새 도메인이면 8장에서 Origin 추가.
  • A specific model returns "(no answer)"특정 모델 "(no answer)" → it ended on a ThinkingBlock with an empty result (fixed, server fallback). If it still fails, check journalctl -u ce-askbot.ThinkingBlock으로 끝나 result가 빈 경우였음(수정됨, 서버 폴백). 안 되면 journalctl -u ce-askbot 확인.
  • "who are you" doesn't show the model name"who are you"에 모델명 안 나옴 → normal. The Agent SDK overlays Claude's identity → the model: badge in the widget header is the real model.정상. Agent SDK가 Claude 정체성을 씌움 → 위젯 헤더의 모델: 배지가 실제 모델.

8-3. Common changes (all via ssh ce-master, sudo needed)8-3. 자주 하는 변경 (전부 ssh ce-master, sudo 필요)

# 0) 현재 설정 / 토큰 보기
sudo systemctl cat ce-askbot              # Environment= 줄 확인
sudo cat /srv/askbot/askbot.env           # 토큰

# 1) 블로그 도메인(Origin) 추가 — 새 사이트에서 위젯을 쓰려면 (쉼표 목록)
sudo sed -i 's|^Environment=ALLOW_ORIGINS=.*|Environment=ALLOW_ORIGINS=https://han-oqo.github.io,https://ce-blog.ce.moreh.dev,http://localhost:8000,https://새도메인|' /etc/systemd/system/ce-askbot.service
sudo systemctl daemon-reload && sudo systemctl restart ce-askbot

# 2) 기본 모델 바꾸기 (위젯이 model을 안 보낼 때 쓰임)
sudo sed -i 's|^Environment=ANTHROPIC_MODEL=.*|Environment=ANTHROPIC_MODEL=claude-moreh-Qwen3.6-27B|' /etc/systemd/system/ce-askbot.service
sudo systemctl daemon-reload && sudo systemctl restart ce-askbot

# 3) 서빙 중인 모델 목록 보기
curl -s http://192.168.2.15:30088/v1/models | python3 -m json.tool          # 게이트웨이 직접
TOK=$(sudo cat /srv/askbot/askbot.env | cut -d= -f2)
curl -s https://askbot.ce.moreh.dev/models -H "x-access-token: $TOK"        # 위젯이 보는 목록

# 4) 토큰 교체(노출 시) — 교체 후 두 블로그 위젯 ⚙에 새 토큰 재입력 필요
NEW=$(openssl rand -hex 24); echo "ACCESS_TOKEN=$NEW" | sudo tee /srv/askbot/askbot.env >/dev/null
sudo chmod 600 /srv/askbot/askbot.env; sudo systemctl restart ce-askbot; echo "새 토큰: $NEW"

# 5) 서버 코드 업데이트 (레포에서 server.py 고친 뒤 — 정본 동기화)
scp assets/ask-bot-server/server.py ce-master:/tmp/s.py
ssh ce-master 'sudo cp /tmp/s.py /srv/askbot/server.py && sudo systemctl restart ce-askbot'

# 6) 로그 / 상태 / 재시작
sudo journalctl -u ce-askbot -n 50 --no-pager
systemctl is-active ce-askbot
sudo systemctl restart ce-askbot
