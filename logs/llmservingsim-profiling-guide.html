1. Why this document is needed1. 왜 이 문서가 필요한가

LLMServingSim 2.0 operates with a LLMServingSim 2.0은 "cost table + behavior model""비용 표 + 행동 모델" structure (see 구조로 동작 (자세한 건 Frontier note §3-1Frontier 노트 §3-1 for details). The essentials: 참고). 핵심은:

  • cost table = per-op latency CSV per (HW × model × dtype × TP)cost table = (HW × 모델 × dtype × TP) 별 op 지연 CSV
  • With this table, the sim runs without a GPU. Without it, it cannot run.이 표가 있으면 sim은 GPU 없이 돌아감. 없으면 못 돔.

The repo ships with CSVs for some combinations pre-built by the KAIST team. To use any other (HW, model) combo you must build it yourself. This document covers the full workflow for that.레포에는 KAIST 팀이 미리 만들어둔 일부 조합 CSV가 들어있음. 다른 (HW, 모델) 조합을 쓰려면 직접 만들어야 함. 이 문서는 그 작업의 전체 흐름.

6. Step-by-step — new HW × model profile (most common case)6. Step-by-step — 새 HW × 모델 프로파일 (가장 흔한 경우)

1Launch the vLLM container (on the GPU machine)vLLM 컨테이너 띄우기 (GPU 머신에서)

cd ~/LLMServingSim
export HF_TOKEN=hf_xxxxxxxxxx       # gated 모델 받으려면
bash scripts/docker-vllm.sh
# → vllm_docker 라는 별도 컨테이너 띄움, --gpus all 자동 적용

2Edit variables in profiler/profile.sh 변수 편집

Only the variables at the top of the script need editing:스크립트 상단의 변수만 손대면 됨:

MODEL="Qwen/Qwen3-32B"        # HF 이름 (config.json 자동 다운)
HARDWARE="H100"                # 자유 라벨 (perf/<이거>/ 폴더가 됨)
TP_DEGREES="1,2,4"             # 측정할 TP 차수 (반드시 1 포함)
MAX_NUM_BATCHED_TOKENS=2048
MAX_NUM_SEQS=256
MEASUREMENT_ITERATIONS=3       # 5로 올리면 분산 ↓, ~1.67× 느려짐
# SKIP_SKEW=1                  # skew sweep 스킵 (분 단위 단축)

3Execute실행

docker exec vllm_docker bash -c "cd /workspace && ./profiler/profile.sh"

Internal behavior:내부 동작:

  1. Read configs/model/<MODEL>.json (auto-downloads from HF + caches if missing) 읽음 (없으면 HF에서 자동 다운로드 + 캐싱)
  2. Match profiler/models/<type>.yaml using the 매칭, model_type field in 의 config.json 의
  3. Write a model config in a tmpdir and bring up the vLLM enginetmpdir에 model config 써놓고 vLLM 엔진 띄움
  4. Four grid sweeps4가지 grid sweep: dense / per_sequence / attention / moe → write CSVs: dense / per_sequence / attention / moe → CSV 작성
  5. (default) heterogeneous decode (기본) heterogeneous decode skew sweepskew sweep → α-law fitting → → α-law fitting → skew_fit.csv
  6. Write meta.yaml (records vllm_version, cuda_version, gpu, etc.) 작성 (vllm_version, cuda_version, gpu 등 환경 기록)

4Live progress monitoring (optional)실시간 진행 모니터링 (선택)

# 다른 터미널에서
docker logs -f vllm_docker

Each sweep stage starts with a header like "Profiling dense:" or "Profiling attention:". If interrupted and rerun, already-completed shots are skipped (resume feature, can be disabled with the 각 sweep 단계가 "Profiling dense:", "Profiling attention:" 같은 헤더로 시작. 중단됐다 다시 실행하면 이미 한 shot은 skip (resume 기능, FORCE=1 env var). 환경변수로 무효화 가능).

7. Authoring a new model architecture YAML (rare case)7. 새 모델 아키텍처 YAML 작성 (드문 케이스)

If the target model isn't in the §3 YAML list, write a new 대상 모델이 §3 YAML 목록에 없으면 profiler/models/<model_type>.yaml. Use 을 새로 작성. qwen3.yaml as a template:을 템플릿으로:

# profiler/models/<model_type>.yaml
sequence:
  prologue:  [embedding]
  pre_attn:  [layernorm, qkv_proj, qk_norm, rotary_emb, attention]
  post_attn: [o_proj, layernorm]
  mlp_dense: [gate_up_proj, act_fn, down_proj]
  mlp_moe:   []                # MoE면 [router, experts, ...]
  head:      [final_layernorm, lm_head, sampler]

catalog:
  dense:
    embedding:     {vllm: VocabParallelEmbedding}
    layernorm:     {vllm: RMSNorm, within: <DecoderLayer클래스명>, tp_stable: true}
    qkv_proj:      {vllm: QKVParallelLinear}
    rotary_emb:    {vllm: RotaryEmbedding}
    o_proj:        {vllm: RowParallelLinear, within: <Attention클래스명>}
    gate_up_proj:  {vllm: MergedColumnParallelLinear}
    act_fn:        {vllm: SiluAndMul}
    down_proj:     {vllm: RowParallelLinear, within: <MLP클래스명>}
    final_layernorm: {vllm: RMSNorm, within: <CausalLM클래스명>, tp_stable: true}
    lm_head:       {vllm: ParallelLMHead}
    sampler:       {vllm: Sampler}

Each entry's 각 항목의 vllm: field is the class name from the vLLM source ( 필드는 vLLM 소스 (vllm/model_executor/models/<model>.py). Fill the catalog by reading that Python file and mapping classes.)의 클래스 이름. 카탈로그 채우려면 그 파이썬 파일을 읽으면서 매핑.

7-1. tp_stable meaning 의미

Ops marked tp_stable: true are measured once at TP=1 and copied to other TP folders. Applies to layers whose time is invariant to TP, such as layernorm. Mislabeling (e.g. marking a TP-dependent op as stable) will skew sim results at other TPs.로 표시한 op는 TP=1로 한 번만 측정하고 다른 TP 폴더로 복제. layernorm 처럼 TP에 따라 시간이 변하지 않는 layer가 해당. 잘못 표시하면 (예: 실제론 TP-dependent한데 stable로 표시) 다른 TP에서 sim 결과가 틀어짐.

7-2. Verification7-2. 검증

After writing YAML, YAML 작성 후 measure both TP=1 and TP=2TP=1 + TP=2 둘 다 측정 and compare 해서 tp1/dense.csv vs 와 tp2/dense.csv. Rows marked 를 비교. tp_stable should be nearly identical (within ~5%) across the two files.로 표시한 row가 두 파일에서 거의 동일하면 (~5% 이내) 맞음.

8. Output artifact structure8. 산출물 구조

profiler/perf/H100/Qwen/Qwen3-32B/bf16/
├── meta.yaml                  # vllm_version, cuda_version, gpu, 측정 옵션
├── tp1/
│   ├── attention.csv          # (prefill_chunk, kv_prefill, n_decode, kv_decode) → time_us
│   ├── dense.csv              # (layer, tokens) → time_us
│   ├── per_sequence.csv       # (layer, sequences) → time_us
│   ├── moe.csv                # (tokens, experts) → time_us (MoE 모델만)
│   ├── skew.csv               # heterogeneous decode 측정 raw
│   └── skew_fit.csv           # α-law fitting 계수
├── tp2/
└── tp4/
Measuring only TP=1 lets other TPs be auto-derivedTP=1만 측정해도 다른 TP는 자동 derive 가능 — TP-stable layers (e.g. layernorm) are measured once and copied to every TP folder. Only TP-dependent layers (QKV/FFN GEMM) are measured separately per TP. — TP-stable layer (layernorm 등)는 한 번만 측정하고 모든 TP 폴더로 복제됨. TP에 의존하는 layer (QKV/FFN GEMM)만 각 TP에서 따로 측정.
