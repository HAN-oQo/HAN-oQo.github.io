one-line summary한 줄 요약
  • One Llama-3.1-70B user at a 1M-token context needs ~320 GB of KV cache, 4× an H100's whole HBM (NVIDIA's figure). It can't live on the GPU.
  • CMX makes the KV cache a tiered, cluster-wide memory: hot on GPU HBM, warm on CPU DRAM, cold on NVMe SSD. cuFile moves it GPU↔NVMe directly, a BlueField-4 DPU schedules it off the host CPU, NIXL shares it across nodes.
  • It pays off because reloading a cached prefix from NVMe is faster than recomputing it.
  • The idea isn't new (LMCache / Mooncake / DeepSeek already tier KV to disk). What's new is standardization + hardware offload.
  • 1M 토큰 컨텍스트에서 Llama-3.1-70B 사용자 한 명의 KV 캐시는 ~320 GB로 H100 HBM 전체의 4배다(NVIDIA 공식 수치). GPU에 올릴 수 없다.
  • CMX는 KV 캐시를 계층화된 클러스터 전역 메모리로 만든다. hot은 GPU HBM, warm은 CPU DRAM, cold는 NVMe SSD에 두고, cuFile이 GPU↔NVMe로 직접 옮기며, BlueField-4 DPU가 호스트 CPU 밖에서 스케줄링하고, NIXL이 노드 간에 공유한다.
  • 캐시된 prefix를 NVMe에서 다시 읽는 게 재계산보다 빠르기 때문에 수지가 맞는다.
  • 아이디어 자체는 새롭지 않다(LMCache/Mooncake/DeepSeek이 이미 KV를 디스크로 계층화한다). 새로운 건 표준화 + 하드웨어 오프로드다.

Glossary용어집

KV cacheKV 캐시

Per-token keys/values attention reuses instead of recomputing the prompt. Grows linearly with context and overflows GPU memory.어텐션이 재계산 대신 재사용하는 토큰별 key/value. 컨텍스트 길이에 비례해 커져 GPU 메모리를 넘친다.

CMX / ICMSP

NVIDIA's platform standardizing KV-cache tiering GPU HBM → CPU DRAM → NVMe. "ICMSP" is the longer form from the announcement URL.KV 캐시 계층화(GPU HBM → CPU DRAM → NVMe)를 표준화한 NVIDIA 플랫폼. "ICMSP"는 발표 URL에 쓰인 긴 이름이다.

cuFile / GPUDirect StoragecuFile / GPUDirect Storage

API that moves data between GPU memory and NVMe without going through the CPU.GPU 메모리와 NVMe 사이 데이터를 CPU를 거치지 않고 옮기는 API.

BlueField-4 DPUBlueField-4 DPU

DPU (800 Gb/s net + 64-core Grace CPU) that runs KV I/O scheduling and eviction off the host CPU. Ships H2 2026.KV I/O 스케줄링·축출을 호스트 CPU 밖에서 돌리는 DPU(800 Gb/s 네트워크 + 64코어 Grace CPU). H2 2026 출시.

NIXL

NVIDIA Inference Transfer Library: moves KV blocks across a cluster (NVLink, InfiniBand RDMA, PCIe, TCP fallback) under Dynamo.NVIDIA Inference Transfer Library. Dynamo 아래에서 KV 블록을 클러스터 전역으로 옮긴다(NVLink, InfiniBand RDMA, PCIe, TCP 폴백).

prefix reuseprefix 재사용

Reusing the computed KV of a shared prefix (system prompt, RAG doc, chat history). The workload CMX targets.공유 prefix(시스템 프롬프트·RAG 문서·대화 이력)의 KV를 재계산 없이 재사용하는 것. CMX가 겨냥한 워크로드다.

1Why now — the KV-cache memory wall왜 지금인가: KV 캐시 메모리 벽

Million-token context windows, reasoning models with long chains of thought, and multi-turn agents arrived together, and all three inflate the KV cache. Per NVIDIA, one Llama-3.1-70B user at 1M tokens needs ~320 GB, four times an entire H100's HBM. It physically cannot stay on the GPU. 100만 토큰 컨텍스트, 긴 사고사슬을 내는 추론 모델, 여러 턴을 이어 가는 에이전트가 한꺼번에 왔고, 셋 다 KV 캐시를 키운다. NVIDIA에 따르면 1M 토큰에서 Llama-3.1-70B 사용자 한 명의 KV 캐시는 ~320 GB로 H100 HBM 전체의 4배다. GPU에 둘 수가 없다.

Fig 1 · The memory wall (128K already caps an H100 at 1–2 users). Figures: NVIDIA / Spheron guide; diagram original.그림 1 · 메모리 벽(128K에서도 H100 동시 사용자는 1–2명). 수치: NVIDIA/Spheron 가이드, 직접 그림.

2The unlock — loading beats recomputing전환점: 읽는 게 재계산보다 빠르다

Tiering to disk only pays if fetching the cache back is cheaper than redoing the work, and that has now flipped. Per the Spheron guide (128K-token prefix, H100): 디스크 계층화는 캐시를 되가져오는 쪽이 다시 계산하는 쪽보다 쌀 때만 의미가 있는데, 이제 그렇게 됐다. Spheron 가이드 기준(128K prefix, H100):

  • Recompute from scratch: ~11 s.
  • Reload ~40 GB of KV from NVMe: about 6 s.
  • Warm block (real prefix-cache hit): ~0.8 s.
  • 1M-token RAG prefill: ~90 s to recompute vs ~8 s to load.
  • 처음부터 재계산: ~11초.
  • NVMe에서 ~40 GB KV 다시 읽기: 약 6초.
  • 아직 warm인 블록(진짜 prefix 캐시 히트): ~0.8초.
  • 1M 토큰 RAG prefill: 재계산 ~90초 vs 로드 ~8초.

Fast SSDs plus GPU-direct transfer made storage cheaper than compute for long, reused prefixes. That is why CMX exists now. 빠른 SSD와 GPU 직접 전송 덕분에 길고 재사용되는 prefix에서는 스토리지가 연산보다 싸졌다. CMX가 지금 나온 이유다.

Fig 2 · Recompute vs NVMe load vs warm hit. Spheron guide's illustrative figures; diagram original.그림 2 · 재계산 vs NVMe 로드 vs warm 히트. Spheron 가이드 예시값, 직접 그림.

3What CMX is — three tiers + a DPUCMX란: 3계층 + DPU

CMX treats the KV cache like a CPU memory hierarchy. Hot blocks (active generation) stay in GPU HBM, warm blocks (finished requests likely to be reused) move to CPU DRAM, and cold blocks (historical context, evicted prefixes) land on NVMe SSD. cuFile, the DPU and NIXL make the movement cheap (Fig 3). CMX는 KV 캐시를 CPU 메모리 계층처럼 다룬다. Hot 블록(생성 중)은 GPU HBM에, warm 블록(재사용될 만한 완료 요청)은 CPU DRAM에, cold 블록(과거 컨텍스트, 축출된 prefix)은 NVMe SSD에 둔다. 이동 비용은 cuFile, DPU, NIXL이 낮춘다(그림 3).

Fig 3 · The three-tier KV hierarchy. Bandwidth/latency per the Spheron guide & NVIDIA; diagram original.그림 3 · 3계층 KV 구조. 대역폭/지연 수치는 Spheron 가이드·NVIDIA 기준, 직접 그림.

The BlueField-4 is the genuinely new hardware: 800 Gb/s networking, a 64-core Grace CPU complex and hardware crypto/CRC, i.e. a storage-and-network computer between the GPUs and the SSDs. It ships in H2 2026, so today the same tiering runs software-only (§4). 진짜 새 하드웨어는 BlueField-4다. 800 Gb/s 네트워킹, 64코어 Grace CPU 복합체, 하드웨어 암호/CRC를 갖춘, GPU와 SSD 사이의 스토리지·네트워크 컴퓨터다. H2 2026 출시라서 지금은 같은 계층화를 소프트웨어로만 돌린다(§4).

4What's special, and when it helps뭐가 특별한가, 언제 도움되나

Spilling the KV cache to CPU DRAM and NVMe is not new. LMCache (open-source, Apache-2.0) does it in software today, and Mooncake and DeepSeek's NVMe cache prove it in production. NVIDIA adds two things: KV 캐시를 CPU DRAM·NVMe로 내리는 아이디어는 새롭지 않다. LMCache(오픈소스, Apache-2.0)가 이미 소프트웨어로 하고 있고, Mooncake와 DeepSeek의 NVMe 캐시가 프로덕션에서 검증했다. NVIDIA가 더하는 것은 두 가지다.

  1. Standardization: one platform plus a storage-partner ecosystem (VAST, WEKA, DDN, Dell, HPE, IBM, Pure Storage…), so KV tiering becomes a product you buy instead of a system you hand-build.
  2. Hardware offload: the BlueField-4 DPU moves I/O scheduling, eviction and tier movement off the host CPU, aiming to cut tail latency at high concurrency.
  1. 표준화: 한 플랫폼과 스토리지 파트너 생태계(VAST·WEKA·DDN·Dell·HPE·IBM·Pure Storage…)로 KV 계층화를 직접 짜는 시스템이 아니라 사서 쓰는 제품으로 만든다.
  2. 하드웨어 오프로드: BlueField-4 DPU가 I/O 스케줄링·축출·계층 이동을 호스트 CPU 밖으로 옮겨, 고동시성에서 tail latency를 줄이려 한다.

The net effect: the KV cache goes from ephemeral, GPU-only to tiered, persistent, cluster-shared memory, and the storage industry enters the inference stack. 결과적으로 KV 캐시는 휘발성·GPU 전용에서 계층화·영속·클러스터 공유 메모리가 되고, 스토리지 산업이 추론 스택 안으로 들어온다.

✓ Helps most when prefixes repeat✓ prefix가 반복될 때 이득

Multi-turn agents; reasoning models (long CoT); 1M-token RAG with reused documents; a shared system prompt across thousands of chats; 512K+ context serving.멀티턴 에이전트, 추론 모델(긴 CoT), 문서를 재사용하는 1M RAG, 수천 개 대화가 공유하는 시스템 프롬프트, 512K+ 컨텍스트 서빙.

✗ No benefit (or slightly worse)✗ 이득 없음 (혹은 약간 손해)

Short-context, single-turn inference with no prefix overlap. There's nothing to reload, and the guide notes DPU scheduling overhead can add a little latency.짧은 컨텍스트·단일턴에 prefix 겹침이 없는 경우. 다시 읽을 캐시가 없고, 가이드에 따르면 DPU 스케줄링 오버헤드로 지연이 조금 늘 수 있다.

Read the numbers carefully (vendor-reported)수치는 조심해서 (벤더 발표)

NVIDIA's headline "up to 5× tokens/sec" and "5× power efficiency" are from the CES 2026 announcement, and "up to 20× time-to-first-token" is from partner benchmarks, all on the most favorable high-prefix-reuse workloads. The guide's per-million-token cost tables are Spheron's June-2026 pricing. Treat these as best-case marketing figures. The checkable fact is the load-vs-recompute crossover in §2. NVIDIA의 대표 수치 "최대 5× tokens/sec", "5× 전력효율"은 CES 2026 발표에서, "최대 20× TTFT"는 파트너 벤치마크에서 나왔고, 모두 prefix 재사용이 가장 많은 유리한 워크로드 기준이다. 가이드의 백만 토큰당 비용 표는 Spheron의 2026년 6월 가격이다. 보장이 아닌 베스트케이스 마케팅 수치로 봐야 한다. 직접 확인할 수 있는 사실은 §2의 로드 vs 재계산 손익분기다.

Editor's note — our take (not NVIDIA's claim)편집자 주: 우리 관점 (NVIDIA 주장 아님)

  1. Separate the idea from the hardware. The load-beats-recompute crossover and three-tier KV cache are vendor-neutral and available now via LMCache, including on our MI250 / AMD boxes (fast NVMe + software tiering + prefix caching).
  2. The BlueField-4 / cuFile / NIXL layer is the NVIDIA-locked accelerator on top. It lowers CPU overhead and tail latency, but arrives H2 2026 and ties you to NVIDIA DPUs + partner storage.
  3. For a heimdall-style gateway, before reaching for special hardware: maximize prefix reuse and give the cache a real second tier.
  1. 아이디어와 하드웨어를 나눠 봐야 한다. 로드가 재계산보다 빠르다는 손익분기와 3계층 KV 캐시는 벤더 중립이고 LMCache로 지금 쓸 수 있다. MI250/AMD 박스에서도 빠른 NVMe, 소프트웨어 계층화, prefix 캐싱만으로 이득을 본다.
  2. BlueField-4/cuFile/NIXL 계층은 그 위에 얹는 NVIDIA 종속 가속기다. CPU 부담과 tail latency를 낮추지만 H2 2026에 나오고 NVIDIA DPU와 파트너 스토리지에 묶인다.
  3. heimdall류 게이트웨이라면 특수 하드웨어보다 먼저 prefix 재사용을 극대화하고 캐시에 진짜 두 번째 계층을 주는 게 실무 교훈이다.
