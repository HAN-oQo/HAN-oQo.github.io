1 Problem — erasing a span post-prefill has global KV fallout 문제 정의: prefill 이후의 삭제는 KV 전체에 번진다

When would you need to erase after prefill?prefill 뒤에 지워야 하는 경우

Pipelines often prefill retrieved documents before the query exists, so a span sometimes has to go after prefill: 요즘 파이프라인은 쿼리가 오기 전에 검색 문서를 미리 prefill한다. 그래서 prefill 뒤에 구간을 지워야 할 때가 생긴다.

  • A RAG passage turns out to be outdated mid-stream.
  • User data must be wiped on request (GDPR/right-to-be-forgotten).
  • A stale fact one session put into a shared KV prefix cache must be cleaned before another session reuses it.
  • 검색한 RAG 문서 하나가 낡은 정보로 밝혀진다.
  • GDPR/삭제권 요청으로 사용자 데이터를 지워야 한다.
  • 공유 KV prefix 캐시에 한 세션이 넣은 잘못된 사실을 다른 세션이 쓰기 전에 치워야 한다.

"a RAG system may prefill retrieved passages before discovering an out-of-date fact"

— §1 · 원문 보기 (§1)

Why the naive fix — delete and shift — breaks"지우고 당기기"가 실패하는 이유

Deleting the tokens from the KV cache and sliding the rest together fails for two reasons: 문제 토큰을 KV 캐시에서 지우고 나머지를 당기는 방법은 두 가지 이유로 실패한다.

  1. RoPE invariance. Suffix tokens move to new positions, but their cached K/Q still encode the old ones, so attention sees wrong distances. Cached vectors cannot be patched in place.
  2. KV contamination. Every suffix token attended to e during prefill and already "absorbed" its signal. Deleting e's rows does not undo that.
  1. RoPE 불변성. suffix 토큰의 위치는 바뀌었는데 캐시된 K/Q는 옛 위치를 담고 있어 어텐션이 거리를 잘못 본다. 캐시된 벡터를 그 자리에서 고칠 방법은 없다.
  2. KV 오염. 위치 문제가 없어도 suffix 토큰은 prefill 때 e를 어텐션하며 그 정보를 "흡수"했다. e의 KV 행을 지워도 이 신호는 남는다.

"the KV cache of the first m−1 tokens remains valid after deleting e, whereas the cache of the remaining T−n tokens is contaminated by the erased span."

— §2 · 원문 보기 (§2)

"directly removing the erased span's KV cache and reusing the rest can result in complete failure."

— §3 Related Work · 원문 보기 (§3)

The standard cure — and its cost표준 처방과 그 비용

The reliable baseline re-runs prefill over p + s (e removed). The KV is exact, but cost scales with suffix length |s|, not |e|. At 32K with |e| = 512, you recompute 31K tokens, a 17.6× overhead. 확실한 기준선은 e를 뺀 p + s로 prefill을 다시 돌리는 것이다. KV는 정확하지만 비용이 |e|가 아니라 suffix 길이 |s|에 비례한다. 32K 컨텍스트에서 |e| = 512면 31K 토큰을 다시 계산하고, 원래 prefill의 17.6× 오버헤드가 든다.

"Its computational cost is therefore governed by suffix length rather than deleted-span length."

— §1 · 원문 보기 (§1)

The paper asks whether this suffix-length dependence can be broken. 논문은 이 suffix 길이 의존성을 끊을 수 있는지 묻는다.

"can post-hoc context erasing be performed directly in KV space, without rerunning prefill on the suffix?"

— §1 · 원문 보기 (§1)

Prior context editing (GRACE, MEMIT, InContext editing) works at decode time. It adds a competing signal but does not rewrite cached states. 기존 문맥 편집 연구(GRACE, MEMIT, InContext editing)는 디코딩 시점에 동작한다. 경쟁 신호를 더할 뿐 캐시된 상태를 다시 쓰지는 않는다.

"after prefill, the suffix KV states have already been contaminated, so a later instruction can only compete with stored evidence at decoding time rather than rewrite the cached states themselves."

— §1 · 원문 보기 (§1)

2 Method — surrogate cache via learned steering states 해결 방법: 학습된 스티어링 상태로 대리 캐시 만들기

"The main challenge of context erasing is that the edit is local, but its effect on the KV cache is global."

— §4 · 원문 보기 (§4)

Key insight: don't reconstruct — substitute핵심 아이디어: 재구성 대신 대체

Rather than reconstruct the exact cache of p + s, KVEraser builds a surrogate cache that leaves suffix KV untouched. This works only if the block placed in the deleted interval compensates for the contamination e left in the suffix. KVEraser는 p + s의 정확한 캐시를 다시 만드는 대신 suffix KV는 그대로 둔 대리 캐시를 만든다. 단, 지운 구간 자리에 넣는 블록이 e가 suffix에 남긴 오염을 상쇄해야 한다.

"Instead of reconstructing the exact edited cache KV(x̃), it constructs a surrogate cache by replacing only the erased interval and reusing the remaining cache unchanged."

— §4.1 · 원문 보기 (§4.1)

The surrogate cache formula대리 캐시 공식

Given a sequence x = (x1:m-1, xm:n, xn+1:T) where xm:n = e is the erased span, the surrogate cache is: 시퀀스 x = (x1:m-1, xm:n, xn+1:T)에서 xm:n = e가 지울 구간일 때 대리 캐시는 다음과 같다. 

KV̂(x; m, n)  =  KV₁:m₋₁(x)  ⊕  KVˢᵗᵉᵉʳ(x; m, n)  ⊕  KVₙ₊₁:T(x)
                 ───────────     ──────────────────     ──────────────
                 prefix KV        steering states         suffix KV
                 (unchanged)       (learned by Eφ)       (reused as-is)

The steering states KVsteer are the only learned part. Sitting in the deleted-span slots, they "undo" contamination in the reused suffix KV. The frozen generator θ (Qwen3-8B) decodes over this cache as if it were real prefill output. 학습되는 부분은 스티어링 상태 KVsteer 하나다. 지운 구간 자리에 들어가 재사용한 suffix KV의 오염을 "되돌린다". 동결된 생성기 θ(Qwen3-8B)는 이 캐시를 실제 prefill 결과처럼 보고 디코딩한다.

What the eraser sees — and what it does noteraser가 보는 것과 보지 않는 것

The eraser Eφ sees only the prefix and erased-span tokens, not the downstream query u. Eraser Eφ의 입력은 prefix 토큰과 지울 구간 토큰뿐이다. 이후에 올 쿼리 u는 보지 않는다.

"the downstream query u does not define the edit itself; it only probes the edited cache after erasure."

— §4.1 · 원문 보기 (§4.1)

So the steering states must work for any query, which forces the eraser to compensate for contamination instead of predicting specific answers. 그래서 스티어링 상태는 어떤 쿼리에도 통해야 한다. eraser는 특정 답을 맞히는 대신 오염 자체를 보정하도록 학습된다.

Complexity: swapping suffix-length for span-length복잡도: suffix 길이 대신 span 길이

The eraser runs over (m-1) + |e| tokens and reuses suffix KV for free: O(|e|(|p| + |e|)) versus O(|s|(|p| + |s|)) for full recomputation. At 32K with a 512-token span after a 2K prefix, that is ~17.6× faster. Eraser는 prefix와 지울 구간, 즉 (m-1) + |e| 토큰만 처리하고 suffix KV는 계산 없이 재사용한다. 비용은 O(|e|(|p| + |e|))로, 전체 재계산의 O(|s|(|p| + |s|))보다 작다. 2K prefix 뒤에 512 토큰 구간이 있는 32K 컨텍스트라면 약 17.6배 빠르다.

"KVEraser therefore replaces suffix-length dependence with erased-span-length dependence."

— §4.2 · 원문 보기 (§4.2)

3 Implementation — Qwen3-8B eraser, two-stage training 구현: Qwen3-8B eraser, 2단계 학습

Eraser architectureEraser 아키텍처

Eφ is a full Qwen3-8B backbone without the LM head, projected to K/V tensors of the generator's shape (32 layers × 2 × seq_len × hidden). The generator θ is also Qwen3-8B and stays frozen, so the steering states live in a compatible representation space. Eφ는 LM head를 뗀 Qwen3-8B 백본이고, 출력을 생성기 KV 모양(32 레이어 × 2 × seq_len × hidden)의 K/V 텐서로 투영한다. 생성기 θ도 Qwen3-8B이고 학습 내내 동결한다. 같은 모델 패밀리라서 스티어링 상태가 생성기와 맞는 표현 공간에 놓인다.

Training objective학습 목표

Loss is teacher-forced cross-entropy on answer tokens. For each (context, erased span, answer) triple, the eraser emits steering states, the surrogate cache is assembled, and the generator scores the reference answer. No contrastive or RL objective; only the eraser is trained. 손실은 답변 토큰에 대한 teacher-forced cross-entropy다. (컨텍스트, 지울 구간, 답변) 묶음마다 eraser가 스티어링 상태를 만들고, 대리 캐시를 조립한 뒤 생성기가 정답 토큰의 손실을 계산한다. 대조 학습이나 강화 학습 목표는 없고 eraser만 학습한다.

Reliability across context lengths컨텍스트 길이가 늘어도 안정적이다

"Among approximate methods, KVEraser is the only one that is reliable across the full 1K–32K range."

— §5.4 · 원문 보기 (§5.4)

Delete-and-shift and InContext degrade at long contexts where contamination is more diffuse. KVEraser holds EM ~0.879 because the eraser always sees the same-length span, not the growing suffix. 지우고 당기기와 InContext는 오염이 넓게 퍼지는 긴 컨텍스트에서 크게 무너진다. KVEraser는 EM ~0.879를 유지한다. eraser가 보는 것은 늘어나는 suffix가 아니라 길이가 같은 span이기 때문이다.

Latency scaling레이턴시: 길수록 유리하다

At 1K–4K the eraser's own forward pass dominates and full recompute is cheaper. From 8K+, recompute grows with suffix length while KVEraser stays fixed at prefix + span. The crossover is around 4K–8K tokens. 1K–4K처럼 짧을 때는 eraser의 순전파가 병목이라 전체 재계산이 더 싸다. 8K+부터는 재계산 비용이 suffix 길이를 따라 커지고 KVEraser는 prefix + span 비용에 머문다. 교차점은 4K–8K 토큰 부근이다.

Limitations and threats to validity한계와 타당성 위협

Limitations: 한계는 다음과 같다.

  1. Evaluated only on Qwen3-8B. Other families (Llama, Mistral, etc.) are unverified.
  2. Only single-span erasing. Multi-span or overlapping erases are not tested.
  3. NIAH and QA test specific retrieval cases. Open-ended generation is unknown.
  4. The 8B-parameter eraser adds sizable memory and compute.
  1. Qwen3-8B에서만 평가했다. 다른 모델 패밀리(Llama, Mistral 등)는 검증하지 않았다.
  2. 단일 span 삭제만 실험했다. 여러 구간이나 겹치는 삭제는 다루지 않는다.
  3. NIAH와 QA는 특정 검색 상황만 본다. 자유 생성에서도 통하는지는 모른다.
  4. 8B 파라미터 eraser는 메모리와 계산 부담이 크다.

5 Discussion — what KV-space steering unlocks 시사점: KV 공간 스티어링이 여는 가능성

"These results suggest that learned local KV steering is viable for efficient context erasing in long-context inference."

— §6 Conclusion · 원문 보기 (§6)

The paper's conclusions논문의 결론

A learned steering module can replace erased-span KV and answer correctly without touching suffix KV. The headline is 17.6× → +24% at 32K. Two-stage training (Wikipedia pre-training → task fine-tuning) takes under a day on 2×A100 80GB. 학습된 스티어링 모듈이 지운 구간의 KV를 대신하고, suffix KV를 건드리지 않고도 정확히 답할 수 있다. 대표 결과는 32K에서 17.6× → +24%다. 2단계 학습(Wikipedia 사전학습 → 태스크 파인튜닝)은 2×A100 80GB에서 하루 안에 끝난다.

Authors' stated future directions저자들이 밝힌 향후 방향

Three directions: 후속 과제는 세 가지다.

  1. Multi-span erasing: several non-contiguous spans at once.
  2. Cross-architecture generalization: erasers for families other than Qwen3.
  3. Privacy-sensitive applications: right-to-be-forgotten requests in shared KV prefix caches, where recomputation at scale is prohibitive.
  1. 다중 span 삭제: 떨어진 여러 구간을 한 번에 지운다.
  2. 크로스 아키텍처 일반화: Qwen3 외 모델 패밀리용 eraser를 학습한다.
  3. 개인정보 보호 응용: 공유 KV prefix 캐시에서 잊힐 권리 요청을 처리한다. 대규모에서는 재계산 비용을 감당하기 어렵다.

Editor's note — not the paper's claim편집자 주: 논문의 주장 아님 Why this matters for production serving: KV prefix caching already ships in vLLM's enable_prefix_caching and SGLang's RadixAttention. The obstacle to sharing prefixes across sessions is staleness: one changed span invalidates everything downstream. KVEraser points to surgical repair of only the affected slot. At 32K, 17.6× recompute vs +24% steering is roughly a 14× cut in per-eviction compute.

The catch for now: The eraser is 8B, the same size as the generator. A second 8B model pays off for high-throughput shared-prefix workloads but is overkill for single-user sessions. Whether a distilled or LoRA-based eraser can match EM 0.879 is the open question. 프로덕션 서빙에서의 의미: KV prefix 캐싱은 이미 vLLM의 enable_prefix_caching과 SGLang의 RadixAttention에 들어가 있다. 세션 간 prefix 공유의 걸림돌은 낡은 데이터다. 공유 prefix의 한 span만 바뀌어도 그 뒤 캐시가 전부 무효가 된다. KVEraser는 해당 슬롯만 고치고 나머지는 살리는 길을 보여 준다. 32K에서 17.6× 재계산과 +24% 스티어링의 차이는 무효화 한 번당 계산을 약 14배 줄이는 셈이다.

당장의 걸림돌: Eraser가 생성기와 같은 8B 파라미터다. 처리량이 큰 공유 prefix 워크로드라면 8B 모델을 하나 더 띄울 만하지만 단일 사용자 세션에는 과하다. 증류나 LoRA 기반 eraser가 EM 0.879를 따라잡을 수 있는지가 남은 질문이다.
