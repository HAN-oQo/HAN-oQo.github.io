SGLang Context Parallelism: why long context needs it, and what's actually in main SGLang Context Parallelism: 긴 컨텍스트에 왜 필요하고, main에는 실제로 무엇이 있나

Context parallelism (CP) splits a single sequence across GPUs along the token axis. This note covers why CP is needed (with KV-size numbers) and the three CP attention algorithms, then uses the code at d86a7e7 to separate what SGLang has merged (prefill-only CP via all-gather, FlashAttention-3) from what the #21788 roadmap only proposes. Context parallelism(CP)은 하나의 시퀀스를 토큰 축으로 GPU들에 나누는 병렬화다. 이 노트는 CP가 왜 필요한지(KV 크기 수치 포함)와 CP 어텐션 알고리즘 세 가지를 정리하고, d86a7e7 코드를 근거로 SGLang이 실제 머지한 것(all-gather 기반 prefill 전용 CP, FlashAttention-3)과 #21788 로드맵이 제안만 한 것을 구분한다.

one-line summary한 줄 요약
  • A long prompt's KV cache grows linearly with length and its prefill attention grows quadratically. TP/DP/PP can't fix this because none of them splits the sequence.
  • CP shards the tokens across GPUs and makes attention work across the shards: ring attention rotates K/V, Ulysses does an all-to-all, SGLang's merged path all-gathers K/V and runs FlashAttention-3 locally.
  • What's in main today is prefill-only CP via all-gather (not ring attention), FA3-only, single-machine (tp≤8), Hopper-tested, "still under experiment".
  • Decode CP, Helix, and ring/seq-dim KV sharding are proposals in the 2026-Q2 roadmap #21788. A unified layers/cp/ module exists, but its methods are NotImplementedError stubs.
  • 긴 프롬프트의 KV 캐시는 길이에 선형으로, prefill 어텐션은 제곱으로 커진다. TP/DP/PP는 시퀀스를 쪼개지 않으므로 이 문제를 못 푼다.
  • CP는 토큰을 GPU들에 나누고 조각 사이에서 어텐션이 돌게 만든다. ring attention은 K/V를 회전하고, Ulysses는 all-to-all을 쓰고, SGLang 머지 경로는 K/V를 all-gather한 뒤 로컬에서 FlashAttention-3를 돌린다.
  • 지금 main에 있는 것은 all-gather 기반 prefill 전용 CP(ring attention 아님)다. FA3 전용, 단일 머신(tp≤8), Hopper 테스트, "아직 실험 중" 상태다.
  • Decode CP, Helix, ring/seq-dim KV 샤딩은 2026-Q2 로드맵 #21788의 제안이다. 통합 layers/cp/ 모듈은 있지만 메서드가 NotImplementedError 스텁이다.

1Why CP exists: the long-context wall, and why TP/DP/PP don't helpCP가 필요한 이유: 긴 컨텍스트의 벽과 TP/DP/PP의 한계

Picture one request with a 1,000,000-token prompt. Two things blow up, both tied to that single sequence: 100만 토큰짜리 프롬프트를 가진 요청 하나를 생각해 보자. 그 시퀀스 하나 때문에 두 가지 문제가 생긴다.

  • KV cache grows linearly with length. Every token leaves a key/value entry per layer. For a 70B-class model that is hundreds of KB per token, so a million-token context needs hundreds of GB of KV, more than one GPU has. KV 캐시가 길이에 선형으로 커진다. 토큰마다 레이어별 key/value가 남는다. 70B급 모델은 토큰당 수백 KB라서 100만 토큰이면 KV가 수백 GB가 되어 GPU 하나를 넘는다.
  • Prefill attention grows quadratically. It is O(length²) over all prompt tokens, an enormous amount of work for one device at a million tokens. Prefill 어텐션이 제곱으로 커진다. 모든 프롬프트 토큰 쌍을 계산하므로 O(길이²)이고, 100만 토큰이면 한 장치로 감당하기 어렵다.

"Dense attention FLOPs scale quadratically with context length … The KV cache grows linearly with context."

— Meta Engineering, "Scaling LLM inference" · engineering.fb.com [blog]

How big is the KV, really?KV가 실제로 얼마나 큰가?

KV bytes ≈ 2 × layers × kv_heads × head_dim × dtype × tokens, assuming GQA with 8 KV heads, head_dim 128, fp16 (2 B). KV 바이트 ≈ 2 × layers × kv_heads × head_dim × dtype × 토큰. 가정은 GQA 8 KV head, head_dim 128, fp16(2 B)이다.

Why the parallelisms you already know don't solve it이미 아는 병렬화로는 왜 안 되나

There are several parallelisms, but only CP splits the sequence itself. 병렬화는 여럿이지만 시퀀스 자체를 쪼개는 것은 CP뿐이다.

"TP2: each rank holds a full KV cache copy … DP2: a single sequence's KV cache still lives on one device … CP2: partitions the KV cache across devices."

— SGLang issue #12196 · github.com/sgl-project/sglang/issues/12196 [issue]

2What CP is: split the sequence, then deal with global attentionCP란: 시퀀스를 쪼갠 뒤 전역 어텐션을 맞추는 일

Give each of the CP ranks a slice of the token positions (and that slice's K/V). The hard part is that attention is global: every query must attend to all earlier keys, which are scattered across ranks. So CP is really about how the ranks exchange K (or Q) so every query sees every key, without any single GPU holding the whole thing for too long. CP rank마다 토큰 위치 한 조각과 그 K/V를 준다. 어려운 점은 어텐션이 전역이라는 데 있다. 모든 query가 앞선 모든 key를 봐야 하는데 key는 rank들에 흩어져 있다. 그래서 CP의 본질은 어느 GPU도 전체를 오래 들고 있지 않으면서 모든 query가 모든 key를 보도록 rank들이 K(또는 Q)를 어떻게 교환하느냐다.

Under a causal mask a contiguous split is unbalanced: the rank with the first tokens has almost nothing to attend to, the rank with the last tokens attends to everything. Implementations, SGLang included, use a "zigzag" assignment (one early block + one late block per rank) to even out the work. 인과 마스크에서는 연속 분할이 불균형하다. 앞 토큰을 가진 rank는 볼 key가 거의 없고, 뒤 토큰을 가진 rank는 전부 본다. 그래서 SGLang을 포함한 구현들은 "zigzag" 배정(rank마다 앞 블록 하나와 뒤 블록 하나)으로 일을 고르게 나눈다.

3The menu: ring attention vs all-to-all vs all-gather세 가지 방법: ring attention, all-to-all, all-gather

There are three common ways to make attention work across CP ranks. The literature is mostly about the first two, while SGLang's merged code uses the third. CP rank 사이에서 어텐션을 맞추는 흔한 방법은 셋이다. 문헌은 주로 앞의 둘을 다루지만 SGLang 머지 코드는 셋째를 쓴다.

① Ring attention① Ring attention

Each rank keeps its query block while K/V blocks rotate around a ring, merged via online softmax. Memory per rank is independent of total length and comm overlaps compute. (arXiv:2310.01889)각 rank는 query 블록을 두고 K/V 블록이 ring을 따라 돈다. 부분 어텐션은 online softmax로 병합한다. rank당 메모리가 전체 길이와 무관하고 통신이 연산과 겹친다. (arXiv:2310.01889)

② All-to-all (Ulysses)② All-to-all (Ulysses)

An all-to-all turns the sequence-sharded tensor into a head-sharded one, each GPU runs full attention for a few heads, then all-to-all back. Low comm, but the degree is capped by the number of heads. (arXiv:2309.14509)all-to-all로 시퀀스 샤딩을 head 샤딩으로 바꾼다. 각 GPU가 head 몇 개의 전체 토큰으로 어텐션한 뒤 다시 all-to-all한다. 통신은 적지만 병렬도가 head 수에 묶인다. (arXiv:2309.14509)

③ All-gather K/V (SGLang today)③ All-gather K/V (SGLang 현재)

Each rank all-gathers the full K/V, writes it into its local pool, and runs ordinary FlashAttention-3 on its query shard. Simplest, but every rank re-holds full-length KV, so vs a single GPU it saves compute, not KV memory.각 rank가 전체 K/V를 all-gather해 로컬 풀에 쓰고, 자기 query 조각에 FlashAttention-3를 돌린다. 가장 단순하지만 모든 rank가 전체 길이 KV를 다시 가지므로, 단일 GPU 대비 아끼는 것은 KV 메모리가 아니라 연산이다.

"each host sends key-value blocks to the next host while receives key-value blocks from the preceding host."

— Ring Attention, §3 · arXiv:2310.01889 [paper]

"each GPU receives the full sequence but only for a non-overlapping subset of the attention heads."

— DeepSpeed-Ulysses, §1 · arXiv:2309.14509 [paper]

Fig 2 · Three ways to do attention across CP ranks. Sources: arXiv:2310.01889, arXiv:2309.14509, SGLang code @ d86a7e7. Schematic.그림 2 · CP rank 간 어텐션 세 방법. 출처: arXiv:2310.01889, arXiv:2309.14509, SGLang 코드 @ d86a7e7. 개략도.

7Status & sources상태와 출처

Status: prefill CP is merged and usable but explicitly experimental (Hopper, FA3, single-machine tp≤8). It splits prefill compute via all-gather, not KV memory. Decode CP, Helix, ring-attention seq-dim KV sharding, and the unified layers/cp/ module are roadmap (#21788). For comparison, vLLM ships a decode context-parallel knob (-dcp / --decode-context-parallel-size) that "reduces the KV cache duplication" across the TP domain [vLLM docs], a different point in the same design space (decode vs SGLang's prefill). 상태: prefill CP는 머지돼 쓸 수 있지만 명시적으로 실험 단계다(Hopper, FA3, 단일 머신 tp≤8). all-gather로 prefill 연산을 나눌 뿐 KV 메모리는 나누지 않는다. Decode CP, Helix, ring-attention 시퀀스 차원 KV 샤딩, 통합 layers/cp/ 모듈은 로드맵(#21788)이다. 참고로 vLLM은 TP 도메인에서 "KV 캐시 중복을 줄이는" decode context-parallel 노브(-dcp / --decode-context-parallel-size)를 제공한다 [vLLM docs]. 같은 설계 공간에서 SGLang(prefill)과 다른 지점(decode)이다.

editor's note: our angle (not an SGLang claim)편집자 주: 우리 관점 (SGLang 주장 아님)
  1. SGLang CP is out of reach for our MI250 lab today: it's FA3-only and Hopper-verified, and single-machine (tp≤8) with "cross-machine precision issues", so not yet a multi-node long-context vehicle.
  2. Still, CP is the only parallelism that attacks the long-context wall directly, and it pairs with the others. The collectives it leans on (all-gather/reduce-scatter) are in the parallelism × communication note.
  3. Watch #25846 (sequence-dim KV sharding with ring attention): it would let a 1M-token KV live across GPUs instead of being re-gathered onto each, the real memory lever. Until then "SGLang CP" means "split the prefill attention compute", narrower than the name suggests.
  1. 우리 MI250 랩에서는 지금 SGLang CP를 쓸 수 없다. FA3 전용·Hopper 검증이고 단일 머신(tp≤8)에 "노드 간 정밀도 문제"까지 있어 아직 멀티노드 롱컨텍스트 수단이 아니다.
  2. 그래도 CP는 긴 컨텍스트 벽을 직접 다루는 유일한 병렬화이고 다른 병렬화와 함께 쓸 수 있다. CP가 기대는 all-gather/reduce-scatter는 병렬화 × 통신 노트에서 다뤘다.
  3. 로드맵에서 볼 것은 #25846(ring attention 기반 시퀀스 차원 KV 샤딩)이다. 1M 토큰 KV를 GPU마다 다시 모으지 않고 여러 GPU에 나눠 두게 해 주는, 진짜 메모리 지렛대다. 그 전까지 "SGLang CP"는 "prefill 어텐션 연산 분할"을 뜻하고 이름보다 범위가 좁다.
