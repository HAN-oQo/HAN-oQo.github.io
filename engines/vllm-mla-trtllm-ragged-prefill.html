TrtllmRaggedPrefillBackend is one of four pluggable MLA-prefill backends in vLLM: it wraps FlashInfer's TRT-LLM-gen kernel trtllm_ragged_attention_deepseek to run MLA prefill (DeepSeek-V2/V3, GLM) over un-padded ("ragged") batches, on Blackwell (SM100) only. This note reads the vLLM code pinned to commit 4bf699d. TrtllmRaggedPrefillBackend는 vLLM의 4개 pluggable MLA-prefill 백엔드 중 하나다. FlashInfer의 TRT-LLM-gen 커널 trtllm_ragged_attention_deepseek를 감싸 MLA 모델(DeepSeek-V2/V3, GLM)의 prefill을 패딩 없는("ragged") 배치로 돌리며, Blackwell(SM100) 전용이다. 커밋 4bf699d의 vLLM 코드를 기준으로 정리했다.

one-line summary한 줄 요약
  • MLA's compressed-latent KV gives prefill a special shape: an up-projection plus asymmetric q/k (e.g. 192) vs v (e.g. 128) head dims. vLLM picks the MLA-prefill kernel from a registry of four backends.
  • TRTLLM_RAGGED runs one SM100-only kernel over un-padded ("ragged") batches, for both the non-causal context-chunk pass and the causal new-tokens pass.
  • Auto-selection still ranks FlashAttention first, so this backend is reached only by explicit override or when FA is unavailable.
  • The only public speed number (≈+12.7% qps / −10.2% TTFT) is a contributor self-bench on a small model, one GPU. Irrelevant to non-NVIDIA (e.g. MI250) hardware.
  • MLA의 압축 latent KV 때문에 prefill은 up-projection과 비대칭 head 차원(q/k 예: 192, v 예: 128)을 가진다. vLLM은 이 커널을 4개 백엔드 registry에서 고른다.
  • TRTLLM_RAGGED는 SM100 전용 커널 하나로 패딩 없는("ragged") 배치를 처리한다. 비인과 context-chunk 패스와 인과 new-tokens 패스를 모두 맡는다.
  • auto 선택에서는 FlashAttention이 여전히 1순위다. 이 백엔드는 명시적 override나 FA를 못 쓸 때만 쓰인다.
  • 공개된 속도 수치는 작은 모델·단일 GPU 기여자 셀프벤치(≈+12.7% qps / −10.2% TTFT) 하나뿐이다. 비-NVIDIA(예: MI250) 하드웨어와는 무관하다.

1What & why — MLA prefill, and what "ragged" means무엇이고 왜 필요한가: MLA prefill과 "ragged"

MLA: the KV cache is a compressed latentMLA: KV 캐시가 압축된 latent

MLA is DeepSeek-V2's way to shrink the KV cache: it stores one small "latent" vector per token and reconstructs per-head keys and values on demand. MLA는 KV 캐시를 줄이려는 DeepSeek-V2의 방법이다. 토큰당 작은 "latent" 벡터 하나만 저장하고, head별 key·value는 필요할 때 복원한다.

"MLA guarantees efficient inference through significantly compressing the Key-Value (KV) cache into a latent vector."

— DeepSeek-V2 abstract · arXiv:2405.04434

This compression makes MLA prefill awkward for a generic attention kernel, for two reasons: 이 압축 때문에 MLA prefill은 범용 어텐션 커널로 처리하기 까다롭다. 이유는 두 가지다.

  • An up-projection step. The cached latent must first be expanded into per-head k_nope and v through kv_b_proj. A vanilla kernel just reads K and V. up-projection 단계. 캐시된 latent를 먼저 kv_b_proj로 head별 k_nope·v로 펼쳐야 한다. 일반 커널은 K·V를 읽기만 한다.
  • Asymmetric head dimensions. A query/key head is qk_nope + qk_rope (e.g. 128+64 = 192) while the value head is v_head_dim (e.g. 128), breaking the common head_dim_qk == head_dim_v assumption. The TRT-LLM backend supports two shapes: DeepSeek (qk_nope 128 / rope 64 / v 128) and GLM-style (192 / 64 / 256). 비대칭 head 차원. query/key head는 qk_nope + qk_rope(예: 128+64 = 192)인데 value head는 v_head_dim(예: 128)이다. 많은 커널이 가정하는 head_dim_qk == head_dim_v가 깨진다. TRT-LLM 백엔드는 DeepSeek 계열(qk_nope 128 / rope 64 / v 128)과 GLM류(192 / 64 / 256) 두 형태를 지원한다.

"Ragged" = un-padded variable-length batching"Ragged" = 무패딩 가변 길이 배칭

Prompts have different lengths. Padding them all to the longest wastes compute. The "ragged" (varlen) layout concatenates sequences into one flat tensor with no padding and finds boundaries with a cumulative-length index array: 프롬프트는 길이가 제각각이다. 가장 긴 것에 맞춰 패딩하면 그만큼 연산이 낭비된다. "ragged"(varlen) 레이아웃은 시퀀스를 패딩 없이 한 텐서로 이어 붙이고, 누적 길이 배열로 각 시퀀스의 경계를 찾는다.

"indptr[i+1]-indptr[i] is the sequence length of request i" … the indptr array has "num_requests+1 elements, the first element is always zero."

— FlashInfer, KV-Layout tutorial (Ragged Tensor) · docs.flashinfer.ai/tutorials/kv_layout

In vLLM this array is query_start_loc. The kernel takes flat q/k/v plus these lengths and never sees padding. "deepseek" in its name means it also handles MLA's asymmetric qk-vs-v head dims natively, in one call. vLLM에서는 이 배열이 query_start_loc(요청별 query 토큰 누적 개수)다. 커널은 q/k/v와 이 누적 길이만 받으므로 패딩 토큰을 보지 않는다. 이름의 "deepseek"은 MLA의 비대칭 qk/v head 차원까지 커널 안에서 처리한다는 뜻이다.

Fig 1 · Padded vs ragged batching (cu_seqlens = query_start_loc). Schematic, per FlashInfer KV-layout docs.그림 1 · 패딩 배칭과 ragged 배칭(cu_seqlens = query_start_loc). 개략도, FlashInfer KV-layout 문서 기준.

2How it works — up-project the latent, two ragged passes, one kernel동작 원리: latent up-project, ragged 두 패스, 커널 하나

vLLM's MLA prefill runs attention in two passes through the same ragged kernel, differing only in is_causal: vLLM의 MLA prefill은 같은 ragged 커널을 두 번 호출한다. 차이는 is_causal 플래그뿐이다.

  • Context-chunk pass (non-causal). When part of the prompt's KV is already cached (chunked prefill / prefix reuse), new queries attend over it. It is all "in the past", so no causal mask. Chunks are merged with merge_attn_states (log-sum-exp merge), which is why the kernel returns the LSE. Context-chunk 패스(비인과). 프롬프트 KV 일부가 이미 캐시돼 있으면(chunked prefill / prefix 재사용) 새 query가 그 context를 어텐션한다. context는 모두 과거 토큰이라 인과 마스크가 없다. 청크별 결과는 merge_attn_states(log-sum-exp 병합)로 합치므로 커널이 LSE도 반환한다.
  • New-tokens pass (causal). The new tokens attend to each other with the usual causal mask (is_causal=True). New-tokens 패스(인과). 새 토큰끼리 일반적인 인과 마스크로 어텐션한다(is_causal=True).

Both passes first up-project the latent through kv_b_proj into k_nope and v, and assemble k = [k_nope | k_pe]. The flat q/k/v + cu_seqlens then go to trtllm_ragged_attention_deepseek. The backend transposes the returned LSE from (q_len, num_heads) to (num_heads, q_len) for the merge. 두 패스 모두 먼저 kv_b_proj로 latent를 up-project 해 k_nope·v를 만들고, key를 k = [k_nope | k_pe](내용 + 공유 RoPE)로 조립한다. 이어서 q/k/v와 cu_seqlens를 trtllm_ragged_attention_deepseek에 넘긴다. 커널이 돌려준 LSE는 (q_len, num_heads) 형태라, 병합을 위해 백엔드가 (num_heads, q_len)로 전치한다.

why prefill gets its own kernel: un-absorbed MLAprefill에 전용 커널이 있는 이유: 비흡수 MLA Decode is memory-bound, so it "absorbs" the up-projection into the weights and runs MQA over the latent. Prefill is compute-bound, so it "un-absorbs": expand to full per-head K/V and run ordinary MHA. trtllm_ragged is that un-absorbed prefill path (the up-projection in Fig 2). The vLLM forum calls prefill "compute-friendly" and decode "data-movement-friendly" [vLLM forum]. Decode는 메모리 바운드라 up-projection을 가중치에 "흡수"하고 압축 latent 위에서 바로 MQA를 돈다. Prefill은 query가 많아 연산 바운드이므로 반대로 "비흡수"한다. latent를 head별 K/V로 펼친 뒤 일반 MHA를 돈다. trtllm_ragged가 이 비흡수 prefill 경로이고, 그림 2의 up-projection이 그 단계다. vLLM 포럼은 prefill을 "compute-friendly", decode를 "data-movement-friendly"라고 표현한다 [vLLM forum].

Fig 2 · MLA prefill: up-project (kv_b_proj), reassemble [k_nope|k_pe], one kernel called twice. Source: vLLM mla_attention.py & trtllm_ragged.py @ 4bf699d.그림 2 · MLA prefill: up-project(kv_b_proj), [k_nope|k_pe] 조립, 커널 하나를 두 번 호출. 출처: vLLM mla_attention.py·trtllm_ragged.py @ 4bf699d.

3The four MLA-prefill backends & how this one is chosen4개 MLA-prefill 백엔드와 선택 방식

At this commit MLA prefill is a pluggable registry: each layer picks one backend at construction. There are four (cuDNN was removed): 이 커밋에서 MLA prefill은 pluggable registry 구조다. 레이어가 생성될 때 백엔드 하나를 고른다. 백엔드는 네 개이고 cuDNN은 빠졌다.

Selection happens in get_mla_prefill_backend(), two ways: 선택은 get_mla_prefill_backend()에서 두 가지 방식으로 이뤄진다.

  1. Explicit override: set mla_prefill_backend=TRTLLM_RAGGED; the branch validates hardware and is_available(), then uses it. 명시적 override: 설정에 mla_prefill_backend=TRTLLM_RAGGED를 주면 하드웨어와 is_available()를 검증한 뒤 쓴다.
  2. Auto: walk a per-hardware priority list and take the first valid, available backend. Auto: 하드웨어별 우선순위 목록에서 사용 가능하고 유효한 첫 백엔드를 고른다.
the surprising part: auto-selection does NOT pick it의외의 지점: auto 선택은 이 백엔드를 고르지 않는다 On Blackwell the order is FLASH_ATTN → TRTLLM_RAGGED → FLASHINFER → TOKENSPEED_MLA (selector.py L59-69 @ 4bf699d); on Hopper/older it is FLASH_ATTN only. FA is first and broadly valid, so TRTLLM_RAGGED is reached only by explicit selection or a config FA can't serve. (Some vLLM docs and secondary write-ups call it the auto-selected Blackwell backend. The selector source disagrees, so treat that as docs lagging the code.) editor's note: our angle (not a vLLM claim)편집자 주: 우리 관점 (vLLM 주장 아님)
  1. Non-event on MI250. CDNA2 has capability.major != 10, so the ROCm list is FlashAttention only. Forcing TRTLLM_RAGGED fails is_available() (no flashinfer kernel) and supports_compute_capability().
  2. Useful signal. MLA prefill is now a pluggable backend registry (like the attention-backend and KV-connector registries), so the kernel for DeepSeek/GLM is a per-hardware policy, not a hardcode.
  3. Benchmarking. A DeepSeek-family model on MI250 runs the FA MLA-prefill path. A fair comparison with a Blackwell box must account for the prefill backend, which may be a different kernel.
  1. MI250에서는 무관하다. CDNA2는 capability.major != 10이라 ROCm의 목록은 FlashAttention 하나다. TRTLLM_RAGGED를 강제해도 is_available()(flashinfer 커널 없음)와 supports_compute_capability()에서 막힌다.
  2. 남겨 둘 신호. MLA prefill이 pluggable 백엔드 registry로 바뀌었다(attention-backend·KV-connector registry와 같은 형태). DeepSeek/GLM을 어떤 커널로 돌릴지가 하드코드가 아니라 하드웨어별 정책이 됐다.
  3. 벤치 비교. MI250에서 DeepSeek 계열을 돌리면 FA MLA-prefill 경로를 탄다. Blackwell 장비와 비교할 때는 prefill 백엔드가 다른 커널일 수 있다는 점을 감안해야 한다.

Mechanism, precisely메커니즘 정확히

One kernel (trtllm_ragged_attention_deepseek) serves both passes, flipped by is_causal. The backend is thin: declare dims, gate on SM100 + flashinfer, reserve a workspace, build cu_seqlens, call the kernel, transpose the LSE. MLA-specific work (up-projection, k assembly, chunk merge) lives in mla_attention.py, shared by all four backends.커널 하나(trtllm_ragged_attention_deepseek)가 is_causal만 바꿔 두 패스를 처리한다. 백엔드는 얇다. 차원 선언, SM100·flashinfer 게이트, workspace 예약, cu_seqlens 구성, 커널 호출, LSE 전치가 전부다. MLA 고유 작업(up-projection, k 조립, 청크 병합)은 4개 백엔드가 공유하는 mla_attention.py에 있다.

7Implementation status구현 상태

Merged, not experimental-gated, but narrow (Blackwell SM100 only, two MLA dim sets, flashinfer required) and not the auto-default (FA outranks it). 머지됐고 experimental 게이트도 없다. 다만 적용 범위가 좁고(Blackwell SM100 전용, MLA 차원 2종, flashinfer 필요) FA보다 순위가 낮아 auto 기본값이 아니다.
