"Service-Induced Congestion in Memory-Constrained LLM Serving" — Ao, Dong, Luo & Simchi-Levi (MIT / Columbia / Peking U). A theory paper: model continuous-batching serving as a discrete-time dynamical system where each request's memory grows during service. The surprising result — left to a greedy admission policy, a saturated server doesn't settle at the no-eviction equilibrium; it provably rolls downhill to a worst-case eviction cycle that can throw away half the throughput. And whether it does turns on the arithmetic of the decode lengths. "Service-Induced Congestion in Memory-Constrained LLM Serving" — Ao, Dong, Luo, Simchi-Levi (MIT / 컬럼비아 / 베이징대). 이론 논문이다: continuous-batching 서빙을, 각 요청의 메모리가 서비스 중에 자라는 이산시간 동역학계로 모델링한다. 놀라운 결과 — 탐욕적 admission에 맡기면, 포화 서버는 무(無)축출 평형에 머무르지 않고, 처리량을 절반까지 버릴 수 있는 최악의 축출 주기로 증명 가능하게 굴러떨어진다. 그리고 그렇게 될지 말지는 decode 길이의 산술이 가른다.

one-line summary한 줄 요약 A KV cache grows by one token every decode step, so a request that fit at admission can overflow GPU memory a few steps later — service creates its own future congestion, something classical queueing (fixed per-job capacity) never sees. The authors model continuous batching as a deterministic map (Execute → Arrive → Evict → Admit) and prove: (1) homogeneous workloads — the no-eviction equilibrium is unstable; greedy admission converges to a worst-case eviction limit cycle losing up to 50% throughput. (2) heterogeneous workloads — the equilibrium is stable iff the decode lengths are coprime (gcd = 1); a shared common divisor synchronizes completions into memory-release pulses that drive eviction. (3) Two cheap fixes: rate-limited admission (cap at the eviction-free rate) and request mixing (route coprime decode lengths together). Simulations (Vidur + a real A800) confirm it — rate-limiting cut evictions to zero and raised throughput 28%. KV 캐시는 decode 스텝마다 토큰 하나씩 자란다. 그래서 admission 시점엔 들어맞던 요청이 몇 스텝 뒤 GPU 메모리를 넘칠 수 있다 — 서비스가 제 미래 혼잡을 만든다. 작업당 용량이 고정된 고전 큐잉은 결코 못 보는 현상이다. 저자들은 continuous batching을 결정론적 사상(Execute → Arrive → Evict → Admit)으로 모델링하고 증명한다: (1) 동질 워크로드 — 무축출 평형은 불안정하고, 탐욕 admission은 처리량을 최대 50% 잃는 최악의 축출 주기로 수렴한다. (2) 이질 워크로드 — 평형은 decode 길이가 서로소(coprime, gcd=1)일 때만 안정적이다; 공약수가 있으면 완료 이벤트가 동기화돼 메모리 방출 펄스를 만들고 축출을 부른다. (3) 두 가지 값싼 처방: rate-limited admission(무축출 속도로 캡)과 request mixing(서로소 decode 길이를 같이 라우팅). 시뮬레이션(Vidur + 실제 A800)이 확인 — rate-limiting은 축출을 0으로, 처리량을 28% 높였다.

📖 KV cache growth📖 KV 캐시 성장

At decode stage j, a request occupies l₀+1+j tokens (input + j generated + 1 reserved). It grows by one token every step until it completes and frees everything.decode 스테이지 j에서 요청은 l₀+1+j 토큰을 점유한다(입력 + 생성 j개 + 예약 1). 완료해 전부 비울 때까지 매 스텝 토큰 하나씩 자란다.

📖 Continuous batching📖 continuous batching

Per iteration, every active request advances one decode step; completed ones leave and new ones are admitted. Keeps the GPU busy — but every active request holds its growing cache.iteration마다 모든 활성 요청이 한 decode 스텝 전진; 끝난 건 나가고 새 요청이 admit된다. GPU를 바쁘게 유지 — 하지만 모든 활성 요청이 자라는 캐시를 쥔다.

📖 Eviction (LPF)📖 축출 (LPF)

When memory overflows, the system drops requests' caches and re-queues them. This model evicts least-progressed-first (earliest decode stage first), then recomputes them later.메모리가 넘치면 요청의 캐시를 버리고 다시 큐에 넣는다. 이 모델은 least-progressed-first(가장 이른 decode 스테이지부터) 축출하고 나중에 재계산한다.

📖 Fixed point vs limit cycle📖 고정점 vs 극한주기

A fixed point = steady state, same occupancy every step, no eviction. A limit cycle = the system oscillates through a repeating pattern (here, with periodic evictions).고정점 = 정상상태, 매 스텝 동일 점유, 축출 없음. 극한주기(limit cycle) = 반복 패턴을 도는 진동(여기선 주기적 축출 동반).

📖 Saturated-input regime📖 포화 입력 영역

A theoretical abstraction: always enough backlog that admission is limited only by memory, not demand. It isolates the memory-driven throughput limit from arrival randomness.이론적 추상: 백로그가 늘 충분해 admission이 수요가 아니라 메모리에만 제한됨. 메모리가 정하는 처리량 한계를 도착 무작위성에서 분리한다.

📖 Coprime / GCD📖 서로소 / 최대공약수

Two numbers are coprime if their greatest common divisor (GCD) is 1 (e.g. 20 & 21). 100 & 125 share GCD 25. The paper's stability hinges on this for decode lengths.두 수의 최대공약수(GCD)가 1이면 서로소(예: 20·21). 100·125는 GCD 25. 논문의 안정성은 decode 길이의 이 성질에 달려 있다.

1 Problem definition 문제 정의

1.1 — A request that fit yesterday can overflow today (§1) 1.1 — 어제 들어맞던 요청이 오늘 넘친다 (§1)

Classical queueing assumes a job grabs a fixed amount of capacity and holds it until done — a server, a slice of bandwidth, a block of memory. LLM decoding breaks that assumption. Each generated token appends a key/value pair to the KV cache, so a request's GPU-memory footprint grows monotonically every step it runs. The consequence is unusual:

고전 큐잉은 작업이 고정된 용량을 잡고 끝날 때까지 쥔다고 가정한다 — 서버, 대역폭 한 조각, 메모리 한 블록. LLM decode는 이 가정을 깬다. 생성되는 토큰마다 KV 캐시에 key/value 쌍이 붙으니, 요청의 GPU 메모리 점유는 도는 매 스텝 단조 증가한다. 그 결과가 특이하다:

"A request that fits in memory at admission may become infeasible solely because it continues to run. … Service itself therefore creates future capacity pressure, giving rise to a new form of congestion."

— §1, ¶6 · 원문 보기 (§1)

The structural difference at the heart of the paper (§1, ¶5–6). Growing footprints make memory a moving target that service itself pushes over the edge.논문의 핵심에 있는 구조적 차이 (§1, ¶5–6). 자라는 점유는 메모리를 움직이는 표적으로 만들고, 서비스 자체가 그걸 벼랑 너머로 민다.

1.2 — The admission tension (§1) 1.2 — admission의 긴장 (§1)

This reshapes what an admission policy must do. A myopic policy admits whenever the request fits right now; but several locally-feasible admissions can all grow together and crest into a synchronized memory peak, forcing an eviction cascade. The opposite extreme — reserving memory for everyone's worst-case future growth — wastes the GPU:

이건 admission 정책이 해야 할 일을 바꾼다. 근시안적 정책은 지금 들어맞으면 admit한다; 하지만 국소적으로 가능한 admission 여러 개가 함께 자라 동기화된 메모리 정점으로 솟구치면 축출 cascade를 부른다. 반대 극단 — 모두의 최악 성장에 대비해 메모리를 예약 — 은 GPU를 낭비한다:

"Such locally feasible decisions can create synchronized memory peaks later, triggering eviction cascades that discard accumulated computation and collapse throughput. At the other extreme, overly conservative policies that reserve memory for worst-case future growth can also perform poorly."

— §1, ¶7 · 원문 보기 (§1)

A subtlety the paper leans on: near-homogeneous workloads are common and dangerous. Schema-constrained apps (a moderation pipeline returning {answer: yes}/{answer: no}, fixed-format tool routing) produce many requests with nearly identical decode lengths — exactly the case prone to synchronized memory growth.

논문이 기대는 미묘한 점: 거의 동질 워크로드가 흔하고 위험하다. 스키마 제약 앱({answer: yes}/{answer: no}를 반환하는 모더레이션 파이프라인, 고정 포맷 tool 라우팅)은 decode 길이가 거의 같은 요청을 대량 생산한다 — 동기화된 메모리 성장에 딱 취약한 경우다.

1.3 — How it differs from prior work (§1.2) 1.3 — 선행 연구와 어떻게 다른가 (§1.2)

The systems literature (PagedAttention/vLLM, RadixAttention/SGLang, FastServe, chunked prefill, prefill–decode disaggregation) builds mechanisms to manage memory. This paper is orthogonal — it asks what dynamics those mechanisms produce:

시스템 문헌(PagedAttention/vLLM, RadixAttention/SGLang, FastServe, chunked prefill, prefill–decode 분리)은 메모리를 관리할 메커니즘을 만든다. 이 논문은 직교한다 — 그 메커니즘들이 어떤 동역학을 만드는지를 묻는다:

"rather than proposing another memory-management primitive, we analyze the system-level dynamics induced by growing KV caches under continuous batching. We show that locally feasible admission can create future memory pressure, leading to eviction cascades and throughput loss when aggregate demand approaches capacity."

— §1.2 · 원문 보기 (§1.2)

Versus classical queueing theory: models with state-dependent service rates, bandwidth sharing, and admission control all exist — but they treat a job's resource requirement as fixed during service. The growing-footprint feature is the new ingredient. The closest serving-theory neighbors are Ao et al. (2025, fluid-guided threshold policies under memory constraints), Li et al. (2025, throughput optimality of work-conserving policies), and Mitzenmacher & Shahout (2025, queueing questions for LLM inference).

고전 큐잉 이론과 대비하면: 상태 의존 서비스율, 대역폭 공유, admission 제어 모델이 모두 있지만 — 작업의 자원 요구를 서비스 중 고정으로 본다. 자라는 점유가 새 요소다. 가장 가까운 서빙 이론 이웃은 Ao 외(2025, 메모리 제약하 fluid 임계 정책), Li 외(2025, work-conserving 정책의 처리량 최적성), Mitzenmacher & Shahout(2025, LLM 추론의 큐잉 질문)이다.

2.2 — The analysis frame: saturated input + three behaviors (§2.3) 2.2 — 분석 틀: 포화 입력 + 세 가지 거동 (§2.3)

To isolate the memory-driven limit from arrival randomness, the theory runs in the saturated-input regime: an effectively infinite backlog, so admission is constrained only by memory feasibility. Post-admission states then sit exactly on the memory boundary ℬ = {X ≥ 0 : Σ w_{k,j} x_{k,j} = M}, and the system reduces to a deterministic map on ℬ. Two long-run behaviors are possible (Definitions 1–2):

메모리가 정하는 한계를 도착 무작위성에서 떼어내려, 이론은 포화 입력 영역에서 돈다: 사실상 무한 백로그라 admission이 메모리 가능성에만 제한된다. admission 직후 상태는 정확히 메모리 경계 ℬ = {X ≥ 0 : Σ w_{k,j} x_{k,j} = M} 위에 놓이고, 시스템은 ℬ 위 결정론적 사상으로 환원된다. 두 가지 장기 거동이 가능하다(정의 1–2):

Fixed point (Def 1)고정점 (정의 1)

F(X*) = X*. A steady regime: same stage occupancy, memory, and throughput every iteration — no eviction. This is the desirable "eviction-free equilibrium."F(X*) = X*. 정상 체제: 매 iteration 같은 스테이지 점유·메모리·처리량 — 축출 없음. 바람직한 "무축출 평형."

Limit cycle (Def 2)극한주기 (정의 2)

A period-p≥2 sequence the system orbits forever. Here cycles come with periodic evictions — the system repeatedly overflows, evicts, refills.시스템이 영원히 도는 주기 p≥2 수열. 여기선 주기에 주기적 축출이 따라온다 — 넘치고, 축출하고, 다시 채우길 반복.

Stability (Def 3) is the usual asymptotic notion: do nearby trajectories converge to the equilibrium/cycle? The whole paper is about which of these the greedy map actually settles into.

안정성(정의 3)은 통상의 점근 개념: 가까운 궤적이 평형/주기로 수렴하는가? 논문 전체가, 탐욕 사상이 실제로 어느 쪽에 정착하는지를 다룬다.

2.3 — The two control policies the theory prescribes (§5) 2.3 — 이론이 처방하는 두 제어 정책 (§5)

Both fixes target the same culprit — transient over-admission (admitting more than the eviction-free rate, then watching it grow into overflow):

두 처방 모두 같은 범인을 노린다 — 일시적 과(過)admission(무축출 속도보다 많이 admit한 뒤 그것이 자라 넘치는 걸 지켜봄):

① Rate-limited admission (§5.1)① rate-limited admission (§5.1)

Cap aggregate admission at the eviction-free equilibrium rate x*. When demand is low the cap is non-binding (low latency); when demand surges it activates, blocking the pulses that cause cascades. No batching delay.총 admission을 무축출 평형 속도 x*로 캡. 수요가 낮으면 캡은 비구속(저지연); 수요가 솟구치면 작동해 cascade를 부르는 펄스를 막는다. 배칭 지연 없음.

② Request mixing (§5.2)② request mixing (§5.2)

Route so each GPU gets a mix of decode lengths with GCD = 1. Coprime completions desynchronize, smoothing memory release. "Mild diversification" keeps most batching/cache-locality benefits.각 GPU가 GCD=1인 decode 길이 혼합을 받도록 라우팅. 서로소 완료는 비동기화돼 메모리 방출을 매끈하게 한다. "온건한 다양화"가 배칭·캐시 지역성 이점 대부분을 유지.

3 Implementation — the analytical machinery 구현 방법 — 분석 기계장치

3.1 — The eviction-free fixed point, in plain terms (§3.1) 3.1 — 무축출 고정점, 쉽게 (§3.1)

In a homogeneous system (drop the class index), the one-iteration memory balance is the cleanest way in. Completing requests free l₀+l₁ tokens each; surviving requests each grew by one token; whatever memory is freed is converted into new stage-0 admissions costing l₀+1 each:

동질 시스템(클래스 인덱스 생략)에선 한-iteration 메모리 균형이 가장 깔끔한 진입로다. 완료 요청은 각각 l₀+l₁ 토큰을 비우고, 생존 요청은 각각 토큰 하나씩 자랐고, 비워진 메모리는 각 l₀+1짜리 새 stage-0 admission으로 환산된다:

(l₀+1) · x₀ⁿ⁺¹ = (l₀+l₁) · x_{l₁−1}ⁿ − Σ_{j=0}^{l₁−2} xⱼⁿ   ... (eq 2)
and stage advance:   x_{j+1}ⁿ⁺¹ = xⱼⁿ

Reading it. Left: memory used by new admissions next step. Right: (l₀+l₁)·x_{l₁−1}ⁿ is the memory released by the requests that just finished (the final stage), minus Σ xⱼ, the one extra token each surviving request consumed by growing. The fixed point is the state where every stage holds the same mass — a flat, self-replicating profile that admits exactly as many as complete, forever, with no eviction. Its admission-per-iteration is the eviction-free throughput, the ideal the whole paper measures losses against.

읽기. 좌변: 다음 스텝 새 admission이 쓰는 메모리. 우변: (l₀+l₁)·x_{l₁−1}ⁿ는 방금 끝난(최종 스테이지) 요청들이 방출한 메모리, 거기서 Σ xⱼ — 생존 요청들이 자라며 먹은 토큰 하나씩 — 을 뺀 것. 고정점은 모든 스테이지가 같은 질량을 쥔 상태 — 완료되는 만큼만 admit하는, 축출 없이 영원히 자기복제하는 평탄한 프로필이다. 그 iteration당 admission이 무축출 처리량, 논문이 손실을 재는 이상치다.

3.2 — Why the equilibrium tips over: imbalance amplification (§3) 3.2 — 평형이 왜 넘어가나: 불균형 증폭 (§3)

The instability proof rests on the spread Gⁿ = max_j xⱼⁿ − min_j xⱼⁿ, the gap between the fullest and emptiest stage. The argument (informally): any imbalance in stage occupancy doesn't damp out — the dynamics amplify it, until some stage empties (a "support loss"), which forces another, cascading down to the maximal-eviction cycle. The equilibrium is a knife-edge: perfectly balanced it stays, but the tiniest perturbation grows. The proof techniques the authors flag as reusable — imbalance-amplification, support-loss analysis, and cycle-stability analysis — are the contribution's analytical core.

불안정성 증명은 스프레드 Gⁿ = max_j xⱼⁿ − min_j xⱼⁿ, 즉 가장 찬 스테이지와 빈 스테이지의 차이에 기댄다. 논변(비격식): 스테이지 점유의 어떤 불균형도 사그라들지 않는다 — 동역학이 그걸 증폭해, 어떤 스테이지가 비고("support loss"), 그게 또 다른 걸 강제하며, 최대-축출 주기로 cascade한다. 평형은 칼날 위다: 완벽히 균형이면 머물지만, 아주 작은 섭동도 자란다. 저자들이 재사용 가능하다고 짚는 증명 기법 — 불균형 증폭, support-loss 분석, 주기-안정성 분석 — 이 이 기여의 분석적 핵심이다.

3.3 — The synchronization mechanism: roots on the unit circle (§4, App. B) 3.3 — 동기화 메커니즘: 단위원 위의 근 (§4, 부록 B)

For heterogeneous classes, the authors linearize the eviction-free dynamics into a finite-order recurrence for admission perturbations, whose characteristic polynomial encodes the decode lengths. Stability = are all roots strictly inside the unit circle? The number-theory enters through the limiting polynomial A(z): when the decode lengths share a common divisor g = gcd(l₁,₁,…) > 1, A(z) has roots at all non-trivial g-th roots of unity z_j = e^{2πij/g} — points sitting on the unit circle. Those are undamped oscillatory modes: completions line up periodically, releasing memory in pulses that the admission loop amplifies. When the lengths are coprime (g = 1), there are no such on-circle roots, completion phases drift apart, and perturbations damp.

이질 클래스에 대해, 저자들은 무축출 동역학을 admission 섭동의 유한차 점화식으로 선형화하는데, 그 특성다항식이 decode 길이를 담는다. 안정성 = 모든 근이 단위원 안에 엄격히 있는가? 정수론은 극한 다항식 A(z)를 통해 들어온다: decode 길이가 공약수 g = gcd(l₁,₁,…) > 1을 가지면, A(z)는 모든 비자명 g차 단위근 z_j = e^{2πij/g}에 근을 갖는다 — 단위원 위에 앉은 점들. 이는 감쇠 없는 진동 모드다: 완료가 주기적으로 정렬돼 메모리를 펄스로 방출하고 admission 루프가 그걸 증폭한다. 길이가 서로소(g=1)면 그런 원-위 근이 없어, 완료 위상이 흩어지고 섭동이 감쇠한다.

"when decoding lengths share a common divisor, completion events align periodically, producing persistent oscillatory modes that drive the system into eviction. When they are coprime, completion phases drift relative to one another, desynchronizing memory release and damping perturbations."

— §1.1 · 원문 보기 (§1.1)

3.4 — How the rate cap is computed (§5.1) 3.4 — rate 캡은 어떻게 계산되나 (§5.1)

aⁿ = min( Qⁿ, Sⁿ / Σ_k p_k(l₀,k+1), x* ),   a_kⁿ = p_k aⁿ

Per iteration the system admits the minimum of three quantities: Qⁿ = total waiting demand (can't admit what isn't there); Sⁿ/Σ p_k(l₀,k+1) = the most that fits in the memory available after execution+eviction (Sⁿ is free memory, the denominator is the stage-0 cost of one unit of proportional admission); and x* = the eviction-free equilibrium rate from §3–4. The third term is the new piece — it's a hard ceiling that prevents over-admission even when memory momentarily looks free. After at most l₁ iterations every active request was admitted under the cap, so eviction stops.

iteration마다 시스템은 세 양의 최솟값을 admit한다: Qⁿ = 총 대기 수요(없는 걸 admit 못 함); Sⁿ/Σ p_k(l₀,k+1) = 실행+축출 후 가용 메모리에 들어가는 최대(Sⁿ은 빈 메모리, 분모는 비례 admission 한 단위의 stage-0 비용); x* = §3–4의 무축출 평형 속도. 셋째 항이 새 조각 — 메모리가 잠깐 비어 보여도 과admission을 막는 단단한 천장이다. 최대 l₁ iteration 뒤 모든 활성 요청이 캡 아래 admit돼, 축출이 멎는다.

4.1 — Homogeneous: it rolls to the worst cycle (Theorem 2) 4.1 — 동질: 최악의 주기로 굴러간다 (정리 2)

For a fixed decode length l₁ ≥ 2, the saturated system has an eviction-free fixed point, a maximal-eviction cycle (eviction level l₁−1), and (for l₁ ≥ 3) intermediate cycles. Theorem 2 ranks their stability — and the ranking is bleak:

고정 decode 길이 l₁ ≥ 2에 대해, 포화 시스템은 무축출 고정점, 최대-축출 주기(축출 레벨 l₁−1), 그리고 (l₁ ≥ 3이면) 중간 주기들을 갖는다. 정리 2가 그 안정성을 순위 매기는데, 결과가 암울하다:

"The eviction-free fixed point is not stable. … Eviction-level-i limit cycles, for i = 1, …, l₁−2, are not stable. … The maximal-eviction limit cycle, at eviction level l₁−1, is asymptotically stable outside ℰ. Its basin of attraction contains every memory-boundary initial state except those whose trajectories are captured exactly by a nonmaximal balanced orbit."

— Theorem 2, §3 · 원문 보기 (Theorem 2)

In words: the good equilibrium and every partial-eviction cycle are unstable. The only stable attractor is the worst one — maximal eviction. The exceptional set ℰ where you'd avoid it has Lebesgue measure zero (a perfectly-balanced knife-edge you'll never land on by chance). So almost any starting condition is pulled into the worst cycle. The throughput cost there is severe:

말로 하면: 좋은 평형과 모든 부분-축출 주기가 불안정하다. 유일한 안정 끌개는 최악의 것 — 최대 축출이다. 그걸 피할 예외집합 ℰ는 르베그 측도 0(우연히 안착할 일 없는 완벽 균형의 칼날). 그래서 거의 모든 초기 조건이 최악 주기로 끌려간다. 거기서의 처리량 비용이 가혹하다:

"The resulting throughput losses approach 50% when decoding lengths are large relative to input lengths, compared with the eviction-free equilibrium."

— §1.1 · 원문 보기 (§1.1)

Conceptual sketch of Theorem 2 (not a paper figure): every benign state is unstable; the system descends to the worst cycle.정리 2의 개념 스케치(논문 그림 아님): 모든 양성 상태가 불안정하고, 시스템은 최악 주기로 내려간다.

4.2 — Heterogeneous: coprime ⇔ stable (Theorem 3) 4.2 — 이질: 서로소 ⇔ 안정 (정리 3)

Two classes, common input l₀, decode lengths l₁,₁ < l₁,₂, admission split p / (1−p), g = gcd(l₁,₁, l₁,₂). For large enough input length l₀:

두 클래스, 공통 입력 l₀, decode 길이 l₁,₁ < l₁,₂, admission 비율 p / (1−p), g = gcd(l₁,₁, l₁,₂). 충분히 큰 입력 길이 l₀에 대해:

"If g > 1, then the eviction-free equilibrium is linearly unstable … If g = 1, then the eviction-free equilibrium is globally asymptotically stable: from any feasible initial active state in the saturated-input continuous model, the system converges to the eviction-free fixed point."

— Theorem 3, §4 · 원문 보기 (Theorem 3)

This is the paper's most striking result: stability is a number-theoretic property of the decode lengths. Coprime → globally stable (you converge to no-eviction from anywhere). Share a factor → unstable. And it's a knife-edge in arithmetic: 20 & 21 is fine; 20 & 22 (both even) is not. The flip side, stated as a warning:

이게 논문의 가장 강렬한 결과다: 안정성이 decode 길이의 정수론적 성질이다. 서로소 → 전역 안정(어디서든 무축출로 수렴). 약수 공유 → 불안정. 그리고 산술의 칼날이다: 20·21은 괜찮고, 20·22(둘 다 짝수)는 아니다. 그 이면을, 경고로 적는다:

"heterogeneity stabilizes the system only when it breaks arithmetic synchronization; not all diversity is beneficial."

— §1.1 · 원문 보기 (§1.1)

4.3 — The finite-input catch (Proposition 4) 4.3 — 유한 입력의 함정 (명제 4)

Theorem 3's "for large enough l₀" hides a real cost. Coprimality only stabilizes asymptotically; at finite scale you need the input to be long enough, and that threshold grows cubically with the longer decode length:

정리 3의 "충분히 큰 l₀"는 실질 비용을 숨긴다. 서로소는 점근적으로만 안정화한다; 유한 규모에선 입력이 충분히 길어야 하고, 그 임계가 더 긴 decode 길이에 대해 세제곱으로 자란다:

l₀,min ∼ [ ((1−p) + pθ)³ / (2π² p(1−p)) ] · l₁,₂³   ... (eq 13),   θ = l₁,₁/l₁,₂

Reading it. The minimum input length needed for a coprime pair to actually be stable scales like the cube of the larger decode length l₁,₂ — because the stabilizing spectral gap shrinks cubically. The prefactor adds operational nuance: stability is hardest when the two decode lengths are close (θ → 1) or the mix is lopsided (p → 0 or 1) — both weaken heterogeneity's desync effect. Concretely, the coprime pair (2, 7) already needs l₀ ≥ 15 to be stable.

읽기. 서로소 쌍이 실제로 안정되려면 필요한 최소 입력 길이가 더 큰 decode 길이 l₁,₂의 세제곱처럼 자란다 — 안정화하는 스펙트럼 갭이 세제곱으로 줄기 때문. 앞쪽 계수가 운영적 뉘앙스를 더한다: 두 decode 길이가 가깝거나(θ → 1) 혼합이 한쪽으로 쏠리면(p → 0 또는 1) 안정이 가장 어렵다 — 둘 다 이질성의 비동기 효과를 약화시킨다. 구체적으로, 서로소 쌍 (2, 7)도 안정되려면 l₀ ≥ 15가 필요하다.

"when decoding lengths are long, the input length needed for the coprime system to become stable scales as l₁,₂³."

4.5 — Threats & what to trust 4.5 — 한계와 믿을 것

Saturated-input idealization포화 입력 이상화

The theorems live in an infinite-backlog regime. Real systems dip in and out; §6.1 shows the mechanism persists under Poisson arrivals, but the clean equilibria are an abstraction.정리들은 무한 백로그 영역에 산다. 실제 시스템은 드나든다; §6.1이 Poisson 도착에서도 메커니즘이 지속됨을 보이나, 깔끔한 평형은 추상이다.

Deterministic lengths결정론적 길이

Each class has a fixed decode length. Real output lengths are random/unknown at admission; the arithmetic-synchronization story softens when lengths are distributions, not integers.각 클래스는 고정 decode 길이. 실제 출력 길이는 admission 시 무작위/미지; 길이가 정수가 아니라 분포면 산술-동기화 이야기는 누그러진다.

Continuous (fluid) state연속(fluid) 상태

Proofs use continuous request "mass" and exact memory-filling. Integer requests and discrete caps (Vidur's cap=5) are approximations of the fluid x*.증명은 연속 요청 "질량"과 정확한 메모리 채움을 쓴다. 정수 요청과 이산 캡(Vidur의 캡=5)은 fluid x*의 근사다.

LPF eviction assumedLPF 축출 가정

Results are for least-progressed-first eviction. Real engines (vLLM swap/recompute, SGLang LRU) differ; the qualitative mechanism is argued to carry, but exact cycles are LPF-specific.결과는 least-progressed-first 축출 기준. 실제 엔진(vLLM swap/recompute, SGLang LRU)은 다르다; 정성적 메커니즘은 이전된다 보지만 정확한 주기는 LPF 한정.

5.4 — Our read (not the paper's claims) 5.4 — 우리 관점의 해석 (논문의 주장 아님)

editor's note — what this means for our serving work편집자 주 — 우리 서빙 작업에 주는 의미 ① The headline is counter-intuitive and worth internalizing: a saturated server under greedy admission doesn't sit at the no-eviction sweet spot — it's an unstable equilibrium, and the system slides to a worst-case eviction cycle on its own. If our long-running vLLM/SGLang benches show creeping eviction at high concurrency, this says it may be structural, not a tuning bug. ② The coprime-decode-length result is genuinely surprising but read its scope carefully: it's proven in the saturated, deterministic-length, fluid, LPF-eviction model, and the finite-input threshold scales as l₁,₂³ — so for realistic long outputs you'd need very long inputs before coprimality visibly helps. Treat "nudge {128,256,512}→{127,255,509}" as a hypothesis to A/B test, not a guaranteed win on a real engine with random output lengths and LRU eviction. ③ The practically useful, low-risk takeaway is the rate-limited admission cap at the eviction-free rate x* — it's exactly the kind of cheap admission-control knob we could prototype on top of our P/D + KV-connector stack, and it complements (doesn't compete with) the CacheWise reuse-aware eviction and Tropical slack-multiplexing notes — those manage which cache to keep / when to co-locate, this manages how fast to admit. ④ Best framing of the whole paper for us: it's the theoretical "why" behind the eviction cascades the systems papers engineer around — and the first to argue admission rate (not just cache policy or routing) is a first-class stability lever. ⑤ Caveat: 101 pages, single-GPU model, no released code; the value here is the conceptual lens and the two policies, not transferable numbers. ① 핵심이 반직관적이라 새겨둘 만하다: 탐욕 admission하의 포화 서버는 무축출 스위트스폿에 머무르지 않는다 — 그건 불안정 평형이고, 시스템은 스스로 최악의 축출 주기로 미끄러진다. 우리 장기 vLLM/SGLang 벤치가 고동시성에서 슬금슬금 축출을 보인다면, 이건 튜닝 버그가 아니라 구조적일 수 있다는 말이다. ② 서로소-decode-길이 결과는 진짜 놀랍지만 범위를 조심히 읽어야 한다: 포화·결정론적 길이·fluid·LPF 축출 모델에서 증명됐고, 유한 입력 임계가 l₁,₂³로 자란다 — 그래서 현실적 긴 출력에선 서로소가 눈에 띄게 도우려면 매우 긴 입력이 필요하다. "{128,256,512}→{127,255,509} 살짝 옮기기"는 무작위 출력 길이·LRU 축출의 실제 엔진에서 보장된 승리가 아니라 A/B 테스트할 가설로 다루자. ③ 실용적이고 위험 낮은 교훈은 무축출 속도 x*에서의 rate-limited admission 캡이다 — 우리 P/D + KV-connector 스택 위에 프로토타이핑할 만한 값싼 admission-제어 손잡이이고, CacheWise의 재사용-aware 축출, Tropical의 slack 멀티플렉싱 노트와 보완 관계다(경쟁 아님) — 그들은 어느 캐시를 남길지/언제 코로케이션할지를, 이건 얼마나 빨리 admit할지를 관리한다. ④ 우리에게 이 논문의 최선의 프레이밍: 시스템 논문들이 우회 설계하는 축출 cascade의 이론적 "왜"이고, admission 속도(캐시 정책·라우팅만이 아니라)가 일급 안정성 레버임을 처음 주장한다. ⑤ 주의: 101쪽, 단일 GPU 모델, 코드 미공개; 여기서의 가치는 개념적 렌즈와 두 정책이지 이식 가능한 수치가 아니다.
