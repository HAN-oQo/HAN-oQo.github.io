one-line summary한 줄 요약 Deleting a token span from a prefilled KV cache silently poisons every suffix token's cached state; KVEraser trains a second Qwen3-8B to produce a surrogate block that replaces only the deleted interval — no suffix recomputation — cutting latency from 17.6× to +24% at 32K context while maintaining EM accuracy of 0.879. prefill된 KV 캐시에서 토큰 구간을 삭제하면 이후 모든 suffix 토큰의 캐시 상태가 조용히 오염된다. KVEraser는 두 번째 Qwen3-8B를 학습시켜 삭제된 구간만 교체하는 대리 블록을 생성하고 suffix 재계산을 건너뛴다 — 32K 컨텍스트에서 레이턴시를 17.6×에서 +24%로 줄이면서 EM 정확도 0.879를 유지한다.

KV CacheKV 캐시

Transformer attention caches each token's key and value vectors layer-by-layer during prefill so decoding never re-computes them. Editing a token retroactively requires touching the cache.트랜스포머 어텐션이 prefill 중 토큰별 key·value 벡터를 레이어마다 저장해 디코딩 시 재계산을 피하는 장치. 토큰을 소급 수정하려면 이 캐시를 건드려야 한다.

KV ContaminationKV 오염

When suffix token j attends to erased span e during prefill, its cached K/V vectors carry e's signal. Simply deleting e's KV rows leaves those suffix states biased — the model still "remembers" e through them.suffix 토큰 j가 prefill 중 삭제 대상 span e를 어텐션했으면, j의 K/V 벡터에 e의 신호가 담겨 있다. e의 KV 행을 삭제해도 suffix 상태에 편향이 남는다.

RoPERoPE

Rotary Position Embedding encodes relative position directly into attention scores by rotating Q/K vectors. Removing tokens and re-indexing the remaining sequence destroys all cached relative-position encodings — a full suffix recompute is needed.Rotary Position Embedding은 Q/K 벡터를 회전시켜 상대 위치를 어텐션 스코어에 직접 인코딩한다. 토큰을 제거하고 나머지를 재번호 매기면 기존 캐시의 모든 상대 위치 인코딩이 깨진다 — suffix 전체 재계산이 필요해진다.

Surrogate Cache대리 캐시

KVEraser's output: KV̂ = prefix KV (unchanged) ⊕ steering states (learned) ⊕ suffix KV (reused as-is). The steering states fill the deleted-span slot and compensate for contamination without touching suffix KV at all.KVEraser의 출력물: KV̂ = 접두사 KV(불변) ⊕ 스티어링 상태(학습) ⊕ 접미사 KV(그대로 재사용). 스티어링 상태가 삭제 구간 슬롯을 채워 suffix KV를 전혀 건드리지 않고 오염을 보정한다.

NIAH BenchmarkNIAH 벤치마크

Needle-In-A-Haystack: two needles with the same key but different values. The earlier needle is erased; the model must retrieve the later (retained) one. Tests whether erasing actually suppresses the unwanted memory.같은 키·다른 값을 가진 두 개의 needle. 앞 needle을 삭제하고 뒤(유지) needle을 정확히 검색해야 한다. 삭제가 실제로 기억을 억제하는지 테스트한다.

Eraser EφEraser Eφ

A full Qwen3-8B backbone (LM head removed) trained end-to-end to predict steering states. It sees prefix + erased span tokens and produces the substitute KV block. The generator θ (also Qwen3-8B) is frozen throughout training.LM head가 제거된 전체 Qwen3-8B 백본으로, 스티어링 상태를 예측하도록 end-to-end 학습된다. 접두사 + 삭제 구간 토큰을 입력받아 대체 KV 블록을 생성한다. 생성기 θ(마찬가지로 Qwen3-8B)는 학습 내내 동결된다.

1 Problem — erasing a span post-prefill has global KV fallout 문제 정의 — prefill 이후의 삭제는 KV 전체에 파급된다

When would you need to erase after prefill?언제 prefill 이후에 삭제가 필요한가?

Modern LLM pipelines prefill entire retrieved documents before a query is even formed. This creates several practical situations where a span must be removed after prefill has already run: a RAG system that discovers mid-stream that one of its retrieved passages is outdated; a multi-turn chat where user data must be wiped on request (GDPR/right-to-be-forgotten); a shared KV prefix cache across multiple users where a stale fact injected by one session must be cleaned before another session uses the same prefix. 현대 LLM 파이프라인은 쿼리가 만들어지기 전에 전체 검색 문서를 prefill한다. 이는 prefill 이후에 구간을 삭제해야 하는 실제 상황을 만든다: 검색된 문서 중 하나가 outdated임을 중간에 발견한 RAG 시스템; GDPR/삭제권 요청에 따라 사용자 데이터를 지워야 하는 멀티턴 채팅; 여러 사용자가 공유하는 KV prefix 캐시에서 한 세션이 주입한 잘못된 사실을 다른 세션이 사용하기 전에 제거해야 하는 경우.

"a RAG system may prefill retrieved passages before discovering an out-of-date fact"

— §1 · 원문 보기 (§1)

Why the naive fix — delete and shift — breaks단순한 해결책 — 삭제 후 이동 — 이 왜 깨지는가

The intuitive approach is to delete the offending tokens from the KV cache and slide the remaining entries together. This fails on two counts. First, RoPE invariance: rotary position embeddings encode each token's position relative to all others by rotating its K/Q vectors. After removing tokens, the remaining suffix tokens are now at shifted absolute positions. Their cached K/Q vectors still encode the old relative positions — any subsequent attention calculation sees wrong distances. There is no way to patch cached vectors in-place; you must recompute from scratch. 직관적인 방법은 문제가 되는 토큰을 KV 캐시에서 삭제하고 나머지를 당기는 것이다. 이는 두 가지 이유로 실패한다. 첫째, RoPE 불변성: rotary position embedding은 K/Q 벡터를 회전시켜 각 토큰의 상대 위치를 인코딩한다. 토큰을 제거하면 남은 suffix 토큰들이 이제 다른 절대 위치에 놓인다. 캐시된 K/Q 벡터는 여전히 이전 상대 위치를 인코딩한다 — 이후 어텐션 계산이 잘못된 거리를 보게 된다. 캐시된 벡터를 제자리에서 수정할 방법이 없다; 처음부터 재계산해야 한다.

Second, even if positions were not an issue, KV contamination would remain. During prefill, every suffix token attended to the erased span. Its cached key and value vectors already "absorbed" information from e. Deleting e's KV rows does nothing to undo that signal from the suffix. 둘째, 위치가 문제가 아니더라도 KV 오염이 남는다. prefill 중 모든 suffix 토큰이 삭제 구간에 어텐션했다. 그것의 cached key·value 벡터는 이미 e로부터의 정보를 "흡수"했다. e의 KV 행을 삭제해도 suffix에서 그 신호를 되돌리지 못한다.

"the KV cache of the first m−1 tokens remains valid after deleting e, whereas the cache of the remaining T−n tokens is contaminated by the erased span."

— §2 · 원문 보기 (§2)

"directly removing the erased span's KV cache and reusing the rest can result in complete failure."

— §3 Related Work · 원문 보기 (§3)

The standard cure — and its cost표준 처방 — 그리고 그 비용

The reliable baseline is to simply re-run prefill over p + s (prefix + suffix, with e removed). This produces exact KV states, avoids contamination, and handles RoPE correctly. But its cost scales with suffix length |s|, not erased span length |e|. In a 32K-token context where |e| = 512 tokens, you pay for 31K tokens of recomputation — a 17.6× overhead over the original prefill. 신뢰할 수 있는 기준선은 단순히 p + s(e를 제거한 접두사 + 접미사)에 대해 prefill을 다시 실행하는 것이다. 이는 정확한 KV 상태를 생성하고, 오염을 피하며, RoPE를 올바르게 처리한다. 그러나 그 비용은 삭제 구간 길이 |e|가 아니라 suffix 길이 |s|에 따라 확장된다. |e| = 512 토큰인 32K 토큰 컨텍스트에서는 31K 토큰의 재계산 비용을 치른다 — 원래 prefill의 17.6× 오버헤드.

"Its computational cost is therefore governed by suffix length rather than deleted-span length."

— §1 · 원문 보기 (§1)

The paper's central question is whether this suffix-length dependence can be broken: 논문의 핵심 질문은 이 suffix-길이 의존성을 깰 수 있는가이다:

"can post-hoc context erasing be performed directly in KV space, without rerunning prefill on the suffix?"

— §1 · 원문 보기 (§1)

Prior work on context editing (GRACE, MEMIT, InContext editing) operates at decode time — instructing the model to ignore something during generation. This does not rewrite cached states; it only adds a competing signal. 문맥 편집에 관한 이전 연구들(GRACE, MEMIT, InContext editing)은 디코딩 시점에 작동한다 — 생성 중 무언가를 무시하라고 모델에 지시한다. 이는 캐시된 상태를 다시 쓰지 않는다; 경쟁 신호를 추가할 뿐이다.

"after prefill, the suffix KV states have already been contaminated, so a later instruction can only compete with stored evidence at decoding time rather than rewrite the cached states themselves."

— §1 · 원문 보기 (§1)

Input sequence structure. Even after deleting e, suffix KV states remain contaminated because they attended to e during prefill. (Paper §2)입력 시퀀스 구조. e를 삭제한 후에도 suffix KV 상태는 prefill 중 e에 어텐션했기 때문에 오염 상태로 남는다. (논문 §2)

2 Method — surrogate cache via learned steering states 해결 방법 — 학습된 스티어링 상태로 대리 캐시 구성

"The main challenge of context erasing is that the edit is local, but its effect on the KV cache is global."

— §4 · 원문 보기 (§4)

Key insight: don't reconstruct — substitute핵심 통찰: 재구성하지 말고 대체하라

Instead of trying to reconstruct the exact KV cache that would result from running prefill on p + s (which requires full suffix recomputation), KVEraser asks: can we build a surrogate cache that produces correct answers without touching the suffix KV at all? The answer is yes — but only if the replacement for the deleted interval compensates for the contamination that e introduced into suffix tokens. p + s에 대한 prefill 실행 결과로 나올 정확한 KV 캐시를 재구성하려는 대신(전체 suffix 재계산 필요), KVEraser는 묻는다: suffix KV를 전혀 건드리지 않고도 올바른 답을 생성하는 대리 캐시를 만들 수 있을까? 답은 예 — 하지만 삭제된 구간의 교체물이 e가 suffix 토큰에 도입한 오염을 보정해야 한다.

"Instead of reconstructing the exact edited cache KV(x̃), it constructs a surrogate cache by replacing only the erased interval and reusing the remaining cache unchanged."

— §4.1 · 원문 보기 (§4.1)

The surrogate cache formula대리 캐시 공식

Given a sequence x = (x1:m-1, xm:n, xn+1:T) where xm:n = e is the erased span, the surrogate cache is: xm:n = e인 시퀀스 x = (x1:m-1, xm:n, xn+1:T)가 주어지면, 대리 캐시는: 

KV̂(x; m, n)  =  KV₁:m₋₁(x)  ⊕  KVˢᵗᵉᵉʳ(x; m, n)  ⊕  KVₙ₊₁:T(x)
                 ───────────     ──────────────────     ──────────────
                 prefix KV        steering states         suffix KV
                 (unchanged)       (learned by Eφ)       (reused as-is)

The steering states KVsteer are the sole learnable component. They must "undo" the contamination in the reused suffix KV by occupying the deleted-span positions. The generator model θ (Qwen3-8B, frozen) then runs decoding over this surrogate cache as if it were a real prefill output. 스티어링 상태 KVsteer가 유일한 학습 가능 구성요소다. 삭제된 구간 위치를 차지함으로써 재사용된 suffix KV의 오염을 "되돌려야" 한다. 생성기 모델 θ(Qwen3-8B, 동결)는 이 대리 캐시를 마치 실제 prefill 출력인 것처럼 디코딩한다.

What the eraser sees — and what it does noteraser가 보는 것 — 그리고 보지 않는 것

The eraser Eφ receives only the prefix tokens and the erased span tokens as input. Critically, it does not see the downstream query u. Eraser Eφ는 접두사 토큰과 삭제 구간 토큰만 입력으로 받는다. 결정적으로, 하위 쿼리 u는 보지 않는다.

"the downstream query u does not define the edit itself; it only probes the edited cache after erasure."

— §4.1 · 원문 보기 (§4.1)

This is an important design choice: the eraser must learn to produce steering states that are useful for any downstream query — not just the one it trained on. This forces the eraser to truly compensate for contamination rather than predict specific answers. 이것은 중요한 설계 선택이다: eraser는 훈련한 것뿐만 아니라 어떤 하위 쿼리에도 유용한 스티어링 상태를 생성하는 법을 배워야 한다. 이는 eraser가 특정 답변을 예측하는 것이 아니라 진정으로 오염을 보정하도록 강제한다.

Complexity: swapping suffix-length for span-length복잡도: suffix 길이를 span 길이로 교체하기

The eraser runs over prefix + erased span = (m-1) + |e| tokens. The suffix KV is reused without any compute. Total cost: O(|e|(|p| + |e|)). Compare to full recomputation: O(|s|(|p| + |s|)). At 32K context with a 512-token erased span in a 2K prefix, this yields ~17.6× speedup. Eraser는 접두사 + 삭제 구간 = (m-1) + |e| 토큰에 대해 실행된다. Suffix KV는 계산 없이 재사용된다. 총 비용: O(|e|(|p| + |e|)). 전체 재계산과 비교: O(|s|(|p| + |s|)). 2K 접두사에서 512 토큰 삭제 구간이 있는 32K 컨텍스트에서 ~17.6배 속도 향상.

"KVEraser therefore replaces suffix-length dependence with erased-span-length dependence."

— §4.2 · 원문 보기 (§4.2)

KVEraser replaces the erased span's KV with learned steering states; suffix KV is reused without any recomputation. (Paper §4.1, Fig. 2)KVEraser는 삭제된 구간의 KV를 학습된 스티어링 상태로 교체한다; suffix KV는 재계산 없이 그대로 재사용된다. (논문 §4.1, Fig. 2)

3 Implementation — Qwen3-8B eraser, two-stage training 구현 방법 — Qwen3-8B eraser, 2단계 학습

Eraser architectureEraser 아키텍처

The eraser Eφ is a full Qwen3-8B backbone with the language model head removed. Its output is projected to produce K/V tensors matching the generator's KV dimensions (32 layers × 2 × seq_len × hidden). The generator θ is also Qwen3-8B and is frozen throughout all training. Using the same model family for both eraser and generator means the steering states live in a compatible representation space. Eraser Eφ는 언어 모델 헤드가 제거된 전체 Qwen3-8B 백본이다. 출력은 생성기의 KV 차원(32 레이어 × 2 × seq_len × hidden)에 맞는 K/V 텐서를 생성하도록 투영된다. 생성기 θ도 Qwen3-8B이며 모든 학습 과정에서 동결된다. 두 eraser와 생성기 모두에 동일한 모델 패밀리를 사용한다는 것은 스티어링 상태가 호환 가능한 표현 공간에 있다는 의미다.

Training objective학습 목표

Training uses teacher-forced cross-entropy on answer tokens. Given a (context, erased span, answer) triple, the eraser produces steering states, the surrogate cache is assembled, and the generator computes the loss on the reference answer tokens. No special contrastive or reinforcement objective — standard next-token prediction over the answer, with the eraser as the only learnable component. 학습은 답변 토큰에 대한 teacher-forced cross-entropy를 사용한다. (컨텍스트, 삭제 구간, 답변) 트리플이 주어지면 eraser가 스티어링 상태를 생성하고, 대리 캐시가 조립되며, 생성기가 참조 답변 토큰에 대한 손실을 계산한다. 특수한 대조 학습이나 강화 학습 목표 없이 — 답변에 대한 표준 다음 토큰 예측이며, eraser만 학습 가능한 구성요소다.

Reliability across context lengths컨텍스트 길이 전반에 걸친 신뢰성

"Among approximate methods, KVEraser is the only one that is reliable across the full 1K–32K range."

— §5.4 · 원문 보기 (§5.4)

Other approximate methods (delete-and-shift, InContext) degrade significantly at longer contexts where contamination is more diffuse. KVEraser maintains EM ~0.879 because the steering states are trained to compensate regardless of context length — the eraser always sees the same-length span (not the growing suffix). 다른 근사 방법들(삭제-이동, InContext)은 오염이 더 분산되는 긴 컨텍스트에서 크게 성능이 저하된다. KVEraser는 스티어링 상태가 컨텍스트 길이와 관계없이 보정하도록 훈련되기 때문에 EM ~0.879를 유지한다 — eraser는 항상 같은 길이의 span을 본다(증가하는 suffix가 아니라).

Latency scaling레이턴시 확장

At short contexts (1K–4K), KVEraser's eraser itself is the bottleneck — it runs forward pass over prefix + span. Full recompute is cheaper here. But at 8K+ context, full recompute scales with suffix length while KVEraser's cost stays fixed at prefix + span. The crossover point is around 4K–8K tokens. 짧은 컨텍스트(1K–4K)에서는 KVEraser의 eraser 자체가 병목이다 — 접두사 + span에 대한 순전파를 실행한다. 전체 재계산이 여기서 더 저렴하다. 그러나 8K+ 컨텍스트에서는 전체 재계산이 suffix 길이에 따라 확장되고 KVEraser의 비용은 접두사 + span에 고정된다. 교차점은 약 4K–8K 토큰 부근이다.

Limitations and threats to validity한계와 타당성 위협

The paper acknowledges several important limitations: (1) KVEraser is evaluated only on Qwen3-8B — generalization to other model families (Llama, Mistral, etc.) is unverified; (2) only single-span erasing is tested; multi-span or overlapping erases are not addressed; (3) the NIAH and QA benchmarks test specific retrieval scenarios — how well erasing generalizes to open-ended generation is unknown; (4) the 8B-parameter eraser adds significant memory and compute overhead compared to lighter alternatives. 논문은 몇 가지 중요한 한계를 인정한다: (1) KVEraser는 Qwen3-8B에서만 평가됨 — 다른 모델 패밀리(Llama, Mistral 등)로의 일반화는 미검증; (2) 단일 span 삭제만 테스트됨; 다중 span 또는 겹치는 삭제는 다루지 않음; (3) NIAH 및 QA 벤치마크는 특정 검색 시나리오를 테스트함 — 오픈엔드 생성으로의 일반화는 알 수 없음; (4) 8B 파라미터 eraser는 가벼운 대안에 비해 상당한 메모리 및 계산 오버헤드를 추가함.

5 Discussion — what KV-space steering unlocks 시사점 — KV 공간 스티어링이 여는 가능성

"These results suggest that learned local KV steering is viable for efficient context erasing in long-context inference."

— §6 Conclusion · 원문 보기 (§6)

The paper's conclusions논문의 결론

KVEraser's core thesis is confirmed: a learned steering module can replace erased-span KV vectors and produce accurate responses without touching suffix KV. The 17.6× → +24% latency gap at 32K context is the headline result. The two-stage training pipeline (generic Wikipedia pre-training → task fine-tuning) is effective and the whole eraser trains in under a day on 2×A100 80GB. KVEraser의 핵심 테제가 확인된다: 학습된 스티어링 모듈이 삭제 구간 KV 벡터를 교체하고 suffix KV를 건드리지 않고 정확한 응답을 생성할 수 있다. 32K 컨텍스트에서 17.6× → +24%의 레이턴시 차이가 핵심 결과다. 2단계 학습 파이프라인(일반 Wikipedia 사전학습 → 태스크 파인튜닝)이 효과적이며 전체 eraser가 2×A100 80GB에서 하루 이내에 학습된다.

Authors' stated future directions저자들이 밝힌 향후 방향

The paper's conclusion section mentions three directions for follow-up work: (1) multi-span erasing — handling multiple non-contiguous deleted spans simultaneously; (2) cross-architecture generalization — training erasers for model families other than Qwen3; (3) privacy-sensitive applications — using KVEraser to comply with right-to-be-forgotten requests in shared KV prefix caches, where recomputation costs would be prohibitive at scale. 논문 결론 섹션은 후속 연구를 위한 세 가지 방향을 언급한다: (1) 다중 span 삭제 — 여러 비연속 삭제 span을 동시에 처리; (2) 크로스 아키텍처 일반화 — Qwen3 이외의 모델 패밀리를 위한 eraser 학습; (3) 개인정보 보호 민감 애플리케이션 — 대규모에서 재계산 비용이 금지적인 공유 KV prefix 캐시에서 잊혀질 권리 요청을 준수하기 위한 KVEraser 사용.

Editor's note — not the paper's claim편집자 주 — 논문의 주장 아님 Why this matters for production serving: KV prefix caching is already deployed in vLLM's enable_prefix_caching and SGLang's RadixAttention. The current bottleneck for sharing cached prefixes across sessions is staleness — once any span in the shared prefix needs updating, the entire downstream cache is invalidated. KVEraser offers a path toward surgical prefix repair: fix only the affected slot, keep the rest, avoid cascading invalidation. At 32K context, the 17.6× recompute vs +24% steering difference maps to roughly a 14× reduction in per-eviction compute on long shared prefixes — material at the latency budgets inference providers care about.

The catch for now: The eraser is 8B parameters — same size as the generator. Deploying a parallel 8B model just for KV steering is viable for high-throughput shared-prefix workloads but overkill for single-user sessions. Whether a distilled or LoRA-based eraser can match the full-backbone EM of 0.879 is the interesting engineering question. 프로덕션 서빙에서 이것이 중요한 이유: KV prefix 캐싱은 이미 vLLM의 enable_prefix_caching과 SGLang의 RadixAttention에 배포되어 있다. 세션 간 캐시 prefix 공유의 현재 병목은 오래된 데이터다 — 공유 prefix의 어떤 span이라도 업데이트가 필요하면 전체 하위 캐시가 무효화된다. KVEraser는 정밀한 prefix 수리로 가는 경로를 제공한다: 영향받은 슬롯만 수정하고 나머지는 유지하며 연쇄 무효화를 피한다. 32K 컨텍스트에서 17.6× 재계산 vs +24% 스티어링 차이는 긴 공유 prefix에서 무효화당 계산을 약 14배 줄이는 것에 해당한다 — 추론 공급자가 신경 쓰는 레이턴시 예산에서 의미 있는 수치다.

당장의 함정: Eraser는 8B 파라미터 — 생성기와 같은 크기다. KV 스티어링만을 위한 병렬 8B 모델 배포는 고처리량 공유-prefix 워크로드에서는 실행 가능하지만 단일 사용자 세션에는 과도하다. 증류되거나 LoRA 기반의 eraser가 전체 백본의 EM 0.879를 맞출 수 있는지가 흥미로운 엔지니어링 질문이다.
