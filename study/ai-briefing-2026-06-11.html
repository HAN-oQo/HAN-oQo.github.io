vLLM lands DiffusionGemma — the first diffusion LLM natively supported vLLMJun 10

vLLM's Jun 10 post introduces native support for DiffusionGemma, a diffusion language model (dLLM) that generates text by iterative denoising rather than left-to-right autoregression. The integration rides on Model Runner V2's ModelState abstraction and — neatly — reuses vLLM's existing speculative-decoding machinery to drive the multi-token denoising steps, showing MRV2 can host non-autoregressive architectures without a fork. For serving teams this opens a path where dLLMs, which trade sequential depth for parallel token refinement, run inside the same engine and scheduler as ordinary LLMs.

vLLM의 6/10 글은 DiffusionGemma 네이티브 지원을 소개한다 — 좌→우 자기회귀가 아니라 반복적 디노이징으로 텍스트를 생성하는 디퓨전 언어 모델(dLLM)이다. 통합은 Model Runner V2의 ModelState 추상화 위에서 이뤄졌고, 기존 speculative decoding 기계를 재사용해 멀티 토큰 디노이징 스텝을 구동한다 — MRV2가 포크 없이 비자기회귀 아키텍처를 수용할 수 있음을 보여준다. 서빙 팀에겐 순차 깊이를 병렬 토큰 정제와 맞바꾸는 dLLM이 일반 LLM과 같은 엔진·스케줄러 안에서 돌아가는 길이 열린다.

Dynamo cuts a DeepSeek-V4-Pro dev build on the TensorRT-LLM backend DynamoJun 6

NVIDIA tagged Dynamo v1.3.0-deepseek-v4-dev.1 (Jun 6), an experimental build that serves DeepSeek-V4-Pro — a ~1.6T-total / ~49B-active MoE with a 1M-token context and three selectable reasoning modes — on the TensorRT-LLM backend. The model enablement comes from the bundled TensorRT-LLM 1.3.0rc15.post1 (~140 DeepSeek-V4 commits: fused mHC RMS-norm, MLA overlap, FP8/NVFP4 quantization, EPLB routing, V2 KV-cache manager), with no model-specific Dynamo code in the tag. It signals how fast the stack moves now: a frontier open-weights flagship gets a runnable, containerized serving build within weeks of release.

NVIDIA가 Dynamo v1.3.0-deepseek-v4-dev.1(6/6)을 태깅했다 — 총 ~1.6T/활성 ~49B MoE에 1M 토큰 컨텍스트, 3가지 추론 모드를 가진 DeepSeek-V4-Pro를 TensorRT-LLM 백엔드에서 서빙하는 실험 빌드다. 모델 지원은 번들된 TensorRT-LLM 1.3.0rc15.post1(~140개 DeepSeek-V4 커밋: fused mHC RMS-norm, MLA 오버랩, FP8/NVFP4 양자화, EPLB 라우팅, V2 KV 캐시 매니저)에서 오며, 이 태그엔 모델 전용 Dynamo 코드가 없다. 프런티어 오픈웨이트 플래그십이 출시 몇 주 만에 실행 가능한 컨테이너 서빙 빌드를 얻는 속도를 보여준다.

Dynamo dev build serves Nemotron-3 Ultra on its vLLM backend DynamoJun 5

A second Dynamo dev tag, v1.3.0-nemotron-ultra-dev.1 (Jun 5), brings NVIDIA Nemotron-3 Ultra — a ~550B hybrid Mamba/Attention/MoE model with ~55B active params in NVFP4 — to Dynamo's vLLM backend on a vLLM v0.22.0 base. The patch stack is the interesting part: Mamba prefix-cache prefill/decode runtime support, hybrid hash-block KV events, MTP conv-state layout handling, and an SSM/NIXL tail fix, with aggregated and disaggregated recipes for B200 and H200. Hybrid SSM models stress exactly the KV-event and P/D plumbing that pure-attention models don't, so these patches map the real engineering cost of serving them disaggregated.

두 번째 Dynamo dev 태그 v1.3.0-nemotron-ultra-dev.1(6/5)은 NVFP4 기준 총 ~550B/활성 ~55B의 하이브리드 Mamba/Attention/MoE 모델 NVIDIA Nemotron-3 Ultra를 vLLM v0.22.0 베이스의 Dynamo vLLM 백엔드에 올린다. 흥미로운 건 패치 스택이다 — Mamba prefix 캐시 prefill/decode 런타임 지원, 하이브리드 해시블록 KV 이벤트, MTP conv-state 레이아웃 처리, SSM/NIXL 테일 수정, 그리고 B200·H200용 통합/분산 레시피. 하이브리드 SSM 모델은 순수 어텐션 모델이 건드리지 않는 KV 이벤트·P/D 배관을 정확히 압박하므로, 이 패치들은 분산 서빙의 실제 엔지니어링 비용을 그대로 보여준다.

EntropyInfer — entropy-guided adaptive inference for long-context LLMssparse attention2606.09508
From Rigid to Dynamic: Entropy-Guided Adaptive Inference for Long-Context LLMs (arXiv 2606.09508) ↗From Rigid to Dynamic: Entropy-Guided Adaptive Inference for Long-Context LLMs (arXiv 2606.09508) ↗
Problem문제 정의Sparse attention and KV-cache compression usually apply one fixed sparsity pattern or a uniform budget to every attention head, even though heads behave very differently — some focus rigidly on a few tokens, others roam across the context. A uniform budget over-serves the rigid heads and starves the dynamic ones, wasting compute or losing accuracy on long contexts.희소 어텐션과 KV 캐시 압축은 보통 모든 어텐션 헤드에 하나의 고정 희소 패턴이나 균일한 예산을 적용한다 — 그러나 헤드들은 매우 다르게 행동한다. 일부는 소수 토큰에 고정 집중하고, 다른 일부는 컨텍스트를 넓게 훑는다. 균일 예산은 고정형 헤드엔 과잉, 동적 헤드엔 부족이라 롱컨텍스트에서 연산을 낭비하거나 정확도를 잃는다.
Method방법The paper identifies two entropy regimes among heads — Rigid Heads and Dynamic Heads — and builds EntropyInfer, a training-free framework that uses attention entropy to allocate compute adaptively at the granularity of individual heads and segments during prefill. For decoding it adds a latent KV-cache compression scheme that uses the already-generated output tokens to identify and retain the most critical cache entries.논문은 헤드들 사이에서 두 가지 엔트로피 패턴 — Rigid Head와 Dynamic Head — 를 식별하고, prefill 동안 어텐션 엔트로피로 헤드·세그먼트 단위 연산을 적응 배분하는 학습 불필요 프레임워크 EntropyInfer를 만든다. 디코딩에는 이미 생성된 출력 토큰을 활용해 가장 중요한 캐시 엔트리를 식별·유지하는 잠재 KV 캐시 압축을 더한다.
Results결과Per-head, entropy-matched budgets let long-context inference keep accuracy where dynamic heads need full attention while cutting compute on rigid heads — a finer-grained operating point than fixed-pattern sparse attention, with no retraining required.헤드별 엔트로피 맞춤 예산은 동적 헤드가 전체 어텐션을 필요로 하는 곳의 정확도를 지키면서 고정형 헤드의 연산을 줄인다 — 고정 패턴 희소 어텐션보다 미세한 동작점을 재학습 없이 얻는다.
Summary요약Attention heads aren't equal — measure each head's entropy and give the wanderers the budget the starers don't need.어텐션 헤드는 동등하지 않다 — 헤드별 엔트로피를 재서, 응시형이 안 쓰는 예산을 방랑형에 주라.

Problem문제 정의Agentic RL couples a GPU training cluster to agents that may run anywhere — browsers, sandboxes, tools, other machines — yet most frameworks assume rollouts and optimization live in one tightly-coupled job. That makes heterogeneous agents, mixed tasks and long-running environments awkward to train, and a single failed rollout can stall the whole run.에이전트 RL은 GPU 학습 클러스터를 브라우저·샌드박스·툴·다른 머신 등 어디서든 돌 수 있는 에이전트와 결합한다 — 그러나 대부분의 프레임워크는 롤아웃과 최적화가 하나의 강결합 잡에 있다고 가정한다. 이로 인해 이종 에이전트·혼합 태스크·장기 실행 환경의 학습이 어렵고, 롤아웃 하나의 실패가 전체 런을 멈출 수 있다.

Summary요약Decouple where agents run from where models train — a swarm of clients feeds one trainer, and neither blocks the other.에이전트가 도는 곳과 모델이 학습되는 곳을 분리 — 클라이언트 스웜이 트레이너 하나를 먹이고, 서로를 막지 않는다.

Problem문제 정의LoRA adapters make multi-tenant customization cheap, but on modern architectures like MoE the per-adapter memory cost grows sharply, and coupled designs — where LoRA math runs inside the base-model workers — scale poorly and inflate tail latency. Hundreds of adapters end up competing with the base model for the same GPU memory and compute.LoRA 어댑터는 멀티테넌트 커스터마이징을 싸게 만들지만, MoE 같은 최신 아키텍처에선 어댑터당 메모리 비용이 급증하고, LoRA 연산이 베이스 모델 워커 안에서 도는 결합형 설계는 확장성이 나쁘고 테일 지연을 키운다. 수백 개 어댑터가 같은 GPU 메모리·연산을 두고 베이스 모델과 경쟁하게 된다.
Method방법InfiniLoRA disaggregates LoRA execution from base-model inference: a shared LoRA Server runs adapter computation with parallelism-aware execution and SLO-driven provisioning, connected to base workers through critical-path optimizations including GPU-initiated communication and hardware-specialized LoRA kernels. Base inference and adapter serving then scale (and are provisioned) independently.InfiniLoRA는 LoRA 실행을 베이스 모델 추론에서 분리한다 — 공유 LoRA 서버가 병렬성 인지 실행과 SLO 기반 프로비저닝으로 어댑터 연산을 수행하고, GPU 주도 통신과 하드웨어 특화 LoRA 커널 등 임계 경로 최적화로 베이스 워커와 연결된다. 베이스 추론과 어댑터 서빙이 독립적으로 확장·프로비저닝된다.
Results결과An average 3.05× higher serviceable request rate under strict latency SLOs, and a 54.0% improvement in the share of LoRA adapters meeting their SLO — disaggregation turns adapter serving from a tail-latency liability into an independently scalable tier.엄격한 지연 SLO 하에서 서비스 가능 요청률 평균 3.05× 향상, SLO를 충족하는 LoRA 어댑터 비율 54.0% 개선 — 분리는 어댑터 서빙을 테일 지연 부채에서 독립 확장 계층으로 바꾼다.
Summary요약Run LoRA on its own server tier, not inside the base model workers — both sides scale on their own terms.LoRA를 베이스 모델 워커 안이 아니라 전용 서버 계층에서 돌려라 — 양쪽이 각자의 조건으로 확장된다.
