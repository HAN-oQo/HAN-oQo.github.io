Tropical — SLO-aware multiplexing for disaggregated LLM serving Tropical — 분리형 LLM 서빙을 위한 SLO-aware 멀티플렉싱

Disaggregation (separate prefill/decode workers) kills prefill→decode interference but piles up prefill queuing; co-location (vLLM) kills queuing but suffers interference — neither meets both the TTFT and TPOT SLO (arXiv:2606.16264, DAC, Shanghai AI Lab et al.). Tropical's "multiplexing toggle" borrows a decode worker's spare TPOT slack to piggyback short prefills: it predicts each prefill's cost and co-locates only when slack ≥ cost (else routes to dedicated prefill workers), with HBM-watermark + chunked-prefill guards and a no-migration design (decode→prefill switching is the expensive direction it avoids). Result: up to 2.09× more requests at 90% SLO, 9× lower P90 TTFT vs DistServe, 2.33–2.8× lower P90 TPOT vs vLLM. Plain-language math (SLO-attainment intersection, slack), verbatim quotes + anchors, Pareto/timeline/architecture diagrams. Honest read: abstract vs body numbers differ, no ablations, no public code (built on vLLM). The "when" to the vLLM P/D note's "how". 분리형(prefill/decode 워커 분리)은 prefill→decode 간섭을 없애지만 prefill 큐잉이 쌓이고, 코로케이션(vLLM)은 큐잉을 없애지만 간섭에 시달림 — 어느 쪽도 TTFT와 TPOT SLO를 동시에 못 맞춤(arXiv:2606.16264, DAC, 상하이 AI Lab 외). Tropical의 "멀티플렉싱 토글"은 decode 워커의 여유 TPOT slack을 빌려 짧은 prefill을 얹는다: 각 prefill 비용을 예측해 slack ≥ 비용일 때만 코로케이션(아니면 전용 prefill 워커로), HBM-watermark + chunked-prefill 가드와 무(無)마이그레이션 설계(피하는 비싼 방향이 decode→prefill 전환). 결과: 90% SLO에서 최대 2.09× 더 많은 요청, DistServe 대비 P90 TTFT 9×, vLLM 대비 P90 TPOT 2.33–2.8×. 수식 쉬운 설명(SLO 달성률 교집합·slack), 원문 인용+앵커, Pareto/타임라인/아키텍처 다이어그램. 정직한 해석: 초록 vs 본문 수치 차이, 분해 실험 없음, 공개 코드 없음(vLLM 기반). vLLM P/D 노트의 "어떻게"에 대한 "언제".

CacheWise — KVCache management for serving LLM coding agents CacheWise — LLM 코딩 에이전트를 위한 KVCache 관리

A coding-agent session is a closed loop (tool-initiated turns ~20× user turns, prefixes ~21× more prefill-heavy than chat) that replays one huge, growing prefix across dozens of turns — and vLLM's FCFS+LRU thrash that cache (arXiv:2606.16824, UW + UVA). CacheWise adds two inference-node knobs: prefix-aware scheduling (dispatch the request reusing the most resident cache, ≈SJF) + predictive eviction (evict the session whose cache stays idle longest, estimating time-to-next-reuse from the tool's name+args via TF-IDF+KMeans survival curves). Result: 2–2.6× fewer evictions, up to 3.5× lower session completion at N>10, negligible CPU overhead. Plain-language math (the residual-life conditional expectation), verbatim quotes + anchors, a formal-model diagram, and a code-walk of the open-sourced predictor (CATraces dataset @181c435) — the system vLLM fork stays unreleased. The per-node twin of the llm-d Agentic Serving note. 코딩 에이전트 세션은 닫힌 루프(tool 촉발 턴이 사용자 턴의 ~20×, 프리픽스는 채팅보다 ~21× prefill 편중)로, 거대하고 자라는 프리픽스 하나를 수십 턴에 재생 — vLLM의 FCFS+LRU는 이 캐시를 갈아엎는다(arXiv:2606.16824, 워싱턴대 + 버지니아대). CacheWise는 추론 노드의 두 손잡이를 더한다: prefix-aware 스케줄링(남은 캐시를 가장 많이 재사용하는 요청을 먼저, ≈SJF) + 예측 축출(캐시가 가장 오래 놀 세션을 축출하되, 다음 재사용까지 시간을 tool 이름+인자로 TF-IDF+KMeans 생존곡선으로 추정). 결과: 축출 2–2.6× 감소, N>10에서 세션 완료 최대 3.5× 단축, CPU 오버헤드 미미. 수식 쉬운 설명(잔여수명 조건부 기댓값), 원문 인용+앵커, 형식 모델 다이어그램, 공개된 예측기 코드 워크(CATraces 데이터셋 @181c435) — 시스템 vLLM 포크는 미공개. llm-d Agentic Serving 노트의 노드-내 쌍둥이.

vLLM MLA × TRT-LLM Ragged Prefill — what it is, how it works, code flow vLLM MLA × TRT-LLM Ragged Prefill — 무엇인지·동작 원리·코드 흐름

MLA models (DeepSeek-V2/V3, GLM) cache the KV as a compressed latent, so their prefill needs an up-projection and has asymmetric q/k-vs-v head dims — not a drop-in for FlashAttention. TrtllmRaggedPrefillBackend is one of four pluggable MLA-prefill backends; it wraps FlashInfer's trtllm_ragged_attention_deepseek (a TRT-LLM-gen kernel), Blackwell SM100-only, running prefill over flat un-padded ("ragged") batches keyed by cu_seqlens — both the non-causal context-chunk pass and the causal new-tokens pass in one kernel. Covers what ragged/MLA-prefill mean, the mechanism, how it's selected (FlashAttention still wins auto), honest effects (the one +12.7% qps number is a small-model single-GPU self-bench; no isolated kernel bench; irrelevant to MI250), usage, and the code flow with permalinks pinned to 4bf699d. Diagrams + cited sources (vLLM PRs #26397/#32623, DeepSeek-V2, FlashInfer). MLA 모델(DeepSeek-V2/V3, GLM)은 KV를 압축 latent로 캐시 → prefill에 up-projection이 필요하고 q/k vs v head 차원이 비대칭 → FlashAttention에 그대로 못 들어감. TrtllmRaggedPrefillBackend는 4개 pluggable MLA-prefill 백엔드 중 하나로, FlashInfer의 trtllm_ragged_attention_deepseek(TRT-LLM-gen 커널)을 감싸 Blackwell SM100 전용으로 cu_seqlens로 주소를 매기는 평평한 무패딩("ragged") 배치에서 prefill을 돌림 — 비인과 context-chunk 패스와 인과 new-tokens 패스를 커널 하나로. ragged/MLA-prefill의 의미, 메커니즘, 선택 방식(auto에선 FlashAttention이 여전히 이김), 정직한 효과(유일한 +12.7% qps는 작은 모델·단일 GPU 셀프벤치; 분리 커널 벤치 없음; MI250엔 무관), 사용법, 4bf699d에 핀된 permalink 코드 흐름. 다이어그램 + 인용 출처(vLLM PR #26397/#32623, DeepSeek-V2, FlashInfer).

Parallel-Synthesis — synthesizing directly from parallel workers' KV caches Parallel-Synthesis — 병렬 워커의 KV cache에서 직접 합성

Agent workflows fan out into parallel branches then merge by concatenating branch text — discarding structure and re-prefilling done work (arXiv:2606.14672, Georgia Tech & Meta). Parallel-Synthesis instead lets the synthesizer consume the workers' KV caches directly, via RoPE positional re-encoding + a learnable cache mapper + a synthesizer LoRA trained to mimic the text route. On 9 datasets (Qwen3-14B): matches/beats text synthesis on 7, beats voting on 8, and cuts TTFT 2.5×–11×. The agent-side mirror of prefix-cache reuse.
