What is a “collective”? A communication op where a whole group of GPUs acts together in one coordinated call — unlike point-to-point (p2p), which is just one sender and one receiver.“collective(집합 통신)”란? GPU 그룹 전체가 하나의 호출로 함께 움직이는 통신 연산 — 보내는 쪽·받는 쪽 둘뿐인 point-to-point(p2p)와 대비된다.

  • p2p = 2 ranks (one send + one recv); a collective = every rank in the group (the “communicator”) joins the same op.p2p = rank 2개(send+recv); collective = 그룹(“communicator”) 안 모든 rank가 같은 연산에 참여.
  • “rank” = one GPU’s slot in the group; N ranks = world size. The library (NCCL on NVIDIA, RCCL on AMD) ships a fixed menu of them — the table below.“rank” = 그룹 내 GPU 한 자리; N개 rank = world size. 라이브러리(NVIDIA NCCL, AMD RCCL)가 고정된 메뉴를 제공 — 아래 표.
  • Each collective has a fixed pattern + a known cost. Choosing a parallelism strategy = choosing which collective runs, and how often.각 collective는 고정된 패턴 + 정해진 비용을 가짐. 병렬화 전략을 고르는 것 = 어떤 collective가 얼마나 자주 도는지를 고르는 것.

"so does ring leave each GPU with one chunk?""그럼 ring은 GPU마다 1청크만 갖는 거야?"No — that's only the halfway point. All-reduce always ends with every GPU holding the complete sum, ring and tree alike. They just take different routes: ring = reduce-scatter (each GPU finishes one chunk) → all-gather (those finished chunks are copied to everyone); tree = reduce (the root collects the full sum) → broadcast (the root copies it to everyone). Same end state, different path. Crucially NOT × L: inference has no backward pass, so only the current layer's activations + the residual are resident → A ≪ W, and ≪ M_kv at long context.   • Units. Compute is per-GPU per layer (× L for the whole model); memory is per-GPU whole model. Each strategy then divides or replicates these by n as the table shows.단위. 연산은 GPU당 레이어당(전체 모델은 × L); 메모리는 GPU당 전체 모델. 각 전략이 이를 표대로 n으로 나누거나 복제.
  • Comm moves activations, never weights. Weights stay put (sharded / replicated on each GPU); only the activation V = b s h (or V_kv = b s h_kv for CP's K/V) crosses GPUs — that's why comm ∝ b s h, not h². Per-GPU bytes = busbw factor × V (§5): all-reduce × 2(n−1)/n, all-gather / reduce-scatter / all-to-all × (n−1)/n, p2p × 1. So TP's 2 all-reduce/layer = 2 × 2(n−1)/n·V = 4(n−1)/n·V; EP's 2 all-to-all of k token-copies = 2(n−1)/n·k·V; PP hands off one V by p2p.통신은 활성값을 옮기지 가중치는 안 옮긴다. 가중치는 각 GPU에 샤딩/복제된 채 그대로 있고, 활성값 V = b s h(CP의 K/V는 V_kv = b s h_kv)만 GPU 사이를 건넌다 — 그래서 통신량 ∝ b s h이지 h²가 아니다. GPU당 바이트 = busbw 계수 × V(§5): all-reduce × 2(n−1)/n, all-gather / reduce-scatter / all-to-all × (n−1)/n, p2p × 1. 그래서 TP의 레이어당 all-reduce 2회 = 2 × 2(n−1)/n·V = 4(n−1)/n·V; EP의 all-to-all 2회(k개 토큰 복사) = 2(n−1)/n·k·V; PP는 V 하나를 p2p로 넘김.
  • The trade-offs jump out. TP divides compute, weights and KV by n · DP replicates weights (×1) and runs full compute on its own batch — pure throughput · EP compute ∝ active k but memory ∝ total e · PP divides weights by depth (L/n) · CP replicates weights but divides the KV by n — its whole reason for existing.트레이드오프가 드러난다. TP는 연산·가중치·KV를 모두 n으로 나눔 · DP는 가중치를 복제(×1)하고 자기 배치로 full 연산 — 순수 처리량 · EP는 연산이 활성 k·메모리가 전체 e에 비례 · PP는 가중치를 깊이(L/n)로 나눔 · CP는 가중치는 복제하되 KV를 n으로 나눔 — 존재 이유.

TP — tensor parallel: split the modelTP — 텐서 병렬: 모델을 쪼갬

  • Shards each GEMM (1st weight column-parallel, 2nd row-parallel) so GeLU needs no sync; the row-parallel output is summed by an all-reduce.각 GEMM을 샤딩(첫 가중치 column-parallel, 둘째 row-parallel)해 GeLU 동기 불필요; row-parallel 출력을 all-reduce로 합산.
  • Weights split, activations stay full (kept identical by the all-reduce). Megatron: 2 all-reduce fwd + 2 bwd → at inference 2 per layer [5]; each moves the b·s·h activation, not the weights.가중치는 쪼개고 activation은 full 유지(all-reduce로 동일하게 유지). Megatron: forward 2 + backward 2 → 추론 레이어당 2회 [5]; 각 all-reduce는 가중치가 아니라 b·s·h activation을 옮김.
  • After the row-parallel GEMMs each GPU holds only a partial [b,s,h]; the all-reduce sums the four partials into one identical full tensor that feeds the next module — two such sums per layer.row-parallel GEMM 뒤 각 GPU는 partial [b,s,h]만 보유; all-reduce가 4개 partial을 합쳐 다음 모듈로 가는 동일한 full 텐서로 만든다 — 레이어당 2회.

When to use언제 쓰나

  • The weights (or the KV cache) don't fit in one GPU — e.g. a 70B model in fp16 ≈ 140 GB > one 80 GB GPU. TP is the first reach.가중치(또는 KV 캐시)가 GPU 하나에 안 들어갈 때 — 예: 70B fp16 ≈ 140 GB > 80 GB GPU 하나. TP가 1순위.
  • You want to cut per-request latency, not just add throughput — TP parallelizes one token's matmuls across GPUs.요청당 지연을 줄이고 싶을 때(처리량만이 아니라) — TP는 토큰 하나의 matmul을 GPU에 나눠 동시 계산.
  • Keep the whole TP group inside one node's fast fabric (NVLink/NVSwitch · xGMI); TP across nodes over IB is brutally slow.TP 그룹 전체를 한 노드의 빠른 패브릭(NVLink/NVSwitch · xGMI) 안에 유지; 노드 간 IB TP는 치명적으로 느림.

  • It splits the weights AND the KV cache ~1/N per GPU → a model + its KV that overflow one GPU now fit. Inference is memory-bound, so adding memory is the first win.가중치와 KV 캐시를 둘 다 GPU당 ~1/N로 쪼갬 → 한 GPU를 넘치던 모델+KV가 들어감. 추론은 메모리 바운드라 메모리 확보가 첫 이득.
  • Lower latency at low concurrency. Unlike DP/PP (which mostly add throughput), TP parallelizes the arithmetic of a single forward pass → time-per-token drops — exactly what interactive serving (small batch, tight TTFT/ITL) needs.낮은 동시성에서 지연↓. DP/PP(주로 처리량)와 달리 TP는 단일 forward의 연산을 병렬화 → 토큰당 시간 감소 — 인터랙티브 서빙(작은 배치, 빠듯한 TTFT/ITL)에 딱.
  • Aggregates HBM bandwidth. Decode re-reads weights+KV from HBM every token; N GPUs give N× the HBM bandwidth, so decode gets faster, not just bigger.HBM 대역폭 합산. 디코드는 토큰마다 HBM에서 가중치+KV를 다시 읽음; GPU N개면 HBM 대역폭 N× → 디코드가 커지기만 하는 게 아니라 빨라짐.
  • Even, synchronous, bubble-free & model-agnostic. Every GPU does an equal slice and syncs twice per layer (all-reduce) — no pipeline bubble (vs PP), works for any dense model (vs EP, MoE-only). On NVLink the all-reduce is cheap, so it's the general-purpose default; beyond one node you wrap it in PP.균등·동기·버블 없음·모델 불문. 모든 GPU가 같은 몫을 맡고 레이어당 2회 동기(all-reduce) — pipeline 버블 없음(PP 대비), 모든 dense 모델에 동작(EP=MoE 전용 대비). NVLink에선 all-reduce가 싸서 범용 기본값; 노드를 넘으면 PP로 감쌈.

  • --tensor-parallel-size N (-tp N) — set to the #GPUs in one node (e.g. -tp 8 on an 8×GPU box).한 노드의 GPU 수로 설정(예: 8×GPU 노드에서 -tp 8).
  • vLLM shards attention heads + MLP + the KV cache across ranks automatically; N must divide the model's attention-head count.vLLM이 attention head + MLP + KV 캐시를 rank에 자동 샤딩; N은 모델의 attention-head 수를 나눠떨어뜨려야 함.
  • Go multi-node by adding PP: -tp 8 -pp 2 = 8-way TP inside each of 2 nodes.멀티노드는 PP 추가: -tp 8 -pp 2 = 2노드 각각에서 8-way TP.

TP + sequence-parallel — shard the LayerNorm/dropout activations tooTP + 시퀀스 병렬 — LayerNorm/dropout 활성값까지 쪼갬

  • Same head/MLP weight split as TP, but outside the GEMM regions the activations stay sequence-sharded [b,s/4,h]. The all-reduce splits into all-gather (→ full, on entry) and reduce-scatter (→ [b,s/4,h], on exit) — the same total bytes.head/MLP 가중치 분할은 TP와 동일하나, GEMM 구간 밖에선 activation이 시퀀스-샤딩 [b,s/4,h]로 유지. all-reduce가 all-gather(→ full, 진입)와 reduce-scatter(→ [b,s/4,h], 이탈)로 갈림 — 총 바이트는 동일.
  • The full [b,s,h] exists only inside the TP GEMM regions; activation memory drops to ~1/n between blocks for the same comm bytes (the all-reduce just becomes AG + RS). This is a big win in training (activations are kept for the whole sequence × every layer for backprop) — but in inference activations are transient and tiny (decode is [b,1,h]), so the saving is marginal. Inference win추론 이득

  • Shards the LayerNorm/dropout/residual activations along the sequence → activation memory between blocks drops ~1/n, for the same comm bytes (all-reduce → all-gather + reduce-scatter).LayerNorm/dropout/residual 활성값을 시퀀스축으로 샤딩 → 블록 사이 activation 메모리 ~1/n, 통신 바이트는 동일(all-reduce → all-gather + reduce-scatter).
  • But activations are a training bottleneck, not an inference one.하지만 activation은 학습 병목이지 추론 병목이 아니다.   • And it's not free at runtime: splitting the all-reduce into AG + RS is 2 collectives and forfeits vLLM's tuned custom / NVLS all-reduce — it can even add a little decode latency. vLLM

  • An optional torch.compile pass (pass_config.enable_sequence_parallelism), off by default. In vLLM its real value is enabling collective + RMSNorm/quant fusions at large TP — not the activation saving — so it's turned on situationally, not as an automatic companion to TP.선택적 torch.compile 패스(pass_config.enable_sequence_parallelism), 기본 비활성. vLLM에서 진짜 가치는 큰 TP에서 collective + RMSNorm/quant 융합을 가능케 하는 것 — activation 절감이 아님 — 그래서 TP의 자동 동반자가 아니라 상황별로 켠다.

EP — expert parallel (MoE): split the expertsEP — expert 병렬(MoE): expert를 쪼갬

  • Each MoE layer routes tokens to the GPU holding their expert (all-to-all dispatch) and sends the results back (all-to-all combine) [8]. Buffers are fixed-size (expert capacity; overflow skips via the residual) [7].각 MoE 레이어가 토큰을 해당 expert의 GPU로(all-to-all dispatch) 보내고 결과를 돌려받음(all-to-all combine) [8]. 버퍼는 고정 크기(expert capacity; 초과는 residual 우회) [7].
  • Attention is still TP-sharded by heads; only the FFN is replaced by experts split across GPUs, so the all-to-all fires on MoE layers only.attention은 여전히 TP가 head로 샤딩; FFN만 GPU에 분산된 expert로 대체돼 all-to-all은 MoE 레이어에서만 발생.
  • Cross-node all-to-all dominates — DeepSeek-V3 measures a "computation-to-communication ratio of approximately 1:1" [8].노드 간 all-to-all이 지배적 — DeepSeek-V3는 "연산-통신 비 ≈1:1" 측정 [8].

Inference win추론 이득

  • Expert weights are partitioned across GPUs (each GPU owns a subset); attention stays replicated/TP → a huge MoE fits and each GPU stores/reads fewer experts.expert 가중치를 GPU에 분할(각 GPU가 일부만 보유); attention은 복제/TP 유지 → 거대 MoE가 들어가고 GPU별 expert 저장/읽기 감소.
  • TP+EP is the low-latency / low-concurrency sweet spot; at high concurrency you move to DP+EP.TP+EP가 저지연/낮은 동시성 최적; 높은 동시성에선 DP+EP로.

  • --enable-expert-parallel (combine with -tp/-dp); EP size = TP × DP.(-tp/-dp와 함께); EP 크기 = TP × DP.
  • The all-to-all dispatch/combine path only engages when dp_size > 1; TP-only EP still uses all-reduce.all-to-all dispatch/combine 경로는 dp_size > 1일 때만; TP 단독 EP는 all-reduce 사용.

DP — data parallel: replicate the modelDP — 데이터 병렬: 모델을 복제

  • At inference each GPU holds the full model and runs a different request batch → no per-layer collective (unlike DP-training, which all-reduces gradients). The mirror image of TP: shapes stay [b/4,s,h] throughout.추론에선 각 GPU가 모델 전체를 갖고 다른 요청 배치를 처리 → 레이어당 collective 없음(gradient를 all-reduce하는 DP-학습과 다름). TP의 거울상: shape가 내내 [b/4,s,h].
  • Exception — vLLM DP-attention (MoE/MLA): attention runs DP (avoids duplicating the KV cache), experts run EP/TP, so ranks step in lockstep — vLLM inserts dummy forward passes + a tiny coordination all-reduce every N steps [15].예외 — vLLM DP-attention(MoE/MLA): attention은 DP(KV cache 중복 회피), expert는 EP/TP → 전 rank가 lockstep; vLLM은 dummy forward + N스텝마다 작은 조정 all-reduce 삽입 [15].

  • The model already fits on one GPU and you want more throughput — each replica handles a different batch of requests.모델이 GPU 하나에 이미 들어가고 처리량을 더 원할 때 — 각 replica가 서로 다른 요청 배치를 처리.

Inference win추론 이득

  • Near-linear throughput scaling with no per-layer collective (replicas independent) — the cheapest way to add QPS.레이어당 collective 없이(replica 독립) 거의 선형 처리량 — QPS를 늘리는 가장 싼 방법.
  • For MoE/MLA, DP-attention runs attention data-parallel so the KV cache isn't duplicated across ranks — a big memory saver vs TP for MLA (tiny KV heads).MoE/MLA에선 DP-attention이 attention을 데이터 병렬로 돌려 KV 캐시를 rank 간 중복 안 함 — MLA(작은 KV head)에선 TP 대비 큰 메모리 절약.

  • --data-parallel-size N (-dp N).

PP — pipeline parallel: split by depthPP — 파이프라인 병렬: 깊이로 쪼갬

  • Each GPU holds a contiguous block of whole layers at full size (faint cells = stages not on that GPU). SP vs CP

Both shard the same axis — the sequence (s). The difference is how far the split reaches into the layer:둘 다 같은 축 — 시퀀스(s) — 를 쪼갠다. 차이는 그 분할이 레이어 안 어디까지 미치느냐다:

  • SP (Megatron sequence-parallel) shards only the activations outside the GEMMs — LayerNorm / dropout / residual. Inside attention & MLP it reverts to TP (full hidden). It rides on TP's existing communication (the all-reduce becomes all-gather + reduce-scatter, same bytes), adds zero extra comm, and does not shard the KV cache. Purpose: shrink activation memory, for free, inside a TP group.SP (Megatron 시퀀스 병렬)는 GEMM 바깥 활성값만 쪼갬 — LayerNorm / dropout / residual. attention·MLP 안에선 TP로 되돌아감(full hidden). TP의 기존 통신에 얹힘(all-reduce가 all-gather + reduce-scatter로, 바이트 동일), 추가 통신 0, KV 캐시는 안 쪼갬. 목적: TP 그룹 안에서 공짜로 활성값 메모리 절감.
  • CP (context parallel) keeps the sequence split through attention — the expensive, token-coupling part. Each GPU owns its tokens and their KV, so attention needs a real cross-GPU exchange (ring-p2p of K/V, or Ulysses all-to-all). Purpose: serve a context longer than one GPU can hold, and scale it across GPUs/nodes.CP (context 병렬)는 시퀀스 분할을 attention까지 유지 — 비싸고 토큰이 서로 얽히는 부분. 각 GPU가 자기 토큰 과 그 KV를 가지므로 attention에서 진짜 GPU 간 교환 필요(K/V ring-p2p, 또는 Ulysses all-to-all). 목적: GPU 하나로 못 담는 길이의 컨텍스트 서빙 + GPU/노드 간 확장.
  • One-liner: SP = a free activation-memory cut inside a node; CP = shard the KV/sequence so long context fits and scales out. Terminology trap: "sequence parallelism" is overloaded — Megatron-SP (LayerNorm/dropout only, this box) vs DeepSpeed-Ulysses "sequence parallelism", which is actually a CP method (it shards attention). In vLLM, CP is exposed as -dcp; Megatron-SP is the internal torch.compile pass.한 줄: SP = 노드 안에서 공짜 활성값 메모리 절감; CP = KV/시퀀스를 쪼개 롱컨텍스트를 담고 확장. 용어 함정: "sequence parallelism"은 중의적 — Megatron-SP(LayerNorm/dropout만, 이 박스) vs DeepSpeed-Ulysses "sequence parallelism"은 사실 CP 계열(attention을 쪼갬). vLLM에선 CP가 -dcp로 노출; Megatron-SP는 내부 torch.compile 패스.

  • For MHA, yes — same amount. TP head-slices the KV to M_kv/n; DP-attention gives each rank the full KV of its own 1/n of requests — also M_kv/n per GPU. Reading the ceiling성능 상한 읽는 법

The ceiling of any strategy = the peak BW of the link its collective lands on (§5 table) × the busbw factor. Two bands dominate: intra-node NVLink/xGMI ≈ 450–900 GB/s, and cross-node NIC ≈ 25–100 GB/s — roughly a 10× cliff. So the practical rule:어떤 전략이든 상한 = 그 collective가 타는 링크의 피크 BW(§5 표) × busbw 계수. 두 대역이 지배적: 노드 내 NVLink/xGMI ≈ 450–900 GB/s, 노드 간 NIC ≈ 25–100 GB/s — 대략 10× 절벽. 그래서 실전 규칙:

  • TP / TP+SP move the activation every layer with all-reduce — BW-heavy, so they must stay intra-node.TP / TP+SP는 레이어마다 all-reduce로 activation을 옮김 — BW 부담이 커서 노드 내에 머물러야 함.
  • EP's all-to-all is the cross-node pain point (the 1:1 comp:comm) — it lives or dies on NIC bandwidth.EP의 all-to-all이 노드 간 고통 지점(1:1 연산:통신) — NIC 대역폭에 생사가 걸림.
  • PP / ring-CP send little (p2p), so they tolerate slow links and cross nodes happily; DP sends ~nothing.PP / ring-CP는 전송량이 작아(p2p) 느린 링크도 견디고 노드를 잘 넘음; DP는 거의 전송 없음.

busbw vs algbw — the number to trustbusbw vs algbw —믿을 수치

nccl-tests prints two bandwidths. algbw = size/time scales with rank count (don't compare to peak). busbw = algbw × a per-collective factor → rank-independent, so it maps onto the hardware peak [25]: all-reduce ×2(n−1)/n; reduce-scatter / all-gather / all-to-all ×(n−1)/n; broadcast/reduce ×1. Workflow: run the collective → read busbw → compare to the peak for the link NCCL_DEBUG says you're on. busbw ≪ peak = you're on a slower path than you think. nccl-tests는 대역폭 둘을 찍음. algbw = size/time은 rank 수에 비례(피크와 비교 X). busbw = algbw × collective별 계수 → rank 무관, HW 피크에 대응 [25]: all-reduce ×2(n−1)/n; reduce-scatter/all-gather/all-to-all ×(n−1)/n; broadcast/reduce ×1. 흐름: collective 실행 → busbw 읽기 → NCCL_DEBUG가 알려준 링크의 피크와 비교. busbw ≪ 피크 = 생각보다 느린 경로.
