1Communication primitives & their cost통신 primitive와 비용

What is a “collective”? A communication op where a whole group of GPUs acts together in one coordinated call — unlike point-to-point (p2p), which is just one sender and one receiver.“collective(집합 통신)”란? GPU 그룹 전체가 하나의 호출로 함께 움직이는 통신 연산 — 보내는 쪽·받는 쪽 둘뿐인 point-to-point(p2p)와 대비된다.

  • p2p = 2 ranks (one send + one recv); a collective = every rank in the group (the “communicator”) joins the same op.p2p = rank 2개(send+recv); collective = 그룹(“communicator”) 안 모든 rank가 같은 연산에 참여.
  • “rank” = one GPU’s slot in the group; N ranks = world size. The library (NCCL on NVIDIA, RCCL on AMD) ships a fixed menu of them — the table below.“rank” = 그룹 내 GPU 한 자리; N개 rank = world size. 라이브러리(NVIDIA NCCL, AMD RCCL)가 고정된 메뉴를 제공 — 아래 표.
  • Each collective has a fixed pattern + a known cost. Choosing a parallelism strategy = choosing which collective runs, and how often.각 collective는 고정된 패턴 + 정해진 비용을 가짐. 병렬화 전략을 고르는 것 = 어떤 collective가 얼마나 자주 도는지를 고르는 것.

Cost model — every collective ≈ α·(#rounds) + β·(bytes moved) (the alpha-beta / Hockney model) [1]:비용 모델 — 모든 collective ≈ α·(라운드 수) + β·(이동 바이트) (alpha-beta / Hockney 모델) [1]:

  • α = per-message latency (the fixed startup cost of each hop); β = per-byte time = 1 / bandwidth.α = 메시지당 지연(홉마다 드는 고정 비용); β = 바이트당 시간 = 1 / 대역폭.
  • small message → latency-bound (α dominates): fewer rounds win → favors a tree.작은 메시지 → 지연 바운드(α 지배): 라운드 적은 쪽이 유리 → tree 유리.
  • large message → bandwidth-bound (β dominates): moving fewer bytes wins → favors a ring.큰 메시지 → 대역폭 바운드(β 지배): 바이트를 적게 옮기는 쪽이 유리 → ring 유리.

two facts that explain everything전부를 설명하는 두 사실
  • ① all-reduce = reduce-scatter + all-gather. NCCL, verbatim: “Executing ReduceScatter, followed by AllGather, is equivalent to the AllReduce operation” [2] — so sequence-parallel TP can swap one all-reduce for AG+RS at identical bytes.① all-reduce = reduce-scatter + all-gather. NCCL 원문: “ReduceScatter 후 AllGather 실행은 AllReduce와 동등” [2] — 그래서 sequence-parallel TP가 all-reduce 하나를 같은 바이트로 AG+RS로 치환 가능.
  • ② Ring vs Tree. Ring all-reduce is bandwidth-optimal (per-rank ≈ 2(N−1)/N·data, N-independent [3]) but its latency grows ∝ N; NCCL’s double-binary trees give O(log N) latency for small messages, auto-switching to rings for bandwidth [4]. (Worked out with numbers at the end of this section.)② Ring vs Tree. Ring all-reduce는 대역폭 최적(rank당 ≈ 2(N−1)/N·data, N 무관 [3])이지만 지연이 N에 비례; NCCL의 double-binary tree는 작은 메시지에 O(log N) 지연을 주고 대역폭이 필요하면 ring으로 자동 전환 [4]. (이 섹션 끝에서 숫자로 계산.)

Ring — N GPUs in a logical circle, each talking only to its 2 neighbors:Ring — N개 GPU를 원으로, 각자 양옆 2개하고만 통신:

"so does ring leave each GPU with one chunk?""그럼 ring은 GPU마다 1청크만 갖는 거야?"No — that's only the halfway point. All-reduce always ends with every GPU holding the complete sum, ring and tree alike. They just take different routes: ring = reduce-scatter (each GPU finishes one chunk) → all-gather (those finished chunks are copied to everyone); tree = reduce (the root collects the full sum) → broadcast (the root copies it to everyone). Same end state, different path. The earlier impression came from the figure showing only ring's reduce-scatter half — now it runs the all-gather too.아니다 — 그건 중간 지점일 뿐. all-reduce는 ring·tree 모두 항상 모든 GPU가 전체 합을 갖고 끝난다. 경로만 다를 뿐: ring = reduce-scatter(각 GPU가 한 청크 완성) → all-gather(완성된 청크들을 전원에 복사); tree = reduce(루트가 전체 합 수집) → broadcast(루트가 전원에 복사). 끝 상태는 같고 길만 다름. 이전 오해는 그림이 ring의 reduce-scatter 절반만 보여줘서였고, 지금은 all-gather까지 돈다.

① Assumptions① 가정

  • N GPUs on one fabric · link bandwidth B · per-hop latency α · per-byte time β = 1/B · message size S (the all-reduce tensor).N개 GPU가 한 패브릭에 · 링크 대역폭 B · 홉당 지연 α · 바이트당 시간 β = 1/B · 메시지 크기 S(all-reduce 텐서).
  • general cost = (rounds)·α + (bytes/GPU)·β. Ring and tree differ on both terms: a ring takes more hops but ships only S/N per hop; a simple tree takes fewer hops but ships the full S every hop. So tree wins the latency term, ring wins the bandwidth term.일반 비용 = (라운드)·α + (GPU당 바이트)·β. ring·tree는 두 항 모두 다르다: ring은 홉이 많지만 홉당 S/N만, 단순 tree는 홉이 적지만 매 홉 전체 S를 보낸다. 그래서 지연 항은 tree, 대역폭 항은 ring이 유리하다.

② Ring cost② Ring 비용

  • rounds = reduce-scatter (N−1) + all-gather (N−1) = 2(N−1)라운드 = reduce-scatter (N−1) + all-gather (N−1) = 2(N−1)
  • T_ring = 2(N−1)·α + (2(N−1)/N)·S·β  — byte term ≈ 2S, independent of N (bandwidth-optimal); latency ∝ N.— 바이트 항 ≈ 2S, N 무관(대역폭 최적); 지연 ∝ N.

③ Tree cost③ Tree 비용

  • rounds = reduce up log₂N + broadcast down log₂N = 2·log₂N라운드 = reduce 올림 log₂N + broadcast 내림 log₂N = 2·log₂N
  • T_tree = 2·log₂N·α + (2·log₂N)·S·β  — fewer hops (O(log N)) but it moves the full S each hop → byte term grows with log₂N (≈ log₂N × ring's). NCCL’s double-binary tree is a smarter variant that recovers ring-like ~2S bandwidth while keeping log-latency.— 홉은 적지만(O(log N)) 매 홉 전체 S를 옮겨 바이트 항이 log₂N에 비례 증가(ring의 ≈ log₂N배). NCCL의 double-binary tree는 ring 수준 ~2S 대역폭을 회복하며 log 지연을 유지하는 개선판.

TP (tensor parallel) — split the model:TP(텐서 병렬) — 모델을 쪼갬:

  • shards each GEMM (1st weight column-parallel, 2nd row-parallel) so GeLU needs no sync; the row-parallel output is summed by an all-reduce.각 GEMM을 샤딩(첫 가중치 column-parallel, 둘째 row-parallel)해 GeLU 동기 불필요; row-parallel 출력을 all-reduce로 합산.
  • weights split, activations stay full (kept identical by the all-reduce). Megatron: 2 all-reduce fwd + 2 bwd → at inference 2 per layer [5]; each moves the b·s·h activation, not the weights.가중치는 쪼개고 activation은 full 유지(all-reduce로 동일하게 유지). Megatron: forward 2 + backward 2 → 추론 레이어당 2회 [5]; 각 all-reduce는 가중치가 아니라 b·s·h activation을 옮김.

EP (expert parallel, MoE) — split the experts:EP(expert 병렬, MoE) — expert를 쪼갬:

  • each MoE layer routes tokens to the GPU holding their expert (all-to-all dispatch) and sends results back (all-to-all combine) [8]. Buffers are fixed-size (expert capacity; overflow skips via the residual) [7].각 MoE 레이어가 토큰을 해당 expert의 GPU로(all-to-all dispatch) 보내고 결과를 돌려받음(all-to-all combine) [8]. 버퍼는 고정 크기(expert capacity; 초과는 residual 우회) [7].
  • cross-node all-to-all dominates — DeepSeek-V3 measures a "computation-to-communication ratio of approximately 1:1" [8].노드 간 all-to-all이 지배적 — DeepSeek-V3는 "연산-통신 비 ≈1:1" 측정 [8].

DP (data parallel) — replicate the model:DP(데이터 병렬) — 모델을 복제:

  • at inference each GPU holds the full model and runs a different request batch → no per-layer collective (unlike DP-training, which all-reduces gradients). The mirror image of TP.추론에선 각 GPU가 모델 전체를 갖고 다른 요청 배치를 처리 → 레이어당 collective 없음(gradient를 all-reduce하는 DP-학습과 다름). TP의 거울상.
  • exception — vLLM DP-attention (MoE/MLA): attention runs DP (avoids duplicating the KV cache), experts run EP/TP, so ranks step in lockstep — vLLM inserts dummy forward passes + a tiny coordination all-reduce every N steps [15].예외 — vLLM DP-attention(MoE/MLA): attention은 DP(KV cache 중복 회피), expert는 EP/TP → 전 rank가 lockstep; vLLM은 dummy forward + N스텝마다 작은 조정 all-reduce 삽입 [15].

CP — context (sequence) parallel, for long contextCP — context(sequence) parallel, 롱컨텍스트용

  • CP shards the sequence — each GPU holds part of the tokens. Everything except attention is token-independent → no comm; attention is the catch (every query must see all K/V).CP는 시퀀스를 쪼갬 — 각 GPU가 토큰 일부만 보유. attention 외엔 토큰 독립 → 통신 없음; attention만 문제(모든 query가 전체 K/V를 봐야 함).
  • Ring attention: Q stays put, the K/V blocks rotate neighbor-to-neighbor (p2p), overlapping transfer with blockwise attention — scales with #GPUs, works for GQA/MQA, but small blocks cost some FlashAttention efficiency [16C].Ring attention: Q 고정, K/V 블록을 이웃끼리 p2p로 회전, 전송과 blockwise attention을 겹침 — GPU 수만큼 확장·GQA/MQA 가능하지만 작은 블록이 FlashAttention 효율을 깎음 [16C].
  • DeepSpeed-Ulysses: 2 all-to-all per attention to transpose sequence↔heads — very efficient intra-node, but parallel degree is capped by head count (poor for GQA/MQA) [17C]; USP fuses the two.DeepSpeed-Ulysses: attention당 all-to-all 2회로 sequence↔heads transpose — 노드 내 매우 효율적이나 병렬도가 head 수에 묶임(GQA/MQA 불리) [17C]; USP가 둘을 결합.
  • vLLM main: Decode Context Parallel -dcp <size> shards the KV cache along tokens to cut KV duplication once TP exceeds the KV-head count (MLA/GQA); MLA chunked-prefill runs a Context-KV all-gather. Prefill CP (PCP) is an open RFC for TTFT [18C]. (Not traced in §3.)vLLM main: Decode Context Parallel -dcp <size>가 TP가 KV-head 수를 넘으면(MLA/GQA) KV 캐시를 토큰축으로 샤딩; MLA chunked-prefill은 Context-KV all-gather 수행. Prefill CP(PCP)는 TTFT용 RFC [18C]. 4The hardware underneath + how to check그 아래 하드웨어 + 확인법

When ncclAllReduce runs, NCCL/RCCL has already (at init) chosen the physical link per GPU pair — a first-match walk P2P → SHM → NET ranked by a distance hierarchy PATH_NVL(NVLink) < PATH_PIX/PXB(PCIe) < PATH_SYS(cross-NUMA) < PATH_NET [NCCL graph.h]. Note: NVLink and PCIe-P2P are the same "P2P transport" (not a code branch); NVSwitch is subsumed as PATH_NVL. Cross-node uses GPUDirect RDMA over InfiniBand/RoCE (or host-staged TCP fallback) [7H]. ncclAllReduce가 돌 때 NCCL/RCCL은 이미(init 때) GPU 쌍별 물리 링크를 선택해 둠 — P2P → SHM → NET 첫-매치 순회, 거리 계층 PATH_NVL(NVLink) < PATH_PIX/PXB(PCIe) < PATH_SYS(NUMA간) < PATH_NET로 랭킹 [NCCL graph.h]. NVLink와 PCIe-P2P는 같은 "P2P transport"(코드 분기 아님); NVSwitch는 PATH_NVL로 포함. 노드 간은 InfiniBand/RoCE 위 GPUDirect RDMA(또는 host-staged TCP 폴백) [7H].

busbw vs algbw — the number to trustbusbw vs algbw —믿을 수치

nccl-tests prints two bandwidths. algbw = size/time scales with rank count (don't compare to peak). busbw = algbw × a per-collective factor → rank-independent, so it maps onto the hardware peak [25]: all-reduce ×2(n−1)/n; reduce-scatter / all-gather / all-to-all ×(n−1)/n; broadcast/reduce ×1. Workflow: run the collective → read busbw → compare to the peak for the link NCCL_DEBUG says you're on. busbw ≪ peak = you're on a slower path than you think. nccl-tests는 대역폭 둘을 찍음. algbw = size/time은 rank 수에 비례(피크와 비교 X). busbw = algbw × collective별 계수 → rank 무관, HW 피크에 대응 [25]: all-reduce ×2(n−1)/n; reduce-scatter/all-gather/all-to-all ×(n−1)/n; broadcast/reduce ×1. 흐름: collective 실행 → busbw 읽기 → NCCL_DEBUG가 알려준 링크의 피크와 비교. busbw ≪ 피크 = 생각보다 느린 경로.
