"Towards Direct Latent-Space Synthesis for Parallel Branches in LLM-Agent Workflows." Agent workflows fan out into parallel branches (explore subtasks, retrieve evidence, sample candidates) then merge. Today they merge by concatenating branch text — which throws away the parallel structure and re-prefills work already done. This paper makes the synthesizer consume the workers' KV caches directly: same answers (7/9 datasets), but 2.5×–11× faster time-to-first-token. "Towards Direct Latent-Space Synthesis for Parallel Branches in LLM-Agent Workflows." 에이전트 워크플로우는 병렬 브랜치(서브태스크 탐색·증거 검색·후보 샘플링)로 펼쳐졌다가 합쳐진다. 지금은 브랜치 텍스트를 이어붙여 합치는데 — 병렬 구조를 버리고 이미 한 일을 re-prefill한다. 이 논문은 합성기가 워커의 KV cache를 직접 소비하게 만든다: 답은 동등(9개 중 7개), 그러나 TTFT 2.5×–11× 빠름.

one-line summary한 줄 요약 m worker agents each produce an output (with its own KV cache); a synthesizer must merge them. The default is to paste the workers' text into one prompt and re-prefill it — redundant compute and lost structure. Parallel-Synthesis instead pastes the workers' KV caches side by side and decodes from them, via (1) RoPE positional re-encoding (re-anchor every branch to a shared point), (2) a learnable cache mapper (per-branch affine calibration of K/V), and (3) a synthesizer LoRA, trained to mimic the text route. Result on 9 datasets (Qwen3-14B): matches/beats text synthesis on 7, beats majority voting on 8, and cuts TTFT 2.5×–11×. No public code. m개의 워커 에이전트가 각자 출력(과 자기 KV cache)을 만들고, 합성기가 그것들을 합쳐야 한다. 기본은 워커 텍스트를 한 프롬프트에 붙여 re-prefill — 중복 연산 + 구조 손실. Parallel-Synthesis는 대신 워커 KV cache를 나란히 붙여 거기서 디코딩한다: (1) RoPE 위치 재인코딩(모든 브랜치를 공유 지점에 재정렬), (2) 학습형 cache mapper(브랜치별 K/V affine 보정), (3) 합성기 LoRA, 텍스트 경로를 모사하도록 학습. 9개 데이터셋(Qwen3-14B) 결과: 7개에서 텍스트 합성 동등/상회, 8개에서 다수결 상회, TTFT 2.5×–11× 단축. 공개 코드 없음.

1Problem — text concatenation throws away the parallel structure문제 정의 — 텍스트 concat이 병렬 구조를 버린다

LLM agents run through a sequential text interface: the whole agent state (history, tool outputs, retrieved evidence, intermediate reasoning) is flattened into one ordered token prefix. LLM 에이전트는 순차 텍스트 인터페이스로 동작한다: 에이전트 상태 전체(히스토리·도구 출력·검색 증거·중간 추론)가 하나의 정렬된 토큰 prefix로 평탄화된다.

"the entire agent state, including message history, tool outputs, retrieved evidence, and intermediate reasoning, is serialized into a single ordered token prefix for next-step execution."

— §1, ¶1 · arXiv:2606.14672 §1

But many workflows are naturally a DAG: independent branches explore subtasks / retrieve / sample candidates, then a synthesizer merges them ("parallel-then-synthesize"). Because the LLM only eats linear text, merging means concatenating the branch outputs into one expanded prompt — which has two costs: 그러나 많은 워크플로우는 본질적으로 DAG다: 독립 브랜치가 서브태스크 탐색/검색/후보 샘플링을 하고, 합성기가 합친다("병렬→합성"). LLM은 선형 텍스트만 먹으니, 합치려면 브랜치 출력을 한 프롬프트로 이어붙여야 하고 — 비용이 둘이다:

"This text-based communication interface discards the original DAG structure of the computation and incurs redundant prefill cost by re-encoding information that has already been processed during worker decoding."

— §1, ¶3 · arXiv:2606.14672 §1

Summarizing each branch first shortens the text but still pays generate→serialize→re-encode and can drop detail. The natural question (§1, ¶4): "can a synthesizer agent directly consume the latent states of parallel worker branches, rather than relying on concatenated plain-text outputs?" Prior latent communication work is mostly one-to-one; this paper is the many-to-one case. And it differs from RAG cache-reuse: there each cached chunk is an isolated document with no generating context and the objective is retrieval; here each branch cache is a coherent worker output and the synthesizer must compare, judge, aggregate. Naively porting RAG cache-reuse methods "leads to weak downstream performance" (§2.2). 브랜치를 먼저 요약하면 텍스트는 짧아지지만 여전히 생성→직렬화→재인코딩 비용을 물고 디테일을 잃을 수 있다. 자연스러운 질문(§1, ¶4): "합성기 에이전트가 이어붙인 평문 출력 대신 병렬 워커 브랜치의 latent 상태를 직접 소비할 수 있을까?" 기존 latent 통신은 대개 일대일; 이 논문은 다대일. 또 RAG cache 재사용과 다르다: 거기선 캐시 청크가 생성 맥락 없는 독립 문서이고 목적은 검색인데, 여기선 각 브랜치 cache가 일관된 워커 출력이고 합성기가 비교·판단·종합해야 한다. RAG cache 재사용을 그대로 옮기면 "다운스트림 성능이 약하다"(§2.2).

Fig 1 — The core swap: paste workers' KV caches instead of re-prefilling their concatenated text. Source: Parallel-Synthesis §1–§2 (arXiv:2606.14672).그림 1 — 핵심 교체: 워커의 이어붙인 텍스트를 re-prefill하는 대신 KV cache를 붙인다. 출처: Parallel-Synthesis §1–§2.

2Method — consume the worker caches directly해결 방법 — 워커 cache를 직접 소비

Parallel-Synthesis is a plug-and-play synthesizer (frozen backbone, small trainable parts) whose goal is to make the cache route behave like the text route: Parallel-Synthesis는 plug-and-play 합성기(동결 백본 + 작은 학습부)로, 목표는 cache 경로가 text 경로처럼 동작하게 만드는 것:

P_kv( y | u, {KV_θ(z_j | c_j)} ) ≈ P_text( y | u, z₁, …, z_m )

i.e. decoding from the pasted caches should give the same output distribution as re-prefilling the concatenated text. Everything below exists to close this gap. Three components (§3.1): 즉 붙인 cache에서 디코딩한 결과가 이어붙인 텍스트를 re-prefill한 것과 같은 출력 분포여야 한다. 아래 전부가 이 격차를 좁히려는 것. 세 구성요소(§3.1):

① Positional re-encoding (RoPE re-anchoring)① 위치 재인코딩 (RoPE 재정렬)

Each worker output z_j was cached at RoPE positions |c_j|+r (after its own context c_j). If you just concatenate caches, branch 2 looks like it comes "after" branch 1 — an artificial order. So re-anchor every branch's first token to a shared position n (the branching point): 각 워커 출력 z_j는 자기 맥락 c_j 뒤, RoPE 위치 |c_j|+r에 캐시됐다. cache를 그냥 이어붙이면 브랜치 2가 브랜치 1 "뒤"인 것처럼 보인다 — 인위적 순서. 그래서 모든 브랜치의 첫 토큰을 공유 위치 n(분기점)으로 재정렬:

k̃z,j,r = R(n+r) · R(|c_j|+r)−1 · kz,j,r (values v unchanged)

Plain-language: R(·) is the RoPE rotation for a position. Multiplying a key by R(|c_j|+r)⁻¹ undoes its original position rotation; then R(n+r) re-applies rotation as if the token sat at the shared position n+r. Values carry no RoPE, so they're left alone. The effect: all branches look like parallel continuations from one branching point, not an arbitrary serialized order — removing the order/position bias the synthesizer would otherwise inherit. 쉽게 말하면: R(·)는 어떤 위치의 RoPE 회전. key에 R(|c_j|+r)⁻¹를 곱하면 원래 위치 회전을 되돌리고, R(n+r)로 그 토큰이 공유 위치 n+r에 있는 것처럼 다시 회전한다. value엔 RoPE가 없어 그대로. 효과: 모든 브랜치가 한 분기점에서의 병렬 연속처럼 보임 — 임의 직렬 순서가 아니라. 합성기가 물려받을 순서/위치 편향 제거.

② Cache mapper (learned affine calibration)② Cache mapper (학습형 affine 보정)

K̂z,j = αK,j(s_j) ⊙ k̃z,j + βK,j(s_j), s_j = (|z_j|, m) (V analogous)

Plain-language: caches generated by separate workers are statistically "off" relative to what a single sequential encoding would have produced. A small MLP looks at per-worker metadata s_j = (output length, #workers) and predicts a per-layer scale α and shift β applied elementwise (⊙) to keys/values — a cheap learned nudge back into a jointly-usable distribution. (A learned cousin of APE's inference-time attention calibration; "negligible overhead compared with re-prefilling," §3.1.) 쉽게 말하면: 별도 워커가 만든 cache는 단일 순차 인코딩이 냈을 것 대비 통계적으로 "어긋나" 있다. 작은 MLP가 워커별 메타데이터 s_j = (출력 길이, 워커 수)를 보고 레이어별 스케일 α·시프트 β를 예측해 key/value에 원소별(⊙) 적용 — 공동 사용 가능한 분포로 되돌리는 싼 학습 보정. (APE의 추론시 attention 보정의 학습형 사촌; "re-prefill 대비 무시 가능한 오버헤드", §3.1.)

③ Synthesizer LoRA + two-track training③ 합성기 LoRA + 2-트랙 학습

Calibration alone isn't enough; a LoRA is trained jointly so the model can actually read the non-sequential cache interface and still reason. Two independent post-training tracks, then merged by weighted averaging (λ=0.5) — sequential tuning was worse (it overwrites earlier abilities): 보정만으론 부족 — LoRA를 함께 학습해 비순차 cache 인터페이스를 실제로 읽고 추론하게 한다. 독립 2-트랙 후학습 후 가중평균(λ=0.5) 병합 — 순차 튜닝은 더 나빴다(이전 능력을 덮어씀):

"We train the two tracks independently and merge them afterward, since sequential tuning gives weaker results … We merge the parameters of the cache mapper and the LoRA by weighted averaging, with λ=0.5 by default."

— §3.2 · arXiv:2606.14672 §3.2

Training loss is ordinary teacher-forced next-token cross-entropy, but conditioned on the calibrated cache interface (so the gradient flows into the cache mapper + LoRA): L = −Σ_t log P_{θ,φ}(y_t* | u, {KV̂}, y_{<t}*), backbone θ frozen, only φ = (cache mapper + LoRA) trained. 학습 손실은 평범한 teacher-forced next-token cross-entropy인데, 보정된 cache 인터페이스에 조건부(그래서 gradient가 cache mapper + LoRA로 흐름): L = −Σ_t log P_{θ,φ}(y_t* | u, {KV̂}, y_{<t}*), 백본 θ 동결, φ = (cache mapper + LoRA)만 학습.

RQ2 — is it just voting? No — it beats pure majority voting on 8 of 9 datasets (loses only on MedQA, a multiple-choice task that suits voting), so the gains come from genuine trajectory-level reasoning, not recovering the most common answer. RQ2 — 그냥 투표 아닌가? 아니다 — 9개 중 8개에서 다수결 상회(MedQA만 패배, 투표에 유리한 객관식), 즉 가장 흔한 답 복원이 아니라 진짜 trajectory 수준 추론에서 이득.

5DiscussionDiscussion

The headline reframing: text is a lossy communication interface for reasoning-heavy content, and the worker caches preserve "richer latent reasoning states" — so direct cache synthesis can be both faster and sometimes more accurate, not merely a speed hack. The enabling ingredient is post-training (the model must learn to read the non-sequential cache interface), not inference-time calibration. 핵심 재해석: 텍스트는 추론 중심 내용에 손실 있는 통신 인터페이스이고, 워커 cache는 "더 풍부한 latent 추론 상태"를 보존 — 그래서 직접 cache 합성은 단순 속도 트릭이 아니라 더 빠르면서 때로 더 정확할 수 있다. 가능케 한 요소는 추론시 보정이 아니라 후학습(모델이 비순차 cache 인터페이스 읽기를 배워야 함).

editor's note — our angle (not the paper's claim)편집자 주 — 우리 관점 (논문 주장 아님) This is the agent-side mirror of the serving-side prefix-cache story in our llm-d note: in both, the win is "don't re-prefill what you already computed." But the framing is sharper here — it argues the KV cache itself is a communication medium, richer than the text it would otherwise be flattened into. Two practical reads for us: (1) it's a training-time capability (a synthesizer LoRA), so it isn't a drop-in serving feature — it needs the model trained for the cache interface, unlike pure prefix-cache reuse which is transparent; (2) the speedup scales with worker-output length, so it's most attractive for fan-out workflows with long branches (multi-agent research, parallel code candidates) — exactly the agentic-coding regime.
