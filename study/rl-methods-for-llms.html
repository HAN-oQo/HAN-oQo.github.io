4.1 — Two paradigms for RL in LLMsLLM RL의 두 패러다임

Paradigm 1 — alignment (RLHF/DPO). Learn a reward model from pairwise human judgments, then push the policy to maximize it → helpful/harmless/honest assistants. Paradigm 2 — capability via verifiable rewards (RLVR). No humans: the reward is a verifiable outcome (answer correct? code passes tests?). DeepSeek-R1 showed GRPO + rule-based rewards grow reasoning with zero preference data. Different goals, but both run on the same four-part machinery (policy, reward, KL constraint, policy-gradient).패러다임 1 — 정렬(RLHF/DPO). 쌍별 인간 판단으로 보상 모델을 학습한 뒤 policy가 그걸 최대화하게 → 도움되고 무해하고 정직한 어시스턴트. 패러다임 2 — 검증 가능한 보상으로 능력 향상(RLVR). 사람 없이 보상이 검증 가능한 결과(정답인가? 코드가 테스트를 통과하나?). DeepSeek-R1은 GRPO+규칙 기반 보상이 선호 데이터 0으로 추론 능력을 키움을 보였다. 목표는 다르되 둘 다 같은 네-요소 기계(policy, reward, KL 제약, policy-gradient)로 돈다.

"This paradigm — RL from Verifiable Rewards (RLVR) — is now the dominant approach for building reasoning models and agentic systems."

4.2 — Text generation as an MDP텍스트 생성을 MDP로

The enabling trick: treat autoregressive decoding as a Markov Decision Process. The model is an agent writing one token at a time.핵심 트릭: 자기회귀 디코딩을 마르코프 결정과정(MDP)으로 본다. 모델은 토큰을 하나씩 쓰는 에이전트다.

state s_t = (x, y₁…y_{t−1}) · action a_t = next token ∈ V · transition = append (deterministic)
reward r = end-of-sequence score (sparse) · policy π_θ(a_t|s_t) = the LLM softmax · γ = 1.0

Reading it. The state is literally the growing context; the action is choosing the next token out of 32K–128K; the transition is just appending it (no environment randomness); the reward usually arrives only at the end (sparse). Crucially, the LLM already is the policy — its softmax defines π_θ for every state, so no separate policy network is built. No discounting (γ=1) because an episode is one finite response.읽기. 상태는 말 그대로 자라는 문맥; 행동은 32K–128K개 중 다음 토큰 선택; 전이는 그냥 이어붙이기(환경 무작위성 없음); 보상은 보통 끝에만 도착(sparse). 결정적으로 LLM이 이미 policy다 — softmax가 모든 상태에서 π_θを 정의하므로 별도 policy 망이 없다. 에피소드가 유한한 한 응답이라 할인 없음(γ=1).

"This mapping is powerful because the LLM already is a policy — its softmax output defines π_θ(a_t|s_t) for every state."

— §4.2 · p.134

4.3 — The RLHF pipelineRLHF 파이프라인

Four stages: (1) SFT on demonstrations → an instruction-following π_SFT; (2) reward-model training on human comparisons (y_w ≻ y_l) via Bradley-Terry; (3) RL optimization (PPO/GRPO) of the policy against the reward, with a KL leash to π_SFT; (4) evaluate & iterate. The RLVR variant swaps the reward model for a verifier and trains SFT on reasoning traces — stage 3 is identical.네 단계: (1) 시연으로 SFT → 지시 따르는 π_SFT; (2) 인간 비교(y_w ≻ y_l)로 Bradley-Terry 기반 보상 모델 학습; (3) 보상에 맞춰 policy를 RL 최적화(PPO/GRPO)하되 π_SFT에 KL로 묶음; (4) 평가·반복. RLVR 변형은 보상 모델을 verifier로 바꾸고 추론 trace로 SFT — 3단계는 동일.

How LLM RL differs from classical RL: deterministic transitions, sparse reward, a 32K–128K action space (exploration is implicit, via sampling temperature), a KL anchor to SFT, and no value function strictly needed (GRPO drops the critic). This is why PPO/GRPO — not DQN-style value methods — dominate.LLM RL이 고전 RL과 다른 점: 결정적 전이, sparse 보상, 32K–128K 행동공간(탐험은 샘플링 온도로 암묵적), SFT로의 KL 앵커, 그리고 value 함수가 꼭 필요치 않음(GRPO는 critic 제거). 그래서 DQN식 value 방법이 아니라 PPO/GRPO가 지배한다.

The map for the tabs that follow: PPO (the RLHF workhorse), DPO (skip RL, learn from pairs), GRPO (critic-free, behind DeepSeek-R1), the preference-optimization variants (KTO/IPO/ORPO/Best-of-N), reward modeling, SFT best practices, and systems engineering for training at scale.이어질 탭의 지도: PPO(RLHF의 일꾼), DPO(RL 건너뛰고 쌍에서 학습), GRPO(critic 없음, DeepSeek-R1의 방법), 선호최적화 변형(KTO/IPO/ORPO/Best-of-N), 보상 모델링, SFT 베스트 프랙티스, 대규모 학습 시스템 엔지니어링.

5PPO — Proximal Policy Optimization

PPO is the RLHF workhorse behind GPT-4-class assistants. The whole design exists to make policy-gradient updates stable without expensive second-order math.PPO는 GPT-4급 어시스턴트 뒤의 RLHF 일꾼이다. 설계 전부가 비싼 2차 최적화 없이 policy-gradient 업데이트를 안정적으로 만들기 위해 존재한다.

5.1 — Motivation & history동기·역사

Vanilla policy gradient has no step-size limit: one unlucky batch shoves the policy into a bad region, which earns low reward, which makes the next update worse — an unrecoverable collapse. TRPO (2015) fixed this with a hard KL constraint but needs second-order optimization (Fisher matrix, conjugate gradients). PPO (2017) gets similar stability with a simple first-order clipped objective — ~10× simpler and scales to distributed training trivially.바닐라 policy gradient는 스텝 크기 제한이 없다: 운 나쁜 배치 하나가 policy를 나쁜 영역으로 밀고, 낮은 보상을 받고, 다음 업데이트가 더 나빠진다 — 회복 불가 붕괴. TRPO(2015)는 강한 KL 제약으로 고쳤지만 2차 최적화(Fisher 행렬, 켤레기울기) 필요. PPO(2017)는 단순한 1차 clipped 목적함수로 비슷한 안정성 — 약 10배 단순하고 분산 학습에 쉽게 확장.

L = L_CLIP − c₁·(V_θ(s_t) − V_target)² + c₂·H[π_θ] (c₁=0.1 value, c₂=0.01 entropy)

5.5 — Rollout buffer (why PPO is on-policy)rollout 버퍼 (PPO가 on-policy인 이유)

PPO's data store is an ephemeral rollout buffer (unlike DQN's permanent replay buffer) because PPO is on-policy: its math only holds for data made by the current policy. A "rollout" in LLMs = generate a full token sequence from a prompt; each token is one step. Lifecycle: collect (a 70B model at batch 128 × 512 tokens → up to ~65K token-level transitions) → train (K=3–10 epochs of clipped mini-batch SGD) → purge (wipe the buffer; stale-policy data would break the clipping guarantees). Because generation is 60–70% of wall-clock, vLLM (batched gen, paged KV, prefix sharing for the N same-prompt samples) is the standard generation backend (OpenRLHF, TRL).PPO의 데이터 저장소는 일회성 rollout 버퍼다(DQN의 영구 replay와 달리). PPO가 on-policy라 수식이 현재 policy가 만든 데이터에만 성립하기 때문. LLM의 "rollout" = 프롬프트에서 토큰열 전체 생성; 토큰 하나가 한 스텝. 수명: 수집(70B, 배치 128 × 512토큰 → 최대 ~65K 토큰 단위 전이) → 학습(K=3–10 epoch clipped 미니배치 SGD) → 폐기(버퍼 비움; 낡은 policy 데이터는 clipping 보장을 깸). 생성이 벽시계의 60–70%라 vLLM(배치 생성, paged KV, N개 동일 프롬프트 표본의 prefix 공유)이 표준 생성 백엔드(OpenRLHF, TRL).

"Because PPO is on-policy, data generated by the old policy cannot be safely reused for the next update cycle."

5.6 — PPO for RLHF: the full loop (worked, 70B)RLHF용 PPO 전체 루프 (70B 실예)

One concrete step for a 70B chat model, 128 prompts: (1) generate (temp 0.7, top-p 0.9; ~60% of time) → (2) score with the reward model → (3) per-token KL KL_t = log π_θ(y_t|·) − log π_ref(y_t|·) (mean KL 3–8) → (4) final reward R = r_RM − 0.05·mean_KL at the last token → (5) GAE advantages, then whiten (zero-mean/unit-variance) → (6) update (4 epochs, mini-batch 16, ε=0.2, grad-norm 1.0). ~0.005 win-rate/step; ~5–10% absolute over SFT after 10K steps.70B 챗 모델, 128 프롬프트의 한 스텝: (1) 생성(temp 0.7, top-p 0.9; 시간의 ~60%) → (2) 채점 보상 모델로 → (3) 토큰별 KL KL_t = log π_θ(y_t|·) − log π_ref(y_t|·)(평균 KL 3–8) → (4) 최종 보상 마지막 토큰에 R = r_RM − 0.05·mean_KL → (5) GAE advantage 후 whiten(평균0·분산1) → (6) 업데이트(4 epoch, 미니배치 16, ε=0.2, grad-norm 1.0). 스텝당 ~0.005 win-rate; 10K 스텝 후 SFT 대비 ~5–10%p.

5.7 — Detailed mechanics: two networks, log-space ratio상세 동작: 두 망, 로그공간 비

During a cycle PPO holds two weight states of the same topology: the live π_θ (updated every mini-batch) and a frozen π_θold snapshot (the anchor). At rollout, the action's log-prob under π_θold is stored as a scalar — so the frozen net isn't re-run during optimization (saves a full forward pass per mini-batch). The ratio is computed in log-space for numerical safety: r_t(θ) = exp( log π_θ(a_t|s_t) − log π_θold(a_t|s_t) ). The weight lifecycle: ratio starts at exactly 1.0 (snapshot==live), drifts as θ updates, gets trapped at 1±ε by clipping, and resets to 1.0 next cycle when the new θ becomes the snapshot.한 사이클 동안 PPO는 같은 구조의 두 가중치 상태를 쥔다: 실시간 π_θ(미니배치마다 업데이트)와 고정 π_θold 스냅샷(앵커). rollout 때 π_θold 하의 행동 log-prob을 스칼라로 저장 → 최적화 중 고정 망을 다시 안 돌림(미니배치당 forward 한 번 절약). 비는 수치 안정을 위해 로그공간에서: r_t(θ) = exp( log π_θ(a_t|s_t) − log π_θold(a_t|s_t) ). 가중치 수명: 비는 정확히 1.0에서 시작(스냅샷==실시간), θ 업데이트로 멀어지고, clipping에 1±ε로 갇히며, 다음 사이클에 새 θ가 스냅샷이 되면 1.0으로 리셋.

6DPO — Direct Preference Optimization

DPO's pitch: skip the RL loop entirely. PPO-RLHF juggles four models and brittle rollouts; DPO turns preference pairs straight into a supervised loss that implicitly optimizes the same RLHF objective — no reward model at train time, no value critic, no rollouts.DPO의 주장: RL 루프를 통째로 건너뛴다. PPO-RLHF는 네 모델과 까다로운 rollout을 굴리지만, DPO는 선호쌍을 곧장 지도학습 손실로 바꿔 같은 RLHF 목적을 암묵적으로 최적화한다 — 학습 시 보상 모델도, value critic도, rollout도 없음.

6.2 — The derivation (why it works)유도 (되는 이유)

Four steps. (1) the RLHF objective is max_π E[r(x,y)] − β·KL(π‖π_ref). (2) its optimum has a closed form — tilt the reference toward reward:네 단계. (1) RLHF 목적은 max_π E[r(x,y)] − β·KL(π‖π_ref). (2) 그 최적해는 닫힌 형태 — reference를 보상 쪽으로 기울임:

π*(y|x) = (1/Z(x))·π_ref(y|x)·exp(r(x,y)/β), Z(x)=Σ_y π_ref(y|x)·exp(r(x,y)/β)

(3) invert it — take logs and solve for the reward: r(x,y) = β·log(π*(y|x)/π_ref(y|x)) + β·log Z(x). This is the heart: the reward is recoverable from the log-ratio of policy to reference, up to a prompt-only constant. (4) plug into Bradley-Terry P(y_w≻y_l)=σ(r(y_w)−r(y_l)) — and the intractable partition function β·log Z(x) (same for both responses) cancels, leaving a plain loss in the trainable π_θ:(3) 뒤집기 — 로그 취해 보상에 대해 풂: r(x,y) = β·log(π*(y|x)/π_ref(y|x)) + β·log Z(x). 핵심은 이것: 보상은 policy 대 reference의 로그비로 복원 가능(프롬프트에만 의존하는 상수 차이만). (4) Bradley-Terry P(y_w≻y_l)=σ(r(y_w)−r(y_l))에 대입 — 다루기 힘든 분배함수 β·log Z(x)(두 응답에 동일)가 소거되고, 학습 대상 π_θ에 대한 단순 손실만 남는다:

L_DPO(θ) = −E[ log σ( β·log(π_θ(y_w|x)/π_ref(y_w|x)) − β·log(π_θ(y_l|x)/π_ref(y_l|x)) ) ]

Implicit reward r̂(x,y)=β·log(π_θ/π_ref): DPO is just binary cross-entropy whose "label" is chosen should out-score rejected. β sets the margin/KL strength — large β moves the policy aggressively (forgetting risk), small β hugs the reference. The reference is the regularizer; any deviation must be justified by better preference alignment.암묵 보상 r̂(x,y)=β·log(π_θ/π_ref): DPO는 "선택이 거부보다 점수 높아야 함"을 라벨로 하는 이진 교차엔트로피일 뿐. β가 margin/KL 강도를 정함 — β 크면 policy를 공격적으로(망각 위험), 작으면 reference에 밀착. reference가 정규화기; 어떤 이탈도 더 나은 선호 정렬로 정당화돼야 함.

"The optimal policy under the RLHF objective (reward maximization + KL penalty) has a closed-form solution. … The Z(x) cancels!"

6.3 — Gradient: effort goes where the model is wronggradient: 틀린 곳에 노력 집중

∇_θ L = −β·σ(r̂_l − r̂_w)·[ ∇_θ log π_θ(y_w|x) − ∇_θ log π_θ(y_l|x) ]

The scalar weight σ(r̂_l−r̂_w) is an adaptive learning rate: ≈0.5 when the model can't tell the pair apart (learn hard), ≈0 once the chosen already dominates (stop). The bracket simultaneously pushes the chosen log-prob up and the rejected down. So gradient concentrates on confusing pairs; easy pairs contribute almost nothing.스칼라 가중 σ(r̂_l−r̂_w)는 적응형 학습률: 모델이 쌍을 구분 못 하면 ≈0.5(열심히 학습), 선택이 이미 우세하면 ≈0(정지). 괄호는 선택의 log-prob을 올리고 거부를 동시에 내림. 그래서 gradient는 헷갈리는 쌍에 집중하고 쉬운 쌍은 거의 기여 안 함.

6.5 / 6.8 — Mechanics & scaling동작 & 스케일링

Sequence log-prob is a sum of per-token log-softmax over the response (same as LM cross-entropy, summed). Only response tokens get gradient (prompt masked, padding masked). Pitfalls: forgetting to mask the prompt; mismatched mean-vs-sum between π_θ and π_ref; using the base model instead of the SFT checkpoint as reference (KL term dominates, gradients vanish); β too large (sigmoid saturates → zero gradient) or too small (∝β·σ vanishes → flat landscape). Memory: DPO holds two copies, but with LoRA the reference is just the base with adapters disabled (ref_model=None), halving memory; or pre-compute reference log-probs once and evict π_ref from GPU. DPO overfits fast — train ~1 epoch.시퀀스 log-prob은 응답에 대한 토큰별 log-softmax의 합(LM 교차엔트로피를 합한 것). 응답 토큰만 gradient(프롬프트·패딩 마스킹). 함정: 프롬프트 마스킹 누락; π_θ와 π_ref 간 mean/sum 불일치; reference로 SFT 대신 base 사용(KL 항 지배, gradient 소멸); β 과대(시그모이드 포화 → gradient 0) 또는 과소(∝β·σ 소멸 → 평평). 메모리: DPO는 두 사본을 쥐지만 LoRA면 reference는 어댑터 끈 base(ref_model=None)라 절반; 또는 reference log-prob을 미리 계산해 π_ref를 GPU에서 제거. 7GRPO — Group Relative Policy Optimization

GRPO is PPO with the critic removed. Instead of training a value network to predict expected reward, it estimates the baseline empirically: sample G responses to the same prompt and use the group's reward statistics. This drops a whole model from memory and is the algorithm behind DeepSeek-R1.GRPO는 critic을 제거한 PPO다. 기대 보상을 예측하는 value 망을 학습하는 대신, 베이스라인을 경험적으로 추정한다: 같은 프롬프트에 G개 응답을 뽑아 그 그룹의 보상 통계를 사용. 모델 하나를 메모리에서 빼고, DeepSeek-R1의 알고리즘이다.

7.1 — Motivation: the critic's three problems동기: critic의 세 문제

PPO's value head fails in three ways for LLMs: memory (shares the 140 GB backbone of a 70B, or doubles it if separate), accuracy (predicting the reward of a partial sequence is very hard → wrong advantages → wrong gradient direction), and training (needs many samples; noisy early predictions destabilize the policy). GRPO's empirical baseline sidesteps all three — and often beats PPO because the empirical mean is a more accurate baseline than a poorly-trained value net.PPO의 value head는 LLM에서 세 가지로 실패한다: 메모리(70B의 140 GB 백본을 공유하거나 분리 시 2배), 정확도(부분 시퀀스의 보상 예측이 매우 어려움 → 틀린 advantage → 틀린 gradient 방향), 학습(많은 표본 필요; 초기 노이즈 예측이 policy를 불안정화). GRPO의 경험적 베이스라인은 셋 다 우회하고 — 잘못 학습된 value 망보다 경험 평균이 더 정확한 베이스라인이라 종종 PPO를 능가한다.

7.2 — Algorithm & the group-relative advantage알고리즘 & 그룹 상대 advantage

For a prompt x: sample G completions, score each (r_i), normalize within the group, then do a PPO-style clipped update with those advantages.프롬프트 x에 대해: G개 완성을 뽑고 각각 채점(r_i), 그룹 안에서 정규화한 뒤, 그 advantage로 PPO식 clipped 업데이트.

Â_i = (r_i − μ_G) / σ_G, μ_G = (1/G)Σ_j r_j, σ_G = std({r_j})

Reading it. The group mean μ_G is a Monte-Carlo estimate of the value function V(s): enough same-prompt samples → average reward ≈ expected reward, so you don't need a critic. Â_i>0 (above the group average) → reinforce that response; Â_i<0 → suppress it. Dividing by σ_G makes advantages scale-invariant across prompts with different reward ranges. The full objective is the PPO clipped surrogate with these Â_i, minus a KL term to π_ref. DeepSeek-R1: pure GRPO with binary correctness rewards (r=1 if right else 0) spontaneously grew chain-of-thought, self-verification, and error correction — with no explicit instruction.읽기. 그룹 평균 μ_G는 value 함수 V(s)의 몬테카를로 추정: 같은 프롬프트 표본이 충분하면 평균 보상 ≈ 기대 보상이라 critic이 불필요. Â_i>0(그룹 평균 위) → 그 응답 강화; Â_i<0 → 억제. σ_G로 나눠 보상 범위가 다른 프롬프트들에서 advantage를 스케일 불변으로. 전체 목적은 이 Â_i를 쓴 PPO clipped 대리손실에서 π_ref로의 KL 항을 뺀 것. 7.4 — Group size & the Goldilocks rule그룹 크기 & 골디락스 규칙

G=2 is too noisy (coin flip); G=8 is the balanced default; G=16 for hard tasks (pass<20%, need many tries to find positives); G=32 only with extreme compute. So filter prompts to a 20–80% pass rate for the current model, and re-filter every ~500 steps as it improves.G=2는 너무 노이즈(동전 던지기); G=8이 균형 잡힌 기본; 어려운 작업엔 G=16(통과<20%, 양성 찾으려 여러 시도 필요); G=32는 극단적 연산에서만. 결정적: 그룹에 성공과 실패가 모두 있어야 함 — G개가 전부 정답(또는 전부 오답)이면 advantage가 전부 0이라 학습 신호 없음. 그래서 현재 모델 기준 통과율 20–80%로 프롬프트를 거르고, 향상되면 ~500스텝마다 재필터링.

8Preference Optimization VariantsPreference Optimization Variants

Each method here fixes one specific limitation of standard offline DPO: distribution shift (Online DPO), the need for paired data (KTO), overfitting to noisy labels (IPO), the reference-model memory cost (ORPO), or training complexity altogether (Best-of-N).여기 각 방법은 표준 오프라인 DPO의 한 가지 한계를 고친다: 분포 이동(Online DPO), 쌍 데이터 필요(KTO), 노이즈 라벨 과적합(IPO), reference 모델 메모리 비용(ORPO), 또는 학습 복잡성 자체(Best-of-N).

8.1 — Online DPO

Offline DPO trains on static pairs made by some other model; as π_θ drifts, those pairs stop matching what the policy now produces — wasted gradient. Online DPO regenerates fresh pairs from the current policy each step, scores them with a reward model, and only then applies the DPO loss. It's the middle ground: DPO's simple supervised loss (no value head) + PPO's on-policy data (no distribution shift). Cost: it now needs a reward model (3 models), but no critic. Use it when offline DPO plateaus.오프라인 DPO는 다른 모델이 만든 고정 쌍으로 학습; π_θ가 표류하면 그 쌍이 현재 생성물과 안 맞음 — gradient 낭비. Online DPO는 매 스텝 현재 policy로 새 쌍을 생성·보상모델로 채점한 뒤 DPO 손실 적용. 중간 지대: DPO의 단순 지도손실(value head 없음) + PPO의 on-policy 데이터(분포 이동 없음). 비용: 보상 모델 필요(3모델), 단 critic은 없음. 오프라인 DPO가 정체될 때 사용.

8.2 — KTO (Kahneman-Tversky Optimization)

DPO needs matched good/bad pairs, but most real feedback is unpaired — a thumbs-up/down on one response. KTO borrows prospect theory: humans feel losses more strongly than gains, so a thumbs-down should give a stronger gradient than a thumbs-up. Each example is scored independently — no pairing.DPO는 짝지어진 좋음/나쁨 쌍이 필요하지만 실제 피드백 대부분은 비쌍 — 한 응답에 좋아요/싫어요. KTO는 전망 이론을 빌린다: 사람은 이득보다 손실을 강하게 느끼니, 싫어요가 좋아요보다 강한 gradient를 줘야 한다. 각 예제를 독립 채점 — 짝 불필요.

L_KTO = E_{y_w}[λ_w(1 − v(x,y_w))] + E_{y_l}[λ_l·v(x,y_l)], v = σ( β·log(π_θ/π_ref) − z_ref )

Reading it. v∈(0,1) is a saturating "value": the implicit reward β·log(π_θ/π_ref) squashed through a sigmoid and shifted by a running KL baseline z_ref — the prospect-theory value curve. The desirable term raises good-response probability with diminishing returns (once v→1 it stops pushing); the undesirable term penalizes bad mass, with loss aversion encoded by allowing λ_l>λ_w. Data is just {prompt, completion, label:true/false} — production thumbs data, star ratings binarized, vote counts. Handles class imbalance better than DPO.읽기. v∈(0,1)은 포화되는 "가치": 암묵 보상 β·log(π_θ/π_ref)을 시그모이드로 누르고 진행 KL 베이스라인 z_ref로 이동 — 전망 이론 가치곡선. 바람직 항은 좋은 응답 확률을 체감하며 올림(v→1이면 멈춤); 비바람직 항은 나쁜 질량을 벌하되 λ_l>λ_w로 손실회피를 인코딩. 데이터는 {prompt, completion, label:true/false}뿐 — 프로덕션 thumbs, 별점 이진화, 투표수. DPO보다 클래스 불균형에 강함.

8.3 — IPO (Identity Preference Optimization)

DPO has a degenerate optimum: its loss −log σ(margin) keeps shrinking as the margin → ∞, so DPO drives chosen→1 / rejected→0 and memorizes pairs (overfits, especially on noisy labels). IPO replaces the log-sigmoid with a squared loss targeting a finite margin:DPO엔 퇴화 최적해가 있다: 손실 −log σ(margin)이 margin → ∞일수록 계속 줄어 선택→1/거부→0으로 몰며 쌍을 암기(특히 노이즈 라벨에서 과적합). IPO는 log-sigmoid를 유한 margin을 겨냥한 제곱 손실로 대체:

L_IPO = E[ ( log(π_θ(y_w)/π_ref(y_w)) − log(π_θ(y_l)/π_ref(y_l)) − 1/(2β) )² ]

The bracket is exactly the DPO margin; IPO subtracts a target 1/(2β) and squares, so the optimum sits at a finite margin (penalizing too-small and too-large gaps). A mislabeled pair gets bounded influence → robust to label noise, generalizes better, survives multiple epochs. It's a loss_type="ipo" in DPOTrainer.괄호는 정확히 DPO margin; IPO는 목표 1/(2β)를 빼고 제곱해 최적이 유한 margin에 위치(너무 작은 것과 큰 것 모두 벌). 오라벨 쌍의 영향이 유한 → 라벨 노이즈에 강하고 일반화 좋고 여러 epoch 견딤. DPOTrainer의 loss_type="ipo".

8.4 — ORPO (Odds Ratio Preference Optimization)

Every method so far needs a reference model (extra memory). ORPO eliminates it by fusing SFT and alignment into one loss, using the odds ratio of chosen vs. rejected as the preference signal while the SFT (NLL) term anchors the model — the role KL-to-reference plays elsewhere.지금까지의 모든 방법은 reference 모델이 필요(추가 메모리). ORPO는 SFT와 정렬을 한 손실로 융합해 이를 제거 — 선택 대 거부의 odds ratio를 선호 신호로, SFT(NLL) 항이 모델을 앵커(다른 곳의 KL-to-reference 역할).

L_ORPO = L_SFT(y_w) − λ·log σ( log( odds_θ(y_w)/odds_θ(y_l) ) ), odds_θ(y)=P_θ(y)/(1−P_θ(y))

"One model, one forward pass, one loss → ~50% less memory" (saves ~70–140 GB for a 70B). Best when memory-constrained, when starting from a base model (ORPO does SFT simultaneously), or when you want the simplest pipeline. Limitation: less battle-tested at 70B+, and the SFT term demands high-quality chosen responses."한 모델, 한 forward, 한 손실 → 메모리 ~50% 절감"(70B에 ~70–140 GB 절약). 메모리 제약, base 모델에서 시작(ORPO가 SFT 동시 수행), 또는 가장 단순한 파이프라인을 원할 때 최선. 한계: 70B+에서 덜 검증, SFT 항이 고품질 선택 응답을 요구.

8.5 — Best-of-N (rejection sampling)

The simplest approach — no RL training at all: generate N candidates, score with a reward model, keep the best y* = argmax_i r(x,y_i). As inference-time decoding it improves quality with zero weight change (N=64 → +15–20% win-rate, sometimes matching PPO). As training (Rejection-sampling Fine-Tuning / RFT): generate → keep winners → SFT → repeat. It implements an implicit KL-constrained policy π_BoN ∝ π_θ^(1−1/N)·r^(1/N) — N tunes how hard you exploit the reward vs. stay on-distribution.가장 단순 — RL 학습 전혀 없음: N개 후보 생성, 보상 모델로 채점, 최선 y* = argmax_i r(x,y_i) 선택. 추론 시 디코딩으로 가중치 변경 0으로 품질 향상(N=64 → win-rate +15–20%, 때로 PPO 필적). 학습(Rejection-sampling Fine-Tuning/RFT)으로: 생성 → 승자 보관 → SFT → 반복. 암묵적 KL 제약 policy π_BoN ∝ π_θ^(1−1/N)·r^(1/N)를 구현 — N이 보상 착취 vs 분포 유지 강도를 조절.

9Reward Model TrainingReward Model Training

The reward model (RM) is the bridge between human preferences and the RL signal. A good RM is essential for RLHF; a poorly-trained one causes reward hacking and misalignment.보상 모델(RM)은 인간 선호와 RL 신호 사이의 다리다. 좋은 RM은 RLHF에 필수; 잘못 학습된 RM은 reward hacking과 오정렬을 부른다.

9.1 — Bradley-Terry

P(y₁ ≻ y₂ | q) = σ( r(y₁,q) − r(y₂,q) ), L_BT = −(1/N)Σ_k log σ( r_φ(y_w) − r_φ(y_l) )

Reading it. The probability that y₁ beats y₂ is a sigmoid of the difference of their scalar rewards — only the gap matters, not the absolute scale. Fitting r_φ is then binary cross-entropy with the human-preferred response as the positive class. Four assumptions (often violated → motivate the extensions below): transitivity, a single scalar reward, difference-only dependence, and independent pairs. A margin variant subtracts a constant m inside the sigmoid to force a minimum gap.읽기. y₁이 y₂를 이길 확률은 두 스칼라 보상 차이의 시그모이드 — 절대 스케일이 아니라 차이만 중요. r_φ 학습은 인간이 선호한 응답을 양성 클래스로 하는 이진 교차엔트로피. 네 가정(자주 위배 → 아래 확장 동기): 추이성, 단일 스칼라 보상, 차이-의존, 독립 쌍. margin 변형은 시그모이드 안에 상수 m을 빼 최소 차이를 강제.

9.2 / 9.3 — Architecture & training tricks아키텍처 & 학습 트릭

An RM = a pretrained LLM with its language-modeling head swapped for a scalar regression head (W∈ℝ^{d×1} on the pooled hidden state — last token for decoder-only, [CLS] for encoders). In TRL: AutoModelForSequenceClassification(num_labels=1) + RewardTrainer. Three tricks keep its output usable as an RL signal: reward centering (subtract the policy's mean reward per prompt → stable PPO), length-bias correction (RMs reward longer responses regardless of quality → length-normalize / calibrate), and margin losses (a hinge max(0, m−(r_w−r_l)) forcing a meaningful gap). Skipping centering → unstable PPO; ignoring length bias → models pad output to farm reward.RM = 사전학습 LLM의 LM head를 스칼라 회귀 head로 교체(pooled hidden state에 W∈ℝ^{d×1} — decoder-only는 마지막 토큰, encoder는 [CLS]). TRL: AutoModelForSequenceClassification(num_labels=1) + RewardTrainer. 출력을 RL 신호로 쓸 수 있게 하는 세 트릭: 보상 센터링(프롬프트별 policy 평균 보상 빼기 → PPO 안정), 길이 편향 보정(RM은 품질과 무관히 긴 응답에 보상 → 길이 정규화/보정), margin 손실(의미 있는 차이를 강제하는 hinge max(0, m−(r_w−r_l))). 센터링 생략 → PPO 불안정; 길이 편향 무시 → 모델이 보상 따려 출력 패딩.

9.4 — PRM vs ORM

An Outcome RM scores only the final answer; a Process RM scores each reasoning step. PRMs give dense credit and are harder to hack, at the cost of expensive step-level annotation and higher inference cost. Theoretically a PRM is Potential-Based Reward Shaping: a potential Φ(s) (e.g. fraction of valid steps) gives per-step signal while preserving the optimal policy that maximizes final correctness — which is what makes dense rewards principled rather than ad-hoc. Step labels can be auto-generated by Monte-Carlo rollouts (fraction of completions from a step that reach the right answer), an LLM judge, or a formal verifier.Outcome RM은 최종 답만 채점; Process RM은 추론 단계마다 채점. PRM은 dense credit을 주고 해킹이 어렵지만, 비싼 단계별 주석과 높은 추론 비용이 든다. 이론적으로 PRM은 잠재 기반 보상 형성(PBRS): 잠재 Φ(s)(예: 유효 단계 비율)가 단계별 신호를 주되 최종 정답을 최대화하는 최적 policy를 보존 — 이것이 dense 보상을 임시방편이 아닌 원칙적으로 만든다. 단계 라벨은 몬테카를로 rollout(한 단계에서 정답에 도달하는 완성 비율), LLM judge, 형식 검증기로 자동 생성 가능.

9.5 — Rule-based rewards (RLVR)규칙 기반 보상 (RLVR)

RLVR replaces the learned RM with deterministic, rule-based functions — the DeepSeek-R1 approach, which sharply reduces reward hacking. Typical composable rules: a format_reward (1.0 iff the <think>…</think><answer>…</answer> pattern matches), a correctness_reward (extracted answer == ground truth), and a code_execution_reward (fraction of unit tests passed, with a strict timeout). Pitfalls to design around: format gaming (right format, wrong content → always combine format + correctness), test-case leakage (tests in training data → memorization), timeout exploitation (emit code that times out → penalize timeouts explicitly), and reward sparsity (binary 0/1 too sparse → add partial credit).RLVR는 학습된 RM을 결정적·규칙 기반 함수로 대체 — DeepSeek-R1 방식으로 reward hacking을 크게 줄인다. 전형적 합성 규칙: format_reward(<think>…</think><answer>…</answer> 패턴 일치 시 1.0), correctness_reward(추출 답 == 정답), code_execution_reward(엄격한 타임아웃 하에 통과한 단위 테스트 비율). 설계 시 피할 함정: 포맷 게이밍(포맷 맞고 내용 틀림 → 포맷+정확도 항상 결합), 테스트 누출(학습 데이터의 테스트 → 암기), 타임아웃 악용(타임아웃 코드 방출 → 타임아웃 명시적 벌점), 보상 희소성(이진 0/1 너무 희소 → 부분점수).

9.6 / 9.7 — Multi-objective & listwise rewards다목적 & listwise 보상

Multi-objective: combining rewards (correctness + format + length), the strategy matters. A plain weighted sum r=Σ w_n r_n is scale-sensitive (the largest-variance reward dominates); the robust default is normalize-then-sum (each reward to zero-mean/unit-variance within the group, then weight) — scale-invariant. Other options: lexicographic (strict priority order), constrained (maximize primary subject to constraints on secondaries), Pareto-front. Listwise: Bradley-Terry only handles pairs, but you often rank K responses at once. The Plackett-Luce model generalizes BT to full rankings as a sequence of "pick the best of the remaining" softmaxes; its NLL is the listwise loss, and for K=2 it reduces exactly to Bradley-Terry. Listwise rewards (ListMLE/ListNet/LambdaRank/RankNet) carry C(K,2) implicit comparisons plus relative margins, calibrate the absolute reward scale better, and map naturally onto GRPO (which already ranks its N samples).다목적: 보상 결합(정확도+포맷+길이) 시 전략이 중요. 단순 가중합 r=Σ w_n r_n은 스케일 민감(분산 큰 보상이 지배); 견고한 기본은 정규화 후 합(각 보상을 그룹 내 평균0·분산1로 정규화 후 가중) — 스케일 불변. 다른 선택: 사전식(엄격한 우선순위), 제약식(부차 제약하에 주 보상 최대화), Pareto front. Listwise: Bradley-Terry는 쌍만 다루나, 흔히 K개 응답을 한 번에 순위 매긴다. Plackett-Luce 모델은 BT를 전체 순위로 일반화 — "남은 것 중 최선 뽑기" 소프트맥스의 연쇄; 그 NLL이 listwise 손실이고 K=2면 정확히 Bradley-Terry로 환원. 10.5 — When SFT hurts: forgetting vs. alignment taxSFT가 해칠 때: 망각 vs 정렬세

Two distinct phenomena cause post-training benchmark regressions; confusing them leads to the wrong fix. Catastrophic forgetting is an unintentional optimization failure — training on a disjoint distribution physically overwrites the weights encoding the old capability (knowledge destroyed, irreversible without retraining; detected by a perplexity spike on a pre-training eval set). Alignment tax is a deliberate trade-off — capability drops because the policy is constrained (by the KL leash) toward safe/aligned outputs (knowledge suppressed not erased; partially reversible by tuning β or the system prompt). Tell them apart: if the base model succeeds where the fine-tuned one totally fails → forgetting; if careful prompting recovers it → tax.두 별개 현상이 포스트트레이닝 벤치 회귀를 일으킨다; 혼동하면 잘못된 처방. 치명적 망각은 비의도적 최적화 실패 — 분리된 분포로 학습이 옛 능력을 인코딩한 가중치를 물리적으로 덮어씀(지식 파괴, 재학습 없이 비가역; 사전학습 평가셋 perplexity 급등으로 탐지). 정렬세는 의도된 거래 — policy가 (KL 끈으로) 안전·정렬 출력으로 제약돼 능력 하락(지식 억제, 삭제 아님; β나 시스템 프롬프트 조정으로 부분 가역). 구분: base 모델이 성공하는데 파인튠이 완전 실패 → 망각; 신중한 프롬프트로 회복 → 정렬세.

10.6 — SFT quality is the RL ceilingSFT 품질이 RL 천장

RL can amplify weak-but-present behaviors, suppress bad ones, and refine style — but it cannot introduce capabilities the SFT model never shows. The reason is mechanical: RL needs a non-zero reward signal, and if the SFT model never produces a correct response, all rewards are 0, all advantages are 0, there is no gradient. Concretely: SFT at 10% correct on math → RL can reach ~80%; SFT at 0% → RL makes no progress. So check pass@k before RL — rule of thumb: pass@1<5% → RL likely fails; pass@k<20% → it will struggle.RL은 약하지만 존재하는 행동을 증폭하고 나쁜 것을 억제하고 스타일을 다듬을 수 있지만, SFT 모델이 결코 보이지 않는 능력은 만들 수 없다. 이유는 기계적: RL은 0이 아닌 보상 신호가 필요하고, SFT 모델이 정답을 결코 못 내면 보상이 전부 0, advantage가 전부 0, gradient가 없다. 구체적으로: 수학 10% 정답 SFT → RL로 ~80% 도달 가능; 0% SFT → RL 진전 없음. 그래서 RL 전 pass@k 확인 — 경험칙: pass@1<5% → RL 실패 가능성; pass@k<20% → 고전.

11.2 — Parallelism strategies병렬화 전략

DDP replicates the full model per GPU, syncs gradients via ring-AllReduce (near-linear to ~64 GPUs; never use the legacy single-process DataParallel). TP (Megatron) splits weight matrices — 2 AllReduce per transformer layer, so it's intra-node only (over InfiniBand the 160 AllReduce/forward of a 70B would add ~640 ms, longer than the compute); constraint: #heads must divide the TP degree. SP splits the sequence dim for LayerNorm/Dropout, reusing TP's communication (AllReduce ≡ ReduceScatter+AllGather just reordered) → pure memory win (~59 GB/GPU on 70B), always enable with TP. PP splits layers into stages; cost is the bubble (P−1)/(P+M−1) → need M≥10(P−1) micro-batches; 1F1B scheduling bounds activation memory. FSDP/ZeRO-3 shards params+grads+optimizer (1/N each), reconstructing full tensors on the fly — 70B drops from 1120 to ~140 GB/GPU, at the cost of ~3× DDP's communication (2 AllGather + 1 ReduceScatter).DDP는 GPU마다 전체 모델 복제, ring-AllReduce로 gradient 동기(~64 GPU까지 거의 선형; 레거시 단일프로세스 DataParallel은 절대 금지). 11.3 — The generation bottleneck (roofline)생성 병목 (roofline)

RLHF rollouts are autoregressive generation, which is memory-bandwidth bound, not compute bound — which is why generation dominates RLHF wall-clock. On an A100 (312 TFLOPS, 2 TB/s) the roofline crossover is 156 FLOP/byte. Single-stream 70B generation reads all 140 GB of weights to make 140 GFLOPs/token → arithmetic intensity = 1 FLOP/byte = 156× below the roofline → ~0.6% of peak (the GPU is 99.4% idle waiting on memory), and token rate = 2 TB/s ÷ 140 GB = 14.3 tok/s. The fix is batching (read weights once for many sequences) plus an optimization stack: vLLM+PagedAttention 2–4×, continuous batching 1.5–2×, speculative decoding 2–3×, INT8/FP8 weights 2×.RLHF rollout은 자기회귀 생성이고 이는 연산이 아니라 메모리 대역폭 바운드 — 그래서 생성이 RLHF 벽시계를 지배. A100(312 TFLOPS, 2 TB/s)에서 roofline 교차점은 156 FLOP/byte. 단일 스트림 70B 생성은 가중치 140 GB 전부를 읽어 토큰당 140 GFLOPs → 산술강도 = 1 FLOP/byte = roofline의 156× 아래 → 피크의 ~0.6%(GPU가 메모리 대기로 99.4% 유휴), 토큰율 = 2 TB/s ÷ 140 GB = 14.3 tok/s. 해법은 배칭(여러 시퀀스에 가중치 한 번 읽기) + 최적화 스택: vLLM+PagedAttention 2–4×, continuous batching 1.5–2×, speculative decoding 2–3×, INT8/FP8 가중치 2×.

11.4–11.5 — Decoupled architecture & weight sync분리형 아키텍처 & 가중치 동기

Systems like DeepSpeed-Chat and OpenRLHF split generation, scoring, and training into independently scalable clusters because the hardware profiles conflict: generation is memory-bandwidth bound (wants fast HBM) while training is compute bound (wants tensor cores). Decoupling lets you scale each separately, use a stateless (fault-tolerant) generation cluster, run mixed precision (INT8 gen / BF16 train), and — the big win — overlap generation(step N+1) with training(step N) for a 30–40% speedup. Fresh weights reach the generation cluster periodically; staleness is fine because PPO's clip was designed for off-policy data (~2% quality loss at 50-step staleness; async streaming <1%).DeepSpeed-Chat, OpenRLHF 같은 시스템은 생성·채점·학습을 독립 확장 클러스터로 나눈다 — 하드웨어 프로필이 상충하기 때문: 생성은 메모리 대역폭 바운드(빠른 HBM 선호), 학습은 연산 바운드(텐서 코어 선호). 분리하면 각각 따로 확장, 무상태(내결함) 생성 클러스터, 혼합 정밀도(INT8 생성/BF16 학습), 그리고 핵심 — 생성(N+1스텝)과 학습(N스텝)을 겹쳐 30–40% 가속. 새 가중치는 주기적으로 생성 클러스터에 도달; staleness는 괜찮은데 PPO clip이 off-policy 데이터를 위해 설계됐기 때문(50스텝 staleness에 ~2% 품질 손실; 비동기 스트리밍 <1%).

11.15 — The RL optimizer mantraRL optimizer 만트라

RL needs different optimizer settings from SFT because its data is non-stationary (the policy makes its own data) and its gradients are spiky. The recipe: small LR (10–100× smaller than SFT — 1e-6 for PPO/GRPO, 5e-7 for DPO), no weight decay (the KL term already regularizes; WD fights it), constant schedule (RL has no fixed horizon), FP32 master weights (BF16-only "reliably causes reward collapse after 100–500 steps" because a 7-bit mantissa can't represent 1e-6-relative updates), aggressive gradient clipping (max_grad_norm=1.0 — "a single unclipped step with ∥∇∥>50 can undo hundreds of steps"), and β₂=0.95 (vs 0.999 — a ~20-step memory adapts faster to the fast-changing landscape).RL은 데이터가 비정상(policy가 제 데이터를 만듦)이고 gradient가 뾰족해 SFT와 다른 optimizer 설정이 필요. 레시피: 작은 LR(SFT의 10–100× 작게 — PPO/GRPO 1e-6, DPO 5e-7), weight decay 없음(KL 항이 이미 정규화; WD는 그와 싸움), 상수 스케줄(RL은 고정 지평선 없음), FP32 master 가중치(BF16 전용은 "100–500스텝 후 reward 붕괴를 안정적으로 유발" — 7비트 가수가 1e-6 상대 업데이트를 표현 못 함), 공격적 gradient clipping(max_grad_norm=1.0 — "∥∇∥>50인 clip 안 된 한 스텝이 수백 스텝을 무를 수 있음"), β₂=0.95(0.999 대비 — ~20스텝 기억이 빠르게 변하는 지형에 더 빨리 적응).

"Always use FP32 master weights for RL training. BF16-only … reliably causes reward collapse in PPO/GRPO after 100–500 steps."

— §11.15.4 · p.218

12LLM Agentic TrainingLLM Agentic Training

The shift from single-turn chatbots to multi-step agents that act over tools/APIs/environments demands new RL: trajectories of 10–100+ tool calls, external (not preference) feedback, structured actions (JSON/code), and long horizons with sparse rewards. Standard RLHF optimizes single-turn quality; agents must reason over entire trajectories.단일턴 챗봇에서 tool/API/환경을 다루는 다단계 에이전트로의 전환은 새 RL을 요구한다: 10–100+회 tool call의 trajectory, (선호가 아닌) 외부 피드백, 구조화 행동(JSON/코드), sparse 보상의 긴 지평선. 표준 RLHF는 단일턴 품질을 최적화하지만, 에이전트는 trajectory 전체를 추론해야 한다.

12.2–12.3 — Trajectory buffers & operational paradigmstrajectory 버퍼 & 운영 패러다임

Classic replay buffers store low-dim tensors; agentic buffers store textual histories. An experience is e_t = (S_t, A_t, R_t, S_{t+1}) where the state is the full context (objective + history + env vars), the action is {text_reasoning, json_tool_call}, and the reward is an external execution signal (tests, compiler, API codes) — usually a single sparse terminal reward. Three ways to use the buffer: (A) self-correction (STaR/Reflexion — save failures, generate a textual critique, retry); (B) off-policy exploration (filter for successful, efficient, diverse trajectories, train only on those); (C) RAG over experiences (the buffer as a vector DB — retrieve the top-k similar successful runs as few-shot demos; zero training).고전 replay 버퍼는 저차원 텐서를 저장; 에이전트 버퍼는 텍스트 이력을 저장. 경험은 e_t = (S_t, A_t, R_t, S_{t+1})이고 상태는 전체 문맥(목표 + 이력 + 환경 변수), 행동은 {text_reasoning, json_tool_call}, 보상은 외부 실행 신호(테스트, 컴파일러, API 코드) — 보통 단일 sparse 종단 보상. 버퍼 사용 세 방식: (A) 자기교정(STaR/Reflexion — 실패 저장, 텍스트 비평 생성, 재시도); (B) off-policy 탐험(성공·효율·다양 trajectory만 거르고 거기서만 학습); (C) 경험 RAG(버퍼를 벡터 DB로 — top-k 유사 성공 런을 few-shot 시연으로 검색; 학습 0).

12.8 — State of the art: GRPO + verifiable rewards + turn-level credit최신: GRPO + 검증 보상 + 턴 단위 credit

The field converges on on-policy policy gradients + fine-grained credit assignment. GRPO is the dominant baseline (no critic → saves 50% memory, which matters when trajectories are 32K–128K tokens; natural fit for binary verifiable rewards). PPO still wins in highly stochastic environments where a step-level value head helps (at 2× memory). The core problem is sparse reward — 20 actions then one failed test punishes all 20 equally — and two fixes dominate: RLVR (reward at deterministic intermediate checkpoints: bash compiles +0.1, SQL returns rows +0.1, final tests pass +1.0 → accelerates learning 3–5× vs sparse-only) and multi-turn trajectory slicing (replay the successful prefix, assign negative reward only to the first divergent step). Alternatives: iterative STaR (offline, avoids RL instability), Reinforcement World-Model Learning (reward predicting the semantic consequence of actions → mitigates reward hacking), and LATS (search-time compute).이 분야는 on-policy policy gradient + 세밀한 credit 할당으로 수렴한다. GRPO가 지배적 베이스라인(critic 없음 → 50% 메모리 절약, trajectory가 32K–128K 토큰일 때 중요; 이진 검증 보상에 자연스러움). PPO는 단계별 value head가 돕는 고확률성 환경에서 여전히 우세(메모리 2×). 핵심 문제는 sparse 보상 — 20개 행동 후 테스트 하나 실패가 20개를 똑같이 벌함 — 이고 두 해법이 지배: RLVR(결정적 중간 체크포인트에 보상: bash 컴파일 +0.1, SQL 행 반환 +0.1, 최종 테스트 통과 +1.0 → sparse 단독 대비 학습 3–5× 가속)과 멀티턴 trajectory slicing(성공한 prefix 재생, 첫 분기 단계에만 음의 보상). 대안: 반복 STaR(오프라인, RL 불안정 회피), 강화 세계모델 학습(행동의 의미적 결과 예측에 보상 → reward hacking 완화), LATS(탐색 시 연산).

"Intermediate rewards provide gradient signal to every step, not just the final one. This dramatically accelerates learning by 3–5× compared to sparse-only rewards."

— §12.8.3 · p.248
