RLHF / RLVR

Two RL paradigms: align to human preferences (a learned reward model) vs. optimize verifiable rewards (answer correct? tests pass?). Same machinery, different reward source.인간 선호(학습된 보상 모델)에 맞추느냐, 검증 가능한 보상(정답인가? 테스트 통과?)을 최적화하느냐의 차이다. 기계는 같고 보상 출처만 다르다.

The 4 models네 모델

PPO-RLHF holds four at once: policy (trains), reference (frozen anchor), reward model (scores), value head (critic). DPO drops the last two; GRPO drops the critic.PPO-RLHF는 policy(학습), reference(고정 앵커), reward model(채점), value head(critic)를 동시에 띄운다. DPO는 뒤 둘을, GRPO는 critic을 뺀다.

"How much better than average was this action/response?" PPO uses a critic + GAE; GRPO uses a group baseline (r−mean)/std over N samples — no critic."이 응답이 평균보다 얼마나 나았나"를 나타낸다. PPO는 critic+GAE로, GRPO는 critic 없이 N개 표본의 그룹 베이스라인 (r−평균)/표준편차로 구한다.

4.1 — Two paradigms for RL in LLMsLLM RL의 두 패러다임

Paradigm 1 — alignment (RLHF/DPO). Learn a reward model from pairwise human judgments, then push the policy to maximize it → helpful/harmless/honest assistants. Paradigm 2 — capability via verifiable rewards (RLVR). No humans: the reward is a verifiable outcome (answer correct? code passes tests?). DeepSeek-R1 showed GRPO + rule-based rewards grow reasoning with zero preference data. Different goals, but both run on the same four-part machinery (policy, reward, KL constraint, policy-gradient).패러다임 1, 정렬(RLHF/DPO). 쌍별 인간 판단으로 보상 모델을 학습하고 policy가 그 보상을 최대화하게 해 도움되고 무해하고 정직한 어시스턴트를 만든다. 패러다임 2, 검증 가능한 보상(RLVR). 정답 여부나 테스트 통과가 곧 보상이다. DeepSeek-R1은 GRPO와 규칙 기반 보상만으로 선호 데이터 0에서 추론 능력을 키웠다. 둘 다 policy, reward, KL 제약, policy-gradient라는 같은 기계로 돈다.

"This paradigm — RL from Verifiable Rewards (RLVR) — is now the dominant approach for building reasoning models and agentic systems."

4.2 — Text generation as an MDP텍스트 생성을 MDP로

The enabling trick: treat autoregressive decoding as a Markov Decision Process. The model is an agent writing one token at a time.자기회귀 디코딩을 마르코프 결정과정(MDP)으로 보는 것이 출발점이다. 모델은 토큰을 하나씩 쓰는 에이전트다.

state s_t = (x, y₁…y_{t−1}) · action a_t = next token ∈ V · transition = append (deterministic)
reward r = end-of-sequence score (sparse) · policy π_θ(a_t|s_t) = the LLM softmax · γ = 1.0

Reading it. The state is literally the growing context; the action is choosing the next token out of 32K–128K; the transition is just appending it (no environment randomness); the reward usually arrives only at the end (sparse). Crucially, the LLM already is the policy — its softmax defines π_θ for every state, so no separate policy network is built. No discounting (γ=1) because an episode is one finite response.읽는 법. 상태는 자라는 문맥이고, 행동은 32K–128K개 중 다음 토큰 하나를 고르는 것이다. 전이는 이어붙이기라 무작위성이 없고, 보상은 보통 끝에만 온다(sparse). LLM의 softmax가 모든 상태에서 π_θ를 정의하므로 LLM이 곧 policy이고 별도 policy 망이 필요 없다. 에피소드가 유한한 응답 하나라 할인도 없다(γ=1).

"This mapping is powerful because the LLM already is a policy — its softmax output defines π_θ(a_t|s_t) for every state."

— §4.2 · p.134

4.3 — The RLHF pipelineRLHF 파이프라인

Four stages: (1) SFT on demonstrations → an instruction-following π_SFT; (2) reward-model training on human comparisons (y_w ≻ y_l) via Bradley-Terry; (3) RL optimization (PPO/GRPO) of the policy against the reward, with a KL leash to π_SFT; (4) evaluate & iterate. The RLVR variant swaps the reward model for a verifier and trains SFT on reasoning traces — stage 3 is identical.(1) 시연 데이터로 SFT해 지시를 따르는 π_SFT를 만든다. (2) 인간 비교(y_w ≻ y_l)로 Bradley-Terry 보상 모델을 학습한다. (3) 이 보상으로 policy를 RL 최적화(PPO/GRPO)하되 π_SFT에 KL로 묶는다. (4) 평가하고 반복한다. RLVR은 보상 모델 자리에 verifier를 쓰고 추론 trace로 SFT한다. 3단계는 같다.

How LLM RL differs from classical RL: deterministic transitions, sparse reward, a 32K–128K action space (exploration is implicit, via sampling temperature), a KL anchor to SFT, and no value function strictly needed (GRPO drops the critic). This is why PPO/GRPO — not DQN-style value methods — dominate.고전 RL과 다른 점: 전이가 결정적이고, 보상이 sparse하고, 행동공간이 32K–128K이며(탐험은 샘플링 온도로 암묵적으로 한다), SFT에 KL 앵커가 있고, value 함수가 꼭 필요하지 않다(GRPO는 critic을 없앤다). 그래서 DQN식 value 방법 대신 PPO/GRPO가 주류다.

5PPO — Proximal Policy Optimization

PPO is the RLHF workhorse behind GPT-4-class assistants. The whole design exists to make policy-gradient updates stable without expensive second-order math.PPO는 GPT-4급 어시스턴트를 만든 RLHF의 일꾼이다. 비싼 2차 최적화 없이 policy-gradient 업데이트를 안정적으로 만드는 것이 설계의 전부다.

5.1 — Motivation & history동기·역사

Vanilla policy gradient has no step-size limit: one unlucky batch shoves the policy into a bad region, which earns low reward, which makes the next update worse — an unrecoverable collapse. TRPO (2015) fixed this with a hard KL constraint but needs second-order optimization (Fisher matrix, conjugate gradients). PPO (2017) gets similar stability with a simple first-order clipped objective — ~10× simpler and scales to distributed training trivially.바닐라 policy gradient에는 스텝 크기 제한이 없어서, 운 나쁜 배치 하나가 policy를 나쁜 영역으로 밀면 보상이 떨어지고 업데이트가 더 나빠지는 붕괴가 온다. TRPO(2015)는 강한 KL 제약으로 막았지만 Fisher 행렬 같은 2차 최적화가 필요하다. PPO(2017)는 1차 clipped 목적함수로 비슷한 안정성을 얻는다. 약 10배 단순하고 분산 학습에도 쉽게 붙는다.

5.3 — Full loss전체 손실

L = L_CLIP − c₁·(V_θ(s_t) − V_target)² + c₂·H[π_θ] (c₁=0.1 value, c₂=0.01 entropy)

Adds a value-loss term (trains the critic V_θ to predict returns; also clipped) and an entropy bonus (rewards a spread-out policy → prevents premature collapse to a deterministic policy; critical for exploration). Value loss is subtracted (minimize error), entropy added (maximize spread).critic V_θ가 return을 예측하도록 학습하는 value 손실(이것도 clip한다)과, 퍼진 policy에 보상을 줘 결정적 policy로 일찍 굳는 것을 막는 엔트로피 보너스를 더한다. 엔트로피 보너스는 탐험에 꼭 필요하다. value 손실은 빼고(오차 최소화) 엔트로피는 더한다.

5.4 — Derivation in six steps6단계 유도

The path from "maximize reward" to the clipped update: (1) objective J(θ)=E_τ[Σr_t]; (2) policy-gradient theorem ∇J = E[Σ ∇log π_θ(a_t|s_t)·Â_t] — push probability toward positive-advantage actions, with the advantage replacing the raw return to cut variance; (3) importance sampling: PPO collects with π_old but updates π, so reweight by r_t(θ) → surrogate L_CPI = E[r_t·Â_t]; (4) unconstrained, r_t can drift far from 1 → extreme weights, collapse (TRPO's hard-KL fix is expensive); (5) PPO's first-order fix = clip the surrogate; its gradient flows only when the unclipped term is the smaller one, and is zeroed once the ratio passes the clip bound in the "already moved enough" direction; (6) the complete update is gradient ascent on L_CLIP − c₁·L_VF + c₂·H. Result: monotonic improvement with only first-order gradients — no Hessians, no line search."보상 최대화"에서 clipped 업데이트까지의 유도다. (1) 목적 J(θ)=E_τ[Σr_t]. 5.5 — Rollout buffer (why PPO is on-policy)rollout 버퍼 (PPO가 on-policy인 이유)

PPO's data store is an ephemeral rollout buffer (unlike DQN's permanent replay buffer) because PPO is on-policy: its math only holds for data made by the current policy. A "rollout" in LLMs = generate a full token sequence from a prompt; each token is one step. Lifecycle: collect (a 70B model at batch 128 × 512 tokens → up to ~65K token-level transitions) → train (K=3–10 epochs of clipped mini-batch SGD) → purge (wipe the buffer; stale-policy data would break the clipping guarantees). Because generation is 60–70% of wall-clock, vLLM (batched gen, paged KV, prefix sharing for the N same-prompt samples) is the standard generation backend (OpenRLHF, TRL).PPO는 on-policy라 현재 policy가 만든 데이터에서만 수식이 성립한다. 그래서 DQN식 영구 replay 대신 일회성 rollout 버퍼를 쓴다. LLM의 rollout은 프롬프트로 토큰열 전체를 생성하는 것이고 토큰 하나가 한 스텝이다. 버퍼는 수집(70B, 배치 128 × 512토큰이면 최대 ~65K 전이) → 학습(K=3–10 epoch) → 폐기를 반복한다. 낡은 데이터는 clipping 보장을 깨기 때문이다. 생성이 벽시계 시간의 60–70%라 vLLM(배치 생성, paged KV, prefix 공유)이 표준 생성 백엔드다(OpenRLHF, TRL).

"Because PPO is on-policy, data generated by the old policy cannot be safely reused for the next update cycle."

— §5.5.3 · p.139

5.6 — PPO for RLHF: the full loop (worked, 70B)RLHF용 PPO 전체 루프 (70B 실예)

One concrete step for a 70B chat model, 128 prompts: (1) generate (temp 0.7, top-p 0.9; ~60% of time) → (2) score with the reward model → (3) per-token KL KL_t = log π_θ(y_t|·) − log π_ref(y_t|·) (mean KL 3–8) → (4) final reward R = r_RM − 0.05·mean_KL at the last token → (5) GAE advantages, then whiten (zero-mean/unit-variance) → (6) update (4 epochs, mini-batch 16, ε=0.2, grad-norm 1.0). ~0.005 win-rate/step; ~5–10% absolute over SFT after 10K steps.70B 챗 모델, 프롬프트 128개의 한 스텝이다. (1) 생성(temp 0.7, top-p 0.9, 시간의 ~60%) → (2) 채점 → (3) 토큰별 KL KL_t = log π_θ(y_t|·) − log π_ref(y_t|·)(평균 3–8) → (4) 최종 보상 R = r_RM − 0.05·mean_KL을 마지막 토큰에 → (5) GAE advantage를 whiten(평균0·분산1) → (6) 업데이트(4 epoch, 미니배치 16, ε=0.2, grad-norm 1.0). win-rate는 스텝당 ~0.005씩 올라 10K 스텝 뒤 SFT보다 ~5–10%p 높다.

tokenization pitfall토크나이즈 함정Reward at only the final token means every earlier token must back-propagate credit through GAE — longer responses get a more diluted signal. Per-token KL also over-penalizes rare words split into more subwords. Mitigate with length-normalized KL or reward at semantic boundaries.보상이 마지막 토큰에만 붙어서 앞의 모든 토큰은 GAE로 credit을 거꾸로 받아야 한다. 응답이 길수록 신호가 묽어진다. 토큰별 KL은 서브워드로 잘게 쪼개지는 희귀어를 과하게 벌한다. 길이 정규화 KL이나 의미 경계 보상으로 완화한다.

5.7 — Detailed mechanics: two networks, log-space ratio상세 동작: 두 망, 로그공간 비

During a cycle PPO holds two weight states of the same topology: the live π_θ (updated every mini-batch) and a frozen π_θold snapshot (the anchor). At rollout, the action's log-prob under π_θold is stored as a scalar — so the frozen net isn't re-run during optimization (saves a full forward pass per mini-batch). The ratio is computed in log-space for numerical safety: r_t(θ) = exp( log π_θ(a_t|s_t) − log π_θold(a_t|s_t) ). The weight lifecycle: ratio starts at exactly 1.0 (snapshot==live), drifts as θ updates, gets trapped at 1±ε by clipping, and resets to 1.0 next cycle when the new θ becomes the snapshot.PPO는 한 사이클 동안 미니배치마다 바뀌는 π_θ와 고정된 π_θold 스냅샷을 함께 쥔다. rollout 때 π_θold의 log-prob을 스칼라로 저장해 두면 고정 망을 다시 돌릴 필요가 없다. 비는 수치 안정을 위해 로그공간에서 계산한다: r_t(θ) = exp( log π_θ(a_t|s_t) − log π_θold(a_t|s_t) ). 비는 1.0에서 시작해 θ가 바뀌며 멀어지고, 1±ε에 갇혔다가, 다음 사이클에 새 스냅샷이 잡히면 1.0으로 돌아간다.

6DPO — Direct Preference Optimization

DPO's pitch: skip the RL loop entirely. PPO-RLHF juggles four models and brittle rollouts; DPO turns preference pairs straight into a supervised loss that implicitly optimizes the same RLHF objective — no reward model at train time, no value critic, no rollouts.DPO는 RL 루프를 통째로 건너뛴다. PPO-RLHF가 네 모델과 까다로운 rollout을 굴리는 데 비해, DPO는 선호쌍을 지도학습 손실로 바꿔 같은 RLHF 목적을 암묵적으로 최적화한다. 학습 때 보상 모델도, value critic도, rollout도 없다.

6.2 — The derivation (why it works)유도 (되는 이유)

Four steps. (1) the RLHF objective is max_π E[r(x,y)] − β·KL(π‖π_ref). (2) its optimum has a closed form — tilt the reference toward reward:네 단계로 유도한다. (1) RLHF 목적은 max_π E[r(x,y)] − β·KL(π‖π_ref)이다. (2) 최적해는 reference를 보상 쪽으로 기울인 닫힌 형태다:

π*(y|x) = (1/Z(x))·π_ref(y|x)·exp(r(x,y)/β), Z(x)=Σ_y π_ref(y|x)·exp(r(x,y)/β)

(3) invert it — take logs and solve for the reward: r(x,y) = β·log(π*(y|x)/π_ref(y|x)) + β·log Z(x). This is the heart: the reward is recoverable from the log-ratio of policy to reference, up to a prompt-only constant. (4) plug into Bradley-Terry P(y_w≻y_l)=σ(r(y_w)−r(y_l)) — and the intractable partition function β·log Z(x) (same for both responses) cancels, leaving a plain loss in the trainable π_θ:(3) 로그를 취해 보상에 대해 풀면 r(x,y) = β·log(π*(y|x)/π_ref(y|x)) + β·log Z(x)가 된다. 보상을 policy 대 reference의 로그비로 되살릴 수 있다는 뜻이다(프롬프트에만 의존하는 상수 차이는 남는다). (4) 이를 Bradley-Terry P(y_w≻y_l)=σ(r(y_w)−r(y_l))에 넣으면 두 응답에 똑같은 분배함수 β·log Z(x)가 소거되고, π_θ에 대한 단순한 손실만 남는다:

L_DPO(θ) = −E[ log σ( β·log(π_θ(y_w|x)/π_ref(y_w|x)) − β·log(π_θ(y_l|x)/π_ref(y_l|x)) ) ]

Implicit reward r̂(x,y)=β·log(π_θ/π_ref): DPO is just binary cross-entropy whose "label" is chosen should out-score rejected. β sets the margin/KL strength — large β moves the policy aggressively (forgetting risk), small β hugs the reference. The reference is the regularizer; any deviation must be justified by better preference alignment.암묵 보상은 r̂(x,y)=β·log(π_θ/π_ref)다. DPO는 "선택이 거부보다 점수가 높아야 한다"를 라벨로 삼는 이진 교차엔트로피일 뿐이다. β는 margin과 KL 강도를 정한다. β가 크면 policy를 공격적으로 밀고(망각 위험), 작으면 reference에 붙어 있다. reference가 정규화기 역할을 해서, 벗어나려면 그만큼 선호 정렬이 좋아져야 한다.

"The optimal policy under the RLHF objective (reward maximization + KL penalty) has a closed-form solution. … The Z(x) cancels!"

6.3 — Gradient: effort goes where the model is wronggradient: 틀린 곳에 노력 집중

∇_θ L = −β·σ(r̂_l − r̂_w)·[ ∇_θ log π_θ(y_w|x) − ∇_θ log π_θ(y_l|x) ]

The scalar weight σ(r̂_l−r̂_w) is an adaptive learning rate: ≈0.5 when the model can't tell the pair apart (learn hard), ≈0 once the chosen already dominates (stop). The bracket simultaneously pushes the chosen log-prob up and the rejected down. So gradient concentrates on confusing pairs; easy pairs contribute almost nothing.스칼라 가중치 σ(r̂_l−r̂_w)는 적응형 학습률처럼 동작한다. 모델이 쌍을 구분 못 하면 ≈0.5로 열심히 배우고, 선택이 이미 앞서면 ≈0으로 멈춘다. 괄호 항은 선택의 log-prob을 올리면서 거부의 log-prob을 내린다. 그래서 gradient는 헷갈리는 쌍에 몰리고 쉬운 쌍은 거의 기여하지 않는다.

6.5 / 6.8 — Mechanics & scaling동작 & 스케일링

Sequence log-prob is a sum of per-token log-softmax over the response (same as LM cross-entropy, summed). Only response tokens get gradient (prompt masked, padding masked). Pitfalls: forgetting to mask the prompt; mismatched mean-vs-sum between π_θ and π_ref; using the base model instead of the SFT checkpoint as reference (KL term dominates, gradients vanish); β too large (sigmoid saturates → zero gradient) or too small (∝β·σ vanishes → flat landscape). Memory: DPO holds two copies, but with LoRA the reference is just the base with adapters disabled (ref_model=None), halving memory; or pre-compute reference log-probs once and evict π_ref from GPU. DPO overfits fast — train ~1 epoch.시퀀스 log-prob은 응답 토큰 log-softmax의 합이고, 프롬프트·패딩은 마스킹한다. 흔한 실수는 마스킹 누락, π_θ와 π_ref의 mean/sum 불일치, reference로 SFT 대신 base 사용(gradient 소멸), β 과대(시그모이드 포화) 또는 과소(신호가 평평해짐)다. 사본이 두 개 필요하지만 LoRA면 어댑터를 끈 base를 reference로 써서(ref_model=None) 절반으로 줄이고, reference log-prob을 미리 계산해 GPU에서 내릴 수도 있다. 7GRPO — Group Relative Policy Optimization

GRPO is PPO with the critic removed. Instead of training a value network to predict expected reward, it estimates the baseline empirically: sample G responses to the same prompt and use the group's reward statistics. This drops a whole model from memory and is the algorithm behind DeepSeek-R1.GRPO는 critic을 없앤 PPO다. 기대 보상을 예측하는 value 망 대신, 같은 프롬프트에 G개 응답을 뽑아 그룹의 보상 통계로 베이스라인을 잡는다. 메모리에서 모델 하나가 빠지고, DeepSeek-R1이 이 알고리즘을 썼다.

7.1 — Motivation: the critic's three problems동기: critic의 세 문제

PPO's value head fails in three ways for LLMs: memory (shares the 140 GB backbone of a 70B, or doubles it if separate), accuracy (predicting the reward of a partial sequence is very hard → wrong advantages → wrong gradient direction), and training (needs many samples; noisy early predictions destabilize the policy). GRPO's empirical baseline sidesteps all three — and often beats PPO because the empirical mean is a more accurate baseline than a poorly-trained value net.PPO의 value head는 LLM에서 세 가지가 문제다. 메모리(70B 백본 140 GB를 공유하거나 분리하면 2배), 정확도(부분 시퀀스로 보상을 예측하기 어려워 gradient 방향이 틀어진다), 학습(표본이 많이 필요하고 초기 노이즈가 policy를 흔든다). GRPO의 경험 평균은 셋을 모두 피하고, 잘못 학습된 value 망보다 정확해서 PPO를 앞서는 경우도 많다.

7.2 — Algorithm & the group-relative advantage알고리즘 & 그룹 상대 advantage

For a prompt x: sample G completions, score each (r_i), normalize within the group, then do a PPO-style clipped update with those advantages.프롬프트 x마다 G개 완성을 뽑아 각각 채점(r_i)하고, 그룹 안에서 정규화한 advantage로 PPO식 clipped 업데이트를 한다.

Â_i = (r_i − μ_G) / σ_G, μ_G = (1/G)Σ_j r_j, σ_G = std({r_j})

Reading it. The group mean μ_G is a Monte-Carlo estimate of the value function V(s): enough same-prompt samples → average reward ≈ expected reward, so you don't need a critic. Â_i>0 (above the group average) → reinforce that response; Â_i<0 → suppress it. Dividing by σ_G makes advantages scale-invariant across prompts with different reward ranges. The full objective is the PPO clipped surrogate with these Â_i, minus a KL term to π_ref. DeepSeek-R1: pure GRPO with binary correctness rewards (r=1 if right else 0) spontaneously grew chain-of-thought, self-verification, and error correction — with no explicit instruction.읽는 법. 그룹 평균 μ_G는 value 함수 V(s)의 몬테카를로 추정이다. 표본이 충분하면 평균 보상이 기대 보상에 가까워 critic이 필요 없다. 평균보다 나은 응답(Â_i>0)은 강화하고 못한 응답은 억제한다. σ_G로 나누면 보상 범위가 다른 프롬프트끼리 스케일이 맞는다. 목적함수는 PPO clipped 대리손실에서 π_ref로의 KL 항을 뺀 형태다. DeepSeek-R1에서는 이진 정답 보상(1 또는 0)만 쓴 GRPO가 chain-of-thought, 자기검증, 오류수정을 스스로 익혔다.

G=2 is too noisy (coin flip); G=8 is the balanced default; G=16 for hard tasks (pass<20%, need many tries to find positives); G=32 only with extreme compute. G=32는 연산이 넉넉할 때만 쓴다. 중요한 점: 그룹 안에 성공과 실패가 함께 있어야 한다. G개가 전부 정답이거나 전부 오답이면 advantage가 모두 0이라 학습 신호가 없다. 그래서 현재 모델 기준 통과율 20–80%인 프롬프트만 남기고, 모델이 나아지면 ~500스텝마다 다시 거른다.

8.1 — Online DPO

Offline DPO trains on static pairs made by some other model; as π_θ drifts, those pairs stop matching what the policy now produces — wasted gradient. Online DPO regenerates fresh pairs from the current policy each step, scores them with a reward model, and only then applies the DPO loss. It's the middle ground: DPO's simple supervised loss (no value head) + PPO's on-policy data (no distribution shift). Cost: it now needs a reward model (3 models), but no critic. Use it when offline DPO plateaus.오프라인 DPO는 다른 모델이 만든 고정 쌍으로 학습한다. π_θ가 움직이면 그 쌍이 현재 생성물과 어긋나 gradient가 낭비된다. Online DPO는 매 스텝 현재 policy로 새 쌍을 만들고 보상 모델로 채점한 뒤 DPO 손실을 적용한다. DPO의 단순한 지도손실(value head 없음)과 PPO의 on-policy 데이터(분포 이동 없음)를 합친 중간 지대다. 보상 모델이 필요해 모델이 셋이지만 critic은 없다. 오프라인 DPO가 정체될 때 쓴다.

8.2 — KTO (Kahneman-Tversky Optimization)

DPO needs matched good/bad pairs, but most real feedback is unpaired — a thumbs-up/down on one response. KTO borrows prospect theory: humans feel losses more strongly than gains, so a thumbs-down should give a stronger gradient than a thumbs-up. Each example is scored independently — no pairing.DPO는 좋음/나쁨 쌍이 필요하지만 실제 피드백은 대부분 한 응답에 좋아요/싫어요를 다는 비쌍 형태다. KTO는 전망 이론을 빌려 온다. 사람은 이득보다 손실을 크게 느끼니 싫어요가 좋아요보다 강한 gradient를 줘야 한다는 것이다. 예제를 하나씩 독립적으로 채점하므로 짝이 필요 없다.

L_KTO = E_{y_w}[λ_w(1 − v(x,y_w))] + E_{y_l}[λ_l·v(x,y_l)], v = σ( β·log(π_θ/π_ref) − z_ref )

Reading it. v∈(0,1) is a saturating "value": the implicit reward β·log(π_θ/π_ref) squashed through a sigmoid and shifted by a running KL baseline z_ref — the prospect-theory value curve. The desirable term raises good-response probability with diminishing returns (once v→1 it stops pushing); the undesirable term penalizes bad mass, with loss aversion encoded by allowing λ_l>λ_w. Data is just {prompt, completion, label:true/false} — production thumbs data, star ratings binarized, vote counts. Handles class imbalance better than DPO.읽는 법. v∈(0,1)은 포화되는 "가치"다. 암묵 보상 β·log(π_θ/π_ref)을 시그모이드로 누르고 진행 중 KL 베이스라인 z_ref만큼 옮긴 것으로, 전망 이론의 가치곡선에 해당한다. 바람직 항은 좋은 응답 확률을 점점 덜 올리고(v→1이면 멈춘다), 비바람직 항은 나쁜 확률 질량을 벌하되 λ_l>λ_w로 손실회피를 넣는다. 데이터는 {prompt, completion, label:true/false}면 충분하다. 프로덕션 thumbs, 이진화한 별점, 투표수를 그대로 쓸 수 있고 DPO보다 클래스 불균형에 강하다.

8.3 — IPO (Identity Preference Optimization)

DPO has a degenerate optimum: its loss −log σ(margin) keeps shrinking as the margin → ∞, so DPO drives chosen→1 / rejected→0 and memorizes pairs (overfits, especially on noisy labels). IPO replaces the log-sigmoid with a squared loss targeting a finite margin:DPO에는 퇴화 최적해가 있다. 손실 −log σ(margin)은 margin이 커질수록 계속 줄어서, 선택을 1로 거부를 0으로 몰며 쌍을 암기한다. 노이즈 라벨에서 특히 과적합한다. IPO는 log-sigmoid를 유한한 margin을 겨냥한 제곱 손실로 바꾼다:

L_IPO = E[ ( log(π_θ(y_w)/π_ref(y_w)) − log(π_θ(y_l)/π_ref(y_l)) − 1/(2β) )² ]

The bracket is exactly the DPO margin; IPO subtracts a target 1/(2β) and squares, so the optimum sits at a finite margin (penalizing too-small and too-large gaps). A mislabeled pair gets bounded influence → robust to label noise, generalizes better, survives multiple epochs. It's a loss_type="ipo" in DPOTrainer.괄호 안은 DPO margin 그대로다. IPO는 여기서 목표 1/(2β)를 빼고 제곱해 최적점을 유한한 margin에 둔다. 너무 작은 margin과 너무 큰 margin을 모두 벌하므로 오라벨 쌍의 영향이 제한된다. 그래서 라벨 노이즈에 강하고 일반화가 좋으며 여러 epoch를 돌려도 버틴다. DPOTrainer의 loss_type="ipo"로 쓴다.

8.4 — ORPO (Odds Ratio Preference Optimization)

Every method so far needs a reference model (extra memory). ORPO eliminates it by fusing SFT and alignment into one loss, using the odds ratio of chosen vs. rejected as the preference signal while the SFT (NLL) term anchors the model — the role KL-to-reference plays elsewhere.앞의 방법은 모두 reference 모델이 필요해 메모리가 더 든다. ORPO는 SFT와 정렬을 한 손실로 합쳐 reference를 없앤다. 선택 대 거부의 odds ratio가 선호 신호이고, SFT(NLL) 항이 다른 방법의 KL-to-reference처럼 모델을 붙잡는다.

L_ORPO = L_SFT(y_w) − λ·log σ( log( odds_θ(y_w)/odds_θ(y_l) ) ), odds_θ(y)=P_θ(y)/(1−P_θ(y))

"One model, one forward pass, one loss → ~50% less memory" (saves ~70–140 GB for a 70B). Best when memory-constrained, when starting from a base model (ORPO does SFT simultaneously), or when you want the simplest pipeline. Limitation: less battle-tested at 70B+, and the SFT term demands high-quality chosen responses."한 모델, 한 forward, 한 손실 → 메모리 ~50% 절감"(70B 기준 ~70–140 GB 절약)이다. 메모리가 빠듯할 때, base 모델에서 시작할 때(ORPO가 SFT를 겸한다), 가장 단순한 파이프라인을 원할 때 좋다. 다만 70B+에서는 검증이 덜 됐고, SFT 항 때문에 선택 응답의 품질이 높아야 한다.

8.5 — Best-of-N (rejection sampling)

The simplest approach — no RL training at all: generate N candidates, score with a reward model, keep the best y* = argmax_i r(x,y_i). As inference-time decoding it improves quality with zero weight change (N=64 → +15–20% win-rate, sometimes matching PPO). As training (Rejection-sampling Fine-Tuning / RFT): generate → keep winners → SFT → repeat. It implements an implicit KL-constrained policy π_BoN ∝ π_θ^(1−1/N)·r^(1/N) — N tunes how hard you exploit the reward vs. stay on-distribution.RL 학습이 전혀 없는 가장 단순한 방법이다. 후보 N개를 생성해 보상 모델로 채점하고 최선 y* = argmax_i r(x,y_i)를 고른다. 추론 시 디코딩으로 쓰면 가중치를 바꾸지 않고 품질이 오른다(N=64면 win-rate +15–20%, 때로 PPO와 비슷). 학습에 쓰면 Rejection-sampling Fine-Tuning(RFT)이 된다. 생성하고, 승자를 남기고, SFT하고, 반복한다. 이는 암묵적인 KL 제약 policy π_BoN ∝ π_θ^(1−1/N)·r^(1/N)에 해당하고, N이 보상 착취와 분포 유지 사이의 균형을 정한다.

9Reward Model TrainingReward Model Training

The reward model (RM) is the bridge between human preferences and the RL signal. A good RM is essential for RLHF; a poorly-trained one causes reward hacking and misalignment.보상 모델(RM)은 인간 선호를 RL 신호로 잇는 다리다. RLHF에는 좋은 RM이 꼭 필요하고, 잘못 학습된 RM은 reward hacking과 오정렬을 부른다.

9.1 — Bradley-Terry

P(y₁ ≻ y₂ | q) = σ( r(y₁,q) − r(y₂,q) ), L_BT = −(1/N)Σ_k log σ( r_φ(y_w) − r_φ(y_l) )

Reading it. The probability that y₁ beats y₂ is a sigmoid of the difference of their scalar rewards — only the gap matters, not the absolute scale. Fitting r_φ is then binary cross-entropy with the human-preferred response as the positive class. Four assumptions (often violated → motivate the extensions below): transitivity, a single scalar reward, difference-only dependence, and independent pairs. A margin variant subtracts a constant m inside the sigmoid to force a minimum gap.읽는 법. y₁이 y₂를 이길 확률은 두 스칼라 보상 차이의 시그모이드다. 절대 스케일은 상관없고 차이만 중요하다. r_φ 학습은 인간이 고른 응답을 양성 클래스로 둔 이진 교차엔트로피다. 이 모델은 추이성, 단일 스칼라 보상, 차이 의존, 독립 쌍이라는 네 가정을 깔고 있고, 이 가정이 자주 깨진다는 점이 아래 확장의 동기다. margin 변형은 시그모이드 안에서 상수 m을 빼 최소 차이를 강제한다.

9.2 / 9.3 — Architecture & training tricks아키텍처 & 학습 트릭

An RM = a pretrained LLM with its language-modeling head swapped for a scalar regression head (W∈ℝ^{d×1} on the pooled hidden state — last token for decoder-only, [CLS] for encoders). In TRL: AutoModelForSequenceClassification(num_labels=1) + RewardTrainer. Three tricks keep its output usable as an RL signal: reward centering (subtract the policy's mean reward per prompt → stable PPO), length-bias correction (RMs reward longer responses regardless of quality → length-normalize / calibrate), and margin losses (a hinge max(0, m−(r_w−r_l)) forcing a meaningful gap). Skipping centering → unstable PPO; ignoring length bias → models pad output to farm reward.RM은 사전학습 LLM의 LM head를 스칼라 회귀 head로 바꾼 것이다(decoder-only는 마지막 토큰, encoder는 [CLS]의 hidden state에 W∈ℝ^{d×1}). TRL은 AutoModelForSequenceClassification(num_labels=1)과 RewardTrainer를 쓴다. RL 신호로 쓰려면 세 가지가 필요하다. 보상 센터링(프롬프트별 평균을 빼야 PPO가 안정된다), 길이 편향 보정(안 하면 모델이 보상을 따려고 출력을 늘린다), margin 손실(hinge max(0, m−(r_w−r_l))로 의미 있는 차이를 강제).

"Reward models are known to exhibit length bias: they tend to assign higher rewards to longer responses, regardless of quality."

9.4 — PRM vs ORM

An Outcome RM scores only the final answer; a Process RM scores each reasoning step. PRMs give dense credit and are harder to hack, at the cost of expensive step-level annotation and higher inference cost. Theoretically a PRM is Potential-Based Reward Shaping: a potential Φ(s) (e.g. fraction of valid steps) gives per-step signal while preserving the optimal policy that maximizes final correctness — which is what makes dense rewards principled rather than ad-hoc. Step labels can be auto-generated by Monte-Carlo rollouts (fraction of completions from a step that reach the right answer), an LLM judge, or a formal verifier.Outcome RM은 최종 답만, Process RM은 추론 단계마다 채점한다. PRM은 촘촘한 credit을 주고 해킹하기 어렵지만, 단계별 주석이 비싸고 추론 비용도 높다. 이론적으로 PRM은 잠재 기반 보상 형성(PBRS)이다. 잠재 Φ(s)(예: 유효 단계 비율)로 단계별 신호를 주면서도 최종 정답을 최대화하는 최적 policy는 그대로 둔다. 그래서 dense 보상이 임시방편이 아니라 원칙 있는 방법이 된다. 단계 라벨은 몬테카를로 rollout(그 단계에서 정답에 이르는 완성 비율), LLM judge, 형식 검증기로 자동 생성할 수 있다.

9.5 — Rule-based rewards (RLVR)규칙 기반 보상 (RLVR)

RLVR replaces the learned RM with deterministic, rule-based functions — the DeepSeek-R1 approach, which sharply reduces reward hacking. Typical composable rules: a format_reward (1.0 iff the <think>…</think><answer>…</answer> pattern matches), a correctness_reward (extracted answer == ground truth), and a code_execution_reward (fraction of unit tests passed, with a strict timeout). Pitfalls to design around: format gaming (right format, wrong content → always combine format + correctness), test-case leakage (tests in training data → memorization), timeout exploitation (emit code that times out → penalize timeouts explicitly), and reward sparsity (binary 0/1 too sparse → add partial credit).RLVR은 학습된 RM 대신 결정적 규칙으로 채점해 reward hacking을 크게 줄인다(DeepSeek-R1 방식). 보통 format_reward(<think>…</think><answer>…</answer> 패턴이면 1.0), correctness_reward(답 == 정답), code_execution_reward(타임아웃 아래 통과한 테스트 비율)를 섞는다. 함정은 포맷 게이밍(포맷과 정확도를 항상 묶는다), 테스트 누출(암기), 타임아웃 악용(타임아웃에 벌점), 보상 희소성(부분점수를 준다)이다.

9.6 / 9.7 — Multi-objective & listwise rewards다목적 & listwise 보상

Multi-objective: combining rewards (correctness + format + length), the strategy matters. A plain weighted sum r=Σ w_n r_n is scale-sensitive (the largest-variance reward dominates); the robust default is normalize-then-sum (each reward to zero-mean/unit-variance within the group, then weight) — scale-invariant. Other options: lexicographic (strict priority order), constrained (maximize primary subject to constraints on secondaries), Pareto-front. Listwise: Bradley-Terry only handles pairs, but you often rank K responses at once. The Plackett-Luce model generalizes BT to full rankings as a sequence of "pick the best of the remaining" softmaxes; its NLL is the listwise loss, and for K=2 it reduces exactly to Bradley-Terry. Listwise rewards (ListMLE/ListNet/LambdaRank/RankNet) carry C(K,2) implicit comparisons plus relative margins, calibrate the absolute reward scale better, and map naturally onto GRPO (which already ranks its N samples).다목적: 단순 가중합 r=Σ w_n r_n은 분산 큰 보상이 지배한다. 기본값은 각 보상을 그룹 안에서 평균0·분산1로 맞춘 뒤 더하는 정규화 후 합이다. 사전식, 제약식, Pareto front도 있다. Listwise: Bradley-Terry는 쌍만 다루지만 K개 응답을 한 번에 순위 매기는 일이 많다. Plackett-Luce는 "남은 것 중 최선 뽑기" 소프트맥스를 이어 붙여 BT를 전체 순위로 넓힌다. K=2면 Bradley-Terry와 같다. Listwise 보상(ListMLE/ListNet/LambdaRank/RankNet)은 C(K,2)개 비교와 상대 margin을 담아 스케일을 더 잘 맞추고, N개 표본을 순위 매기는 GRPO와 잘 맞는다.

10.1–10.4 — The efficiency mechanics효율 메커니즘

Sequence packing시퀀스 패킹

Padding to the longest sequence wastes 50–80% of compute on high-variance data. Pack multiple short examples into one max_seq_length sequence with a block-diagonal attention mask (so examples can't attend across each other). 85–95% efficiency, 2–4× speedup; memory unchanged (same total tokens). SFTConfig(packing=True). Danger: a wrong mask leaks across examples.가장 긴 시퀀스에 맞춰 패딩하면 길이 편차가 큰 데이터에서 연산의 50–80%가 버려진다. 짧은 예제 여럿을 max_seq_length 시퀀스 하나에 묶고 블록 대각 어텐션 마스크로 예제끼리 어텐션을 막는다. 효율이 85–95%로 오르고 2–4배 빨라지며, 총 토큰이 같아 메모리는 그대로다. SFTConfig(packing=True)로 켠다. 마스크가 틀리면 예제 사이로 정보가 샌다.

Chat templates챗 템플릿

Instruction models need role structure (system/user/assistant) in the token stream — ChatML (<|im_start|>) or Llama-3 special tokens. Using the wrong template at inference causes significant degradation. tokenizer.apply_chat_template(...); match the model family.지시 모델은 토큰열에 system/user/assistant 역할 구조가 있어야 한다. ChatML(<|im_start|>)이나 Llama-3 특수 토큰을 쓴다. 추론 때 템플릿이 틀리면 성능이 크게 떨어진다. tokenizer.apply_chat_template(...)을 쓰고 모델 계열에 맞춘다.

Completion-only masking완성 전용 마스킹

Compute loss only on the assistant response, not the prompt (zeroes loss on non-assistant tokens via a response_template). The template must match the tokenized form exactly; multi-turn chats must mask all non-assistant turns.손실은 프롬프트가 아니라 어시스턴트 응답에만 계산한다(response_template로 나머지 토큰의 손실을 0으로). 템플릿은 토큰화 결과와 정확히 일치해야 하고, 멀티턴이면 어시스턴트가 아닌 모든 턴을 마스킹한다.

Data mixing데이터 혼합

10.5 — When SFT hurts: forgetting vs. alignment taxSFT가 해칠 때: 망각 vs 정렬세

Two distinct phenomena cause post-training benchmark regressions; confusing them leads to the wrong fix. Catastrophic forgetting is an unintentional optimization failure — training on a disjoint distribution physically overwrites the weights encoding the old capability (knowledge destroyed, irreversible without retraining; detected by a perplexity spike on a pre-training eval set). Alignment tax is a deliberate trade-off — capability drops because the policy is constrained (by the KL leash) toward safe/aligned outputs (knowledge suppressed not erased; partially reversible by tuning β or the system prompt). Tell them apart: if the base model succeeds where the fine-tuned one totally fails → forgetting; if careful prompting recovers it → tax.포스트트레이닝 뒤 벤치마크 하락은 서로 다른 두 현상에서 오고, 헷갈리면 처방이 틀린다. 치명적 망각은 의도치 않은 실패다. 동떨어진 분포로 학습하다 옛 능력을 담은 가중치를 덮어써 지식이 파괴된다. 재학습 없이는 되돌릴 수 없고 사전학습 평가셋 perplexity가 급등한다. 정렬세는 의도된 거래다. KL 끈으로 안전한 출력에 묶은 대가로, 지식은 지워진 게 아니라 눌린 상태라 β나 시스템 프롬프트로 일부 되돌릴 수 있다. base 모델은 되는데 파인튠이 완전히 실패하면 망각, 신중한 프롬프트로 회복되면 정렬세다.

10.6 — SFT quality is the RL ceilingSFT 품질이 RL 천장

RL can amplify weak-but-present behaviors, suppress bad ones, and refine style — but it cannot introduce capabilities the SFT model never shows. The reason is mechanical: RL needs a non-zero reward signal, and if the SFT model never produces a correct response, all rewards are 0, all advantages are 0, there is no gradient. Concretely: SFT at 10% correct on math → RL can reach ~80%; SFT at 0% → RL makes no progress. So check pass@k before RL — rule of thumb: pass@1<5% → RL likely fails; pass@k<20% → it will struggle.RL은 약하게라도 있는 행동을 키우고 나쁜 행동을 누르고 스타일을 다듬을 뿐, SFT 모델이 한 번도 보이지 않는 능력은 만들 수 없다. 정답이 한 번도 안 나오면 보상과 advantage가 모두 0이라 gradient가 없기 때문이다. 수학 정답률 10%인 SFT는 RL로 ~80%까지 가지만 0%면 제자리다. 그래서 RL 전에 pass@k를 확인한다. pass@1<5%면 실패하기 쉽고 pass@k<20%면 고전한다.

11System Architecture & Infrastructure at ScaleSystem Architecture & Infrastructure at Scale

RLHF is a systems problem as much as an algorithm: unlike SFT (one model, one forward-backward), it holds four models at once and runs a rollout→score→train loop across dozens-to-hundreds of GPUs. This is the longest chapter (11.1–11.15); here are the load-bearing parts.RLHF는 알고리즘만큼이나 시스템 문제다. 모델 하나로 forward-backward를 도는 SFT와 달리, 네 모델을 동시에 띄우고 수십~수백 GPU에서 rollout→채점→학습 루프를 돈다. 가장 긴 장(11.1–11.15)이라 핵심만 추린다.

11.2 — Parallelism strategies병렬화 전략

DDP replicates the full model per GPU, syncs gradients via ring-AllReduce (near-linear to ~64 GPUs; never use the legacy single-process DataParallel). TP (Megatron) splits weight matrices — 2 AllReduce per transformer layer, so it's intra-node only (over InfiniBand the 160 AllReduce/forward of a 70B would add ~640 ms, longer than the compute); constraint: #heads must divide the TP degree. SP splits the sequence dim for LayerNorm/Dropout, reusing TP's communication (AllReduce ≡ ReduceScatter+AllGather just reordered) → pure memory win (~59 GB/GPU on 70B), always enable with TP. PP splits layers into stages; cost is the bubble (P−1)/(P+M−1) → need M≥10(P−1) micro-batches; 1F1B scheduling bounds activation memory. FSDP/ZeRO-3 shards params+grads+optimizer (1/N each), reconstructing full tensors on the fly — 70B drops from 1120 to ~140 GB/GPU, at the cost of ~3× DDP's communication (2 AllGather + 1 ReduceScatter).DDP는 GPU마다 모델을 통째로 복제하고 ring-AllReduce로 gradient를 맞춘다(~64 GPU까지 거의 선형. DataParallel은 쓰지 않는다). TP(Megatron)는 가중치 행렬을 쪼갠다. 레이어당 AllReduce가 2회라 노드 안에서만 쓴다. InfiniBand로 넘기면 70B forward 한 번의 AllReduce 160회가 ~640 ms를 더한다. head 수가 TP 차수로 나눠떨어져야 한다. SP는 LayerNorm/Dropout의 시퀀스 차원을 쪼개되 TP 통신을 재배열해 쓰므로(AllReduce ≡ ReduceScatter+AllGather) 추가 통신 없이 메모리만 아낀다(70B에서 ~59 GB/GPU). 11.3 — The generation bottleneck (roofline)생성 병목 (roofline)

RLHF rollouts are autoregressive generation, which is memory-bandwidth bound, not compute bound — which is why generation dominates RLHF wall-clock. On an A100 (312 TFLOPS, 2 TB/s) the roofline crossover is 156 FLOP/byte. Single-stream 70B generation reads all 140 GB of weights to make 140 GFLOPs/token → arithmetic intensity = 1 FLOP/byte = 156× below the roofline → ~0.6% of peak (the GPU is 99.4% idle waiting on memory), and token rate = 2 TB/s ÷ 140 GB = 14.3 tok/s. The fix is batching (read weights once for many sequences) plus an optimization stack: vLLM+PagedAttention 2–4×, continuous batching 1.5–2×, speculative decoding 2–3×, INT8/FP8 weights 2×.rollout은 자기회귀 생성이라 메모리 대역폭이 병목이고, 그래서 RLHF 시간을 지배한다. A100(312 TFLOPS, 2 TB/s)의 roofline 교차점은 156 FLOP/byte다. 70B 단일 스트림은 토큰마다 가중치 140 GB를 읽고 140 GFLOPs를 계산하니 1 FLOP/byte, 교차점의 156분의 1이다. 피크의 ~0.6%만 쓰고(99.4%는 메모리 대기), 2 TB/s ÷ 140 GB = 14.3 tok/s다. 해법은 배칭과 최적화 스택이다. vLLM+PagedAttention 2–4×, continuous batching 1.5–2×, speculative decoding 2–3×, INT8/FP8 가중치 2×.

11.4–11.5 — Decoupled architecture & weight sync분리형 아키텍처 & 가중치 동기

Systems like DeepSpeed-Chat and OpenRLHF split generation, scoring, and training into independently scalable clusters because the hardware profiles conflict: generation is memory-bandwidth bound (wants fast HBM) while training is compute bound (wants tensor cores). Decoupling lets you scale each separately, use a stateless (fault-tolerant) generation cluster, run mixed precision (INT8 gen / BF16 train), and — the big win — overlap generation(step N+1) with training(step N) for a 30–40% speedup. Fresh weights reach the generation cluster periodically; staleness is fine because PPO's clip was designed for off-policy data (~2% quality loss at 50-step staleness; async streaming <1%).DeepSpeed-Chat, OpenRLHF는 생성·채점·학습을 별도 클러스터로 나눈다. 생성은 메모리 대역폭, 학습은 연산이 병목이라 맞는 하드웨어가 다르다. 나누면 따로 확장하고, 생성 클러스터를 무상태로 두고, INT8 생성/BF16 학습처럼 정밀도를 섞을 수 있다. 가장 큰 이득은 N+1스텝 생성과 N스텝 학습을 겹쳐 30–40% 빨라지는 것이다. PPO clip이 off-policy 데이터를 견디도록 설계돼서 가중치가 조금 늦게 도착해도 괜찮다(50스텝 staleness에 ~2% 손실, 비동기 스트리밍이면 <1%).

"PPO's clipped objective was designed for off-policy data!"

11.15 — The RL optimizer mantraRL optimizer 만트라

RL needs different optimizer settings from SFT because its data is non-stationary (the policy makes its own data) and its gradients are spiky. The recipe: small LR (10–100× smaller than SFT — 1e-6 for PPO/GRPO, 5e-7 for DPO), no weight decay (the KL term already regularizes; WD fights it), constant schedule (RL has no fixed horizon), FP32 master weights (BF16-only "reliably causes reward collapse after 100–500 steps" because a 7-bit mantissa can't represent 1e-6-relative updates), aggressive gradient clipping (max_grad_norm=1.0 — "a single unclipped step with ∥∇∥>50 can undo hundreds of steps"), and β₂=0.95 (vs 0.999 — a ~20-step memory adapts faster to the fast-changing landscape).RL은 데이터 분포가 계속 바뀌고 gradient가 뾰족해서 optimizer 설정이 SFT와 다르다. 작은 LR(SFT의 10–100분의 1. PPO/GRPO 1e-6, DPO 5e-7), weight decay 없음(KL 항이 이미 정규화한다), 상수 스케줄, FP32 master 가중치(BF16만 쓰면 "100–500스텝 후 reward 붕괴를 안정적으로 유발"한다. 가수 7비트로는 1e-6 업데이트를 표현 못 한다), 강한 gradient clipping(max_grad_norm=1.0. "∥∇∥>50인 스텝 하나가 수백 스텝을 무를 수 있다"), β₂=0.95(0.999 대신. ~20스텝 기억으로 빨리 적응한다).

"Always use FP32 master weights for RL training. BF16-only … reliably causes reward collapse in PPO/GRPO after 100–500 steps."

12LLM Agentic TrainingLLM Agentic Training

The shift from single-turn chatbots to multi-step agents that act over tools/APIs/environments demands new RL: trajectories of 10–100+ tool calls, external (not preference) feedback, structured actions (JSON/code), and long horizons with sparse rewards. Standard RLHF optimizes single-turn quality; agents must reason over entire trajectories.단일턴 챗봇에서 tool·API·환경을 다루는 다단계 에이전트로 넘어가면 다른 RL이 필요하다. tool call이 10–100+회인 trajectory, 선호가 아닌 외부 피드백, JSON·코드 같은 구조화된 행동, 보상이 sparse한 긴 지평선이 특징이다. 표준 RLHF는 단일턴 품질을 최적화하지만 에이전트는 trajectory 전체를 보고 판단해야 한다.

12.2–12.3 — Trajectory buffers & operational paradigmstrajectory 버퍼 & 운영 패러다임

Classic replay buffers store low-dim tensors; agentic buffers store textual histories. An experience is e_t = (S_t, A_t, R_t, S_{t+1}) where the state is the full context (objective + history + env vars), the action is {text_reasoning, json_tool_call}, and the reward is an external execution signal (tests, compiler, API codes) — usually a single sparse terminal reward. Three ways to use the buffer: (A) self-correction (STaR/Reflexion — save failures, generate a textual critique, retry); (B) off-policy exploration (filter for successful, efficient, diverse trajectories, train only on those); (C) RAG over experiences (the buffer as a vector DB — retrieve the top-k similar successful runs as few-shot demos; zero training).에이전트 버퍼는 텐서가 아니라 텍스트 이력을 저장한다. 경험 e_t = (S_t, A_t, R_t, S_{t+1})에서 상태는 목표·이력·환경 변수를 담은 문맥, 행동은 {text_reasoning, json_tool_call}, 보상은 테스트·컴파일러·API 코드 같은 외부 신호다(보통 끝에 한 번). 쓰는 방식은 셋이다. (A) 자기교정(STaR/Reflexion: 실패를 저장하고 비평을 만들어 재시도), (B) off-policy 탐험(좋은 trajectory만 골라 학습), (C) 경험 RAG(비슷한 성공 런을 few-shot으로 검색. 학습 없음).

12.8 — State of the art: GRPO + verifiable rewards + turn-level credit최신: GRPO + 검증 보상 + 턴 단위 credit

The field converges on on-policy policy gradients + fine-grained credit assignment. GRPO is the dominant baseline (no critic → saves 50% memory, which matters when trajectories are 32K–128K tokens; natural fit for binary verifiable rewards). PPO still wins in highly stochastic environments where a step-level value head helps (at 2× memory). The core problem is sparse reward — 20 actions then one failed test punishes all 20 equally — and two fixes dominate: RLVR (reward at deterministic intermediate checkpoints: bash compiles +0.1, SQL returns rows +0.1, final tests pass +1.0 → accelerates learning 3–5× vs sparse-only) and multi-turn trajectory slicing (replay the successful prefix, assign negative reward only to the first divergent step). Alternatives: iterative STaR (offline, avoids RL instability), Reinforcement World-Model Learning (reward predicting the semantic consequence of actions → mitigates reward hacking), and LATS (search-time compute).이 분야는 on-policy policy gradient + 세밀한 credit 할당으로 모이고 있다. GRPO가 주류다. critic이 없어 메모리를 50% 아끼는데 trajectory가 32K–128K 토큰이면 이 차이가 크다. 확률성이 높은 환경에서는 단계별 value head 덕에 PPO가 여전히 앞선다(메모리 2×). 핵심 문제는 sparse 보상이다. 행동 20개 뒤 테스트 하나가 실패하면 20개가 똑같이 벌을 받는다. RLVR은 중간 체크포인트에 보상을 줘(bash 컴파일 +0.1, SQL 행 반환 +0.1, 최종 통과 +1.0) 학습을 3–5× 앞당기고, 멀티턴 trajectory slicing은 성공한 prefix를 재생하고 처음 갈라진 단계에만 음의 보상을 준다. 대안으로 반복 STaR, 강화 세계모델 학습, LATS가 있다.
