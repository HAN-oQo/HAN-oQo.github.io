vLLM announces vime — a simple, stable RL framework on vLLM rollouts enginesJun 9

vLLM's latest post (Jun 9) introduces vime, an RL post-training framework that connects slime's training stack with vLLM rollouts for a simple, stable, efficient pipeline. It extends vLLM's recent push to be the rollout backbone for reinforcement learning, after Native RL APIs and the bitwise-consistent train/inference work. For teams doing RLHF or agentic RL, using one engine for both generation and training removes a whole class of train-inference mismatch bugs.

vLLM의 최신 글(6/9)은 vime를 소개한다 — slime 학습 스택과 vLLM 롤아웃을 연결해 단순·안정·효율적 파이프라인을 제공하는 RL 사후학습 프레임워크다. Native RL API와 비트와이즈 일치 학습/추론 작업에 이어, 추론 엔진을 강화학습 롤아웃의 중추로 만드는 최근 흐름을 잇는다. RLHF·에이전트 RL 팀에게 생성과 학습에 같은 엔진을 쓰면 학습-추론 불일치 버그 부류 전체가 사라진다.

Problem문제 정의Quantizing the KV cache cuts the memory cost of long-context inference but introduces approximation error, and that error is usually uncontrolled — you find out it mattered only when an answer is wrong. Production systems want the memory savings and a guarantee that quantization never silently degrades a given request beyond a known bound.KV 캐시 양자화는 롱컨텍스트 추론의 메모리 비용을 줄이지만 근사 오차를 들이고, 그 오차는 대개 통제되지 않는다 — 답이 틀리고 나서야 영향을 알게 된다. 프로덕션 시스템은 메모리 절감과, 양자화가 특정 요청을 알려진 한계 너머로 조용히 악화시키지 않는다는 보장을 함께 원한다.
Method방법A tiered KV-cache architecture stores INT8 keys and INT4 values in GPU memory while retaining the FP16 originals in system RAM. Using error decomposition it derives per-step error bounds at runtime; when the certified bound for a step is safe it uses the quantized cache, and when it isn't it deterministically falls back to the FP16 originals — so quality is certified, not hoped for.계층형 KV 캐시 아키텍처가 INT8 키와 INT4 값을 GPU 메모리에 두고 FP16 원본은 시스템 RAM에 유지한다. 오차 분해로 런타임에 스텝별 오차 한계를 유도해, 인증된 한계가 안전하면 양자화 캐시를 쓰고 그렇지 않으면 결정적으로 FP16 원본으로 폴백한다 — 품질을 바라는 게 아니라 인증한다.
Results결과The memory footprint of low-bit KV quantization with a runtime-certified error guarantee and a deterministic fallback path — giving operators the savings of INT4/INT8 KV without an uncontrolled accuracy risk on hard requests.저비트 KV 양자화의 메모리 절감을, 런타임 인증 오차 보장과 결정적 폴백 경로와 함께 제공한다 — 어려운 요청에서 통제 불가능한 정확도 위험 없이 INT4/INT8 KV의 이득을 운영자에게 준다.
Summary요약Quantize the cache, but certify the error each step — and keep an FP16 safety net in RAM for when the bound says "not safe."캐시는 양자화하되 스텝마다 오차를 인증 — 한계가 "안전하지 않다"고 하면 RAM의 FP16 안전망으로.

Method방법DualScale combines phase-aware placement (assigning prefill and decode work to suit each phase) with dynamic voltage/frequency scaling (DVFS): it raises clocks where they cut latency on the critical path and lowers them where headroom exists, tuning the GPU operating point separately for the prefill and decode phases under the request's SLO.DualScale은 단계 인지 배치(각 단계에 맞춰 prefill·decode 작업을 배정)와 동적 전압/주파수 스케일링(DVFS)을 결합한다 — 임계 경로에서 지연을 줄이는 곳은 클럭을 올리고 여유가 있는 곳은 내려, 요청 SLO 하에서 prefill·decode 단계별로 GPU 동작점을 따로 조정한다.
