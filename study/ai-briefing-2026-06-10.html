NVIDIA Dynamo Snapshot — CRIU-based fast startup, 21× faster cold start DynamoJun 5

On Jun 5 NVIDIA released Dynamo Snapshot, which uses CRIU and cuda-checkpoint to freeze and restore single-GPU inference workers on Kubernetes instead of cold-starting them from scratch. A key trick is unmapping the KV cache before checkpoint (cuMemUnmap/cuMemRelease), shrinking the artifact for Qwen3-0.6B on a B200 from ~190 GiB to ~6 GiB; in a PoC over 8 striped NVMe SSDs it cut gpt-oss-120b startup 21× to under 5s. The experimental release supports single-GPU vLLM and SGLang workloads — for autoscaling and spot/preemptible fleets, sub-5s restores change the economics of scaling inference up and down.

6/5 NVIDIA가 Dynamo Snapshot을 공개했다 — CRIU와 cuda-checkpoint로 단일 GPU 추론 워커를 처음부터 콜드스타트하는 대신 동결·복원한다. 핵심 트릭은 체크포인트 전에 KV 캐시를 언맵(cuMemUnmap/cuMemRelease)해, B200의 Qwen3-0.6B 아티팩트를 ~190 GiB에서 ~6 GiB로 줄인 것 — 8개 스트라이프 NVMe SSD PoC에서 gpt-oss-120b 시작을 21× 단축해 5초 미만으로 만들었다. 실험적 릴리스는 단일 GPU vLLM·SGLang 워크로드를 지원하며, 오토스케일링·스팟/선점형 플릿에서 5초 미만 복원은 추론을 켜고 끄는 경제성을 바꾼다.

SparDA — Sparse Decoupled Attentionsparse attn2606.04511

Problem문제 정의In long-context inference the KV cache grows linearly with sequence length, so attending to all of it is infeasible. Sparse attention helps, but it still pays a heavy cost just to select which KV blocks each query should attend to — and that selection sits on the critical path of every layer, so the GPU stalls waiting for "which blocks?" before it can compute "attend to them." On very long prompts this selection-plus-fetch overhead, not the attention math itself, becomes the bottleneck.롱컨텍스트 추론에서 KV 캐시는 시퀀스 길이에 비례해 선형으로 커져 전체를 어텐션하기가 비현실적이다. 희소 어텐션이 돕긴 하지만, 각 쿼리가 어느 KV 블록에 주목할지 선택하는 데만도 큰 비용이 들고, 이 선택이 매 레이어의 임계 경로에 놓여 GPU가 "어느 블록?"을 기다린 뒤에야 "그 블록을 어텐션"할 수 있다. 매우 긴 프롬프트에서는 어텐션 연산 자체가 아니라 이 선택+페치 오버헤드가 병목이 된다.
Method방법SparDA decouples block selection from attention computation. A lightweight forecast step runs during layer L and predicts which KV blocks layer L+1 will need before L finishes. With that prediction the system prefetches the required blocks from host memory to the GPU while layer L is still computing, so by the time L+1 starts its KV is already resident. Selection stops being a serial stall and becomes work that overlaps with useful compute.SparDA는 블록 선택과 어텐션 연산을 분리한다. 가벼운 예측 단계가 레이어 L 처리 중에 돌면서, L이 끝나기 전에 다음 레이어 L+1이 필요로 할 KV 블록을 미리 예측한다. 이 예측으로 레이어 L이 아직 연산 중인 동안 필요한 블록을 호스트 메모리에서 GPU로 프리페치해, L+1이 시작될 때 KV가 이미 상주해 있다. 선택이 직렬 멈춤이 아니라 유용한 연산과 겹치는 작업이 된다.
Results결과By hiding both selection and host→GPU transfer latency behind layer compute, SparDA shrinks the long-context attention bottleneck and improves decode throughput, while preserving the accuracy of dense and prior sparse-attention baselines (the same blocks get attended to — they are just fetched earlier).선택과 호스트→GPU 전송 지연을 모두 레이어 연산 뒤로 숨겨, 롱컨텍스트 어텐션 병목을 줄이고 디코드 처리량을 높이면서, 밀집·기존 희소 어텐션 베이스라인의 정확도를 유지한다(결국 같은 블록을 어텐션하되 더 일찍 가져올 뿐이다).
Summary요약"Predict next layer's KV needs and prefetch early." A decoupled, lookahead design that turns sparse-attention selection from a per-layer stall into overlapped, hidden work."다음 레이어의 KV 수요를 예측해 미리 프리페치." 희소 어텐션의 선택을 레이어마다의 멈춤이 아니라 겹쳐서 숨겨지는 작업으로 바꾸는 분리·선행형 설계.

RedKnot — Head-aware KV reuse & SegPagedAttentionlong-context2606.06256
RedKnot (arXiv 2606.06256) ↗RedKnot (arXiv 2606.06256) ↗
Problem문제 정의For long contexts the KV cache — not the weights — dominates GPU memory and bandwidth, capping how many requests you can serve at once. But heads are not equal: empirically only some attention heads genuinely look far back, while many mostly attend to recent tokens. Storing the full history for every head therefore wastes memory on heads that never use it.긴 컨텍스트에서는 가중치가 아니라 KV 캐시가 GPU 메모리·대역폭을 지배해 동시 처리 가능한 요청 수를 제한한다. 그런데 헤드는 평등하지 않다 — 경험적으로 일부 어텐션 헤드만 실제로 먼 과거를 보고 다수는 대체로 최근 토큰에 주목한다. 따라서 모든 헤드에 전체 히스토리를 저장하는 것은, 그것을 쓰지도 않는 헤드에 메모리를 낭비하는 셈이다.
