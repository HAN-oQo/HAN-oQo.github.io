the one line한 줄 요약 VLA inference is LLM inference turned inside out — batch-1, latency-bound, inside a real-time control loop. This plan climbs from "what is a VLA" to that reality in seven rungs, OpenVLA as the anchor, one reading + one study note per rung. VLA 추론은 LLM 추론을 뒤집은 것 — batch-1, 지연 바운드, 실시간 제어 루프 안. 이 계획은 "VLA란 무엇인가"에서 그 현실까지 일곱 칸을 오른다. OpenVLA를 앵커로, 칸마다 읽기 하나 + 스터디 노트 하나.

Terms you'll need first먼저 필요한 용어

📖 VLA (Vision-Language-Action)📖 VLA (Vision-Language-Action)

A policy that maps camera image(s) + a language instruction (+ the robot's own joint/pose state) to actions. In practice: a vision-language model (VLM) with an added "action head."카메라 이미지 + 언어 지시(+ 로봇 자신의 관절/자세 상태)를 행동으로 매핑하는 정책. 실제로는 비전-언어 모델(VLM)에 "행동 헤드"를 붙인 것.

📖 Action space📖 행동 공간

What the model outputs each step — e.g. end-effector deltas (Δx, Δy, Δz + rotation + gripper open/close) or joint angles. Low-dimensional (~7 numbers), and often continuous.모델이 매 스텝 내놓는 것 — 예: 엔드이펙터 델타(Δx, Δy, Δz + 회전 + 그리퍼 개폐)나 관절 각도. 저차원(~7개 수), 보통 연속값.

📖 Control loop & frequency📖 제어 루프 · 주파수

A robot re-senses and re-acts many times a second (≈5–50 Hz). The model must return an action within that budget — so inference latency is a hard constraint, not a throughput nicety.로봇은 초당 수차례 다시 감지·행동한다(≈5–50 Hz). 모델은 그 예산 안에 행동을 내야 한다 — 그래서 추론 지연이 처리량 편의가 아니라 하드 제약.

📖 Action chunking📖 행동 청킹

Predict a short sequence of H future actions in one forward pass, then execute them open-loop. Amortizes the expensive inference over many control steps (π0 uses H=50).한 번의 forward로 미래 H개 행동을 예측하고 open-loop로 실행. 비싼 추론을 여러 제어 스텝에 분산(π0는 H=50).

📖 Tokens vs diffusion/flow📖 토큰 vs 디퓨전/플로우

Two ways to emit actions: discretize into tokens and decode autoregressively (RT-2, OpenVLA; FAST compresses these), or generate continuous actions by iterative denoising — diffusion (Octo) / flow matching (π0). Different latency shapes.행동을 내놓는 두 방식: 토큰으로 이산화해 자기회귀 디코드(RT-2, OpenVLA; FAST가 이를 압축), 또는 반복 디노이징으로 연속 행동 생성 — 디퓨전(Octo)/플로우 매칭(π0). 지연 형태가 다르다.

📖 Batch-1 latency regime📖 batch-1 지연 영역

One robot = one request stream. Unlike LLM serving (batch many prompts for throughput), VLA inference is usually single-stream and latency-bound — so the optimization surface is a different one from the rest of this site.로봇 하나 = 요청 스트림 하나. LLM 서빙(처리량 위해 여러 프롬프트 배치)과 달리 VLA 추론은 대개 단일 스트림·지연 바운드 — 이 사이트의 다른 글과는 최적화 지형이 다르다.

editor's note — why this order편집자 주 — 이 순서인 이유 This is our roadmap, not a claim from any one paper. The spine is a single contrast: VLA inference is batch-1 and latency-bound inside a control loop — the mirror image of the throughput-batched LLM serving the rest of this site dissects. We anchor on OpenVLA (rungs 1–2) because it's open and reproducible, then let each later rung add exactly one new idea — chunking → action representation → edge → scale — so a gap in understanding is easy to localize. Hands-on is deferred by choice; when you want it, rungs 2 and 5 are the natural first Docker experiments on an MI250 node (run OpenVLA's predict_action, measure action-decode latency). 이건 우리의 로드맵이지 특정 논문의 주장이 아니다. 척추는 하나의 대조: VLA 추론은 제어 루프 안에서 batch-1·지연 바운드 — 이 사이트가 해부하는 처리량 배치 LLM 서빙의 거울상. OpenVLA에 앵커를 두는 건(1–2칸) 열려 있고 재현 가능하기 때문 — 이후 각 칸이 정확히 새 개념 하나씩만 더한다: 청킹 → 행동 표현 → 엣지 → 확장, 그래서 이해의 빈틈을 짚기 쉽다. 실습은 선택에 따라 뒤로 미룸; 원할 때 2·5칸이 MI250 노드에서의 자연스러운 첫 Docker 실험(OpenVLA predict_action 실행, 행동 디코드 지연 측정).
