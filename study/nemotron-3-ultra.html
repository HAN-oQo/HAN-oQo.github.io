Nemotron 3 Ultra — model report Nemotron 3 Ultra — 모델 정리

NVIDIA's 550B-total / 55B-active open MoE model with a hybrid Mamba-Attention backbone — built to win on the throughput-per-accuracy frontier for long-running agents. ~6× the inference throughput of comparable open LLMs at on-par accuracy, with a 1M-token context. NVIDIA가 공개한 총 550B·활성 55B MoE 모델. 하이브리드 Mamba-Attention 백본으로 정확도 대비 처리량 경계를 끌어올려, 장시간 도는 에이전트용으로 설계됐다. 동급 오픈 LLM 대비 추론 처리량 약 6배, 정확도는 동등, 컨텍스트 1M 토큰.

MoE · active paramsMoE · 활성 파라미터

A Mixture-of-Experts routes each token to a few of many experts. "550B-A55B" = 550B weights stored, only 55B used per token → big-model accuracy at small-model compute.MoE는 토큰마다 다수 전문가 중 몇 개에만 라우팅한다. "550B-A55B" = 저장된 가중치 550B, 토큰당 55B만 사용 → 큰 모델 정확도를 작은 모델 연산량으로.

Hybrid Mamba-Attention하이브리드 Mamba-Attention

Mostly Mamba-2 (constant per-step decode cost, tiny cache) with a few Attention layers as "global anchors". Cuts KV-cache and attention cost → faster decode.대부분 Mamba-2(스텝당 디코드 비용 일정, 캐시 작음)에 Attention 몇 층만 "전역 앵커"로. KV-cache와 attention 비용을 줄여 디코드가 빨라진다.

LatentMoE

NVIDIA's MoE variant: trades hidden-dim width to buy more routed experts at the same inference cost → better accuracy per FLOP/param than standard granular MoE.NVIDIA의 MoE 변형: 히든 차원 폭을 줄이는 대신 같은 추론 비용으로 라우팅 전문가 수를 늘림 → 일반 granular MoE보다 FLOP/파라미터당 정확도↑.

NVFP4

NVIDIA's 4-bit float (E2M1) with block scaling. Here used for pre-training itself (not just post-quant) — claimed the largest-scale stable FP4 training to date.NVIDIA의 4비트 부동소수(E2M1) + 블록 스케일링. 여기선 사후 양자화가 아니라 사전학습 자체에 사용 — 역대 최대 규모의 안정적 FP4 학습이라 주장.

MTP · speculative decodeMTP · 추측 디코딩

Multi-Token Prediction heads let the model draft several tokens at once and verify them — native speculative decoding, no separate draft model.Multi-Token Prediction 헤드가 여러 토큰을 한 번에 초안 작성 후 검증 — 별도 draft 모델 없는 네이티브 추측 디코딩.

MOPD

Multi-teacher On-Policy Distillation: 10+ domain-specialist teachers give dense token-level guidance on the student's own rollouts. The headline post-training trick.Multi-teacher On-Policy Distillation: 10개+ 도메인 특화 교사가 학생의 자기 롤아웃에 토큰 단위로 조밀하게 지도. 이 모델의 핵심 후학습 기법.

1What it is & where it sits의미와 오픈 모델 내 위치

Nemotron 3 Ultra is the largest, final model of NVIDIA's Nemotron 3 family. Its thesis is not "highest accuracy at any cost" but best accuracy per unit of inference throughput — the metric that matters when an LLM is no longer a chatbot but an agent that runs for hours writing code or doing research.

Nemotron 3 Ultra는 NVIDIA Nemotron 3 패밀리의 가장 크고 마지막 모델입니다. 핵심 주장은 "무조건 최고 정확도"가 아니라 추론 처리량 단위당 최고 정확도 — LLM이 챗봇이 아니라 몇 시간씩 코드를 짜고 리서치하는 에이전트가 될 때 진짜 중요해지는 지표죠.

headline claim (Abstract)핵심 주장 (초록) "achieves up to ∼6× higher inference throughput as compared to state-of-the-art publicly available LLMs while attaining on-par accuracy." Concretely (8K in / 64K out, max throughput): 5.9× vs GLM-5.1-754B-A40B, 4.8× vs Kimi-K2.6-1T-A32B, 1.6× vs Qwen-3.5-397B-17B. "동급 최고 오픈 LLM 대비 추론 처리량 최대 약 6배, 정확도는 동등." 구체적으로(8K 입력 / 64K 출력, 최대 처리량): GLM-5.1-754B-A40B 대비 5.9배, Kimi-K2.6-1T-A32B 대비 4.8배, Qwen-3.5-397B-17B 대비 1.6배.

Position among open models. The report benchmarks it against the strongest open releases of its generation — its base model is claimed to beat DeepSeek v3.2, Mistral Large 3, Kimi-K2 and GLM-4.5 bases; the post-trained model is compared head-to-head with MiniMax-2.7, GLM-5.1 (744B-A40B), Kimi-K2.6 (1T-A32B), Qwen-3.5 (397B-17B), and DeepSeek-v4 Pro/Flash (Table 10). Independent confirmation: Artificial Analysis scores it 48 on its Intelligence Index — the new leader among US open-weight models (Gemma 4 31B = 39, Nemotron 3 Super = 36, gpt-oss-120b = 33) but still behind China's Kimi K2.6 = 54. So it sits as a top-tier open agentic model whose distinguishing axis is efficiency, not a raw-accuracy crown.

오픈 모델 내 위치. 리포트는 동세대 최강 오픈 모델들과 비교합니다 — 베이스 모델은 DeepSeek v3.2·Mistral Large 3·Kimi-K2·GLM-4.5 베이스를 능가한다고 주장하고, 후학습 모델은 MiniMax-2.7·GLM-5.1(744B-A40B)·Kimi-K2.6(1T-A32B)·Qwen-3.5(397B-17B)·DeepSeek-v4 Pro/Flash와 정면 비교됩니다(Table 10). 독립 검증: Artificial Analysis 지능 지수 48점 — 미국 오픈웨이트 중 1위(Gemma 4 31B 39, Nemotron 3 Super 36, gpt-oss-120b 33)이지만 중국 Kimi K2.6 54점에는 뒤집니다. 즉 "원시 정확도 1위"가 아니라 효율을 차별점으로 둔 최상위 오픈 에이전트 모델이라는 자리매김입니다.

"Our pretrained base model achieves significantly higher accuracy than other publicly available base models, such as DeepSeek v3.2, Mistral Large 3, Kimi-K2, and GLM-4.5."

2Architecture, size, active params구조 · 크기 · 활성 파라미터

Same architecture as Nemotron 3 Super, scaled to 550B total / 55B active per token. The backbone is a repeating stack of Mamba-2 layers and LatentMoE layers, with sparse Attention layers placed periodically as global anchors. 108 layers total.

Nemotron 3 Super와 같은 구조를 총 550B·토큰당 활성 55B로 키웠습니다. 백본은 Mamba-2 층과 LatentMoE 층이 반복되고, 그 사이에 Attention 층이 전역 앵커로 주기적으로 박힌 구조입니다. 총 108층.

Backbone schematic (Tech Report Table 1 + Figure 2). The Mamba-heavy mix is what makes decode cheap; attention layers stay sparse.백본 개략도 (테크 리포트 Table 1 + Figure 2). Mamba 위주 구성이 디코드를 싸게 만들고, attention 층은 희소하게 유지된다.

3Training — what's unusual학습 — 특이한 점

Pre-training: FP4 at 20T tokens사전학습: 20T 토큰을 FP4로

20 trillion text tokens, with a Warmup-Stable-Decay schedule and a two-phase data split: 15T tokens of broad/diverse data, then 5T of high-quality data (~75% / 25%). The unusual part is precision: the model is pre-trained natively in NVFP4 (4-bit float), not merely quantized afterward — using E2M1 weights with 2D block quantization, Random Hadamard Transforms on inputs, and stochastic rounding on gradients. The report calls it "the largest-scale demonstration of stable and accurate NVFP4 training to date," with the BF16-vs-NVFP4 training-loss gap under 0.4%. (~15% of the network — 16 layers — plus Mamba/latent/QKV/MTP/embedding projections stay in higher precision.)

텍스트 20조 토큰, Warmup-Stable-Decay 스케줄, 2단계 데이터 분할: 다양·광범위 15T → 고품질 5T(약 75% / 25%). 특이점은 정밀도입니다 — 사후 양자화가 아니라 NVFP4(4비트 부동소수)로 네이티브 사전학습했습니다. E2M1 가중치 + 2D 블록 양자화, 입력에 Random Hadamard Transform, 그래디언트에 stochastic rounding. 리포트는 "역대 최대 규모의 안정적·정확한 NVFP4 학습"이라 칭하며 BF16 대비 학습 손실 격차 0.4% 미만이라고 합니다. (신경망의 약 15% — 16개 층 — 과 Mamba/latent/QKV/MTP/임베딩 투영은 고정밀 유지.)

"NVFP4 layers use the E2M1 datatype with two-dimensional block quantization on weights, Random Hadamard Transforms on inputs to wgrad, and stochastic rounding on gradients. … the largest-scale demonstration of stable and accurate NVFP4 training to date."

— Tech Report §2.2 · 원문 보기 (PDF)

Post-training: the MOPD pipeline후학습: MOPD 파이프라인

The pipeline is SFT → unified RLVR → MOPD (×2 cycles) → MTP boosting. The standout is MOPD (Multi-teacher On-Policy Distillation): more than ten domain-specialist teacher models (software engineering, office/GDPval-style tasks, search, terminal use, tool-calling, safety, chat, STEM, competitive coding…) each give dense token-level guidance on the student's own on-policy rollouts. Unlike offline distillation on a fixed dataset, the student generates, and the right teacher scores each token in-flight (asynchronously, with PPO-style clipping). A one-time "MOPD warmup" SFT first aligns the student's output distribution with the teachers' to avoid mismatch.

파이프라인은 SFT → 통합 RLVR → MOPD(×2 사이클) → MTP 부스팅입니다. 백미는 MOPD(Multi-teacher On-Policy Distillation): 10개가 넘는 도메인 특화 교사 모델(소프트웨어 엔지니어링, 오피스/GDPval형 업무, 검색, 터미널, 툴콜, 안전, 챗, STEM, 경쟁 코딩 등)이 각자 학생 자신의 on-policy 롤아웃에 토큰 단위로 조밀하게 지도합니다. 고정 데이터셋 기반 오프라인 증류와 달리, 학생이 생성하면 해당 도메인 교사가 토큰마다 즉석 채점(비동기, PPO식 clipping). 사전에 1회 "MOPD warmup" SFT로 학생 출력 분포를 교사와 맞춰 미스매치를 줄입니다.

Reasoning budget control추론 예산 제어

Three modes — reasoning-off / regular / medium-effort. Medium-effort uses ~2.5× fewer tokens than regular for ~7% accuracy drop. A deployment knob for cost vs quality.세 모드 — off / regular / medium-effort. medium은 regular 대비 토큰 ~2.5배 절약, 정확도 ~7% 하락. 비용 대 품질 배포 노브.

MTP boostingMTP 부스팅

A final head-only distillation that updates just the MTP head (backbone frozen), exposing it to inference-like noise → higher speculative acceptance length.백본을 얼린 채 MTP 헤드만 갱신하는 마지막 증류. 추론 유사 노이즈에 노출시켜 추측 디코딩 수용 길이↑.

Also notable: GenRM (a generative reward model built on Ultra) drives RLHF and curbs reward hacking; RLVR spans ~16 verifiable environments in one unified stage. Two pre-training divergences (~8T, ~16T tokens) forced an FP32 gradient-reduction fix and an early LR anneal, cutting the horizon to 20T.그 외: GenRM(Ultra 기반 생성형 보상 모델)이 RLHF를 이끌며 reward hacking을 억제하고, RLVR은 검증 가능한 환경 ~16종을 한 단계로 통합. 사전학습 중 발산 2회(~8T, ~16T 토큰)로 FP32 그래디언트 합산 수정과 조기 LR 감쇠를 적용, 학습 지평을 20T로 단축.

reproducibility caveat (NVIDIA's own repo)재현성 단서 (NVIDIA 자체 레포) "Fully open" has limits the repo states itself: the multi-iteration MOPD/RL post-training is not reproducible from released artifacts — "the intermediate checkpoints it depends on have not been open-sourced" (docs/nemotron/ultra3/README.md). The 1M long-context phase data is also not released. So you get the weights, recipe, and most data — but not a one-click rebuild of the post-trained model. "완전 공개"에는 레포 스스로 밝히는 한계가 있습니다: 다회 반복 MOPD/RL 후학습은 공개된 산출물만으로 재현 불가 — "그게 의존하는 중간 체크포인트가 공개되지 않았다"(docs/nemotron/ultra3/README.md). 1M 장문 단계 데이터도 미공개. 즉 가중치·레시피·데이터 대부분은 받지만, 후학습 모델을 원클릭으로 재구축할 수는 없습니다.

4Compute profile & inference points연산적 특성 · 추론 포인트

Decode-heavy throughput (Tech Report §1, Fig. 15). Ultra runs on TensorRT-LLM; others on vLLM, best-of with/without spec decoding.디코드 위주 처리량 (테크 리포트 §1, Fig. 15). Ultra는 TensorRT-LLM, 나머지는 vLLM, 추측 디코딩 유무 중 최고값.

Why so fast — and the catch. The win is on decode: Mamba-2's per-step cost is constant in sequence length and its state is tiny, so long-output generation is cheap and KV-cache stays bounded; MoE gives accuracy per active param; MTP adds native speculative decoding. But on prefill it actually trails — at 50K in / 2K out it carries a ~3.2× FLOPs penalty vs Qwen-3.5 (55B vs 17B active). On decode-heavy 8K/64K the gap shrinks to ~1.39× (total params) and Ultra pulls ahead. So the throughput story is decode-bound, long-output, agentic workloads.

왜 빠른가 — 그리고 함정. 강점은 디코드입니다: Mamba-2는 스텝당 비용이 시퀀스 길이와 무관하게 일정하고 상태가 작아 긴 출력 생성이 싸고 KV-cache가 제한됩니다. MoE는 활성 파라미터당 정확도를, MTP는 네이티브 추측 디코딩을 더합니다. 그러나 prefill에선 오히려 뒤집니다 — 50K 입력 / 2K 출력에선 Qwen-3.5 대비 FLOPs ~3.2배 불리(활성 55B vs 17B). 디코드 위주 8K/64K에선 격차가 ~1.39배(총 파라미터)로 줄며 Ultra가 앞섭니다. 즉 처리량 우위는 디코드 바운드·긴 출력·에이전트 워크로드에서의 이야기입니다.

"a hybrid Mamba-2 stack with sparse global Attention anchors, which gives sub-quadratic sequence-length scaling during prefill and a bounded KV-cache footprint during decode."

— Tech Report §5 · 원문 보기 (PDF)

Things to watch when serving서빙할 때 신경 쓸 점

One NVFP4 ckpt, two GPU gensNVFP4 1개로 두 세대 GPU

Blackwell runs native FP4 (W4A4); Hopper falls back to W4A16 (FP4 weights, BF16 activations) since it lacks FP4 tensor cores. They deliberately did not ship W4A8.Blackwell은 네이티브 FP4(W4A4), Hopper는 FP4 텐서코어가 없어 W4A16(FP4 가중치+BF16 활성)로 폴백. W4A8은 일부러 내지 않음.

Two caches, not one캐시가 둘이다

KV cache is FP8; the Mamba SSM cache is FP16 (stochastic rounding). Below ~64K seq length the Mamba cache is actually larger than the FP8 KV cache — budget for both.KV 캐시는 FP8, Mamba SSM 캐시는 FP16(stochastic rounding). ~64K 길이 이하에선 Mamba 캐시가 FP8 KV보다 크다 — 둘 다 메모리 예산에 넣을 것.

Speculation is a knob추측 디코딩은 노브

MTP draft length helps at small batch / low latency, hurts at large batch — tune it. Single-user decode peaked at ~2.89× at draft length 6.MTP draft length는 소배치·저지연에 유리, 대배치엔 불리 — 튜닝 대상. 단일 사용자 디코드는 draft length 6에서 ~2.89배 정점.

Fits an 8-GPU node (NVFP4)8-GPU 노드에 적재 (NVFP4)

BF16 ≈ 1.1 TB (won't fit one node). NVFP4 ≈ 330 GiB on a TP=8 H100 node leaves ~40 GiB/GPU; FP8 ≈ 540 GiB leaves only ~10.BF16 ≈ 1.1 TB(단일 노드 불가). NVFP4 ≈ 330 GiB는 TP=8 H100 노드에서 GPU당 ~40 GiB 여유, FP8 ≈ 540 GiB는 ~10뿐.

Frameworks: TensorRT-LLM (headline throughput) and vLLM (prefill-decode disaggregation — which must move both KV and Mamba state — plus MoE chunking, both landed upstream). editor's note — for our inference work편집자 주 — 우리 추론 작업 관점 The interesting bit for serving is the two-cache reality: a hybrid model means KV-cache and Mamba state, and disaggregation/prefix-caching machinery built for pure-attention models needs hybrid-aware changes (the report had to patch vLLM for exactly this). And the prefill/decode asymmetry (trails on prefill, wins on decode) is a clean argument for P/D disaggregation — put Ultra where output is long. 서빙 관점의 포인트는 캐시가 둘이라는 현실: 하이브리드 모델은 KV-cache와 Mamba 상태를 함께 가지며, 순수 attention 모델용 분리 서빙·prefix 캐싱 장치는 하이브리드 대응 수정이 필요합니다(리포트도 바로 이걸 위해 vLLM을 패치). 그리고 prefill/decode 비대칭(prefill 열세, decode 우세)은 P/D 분리 서빙의 깔끔한 근거 — 출력이 긴 곳에 Ultra를 둘 것.
