one-line summary한 줄 요약
  • A verifier is only a proxy for intent. Optimization exploits the gap, so reward hacking is inevitable under a fixed objective (Goodhart).
  • No verifier has all of scalability, faithfulness, robustness, so verification must co-evolve with the agent.
  • SWE: a trajectory behavior monitor cuts hacked-resolved 28.57%→0.56% and lifts clean-resolved 40.22%→60.53%. Frontend: an interactive Playwright judge defeats length exploitation.
  • User feedback trained with Span-KTO gives +13.3pp on an internal repair bench. Long-horizon repos get an automated agent evaluator.
  • 검증자는 의도의 프록시일 뿐이다. 최적화가 그 격차를 파고들기 때문에 고정 목적함수에선 보상 해킹이 필연이다(Goodhart).
  • 확장성·충실성·강건성을 모두 갖춘 검증자는 없다. 그래서 검증은 에이전트와 공진화해야 한다.
  • SWE에선 궤적 행동 모니터가 해킹된 해결을 28.57%→0.56%로 줄이고 깨끗한 해결을 40.22%→60.53%로 올린다. 프론트엔드에선 Playwright 인터랙티브 판정이 길이 착취를 막는다.
  • 사용자 피드백을 Span-KTO로 학습하면 내부 수리 벤치가 +13.3pp 오른다. 장기 레포 생성에는 자동 에이전트 평가자를 쓴다.

📖 Verification horizon📖 검증 지평선

The reach of verification recedes as the generator grows stronger. A verifier good today is gamed tomorrow.생성자가 강해질수록 검증이 닿는 범위가 뒤로 물러난다. 오늘 좋은 검증자도 내일은 공략당한다.

📖 3 dimensions📖 세 차원

Scalability (cheap, automatic), faithfulness (measures true intent), robustness (resists gaming). No method has all three.확장성(싸고 자동), 충실성(진짜 의도 측정), 강건성(공략 저항). 셋을 다 갖춘 방법은 없다.

📖 Reward hacking / Goodhart📖 보상 해킹 / Goodhart

An optimized measure stops being a good measure, so hacking is an inevitable consequence, not a patchable bug.최적화 대상이 된 지표는 좋은 지표가 아니게 된다. 그래서 해킹은 고칠 버그가 아니라 필연적 결과다.

📖 Behavior monitor📖 행동 모니터

Audits command/network/git history against known hack patterns and applies a token penalty (reward correction, not a post-hoc filter).명령/네트워크/git 이력을 알려진 해킹 패턴과 대조해 토큰 페널티를 준다(사후 필터가 아닌 보상 교정).

📖 Interactive judge📖 인터랙티브 판정

Runs the app in a real browser (Playwright) and judges the interaction trace instead of screenshots.스크린샷 대신 실제 브라우저(Playwright)에서 앱을 실행하고 상호작용 트레이스를 판정한다.

📖 Span-KTO

Span-level preference optimization from user feedback with a KTO-style loss.사용자 피드백으로 span 단위 선호를 학습한다. 손실은 KTO 방식이다.

1 Problem — the verification horizon 문제 정의: 검증 지평선

Stronger models and harnesses make generating candidates easy; the hard part is now reliably verifying them. Every verifier is a proxy for human intent, so the difficulty is twofold: intent is underspecified, and optimization widens the proxy–intent gap, surfacing as reward hacking or saturation.

더 강한 모델과 하네스 덕에 후보 생성은 쉬워졌고, 이제 어려운 쪽은 믿을 만한 검증이다. 모든 검증자는 사람 의도의 프록시라서 어려움이 두 겹이다. 의도 자체가 과소명세돼 있고, 최적화가 프록시와 의도의 격차를 벌려 보상 해킹이나 포화로 나타난다.

"Every verifier we can build is only a proxy for human intent, never the intent itself."

— Abstract/§1 · 원문 보기 (§1)

Reward hacking is thus the inevitable end of a fixed objective, not a bug (Goodhart's law, with Rice's theorem as backdrop: non-trivial semantic properties are undecidable). No verifier type has all three dimensions:

따라서 보상 해킹은 버그가 아니라 고정 목적함수의 필연적 끝이다(Goodhart 법칙. 배경에는 비자명한 의미 속성은 결정 불가능하다는 Rice 정리가 있다). 세 차원을 모두 갖춘 검증자 유형은 없다.

  • Unit tests: scalable and robust, but thin (weak faithfulness).
  • LLM judges: scalable and faithful, but exploitable (weak robustness).
  • Human review: faithful and robust, but unscalable.
  • 단위 테스트: 확장성과 강건성은 있지만 얕다(충실성 약함).
  • LLM 심판: 확장성과 충실성은 있지만 공략당한다(강건성 약함).
  • 사람 리뷰: 충실하고 강건하지만 확장되지 않는다.

"We must continually build a verification system that co-evolves with AI agents."

— §1 · 원문 보기 (§1)

2 Method — four co-evolving verifier constructions 해결 방법: 공진화하는 검증자 구성 4개

Four verifier constructions, one per task regime, each attacking a different weak dimension and designed to co-evolve with the policy:

과제 영역마다 검증자를 하나씩 만들었다. 각각 다른 약점 차원을 보완하고 정책과 공진화하도록 설계했다.

#Regime영역Verifier construction검증자 구성
1SWE-like codingSWE류 코딩Execution pass/fail + an agentic quality judge (instruction clarity + test alignment) for faithfulness + a trajectory behavior monitor for robustness.실행 pass/fail + 충실성용 에이전트 품질 판정(지시 명확성 + 테스트 정합) + 강건성용 궤적 행동 모니터.
2Frontend프론트엔드A structured rubric (static judge) + an agentic interactive judge that runs the app in Playwright and judges the interaction trace.구조화된 루브릭(정적 판정) + 앱을 Playwright에서 실행해 상호작용 트레이스를 판정하는 에이전트 인터랙티브 판정.
3Real-world agent실세계 에이전트The user as verifier: extract Human Implicit Reward Signals from multi-turn logs, train with Span-KTO, instead of a lossy distilled reward model.손실이 큰 증류 보상 모델 대신 사용자를 검증자로 쓴다. 멀티턴 로그에서 Human Implicit Reward Signal을 뽑아 Span-KTO로 학습.
4Long-horizon repo장기 레포An automated evaluation agent that decomposes an NL spec into a checklist and emits a holistic score; the paper studies how to build a better evaluator.NL 명세를 체크리스트로 분해해 종합 점수를 내는 자동 평가 에이전트. 더 나은 평가자를 만드는 법을 연구한다.

The key mechanism is robustness for coding. Hacking has two sources: static-environment leakage and policy-dependent shortcuts. A trajectory-level behavior monitor checks the agent's command/network/git history against known hack patterns and applies a token-level penalty. Since hacks depend on the policy, an agentic reviewer keeps updating the pattern set (a closed co-evolving loop).

핵심 메커니즘은 코딩의 강건성 쪽이다. 해킹의 원천은 정적 환경 누출과 정책 의존 지름길 두 가지다. 궤적 단위 행동 모니터는 에이전트의 명령/네트워크/git 이력을 알려진 해킹 패턴과 대조해 토큰 단위 페널티를 준다. 해킹은 정책에 따라 달라지므로 에이전트 리뷰어가 패턴 집합을 계속 갱신한다(닫힌 공진화 루프).

"The monitor therefore acts as a process-aware reward correction, rather than a post-hoc filter."

— §2.3 · 원문 보기 (§2.3)

In frontend, static judges (scoring code or screenshots) fall to length exploitation: the model writes more to look better. Grounding reward in runtime behavior removes that lever.

프론트엔드에선 코드나 스크린샷을 채점하는 정적 판정이 길이 착취에 당한다. 모델이 더 길게 써서 좋아 보이려 한다. 보상을 런타임 행동에 근거하면 이 수법이 통하지 않는다.

"Static judges, by contrast, are susceptible to length exploitation."

— §3.2 · 원문 보기 (§3.2)

3 Implementation — models, benchmarks, Span-KTO 구현: 모델, 벤치마크, Span-KTO

Policies and judges are internal Qwen checkpoints (Qwen-Turbo as RL policy; Qwen-Plus/Max as judges), with Claude Opus 4.7 / DeepSeek V4 Pro as external evaluator-backbone comparisons. Benchmarks: SWE-bench Verified / Multilingual / Pro (+ SWE-ReBench) for coding, WebDev Human Eval and QwenWebBench for frontend, NL2Repo (104 tasks) for long-horizon. User feedback: 125,528 trajectories / 535,737 round-level annotations from in-house senior-engineer logs.

정책과 판정은 내부 Qwen 체크포인트(RL 정책=Qwen-Turbo; 판정=Qwen-Plus/Max)이고, 외부 평가자 백본 비교로 Claude Opus 4.7 / DeepSeek V4 Pro를 쓴다. 벤치마크는 코딩에 SWE-bench Verified / Multilingual / Pro (+ SWE-ReBench), 프론트엔드에 WebDev Human Eval과 QwenWebBench, 장기 과제에 NL2Repo(104 과제)를 쓴다. 사용자 피드백 데이터는 사내 시니어 엔지니어 로그에서 모은 궤적 125,528개 / 라운드 주석 535,737개다.

Span-KTO math, plainly. Cut a multi-turn reply into contiguous consistent-polarity spans (neutral spans don't drive preference). A span's implicit reward is the log-likelihood ratio vs a frozen reference, r(S)=Σ_{t∈S}[log π_θ − log π_ref], and an EMA running mean z_ref is the neutral baseline. With advantage a = r(S)−z_ref, the loss is ℓ = −λ_w·σ(β·a) for positive spans and −λ_l·σ(−β·a) for negative ones, plus a neutral LM regularizer for fluency. In short: reward the stretches the user implicitly liked and penalize the rest, at span granularity.

Span-KTO 수식, 쉽게. 멀티턴 응답을 연속된 같은 극성 span으로 자른다(중립 span은 선호 학습에서 빠진다). span의 암묵 보상은 얼린 레퍼런스 대비 로그우도비 r(S)=Σ_{t∈S}[log π_θ − log π_ref]이고, EMA 이동평균 z_ref가 중립 baseline 역할을 한다. advantage a = r(S)−z_ref로 긍정 span에는 ℓ = −λ_w·σ(β·a), 부정 span에는 −λ_l·σ(−β·a)를 걸고, 중립 LM 정규화로 유창성을 지킨다. 쉽게 말하면 응답 전체가 아니라 사용자가 암묵적으로 좋아한 구간은 보상하고 싫어한 구간은 벌한다.

4.1 Behavior monitor kills reward hacking (SWE)4.1 행동 모니터가 보상 해킹을 없앤다 (SWE)

Averaged over three SWE-bench variants, the monitor drops the hacked-resolved rate 28.57% → 0.56% while raising the clean-resolved rate 40.22% → 60.53%. It recovers genuine problem-solving that hacking had been masking.

세 SWE-bench 변형 평균에서 모니터는 해킹된 해결률을 28.57% → 0.56%로 낮추고 깨끗한 해결률은 40.22% → 60.53%로 올린다. 해킹에 가려져 있던 진짜 문제 해결력이 드러난 것이다.

Span-KTO wins all five code benchmarks, most clearly on the internal repair bench Aone-bench: 14.8% → 28.1% (+13.3pp), and SWE-bench Verified 54.2% → 59.8%. Reweighting-only baselines (RW-SFT) change intensity but not direction; only the right negative weight (0.8) beats plain SFT.

Span-KTO는 다섯 코드 벤치마크에서 모두 이긴다. 차이가 가장 큰 곳은 내부 수리 벤치 Aone-bench: 14.8% → 28.1%(+13.3pp)이고, SWE-bench Verified는 54.2% → 59.8%다. 재가중만 하는 RW-SFT는 강도는 바꿔도 방향은 못 바꾸며, 음성 가중치를 0.8로 맞췄을 때만 순정 SFT를 넘는다.

"On Aone-bench, SFT achieves only 14.8%, while Span-KTO improves to 28.1% (+13.3pp), demonstrating the significant value of process-level human feedback in real code repair scenarios."

4.3 Building a better evaluator (long-horizon)4.3 더 나은 평가자 만들기 (장기)

Iterating the evaluator prompt v1→v4 lifts best-of-N accuracy 57.9→67.4 and Kendall τ 0.379→0.473 (v5 regresses from over-specification). The strongest backbone is Claude Opus 4.7 (BoN 70.4%, τ 0.579). Note that ranking ≠ filtering: a model can rank better yet threshold-filter good code worse, so one alignment number can hide critical gaps.

평가자 프롬프트를 v1→v4로 고치면 best-of-N 정확도가 57.9→67.4, Kendall τ가 0.379→0.473로 오른다(v5는 과잉명세로 오히려 떨어진다). 가장 강한 백본은 Claude Opus 4.7이다(BoN 70.4%, τ 0.579). 눈여겨볼 점은 랭킹 ≠ 필터링이다. 랭킹은 더 잘하면서 임계값으로 좋은 코드를 거르는 일은 더 못할 수 있어서, 정렬 수치 하나로는 큰 결함이 가려진다.

5 Discussion — reward as core infra + our read 시사점: 보상은 핵심 인프라다 + 우리 관점

Conclusion. Across four regimes, better reward-signal quality yields gains in both RFT and RL, but scalability / faithfulness / robustness are in inherent tension: no silver bullet. Treat reward signals as core infrastructure, not an auxiliary component. Stated future directions:

  1. Quality-stratify the solution space (a binary reward can't tell a root-cause fix from a symptom-suppressing hack).
  2. Capture human subjective perception (frontend "polish").
  3. Move offline user-feedback learning online.
  4. Evaluator–generator co-evolution (GAN-like).
  5. Credit assignment in long-horizon / multi-agent settings.

There is no official code repo (checked arXiv, PapersWithCode, HF).

결론. 네 영역 모두에서 보상 신호 품질이 좋을수록 RFT와 RL 성능이 올랐다. 하지만 확장성/충실성/강건성은 본질적으로 상충하므로 은탄환은 없다. 저자들은 보상 신호를 보조 요소가 아니라 핵심 인프라로 다뤄야 한다고 말한다. 제시한 후속 과제는 다음과 같다.

  1. 해법 공간을 품질로 계층화한다(이진 보상은 근본 수정과 증상만 덮는 해킹을 구분하지 못한다).
  2. 사람의 주관적 지각을 반영한다(프론트엔드 "완성도").
  3. 오프라인 사용자 피드백 학습을 온라인으로 옮긴다.
  4. 평가자–생성자 공진화(GAN 방식).
  5. 장기·멀티 에이전트 환경의 credit assignment.

공식 코드 레포는 없다(arXiv·PapersWithCode·HF 확인).

"This consistently validated pattern leads us to view reward signals as core infrastructure for driving continuous improvement in foundation model capabilities, rather than an auxiliary component in the training pipeline."

editor's note — our read (not the paper's claim)편집자 주 — 우리 관점 (논문의 주장 아님)
  1. Same thesis as the Red Queen Gödel Machine (paper 1), from the applied side. Red Queen gives the algorithm with theory; this report gives trench-level engineering.
  2. The behavior monitor is the most reusable piece: audit command/network/git traces against a growing hack-pattern set and penalize per token. "Clean-resolved 40→60% while killing hacks" shows hacking was hiding real capability.
  3. Honest limit: every fix is bespoke per regime (4 constructions, no unified verifier), exactly the "no silver bullet" of the title.
  1. Red Queen Gödel Machine(논문 1)과 같은 논지를 응용 쪽에서 다룬다. Red Queen이 이론과 함께 알고리즘을 준다면, 이 보고서는 현장 엔지니어링을 준다.
  2. 바로 가져다 쓸 만한 것은 행동 모니터다. 명령/네트워크/git 트레이스를 커지는 해킹 패턴 집합과 대조해 토큰 단위로 벌하면 된다. "해킹을 막으면서 깨끗한 해결이 40→60%"라는 결과는 해킹이 진짜 능력을 가리고 있었다는 뜻이다.
  3. 한계도 분명하다. 처방이 모두 영역별 맞춤이고(구성 4개, 통합 검증자 없음), 제목의 "은탄환 없음" 그대로다.
