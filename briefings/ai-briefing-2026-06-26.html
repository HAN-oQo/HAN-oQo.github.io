Problem문제 정의Long-context LLM inference is increasingly bottlenecked by the memory footprint and decoding cost of the key-value cache, which grows with sequence length. Generic eviction policies throw away tokens that turn out to matter, hurting answer quality on long inputs.롱컨텍스트 LLM 추론은 시퀀스 길이에 비례해 커지는 KV 캐시의 메모리 점유와 디코딩 비용에 점점 더 발목을 잡힌다. 범용 제거 정책은 정작 중요한 토큰을 버려 긴 입력에서 답변 품질을 해친다.
Method방법CompressKV identifies "Semantic Retrieval Heads" — attention heads that reliably attend to the prompt's initial and final tokens plus the semantically important mid-context evidence — and uses their attention to select which tokens' KV pairs to retain, on GQA-based models. Compression is therefore guided by what the model actually retrieves, not by position or recency heuristics alone.CompressKV는 프롬프트의 처음·끝 토큰과 의미상 중요한 중간 근거에 일관되게 주목하는 어텐션 헤드인 "시맨틱 검색 헤드"를 찾아, 그 어텐션으로 (GQA 기반 모델에서) 어떤 토큰의 KV를 보존할지 고른다. 따라서 압축이 위치·최근성 휴리스틱이 아니라 모델이 실제로 검색하는 내용에 따라 이뤄진다.
Results결과By retaining the KV of retrieval-relevant tokens, the method keeps long-context accuracy under a tighter cache budget than position-based eviction, making long-context serving cheaper in memory and decode time. The paper frames this as resource-efficient compression for GQA LLMs.검색에 관련된 토큰의 KV를 보존함으로써, 위치 기반 제거보다 더 빠듯한 캐시 예산에서도 롱컨텍스트 정확도를 유지해 메모리·디코드 시간 측면에서 롱컨텍스트 서빙을 더 싸게 만든다. 논문은 이를 GQA LLM을 위한 자원 효율 압축으로 규정한다.
Summary요약Let the model's own retrieval heads decide which KV pairs survive compression, so long-context quality holds under a smaller cache.압축에서 어떤 KV를 남길지 모델 자신의 검색 헤드가 정하게 해, 더 작은 캐시에서도 롱컨텍스트 품질이 유지되게 하라.

Problem문제 정의Speculative decoding accelerates generation by drafting tokens with a small model and verifying them with the target, but the verification step is purely about acceptance — it has no notion of whether the accepted continuation is risky or unsafe. Speed and safety are optimized separately.추측 디코딩은 작은 모델로 토큰을 초안하고 타깃으로 검증해 생성을 가속하지만, 검증 단계는 오로지 수용 여부만 따질 뿐 수용된 연속이 위험·유해한지에 대한 개념이 없다. 속도와 안전이 따로 최적화된다.
Method방법SafeSpec is a safety-aware speculative inference framework that integrates risk estimation directly into the verification process, using dynamic reflective sampling so the verifier weighs both correctness and risk before accepting drafted tokens. Safety becomes part of the accept/reject decision rather than a separate post-filter.SafeSpec은 위험 추정을 검증 과정에 직접 통합한 안전 인식 추측 추론 프레임워크로, 동적 반영 샘플링을 써서 검증기가 초안 토큰을 수용하기 전에 정확성과 위험을 함께 저울질하게 한다. 안전이 별도 사후 필터가 아니라 수용/거부 결정의 일부가 된다.
Results결과The framework aims to keep speculative decoding's latency benefits while reducing the chance of accepting unsafe continuations, i.e., "fast and safe" decoding in a single loop. Risk-aware verification is presented as a drop-in change to the speculative pipeline.이 프레임워크는 추측 디코딩의 지연 이점을 유지하면서 유해한 연속을 수용할 가능성을 줄이는, 즉 한 루프 안의 "빠르고 안전한" 디코딩을 목표로 한다. 위험 인식 검증을 추측 파이프라인에 끼워 넣는 변경으로 제시한다.
Summary요약Make the speculative verifier weigh risk, not just acceptance, so fast drafting doesn't smuggle in unsafe tokens.추측 검증기가 수용 여부만이 아니라 위험까지 따지게 해, 빠른 초안이 유해 토큰을 몰래 들이지 않게 하라.

CacheWeaver: Cache-Aware Evidence Ordering for Efficient Grounded RAG Inference (arXiv 2606.19667, submitted Jun 2026) ↗CacheWeaver: Cache-Aware Evidence Ordering for Efficient Grounded RAG Inference (arXiv 2606.19667, 6월 제출) ↗
Problem문제 정의Retrieval-augmented generation lengthens prompts and raises prefill cost, and prefix caching in engines like vLLM only saves work when requests share the same token prefix. In grounded generation, adjacent queries often retrieve overlapping evidence in different orders, so set overlap never becomes reusable prefix overlap.검색 증강 생성은 프롬프트를 늘려 prefill 비용을 키우고, vLLM 같은 엔진의 접두사 캐싱은 요청들이 동일 토큰 접두사를 공유할 때만 작업을 아낀다. 근거 기반 생성에서는 인접 질의가 겹치는 근거를 서로 다른 순서로 가져오는 경우가 많아, 집합 겹침이 재사용 가능한 접두사 겹침으로 이어지지 못한다.
Method방법CacheWeaver reorders retrieved evidence so that overlapping chunks line up into a shared, cacheable prefix across requests, turning set-level overlap into actual prefix-cache hits. The ordering is chosen with the serving cache in mind rather than purely by relevance rank.CacheWeaver는 검색된 근거를 재정렬해 겹치는 청크가 요청 간 공유·캐시 가능한 접두사로 정렬되게 함으로써, 집합 수준 겹침을 실제 접두사 캐시 적중으로 바꾼다. 순서를 관련도 랭크만이 아니라 서빙 캐시를 염두에 두고 고른다.
Results결과By making retrieved evidence cache-friendly, the method cuts redundant prefill for grounded RAG without changing the answer content, improving efficiency on workloads where queries share evidence. It targets the gap between "same evidence set" and "same token prefix."검색 근거를 캐시 친화적으로 만들어, 답변 내용을 바꾸지 않고도 근거 기반 RAG의 중복 prefill을 줄여 근거를 공유하는 워크로드에서 효율을 높인다. "같은 근거 집합"과 "같은 토큰 접두사" 사이의 간극을 겨냥한다.
Summary요약Order retrieved evidence so overlapping chunks become a shared prefix, turning RAG's set overlap into real prefix-cache hits.검색 근거를 정렬해 겹치는 청크가 공유 접두사가 되게 함으로써, RAG의 집합 겹침을 실제 접두사 캐시 적중으로 바꿔라.

Problem문제 정의Modern GPUs (Hopper, Blackwell) natively support low-bit integer and floating-point formats (INT8/INT4, FP8/FP4) that offer far higher matmul throughput than 16-bit, but uniform 4-bit quantization is hard because a few outlier values blow up the error. Treating all values the same wastes either accuracy or hardware speed.현대 GPU(Hopper·Blackwell)는 16비트보다 훨씬 높은 행렬곱 처리량을 주는 저비트 정수·부동소수 포맷(INT8/INT4·FP8/FP4)을 기본 지원하지만, 소수의 이상치가 오차를 키워 균일 4비트 양자화는 어렵다. 모든 값을 똑같이 다루면 정확도나 하드웨어 속도 중 하나를 잃는다.
Method방법MosaicQuant disaggregates inliers from outliers and quantizes each population appropriately, so the bulk of the weights/activations ride the fast 4-bit path while outliers are handled separately, yielding a "unified" 4-bit scheme. The split is designed to match the native low-bit formats on current GPUs.MosaicQuant은 인라이어와 아웃라이어를 분리해 각 집단을 적절히 양자화함으로써, 대부분의 가중치·활성은 빠른 4비트 경로를 타고 이상치는 따로 처리하는 "통합" 4비트 방식을 만든다. 이 분리는 현 GPU의 기본 저비트 포맷에 맞추도록 설계됐다.
Results결과By isolating outliers, the method keeps accuracy closer to higher precision while still spending most of the matmul in 4-bit, capturing the throughput of native low-bit hardware. It positions inlier/outlier disaggregation as the lever that makes unified 4-bit practical.이상치를 격리함으로써 대부분의 행렬곱을 4비트로 처리하면서도 정확도를 더 높은 정밀도에 가깝게 유지해, 기본 저비트 하드웨어의 처리량을 취한다. 인라이어/아웃라이어 분리를 통합 4비트를 실용화하는 레버로 제시한다.
Summary요약Split the rare outliers out so the common values can ride a fast, accurate unified 4-bit path on Hopper/Blackwell.드문 이상치를 떼어내, 흔한 값들이 Hopper/Blackwell에서 빠르고 정확한 통합 4비트 경로를 타게 하라.
