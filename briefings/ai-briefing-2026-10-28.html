Learning When to Commit: Schedule Distillation for Fast Diffusion Language Modelsdiffusion LLMparallel decodingarXiv:2610.35804
arxiv.org/abs/2610.35804 →

Problem문제 정의Diffusion language models can emit several tokens per round, but they often need many decoding rounds to finish a response. Speed depends not only on which tokens are easy, but on how committing one token makes the remaining positions easier to predict.확산 언어 모델은 한 라운드에 여러 토큰을 낼 수 있지만 응답을 끝내는 데 많은 디코딩 라운드가 필요한 경우가 많다. 속도는 어떤 토큰이 쉬운가뿐 아니라, 한 토큰을 확정하는 일이 나머지 위치의 예측을 얼마나 쉽게 만드는가에도 달려 있다.

Method방법dSpark builds unmasking schedules that favor tokens whose reveal lowers uncertainty elsewhere early in decoding, then distills those schedules into the model for faster parallel sampling. A KL-divergence regularizer helps preserve output quality.dSpark는 초기 디코딩에서 공개했을 때 다른 위치의 불확실성을 줄여 주는 토큰을 우선하는 언마스킹 스케줄을 만든 뒤, 이를 모델에 증류해 더 빠른 병렬 샘플링을 가능하게 한다. KL 발산 정규화로 출력 품질을 유지한다.

Results결과On GSM8K the paper reports speedups of 10.12x on LLaDA-8B-Instruct and 5.12x on Dream-7B-Instruct over baselines while keeping strong task performance, evaluated on math reasoning and code generation.GSM8K에서 기준선 대비 LLaDA-8B-Instruct 10.12배, Dream-7B-Instruct 5.12배의 속도 향상을 보고하며 강한 과제 성능을 유지한다. 평가는 수학 추론과 코드 생성에서 이뤄졌다.

Summary요약Learning which token to reveal first lets a diffusion LLM finish in far fewer decoding rounds.어떤 토큰을 먼저 공개할지 학습하면 확산 LLM이 훨씬 적은 디코딩 라운드로 끝낼 수 있다.

Problem문제 정의Direct FP4 post-training quantization cuts inference cost but still loses accuracy. SVDQuant closes part of the gap with high-precision low-rank corrections, which need many bits per rank and run on the same tensor cores as the main matmul.FP4 사후 양자화는 추론 비용을 줄이지만 정확도 손실이 남는다. SVDQuant는 고정밀 저랭크 보정으로 격차를 일부 메우지만, 보정에 랭크당 많은 비트가 들고 주 행렬곱과 같은 텐서 코어에서 실행된다.

Method방법BiLoCo stores both correction factors as ±1 sign vectors instead of BF16, using 16x less storage per rank-one component. The correction becomes additions and subtractions, so it can run on CUDA cores concurrently with the FP4 tensor-core GEMM, fused into one kernel on a B300.BiLoCo는 두 보정 인자를 BF16 대신 ±1 부호 벡터로 저장해 랭크-1 성분당 저장량을 16배 줄인다. 보정이 덧셈·뺄셈만 필요해 FP4 텐서 코어 GEMM과 동시에 CUDA 코어에서 돌릴 수 있으며, B300에서 단일 융합 커널로 구현했다.

Results결과On LLMs from 4B to 72B parameters it matches or outperforms SVDQuant at the same memory budget. At batch size 1 the fused kernel is at most 11% slower than FP4-only GEMM for ranks up to 512; at rank 128 it is at most 20% slower up to batch size 8.4B~72B 파라미터 LLM에서 같은 메모리 예산으로 SVDQuant와 같거나 더 낫다. 배치 크기 1에서 융합 커널은 랭크 512까지 FP4 단독 GEMM보다 최대 11% 느리고, 랭크 128에서는 배치 8까지 최대 20% 느리다.

Summary요약Sign-vector corrections make low-rank error recovery cheap enough to overlap with the FP4 matmul.부호 벡터 보정 덕분에 저랭크 오차 복구가 FP4 행렬곱과 겹쳐 실행될 만큼 저렴해진다.

Problem문제 정의Most FlashAttention follow-ups target GPUs. Porting PyTorch's CPU FlashAttention kernel to a RISC-V processor with 2KB vector registers reaches only 16.2% of peak floating-point throughput.FlashAttention 후속 연구는 대부분 GPU를 겨냥한다. PyTorch CPU FlashAttention 커널을 2KB 벡터 레지스터의 RISC-V 프로세서로 옮기면 피크 부동소수점 처리량의 16.2%에 그친다.

Method방법The authors trace the loss to row-at-a-time processing, which vectorizes along the head dimension and wastes register width on per-row max and sum reductions, and to register spills from the software exponential. They transpose the score tile and output so queries lie on the contiguous axis, and move the polynomial coefficients into scalar registers.저자들은 손실의 원인을 헤드 차원으로 벡터화하며 행별 max·sum 리덕션에 레지스터 폭을 낭비하는 행 단위 처리와, 소프트웨어 지수 함수의 레지스터 스필로 짚는다. 점수 타일과 출력을 전치해 쿼리가 연속 축에 놓이게 하고, 다항식 계수를 스칼라 레지스터로 옮긴다.

Results결과On silicon, whole-kernel cycles fall 1.84x to 2.08x at head dimension 64, and utilization rises from 16.2% to 29.7% of peak. Problem문제 정의In disaggregated serving, prefill and decode run on separate node pools, so a cache miss costs a network transfer as well as recomputation, and admitting a block to the global cache consumes bandwidth. Poor retention decisions waste both memory and bandwidth.분리형 서빙에서는 프리필과 디코드가 서로 다른 노드 풀에서 돌아 캐시 미스가 재계산뿐 아니라 네트워크 전송 비용도 낳고, 전역 캐시에 블록을 넣는 일도 대역폭을 쓴다. 나쁜 보존 결정은 메모리와 대역폭을 모두 낭비한다.

Method방법KVLearn has a lightweight predictor of reuse probability from prefix features without touching model weights, a retention score that adds recomputation, transfer and storage costs, and an online controller that tunes admission thresholds from hit rate and memory pressure.KVLearn은 모델 가중치를 건드리지 않고 접두 특징으로 재사용 확률을 예측하는 경량 예측기, 재계산·전송·저장 비용을 더한 보존 점수, 적중률과 메모리 압력에 따라 승인 임계값을 조정하는 온라인 제어기로 구성된다.

The Token-Energy Law of LLM Decode: Active Bytes and Realized Time Account for Joules per TokenenergydecodearXiv:2610.28576
arxiv.org/abs/2610.28576 →

Problem문제 정의Estimating the GPU energy spent per generated token while decoding with full context is hard to do from a simple, interpretable model.전체 컨텍스트를 유지한 채 디코딩할 때 토큰당 GPU 에너지를 단순하고 해석 가능한 모델로 추정하기는 어렵다.

Method방법The authors give a formula built from two factors: bytes accessed per output token, split into weights shared across a decoding step and per-request KV-cache data, and the average time to produce each token. Coefficients are calibrated per model and hardware/software setup.저자들은 출력 토큰당 접근 바이트(디코딩 스텝이 공유하는 가중치와 요청별 KV 캐시 데이터로 분리)와 토큰당 평균 생성 시간이라는 두 요인으로 공식을 만든다. 계수는 모델과 하드웨어·소프트웨어 구성별로 보정한다.

Results결과The law explains how batching spreads shared-weight cost, how longer contexts add cache traffic, and how higher throughput cuts the time-based energy share.
