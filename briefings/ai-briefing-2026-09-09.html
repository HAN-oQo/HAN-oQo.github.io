How to Speculate about Uncertainty in Agentic Coding? A Draft-Model Gate Methodspeculative decodinguncertaintyarXiv:2609.05274
arxiv.org/abs/2609.05274 →
Problem문제 정의Software-engineering agents fail expensively: they act confidently wrong, and the mistake only surfaces after the action has been executed and retried. The usual uncertainty signals are unavailable for a deployed black-box agent — no logits, no weights, no activations — and repeated sampling to estimate confidence multiplies the very cost you are trying to avoid.소프트웨어 엔지니어링 에이전트는 자신 있게 틀리고, 그 잘못은 실행 뒤에야 드러난다. 블랙박스 에이전트에서는 로짓·가중치·활성 같은 불확실성 신호를 얻을 수 없고, 반복 샘플링은 비용을 더 늘린다.
Method방법Speculative Uncertainty inverts speculative decoding. Instead of a small draft model proposing tokens for a large model to verify, a small open-weight draft model scores the agent's already-generated trajectory in a single forward pass. The resulting cross-likelihoods are split into phase-aware features — reasoning spans separated from action spans — and calibrated against a verifiable objective, yielding a failure-likelihood score any downstream policy can consume. The paper instantiates one such policy, a pre-execution veto gate.Speculative Uncertainty는 스펙 디코딩을 뒤집는다. 작은 공개 가중치 초안 모델이 에이전트가 이미 생성한 궤적을 순전파 한 번으로 채점하고, 추론 구간과 행동 구간의 교차 우도를 보정해 실패 가능성 점수를 만든다. 이 점수로 실행 전 거부 게이트를 구현했다.
Results결과On Qwen3-Coder-480B and the closed-source Claude 3.5 Sonnet, the veto gate cuts execution error rate by 6–8 percentage points and token cost by 14–19% in deployment. The signal transfers to out-of-distribution benchmarks without retraining and generalizes across agent models.Qwen3-Coder-480B와 Claude 3.5 Sonnet에서 실행 오류율을 6~8%p, 토큰 비용을 14~19% 줄였다. 재학습 없이 분포 밖 벤치마크와 다른 에이전트 모델로도 옮겨 간다.
Summary요약A neat reuse of infrastructure that serving stacks already have. Draft models were built to make decoding cheaper; here the same small model, run backwards over a finished trajectory, becomes a cheap confidence meter for an agent whose internals you cannot see.디코딩을 싸게 하려고 만든 초안 모델을, 내부를 볼 수 없는 에이전트의 값싼 신뢰도 계기로 재활용한 점이 깔끔하다.

Compression Beyond the Uncompressed: A Two-Stage Training Recipe for Soft Context Compression in RAGcontext compressionRAGarXiv:2609.05152
arxiv.org/abs/2609.05152 →
Problem문제 정의Retrieval-augmented generation pays for its knowledge in input length: the retrieved passages inflate the prompt and drag inference down. Soft context compression encodes each document into a much shorter embedding sequence, but almost every such compressor is trained by distilling the outputs of the uncompressed RAG system — which caps it, by construction, at the teacher's performance.RAG는 검색 문단이 프롬프트를 부풀려 추론을 느리게 한다. 소프트 문맥 압축기는 대부분 압축하지 않은 RAG의 출력을 증류해 학습하므로 교사 성능이 상한이 된다.
Method방법DEX-Comp splits training in two. Pure Distillation warm-starts the compression model on only the uncompressed system's correct responses. Hard Exploration then runs reinforcement learning exclusively on the queries the uncompressed RAG gets wrong, which forces the compressor to search for computation patterns suited to compressed representations rather than imitating a teacher that has already failed on those inputs.DEX-Comp은 학습을 둘로 나눈다. Pure Distillation은 교사가 맞힌 응답으로 예열하고, Hard Exploration은 교사가 틀린 질의에서만 강화학습을 돌려 압축 표현에 맞는 계산을 스스로 찾게 한다.
Results결과Across five open-domain QA benchmarks at retrieval depths from top-5 to top-30, DEX-Comp compresses retrieved context by 16x and accelerates inference by 4x–24x, while matching or exceeding the uncompressed RAG baseline. Ablations attribute the gain to both stages, and the pattern holds across datasets and backbones.오픈 도메인 QA 다섯 개, top-5~top-30 검색 깊이에서 문맥을 16배 압축하고 추론을 4~24배 빠르게 하면서 압축하지 않은 RAG와 같거나 낫다. 절제 실험상 두 단계 모두 기여한다.
Summary요약The interesting move is choosing the training data by the teacher's failures. Distillation ceilings are a standard complaint about compression work; this is a concrete recipe for breaking through one, and the 16x figure is the kind that changes what a long-context RAG deployment costs.교사의 실패로 학습 데이터를 고른 것이 핵심이다. 증류의 천장을 뚫는 구체적 레시피이고, 16배 압축은 롱컨텍스트 RAG 비용을 바꿀 수준이다.

BeaconKV: Key-Value Cache Compression Guided by Beacon Queries for Efficient Large Reasoning Model InferenceKV cachereasoningarXiv:2609.04971
arxiv.org/abs/2609.04971 →
Problem문제 정의Large reasoning models get their accuracy from long chain-of-thought traces, and the KV cache grows linearly with that length until it exceeds GPU capacity. Existing compressors estimate which entries matter from recent queries, assuming recent attention predicts future attention. In long-horizon reasoning that assumption breaks: certain decoding steps re-attend to distant earlier context, typically the plan the model formulated at the start of the trace.추론 모델의 KV 캐시는 사고 사슬 길이만큼 자란다. 기존 압축기는 최근 어텐션이 미래 어텐션을 예측한다고 가정하지만, 장기 추론에서는 트레이스 초반의 계획으로 되돌아가는 단계가 있어 이 가정이 깨진다.
Method방법The paper names these Thought Revisiting Tokens and shows that the queries producing them cluster into a small number of similarity groups in embedding space. BeaconKV keeps one compact representative — a beacon query — per cluster, and uses those beacons to anticipate which KV pairs will be revisited, without storing the full query history. It is training-free.논문은 이를 Thought Revisiting Token이라 부르고, 이런 토큰의 쿼리가 소수의 유사도 그룹으로 뭉친다는 것을 보인다. BeaconKV는 클러스터마다 대표 쿼리(비콘) 하나를 두고 어떤 KV 쌍이 재방문될지 예측한다. 학습이 필요 없다.
Results결과Across four open-source large reasoning models and a range of reasoning benchmarks, BeaconKV generally outperforms existing compression methods, reporting up to 5.8x memory reduction while nearly preserving full-cache accuracy and improving throughput by over 4.3x.공개 추론 모델 네 개에서 기존 압축 방법을 대체로 앞서며, 전체 캐시 정확도를 거의 유지한 채 최대 5.8배 메모리 절감과 4.3배 이상 처리량 향상을 보고한다.
Summary요약Recency-based eviction is a reasonable prior for chat and a poor one for reasoning, and this paper isolates exactly why: reasoning traces revisit their own plans. Clustering the revisiting queries into a handful of beacons is a cheap way to keep that structure in the budget without keeping the history.최근성 기반 축출은 채팅에는 맞지만 추론에는 맞지 않는다. 추론 트레이스는 자기 계획을 다시 찾기 때문이다. 비콘 몇 개로 그 구조를 싸게 지킨다.
