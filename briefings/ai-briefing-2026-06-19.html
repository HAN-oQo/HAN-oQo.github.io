TurboServe: Serving Streaming Video Generation Efficiently and Economically (arXiv 2606.19271, submitted Jun 17) ↗TurboServe: Serving Streaming Video Generation Efficiently and Economically (arXiv 2606.19271, 6/17 제출) ↗
Problem문제 정의Streaming video generation is a new serving workload: users hold long-lived sessions that generate video chunk by chunk. Unlike offline video or typical LLM serving, it must preserve session state across active and idle periods, repeatedly reschedule ongoing sessions, and deliver each chunk under a tight latency target — creating two challenges, session-duration heterogeneity and sharply fluctuating user demand.스트리밍 영상 생성은 새 서빙 워크로드다 — 사용자가 청크 단위로 영상을 만드는 장기 세션을 유지한다. 오프라인 영상이나 통상 LLM 서빙과 달리, 활성·유휴 구간에 걸쳐 세션 상태를 보존하고, 진행 세션을 반복 재스케줄하며, 각 청크를 빡빡한 지연 목표 안에 전달해야 한다 — 세션 지속시간 이질성과 급변하는 사용자 수요라는 두 도전을 낳는다.
Method방법TurboServe formulates serving as an online scheduling problem that jointly coordinates session placement and GPU provisioning. A migration-aware placement controller rebalances sessions across GPUs to reduce the maximum per-chunk latency, while a load-driven autoscaler adapts the GPU budget. It adds coalesced chunk processing to batch concurrent sessions, GPU–CPU offloading for suspend/resume, and NCCL-based GPU-to-GPU migration for online rebalancing.TurboServe는 서빙을 세션 배치와 GPU 프로비저닝을 함께 조율하는 온라인 스케줄링 문제로 정식화한다. 마이그레이션 인식 배치 컨트롤러가 청크별 최대 지연을 줄이도록 세션을 GPU 간 재분배하고, 부하 기반 오토스케일러가 GPU 예산을 조정한다. 동시 세션을 배치하는 통합 청크 처리, 일시중단·재개를 위한 GPU–CPU 오프로딩, 온라인 재분배를 위한 NCCL 기반 GPU 간 마이그레이션을 더한다.
Results결과Evaluated on real production traces from Shengshu Technology across multiple model sizes and GPU clusters with up to NVIDIA B-class GPUs, TurboServe — the first serving system built specifically for streaming video generation — improves per-chunk latency and cost efficiency over baseline serving configurations.여러 모델 크기와 NVIDIA B급 GPU까지의 클러스터에서 Shengshu Technology의 실제 프로덕션 트레이스로 평가했을 때, 스트리밍 영상 생성을 위해 처음 만들어진 서빙 시스템 TurboServe는 기준 서빙 구성 대비 청크별 지연과 비용 효율을 개선한다.

EfficientRollout — system-aware self-speculative decoding for RL rolloutsspec decodeRL systems2606.18967
EfficientRollout: System-Aware Self-Speculative Decoding for RL Rollouts (arXiv 2606.18967, submitted Jun 17) ↗EfficientRollout: System-Aware Self-Speculative Decoding for RL Rollouts (arXiv 2606.18967, 6/17 제출) ↗
Problem문제 정의RL post-training of LLMs is bottlenecked by rollout generation, where autoregressive sampling decodes sequentially and a few long-tailed generations dominate completion time.
