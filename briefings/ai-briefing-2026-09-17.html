vLLM — a KV connector and multi-token prediction stop deadlocking each other under cache pressure Sep 16

Sixty-two commits in the window, no new tag. The deadlock fix is the one that matters operationally: with a KV connector active and multi-token prediction enabled, a run could wedge when the KV cache came under pressure. Both features want to hold blocks — the connector while it moves a transfer, MTP while it keeps speculative positions alive — and when free space runs out neither side gives way, so the engine stops rather than degrades. That is the worst failure shape for a serving fleet, because a stall looks like a hang rather than a slowdown. Around it, the frontend layer got measurably more observable: per-request metrics were added to the Responses API, /inference/v1/generate now returns prompt metadata, and Responses gained a cache_write_tokens field for API compatibility and cache-accounting parity. On the DeepSeek V4.1 path the MegaMoE padding and its shared padding workaround were removed, causal image sliding-window attention was restored, and an earlier ROCm change was reverted after it broke DeepSeek-V4 accuracy. The DeepGEMM pin moved, a Cutlass FP8 linear was stopped from claiming support on A100, and a NumPy float leaking into the KV-transfer metrics log was cleaned up. 구간 내 커밋 62개, 새 태그 없음. 운영 관점에서 중요한 것은 교착 수정이다. KV 커넥터가 활성이고 다중 토큰 예측이 켜진 상태에서 KV 캐시가 압박을 받으면 실행이 멈출 수 있었다. 두 기능 모두 블록을 붙잡고 싶어 한다. 커넥터는 전송을 옮기는 동안, MTP는 추측 위치를 살려 두는 동안. 여유 공간이 바닥나면 어느 쪽도 양보하지 않아 엔진이 느려지는 대신 멈춘다. 서빙 설비에서 가장 나쁜 고장 형태다. 멈춤은 감속이 아니라 행으로 보이기 때문이다. 그 주변으로 프런트엔드 계층의 관측 가능성이 눈에 띄게 올라갔다. Responses API에 요청별 지표가 붙었고, /inference/v1/generate가 프롬프트 메타데이터를 돌려주며, Responses에 API 호환과 캐시 회계 일치를 위한 cache_write_tokens 필드가 생겼다. SGLang — a whole DeepSeek-V4.1 kernel series lands at once, and the router learns to drain before it dies Sep 16

Fifty-two commits, no new tag. The striking pattern is that DeepSeek-V4.1 support arrived as a coordinated series rather than a single patch: Hopper FP8 matmul kernels with tuning, RoPE and FP4 packing kernels, compression, KV I/O and metadata kernels, and a candidate indexer library — four separate merges within four hours. Reading them together, the model's serving path is being built bottom-up from the arithmetic outward: pack the weights, move the cache, index the candidates, then tune the matmul. On the router side the change with the clearest production payoff is drain-before-SIGTERM: the router now becomes unready and lets Kubernetes deregister the pod from the service before shutdown proceeds, which is the difference between a rolling update that drops requests and one that does not. The fleet-wide sampling contract reached its third and final part, splicing sampling parameters into a request without re-serializing it, and the gRPC layer exposed native pause status. Dynamo — a Qwen3-VL worker stops serving video under someone else's contract Sep 16

Thirty-three commits in the window; the newest tag is a model-specific pre-release rather than a stable cut. The discovery fix is the interesting one: in a fleet where several workers register for the same model family, a Qwen3-VL worker could end up serving video requests against a contract another worker had published. A contract here is the declaration of what a worker will accept — modalities, limits, routing keys — and honoring the wrong one means the request is dispatched to hardware that never agreed to it. The rest of the window is a run of correctness-under-lifecycle fixes that read like a fleet being hardened: the GPU-model service now honors its configured timeout during initial weights admission, the Python bindings drain bridge tasks before interpreter finalization, the sidecar honors a worker namespace suffix, and the frontend evicts async tokenizer executors when a tokenizer is retired instead of leaving them attached to a dead object. Protocol hygiene got a fix too — KServe datatypes are reported by their wire names rather than their protobuf variant names — and multimodal routing documentation now covers video KV routing explicitly. 구간 내 커밋 33개. 가장 최근 태그는 안정 릴리스가 아니라 모델별 프리릴리스다. 흥미로운 것은 디스커버리 수정이다. 여러 워커가 같은 모델 계열로 등록된 설비에서 Qwen3-VL 워커가 다른 워커가 게시한 계약으로 영상 요청을 처리하게 될 수 있었다. 여기서 계약이란 워커가 무엇을 받아들일지 — 모달리티, 한계, 라우팅 키 — 선언한 것이고, 잘못된 계약을 따른다는 것은 동의한 적 없는 하드웨어로 요청이 배분된다는 뜻이다. 구간의 나머지는 설비를 단단히 죄는 생애주기 정합성 수정들이다. JustFit: 200K-Token LLM Serving on a 24 GiB Laptop with Just-in-Time State Managementlong contextlocal servingarXiv:2609.17475
arxiv.org/abs/2609.17475 →
Problem문제 정의 Capable open-weight models make local coding and reasoning attractive, but a laptop's memory is strained by two things at once: the context and the execution state around it. Weight quantization addresses only the first of those. The practical ceiling is not "will the model load" but "how far can a single request run before the machine runs out of room". 쓸 만한 개방 가중치 모델 덕에 로컬 코딩·추론이 매력적이지만, 노트북 메모리는 두 가지에 동시에 눌린다. 문맥, 그리고 그 주변의 실행 상태다. 가중치 양자화는 그중 첫째만 다룬다. 실질적 천장은 "모델이 올라가는가"가 아니라 "요청 하나가 기계가 자리를 다 쓰기 전에 얼마나 멀리 갈 수 있는가"다.
Method방법 JustFit is an MLX-based inference runtime built from three mechanisms: KVExec for compressed KV execution, PhaseSwap for component residency, and StateTrans for state-preserving serving transitions. Problem문제 정의 Ternary LLMs store every weight as one of {−1, 0, +1}, and the field quotes their cost against the information-theoretic log₂3 ≈ 1.585 bits per weight. Method방법 VC-Attention is training-free and pairs two pieces.
