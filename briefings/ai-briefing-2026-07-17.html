Nemotron-Labs-3-Puzzle-75B-A9B: Compressing Hybrid MoE LLMsMoE servingcompression2607.04371
Nemotron-Labs-3-Puzzle-75B-A9B (arXiv 2607.04371) ↗Nemotron-Labs-3-Puzzle-75B-A9B (arXiv 2607.04371) ↗
Problem문제 정의Interactive deployment must meet throughput, latency, and context-length targets at once. Post-training compression (pruning, quantization, distillation) struggles to preserve accuracy, especially in hybrid MoE, where results depend on which experts and layers are cut.인터랙티브 배포는 처리량·지연·컨텍스트 길이를 한꺼번에 맞춰야 한다. 사후 압축(프루닝·양자화·증류)은 정확도를 지키기 어렵고, 어떤 전문가·레이어를 자르느냐에 민감한 하이브리드 MoE에서 특히 그렇다.
Method방법A compressed Nemotron-3-Super built with Iterative Puzzle plus distillation, RL, quantization, and a Multi-Token-Prediction head. It jointly optimizes heterogeneous MoE pruning and the active-parameter budget for server throughput under high user-throughput constraints.Nemotron-3-Super를 Iterative Puzzle 압축에 증류·RL·양자화·Multi-Token-Prediction 헤드를 더해 줄인 모델이다. 이질적 MoE 프루닝과 활성 파라미터 예산을 함께 최적화해, 높은 사용자 처리량 조건에서 서버 처리량을 끌어올린다.
Results결과On a single 8×B200 node it reaches roughly 2× the server throughput of Nemotron-3-Super at matched user throughput, and on a single H100 it raises 1M-token capacity. Accuracy stays close to the parent across reasoning, coding, multilingual, long-context, and agentic benchmarks.단일 8×B200 노드에서 같은 사용자 처리량 기준 Nemotron-3-Super보다 서버 처리량이 약 2배이고, 단일 H100에선 1M 토큰 용량이 늘었다. 추론·코딩·다국어·장문·에이전트 벤치마크에서 정확도는 부모 모델에 가깝다.
Summary요약Treat hybrid-MoE compression as a joint expert-pruning + active-parameter problem tied to server-throughput goals, and a 75B model can roughly double interactive throughput while holding accuracy.전문가 프루닝과 활성 파라미터를 서버 처리량 목표에 맞춰 함께 풀면, 75B 모델도 정확도를 지키며 인터랙티브 처리량을 2배 가까이 올린다.

From Tensor Buffer to Distributed Memory Hierarchy: A Survey of KV Cache Management for LLM ServingsurveyKV cache2607.02574
KV Cache Management Survey (arXiv 2607.02574) ↗KV 캐시 관리 서베이 (arXiv 2607.02574) ↗
Problem문제 정의The KV cache has become the dominant memory and bandwidth cost of LLM serving, and techniques to manage it are now scattered across many sub-areas. There is a need to organize how KV-cache management has evolved from a simple on-device tensor buffer into a full distributed memory hierarchy spanning GPU, host, and remote tiers.KV 캐시는 LLM 서빙에서 가장 큰 메모리·대역폭 비용이 됐고, 관리 기법은 여러 분야에 흩어져 있다. 온디바이스 텐서 버퍼가 GPU·호스트·원격을 잇는 분산 메모리 계층으로 바뀐 과정을 정리할 필요가 있다.
Method방법The paper is a survey that frames KV-cache management along a "tensor buffer → distributed memory hierarchy" axis, organizing the design space and the relationships between families of techniques (such as compression, eviction, offloading, disaggregation, and reuse/sharing) rather than proposing a new system.새 시스템이 아닌 서베이다. "텐서 버퍼 → 분산 메모리 계층" 축 위에 압축·축출·오프로딩·분리·재사용/공유 같은 기법 계열을 배치한다.
Results결과It offers a shared vocabulary and taxonomy for where KV state should live and move under memory and bandwidth pressure, a common map for placing individual serving papers.메모리·대역폭이 빠듯할 때 KV 상태를 어디에 두고 어떻게 옮길지 논할 공통 어휘와 분류 체계를 준다. 개별 서빙 논문을 한 지도 위에 놓아 볼 수 있다.
Summary요약A map of KV-cache management as a memory-hierarchy problem, from a single tensor buffer up to distributed, disaggregated tiers.KV 캐시 관리를 텐서 버퍼부터 분산·분리 계층까지 이어지는 메모리 계층 문제로 그린 지도다.

Remember When It Matters: Proactive Memory Agent for Long-Horizon Agentsagent memoryagentic RL2607.08716
Proactive Memory Agent (arXiv 2607.08716) ↗Proactive Memory Agent (arXiv 2607.08716) ↗
Problem문제 정의In long-horizon tasks, decision-relevant state is scattered across an ever-expanding trajectory. Task requirements, environment facts, prior attempts, diagnoses, and open subgoals get buried in or pushed out of the context window and stop influencing the next action. The authors call this "behavioral state decay."장기 태스크에선 요구사항·환경 사실·이전 시도·미해결 하위 목표가 긴 궤적 속에 묻히거나 컨텍스트 밖으로 밀려 다음 행동에 반영되지 않는다. 저자들은 이를 "행동 상태 감쇠(behavioral state decay)"라 부른다.
Method방법They study memory as an active intervention rather than passive retrieval. A two-phase memory agent first manages a memory bank, then selects when to transiently inject remembered execution state back into the acting agent. The intervention policy is learned, so the model decides when a memory will help and when to stay silent.메모리를 수동 검색이 아닌 능동 개입으로 본다. 2단계 메모리 에이전트가 메모리 뱅크를 관리하다가, 실행 상태를 행동 에이전트에 잠깐 다시 넣을 시점을 고른다. 이 개입 정책은 학습되며, 기억이 도움이 될 때와 가만히 있는 편이 나을 때를 모델이 판단한다.
Results결과The approach is evaluated on long-horizon agent benchmarks including Terminal-Bench 2.0 and τ²-Bench. The aim is a better intervention policy, not more memory use: the right state at the right step, so it actually changes the action.Terminal-Bench 2.0, τ²-Bench 같은 장기 에이전트 벤치마크로 평가한다. 목표는 메모리를 많이 쓰는 것이 아니라, 맞는 상태를 맞는 단계에 꺼내 실제 행동을 바꾸는 것이다.
Summary요약Make memory a learned, proactive intervention that decides when to re-inject execution state, countering behavioral state decay.실행 상태를 언제 다시 넣을지 학습하는 능동 메모리로 장기 에이전트의 행동 상태 감쇠를 줄인다.

AgentLTL: A Trace-Verification Framework for Measuring, Enforcing, and Training Procedural Compliance in Tool-Using LLM Agentsverificationtool use2607.02599
AgentLTL (arXiv 2607.02599) ↗AgentLTL (arXiv 2607.02599) ↗
Problem문제 정의Tool-using agents must call the right tools in the right order, respect preconditions, and avoid forbidden steps, but there is no general way to state such rules and check them against real execution traces. Ad-hoc string checks and manual review don't scale.도구 사용 에이전트는 맞는 도구를 맞는 순서로 부르고, 전제조건을 지키고, 금지 단계를 피해야 한다. 그런데 이런 규칙을 적고 실제 실행 트레이스와 대조할 일반적인 방법이 없다. 문자열 검사나 수작업 리뷰로는 규모를 감당하지 못한다.
Method방법AgentLTL is a trace-verification framework that specifies required procedures as formal temporal-logic properties and checks the agent's execution trace against them. The same spec measures compliance, enforces it at runtime, and serves as a training signal.AgentLTL은 요구 절차를 시간논리 속성으로 적고 실행 트레이스를 그에 대조하는 검증 프레임워크다. 같은 명세로 준수도를 재고, 런타임에 강제하고, 학습 신호로도 쓴다.
Results결과One checkable spec covers measurement, runtime enforcement, and training, closing the loop between stating what an agent should do and making it do so.검사 가능한 명세 하나로 측정·강제·학습을 모두 처리해, 해야 할 일을 적는 단계와 실제로 하게 만드는 단계를 잇는다.
Summary요약Write agent procedures as temporal-logic properties over execution traces, then reuse that one spec to measure, enforce, and train procedural compliance.절차를 실행 트레이스 위의 시간논리 속성으로 쓰고, 그 명세를 측정·강제·학습에 그대로 쓴다.
