Nemotron-Labs-3-Puzzle-75B-A9B: Compressing Hybrid MoE LLMsMoE servingcompression2607.04371
Nemotron-Labs-3-Puzzle-75B-A9B (arXiv 2607.04371) ↗Nemotron-Labs-3-Puzzle-75B-A9B (arXiv 2607.04371) ↗
Problem문제 정의Interactive deployment must satisfy strict throughput, latency, and context-length requirements at once. A common route is post-training compression, but existing pruning/quantization/distillation techniques struggle to preserve accuracy — especially for hybrid MoE architectures, where performance is sensitive to which experts and layers are cut.인터랙티브 배포는 엄격한 처리량·지연·컨텍스트 길이 요구를 동시에 만족해야 한다. 흔한 경로는 사후 학습 압축이지만, 기존 프루닝·양자화·증류는 정확도 보존이 어렵다 — 특히 어떤 전문가·레이어를 잘라내느냐에 성능이 민감한 하이브리드 MoE에서 그렇다.
Method방법Puzzle-75B-A9B is a compressed variant of Nemotron-3-Super built with a multi-stage pipeline: the Iterative Puzzle compression framework combined with knowledge distillation, reinforcement learning, quantization, and a Multi-Token-Prediction head. The compression jointly optimizes heterogeneous MoE pruning and active-parameter budget, explicitly targeting server throughput under high user-throughput constraints.Puzzle-75B-A9B는 Nemotron-3-Super의 압축본으로, 다단계 파이프라인으로 구축된다 — Iterative Puzzle 압축 프레임워크에 지식 증류·강화학습·양자화·Multi-Token-Prediction 헤드를 결합. 압축은 이질적 MoE 프루닝과 활성 파라미터 예산을 함께 최적화하며, 높은 사용자 처리량 제약 하의 서버 처리량을 명시적으로 겨냥한다.
Results결과On interactive serving workloads on a single 8×B200 node, Puzzle-75B-A9B reaches roughly 2× higher server throughput than Nemotron-3-Super at matched user-throughput constraints, and in ultra-long-context deployment on a single H100 it increases 1M-token capacity. Across reasoning, coding, multilingual, long-context, and agentic benchmarks it retains strong accuracy relative to the parent despite substantial compression.단일 8×B200 노드의 인터랙티브 서빙에서 Puzzle-75B-A9B는 동일 사용자 처리량 제약에서 Nemotron-3-Super 대비 약 2배 높은 서버 처리량에 도달하고, 단일 H100의 초장문 배포에선 1M 토큰 용량을 늘린다. 추론·코딩·다국어·장문·에이전트 벤치마크 전반에서 상당한 압축에도 부모 모델 대비 강한 정확도를 유지한다.
Summary요약Treat hybrid-MoE compression as a joint expert-pruning + active-parameter problem tied to server-throughput goals, and a 75B model can roughly double interactive throughput while holding accuracy.하이브리드 MoE 압축을 서버 처리량 목표에 결부된 전문가 프루닝+활성 파라미터 공동 문제로 다루면, 75B 모델이 정확도를 지키면서 인터랙티브 처리량을 대략 2배로 늘릴 수 있다.

From Tensor Buffer to Distributed Memory Hierarchy: A Survey of KV Cache Management for LLM ServingsurveyKV cache2607.02574
KV Cache Management Survey (arXiv 2607.02574) ↗KV 캐시 관리 서베이 (arXiv 2607.02574) ↗
Problem문제 정의The KV cache has become the dominant memory and bandwidth cost of LLM serving, and techniques to manage it are now scattered across many sub-areas. There is a need to organize how KV-cache management has evolved from a simple on-device tensor buffer into a full distributed memory hierarchy spanning GPU, host, and remote tiers.KV 캐시는 LLM 서빙의 지배적 메모리·대역폭 비용이 됐고, 이를 관리하는 기법들이 여러 하위 분야로 흩어져 있다. KV 캐시 관리가 단순한 온디바이스 텐서 버퍼에서 GPU·호스트·원격 계층을 아우르는 완전한 분산 메모리 계층으로 어떻게 진화했는지 정리할 필요가 있다.
Method방법The paper is a survey that frames KV-cache management along a "tensor buffer → distributed memory hierarchy" axis, organizing the design space and the relationships between families of techniques (such as compression, eviction, offloading, disaggregation, and reuse/sharing) rather than proposing a new system.이 논문은 새 시스템을 제안하기보다, KV 캐시 관리를 "텐서 버퍼 → 분산 메모리 계층" 축으로 놓고 설계 공간과 기법 계열(압축·축출·오프로딩·분리·재사용/공유 등) 사이의 관계를 정리하는 서베이다.
Results결과By tracing that progression, the survey gives a shared vocabulary and taxonomy for reasoning about where KV state should live and move under memory and bandwidth pressure — useful for placing individual serving papers within a common map.그 전개를 추적함으로써, 서베이는 메모리·대역폭 압력 하에서 KV 상태가 어디에 있고 어떻게 이동해야 하는지를 사고하기 위한 공통 어휘와 분류 체계를 제공한다 — 개별 서빙 논문을 공통 지도 위에 놓는 데 유용하다.
Summary요약A map of KV-cache management as a memory-hierarchy problem, from a single tensor buffer up to distributed, disaggregated tiers.KV 캐시 관리를 단일 텐서 버퍼에서 분산·분리 계층까지의 메모리 계층 문제로 보는 지도.

Remember When It Matters: Proactive Memory Agent for Long-Horizon Agentsagent memoryagentic RL2607.08716
Proactive Memory Agent (arXiv 2607.08716) ↗Proactive Memory Agent (arXiv 2607.08716) ↗
Problem문제 정의In long-horizon tasks, decision-relevant state is scattered across an ever-expanding trajectory. Task requirements, environment facts, prior attempts, diagnoses, and open subgoals get buried deep in the context window or pushed past it, so they fail to influence the next action — a failure the authors call "behavioral state decay."장기 태스크에선 결정에 필요한 상태가 계속 늘어나는 궤적 곳곳에 흩어진다. 태스크 요구·환경 사실·이전 시도·진단·미해결 하위 목표가 컨텍스트 창 깊숙이 묻히거나 밖으로 밀려, 다음 행동에 영향을 못 준다 — 저자들은 이를 "행동 상태 감쇠(behavioral state decay)"라 부른다.
Method방법They study memory as an active intervention rather than passive retrieval. A two-phase memory agent first manages a memory bank, then selects when to transiently inject remembered execution state back into the acting agent. The intervention policy is learned so the model decides when a memory is likely to help the next decision — and when silence is preferable.메모리를 수동적 검색이 아니라 능동적 개입으로 본다. 2단계 메모리 에이전트가 먼저 메모리 뱅크를 관리하고, 이어 기억된 실행 상태를 행동 에이전트에 일시적으로 다시 주입할 시점을 선택한다. 개입 정책은 학습돼, 어떤 기억이 다음 결정에 도움될지 — 그리고 침묵이 나을 때가 언제인지 — 를 모델이 판단한다.
Results결과The approach is evaluated on long-horizon agent benchmarks including Terminal-Bench 2.0 and τ²-Bench. The goal is framed not as maximizing memory usage but as improving the intervention policy — surfacing the right state at the right step so it actually changes the action taken.이 방법은 Terminal-Bench 2.0, τ²-Bench 등 장기 에이전트 벤치마크에서 평가된다. 목표는 메모리 사용량 최대화가 아니라 개입 정책 개선으로 규정된다 — 옳은 상태를 옳은 단계에 드러내 실제로 행동을 바꾸게 한다.
Summary요약Make memory a learned, proactive intervention — decide when to re-inject execution state — to counter behavioral state decay in long-horizon agents.메모리를 학습된 능동 개입으로 만들어 — 실행 상태를 언제 재주입할지 결정 — 장기 에이전트의 행동 상태 감쇠에 맞선다.

AgentLTL: A Trace-Verification Framework for Measuring, Enforcing, and Training Procedural Compliance in Tool-Using LLM Agentsverificationtool use2607.02599
AgentLTL (arXiv 2607.02599) ↗AgentLTL (arXiv 2607.02599) ↗
Problem문제 정의Tool-using LLM agents are expected to follow procedures — call the right tools in the right order, respect preconditions, and avoid forbidden steps — but there is no clean, general way to state such rules and check whether an agent's actual execution trace obeys them. Ad-hoc string checks and manual review don't scale.도구 사용 LLM 에이전트는 절차를 지켜야 한다 — 옳은 도구를 옳은 순서로 호출하고, 전제조건을 존중하며, 금지된 단계를 피해야 한다 — 그러나 그런 규칙을 명시하고 에이전트의 실제 실행 트레이스가 이를 지키는지 확인할 깔끔하고 일반적인 방법이 없다. 임시 문자열 검사와 수작업 리뷰는 확장되지 않는다.
Method방법AgentLTL is a trace-verification framework that specifies required procedures as formal temporal-logic properties and checks the agent's execution trace against them. The same specification is used three ways: to measure compliance, to enforce it at runtime, and to provide a training signal that pushes the agent toward procedurally correct behavior.AgentLTL은 요구 절차를 형식 시간논리 속성으로 명세하고 에이전트의 실행 트레이스를 그에 대조하는 트레이스 검증 프레임워크다. 동일 명세를 세 가지로 쓴다 — 준수도를 측정하고, 런타임에 강제하며, 절차적으로 올바른 행동으로 에이전트를 이끄는 학습 신호로 제공한다.
Results결과By turning procedural rules into checkable temporal-logic properties over traces, the framework offers one consistent artifact for measurement, runtime enforcement, and training — closing the loop between specifying what an agent should do and getting it to actually do so.절차 규칙을 트레이스에 대한 검사 가능한 시간논리 속성으로 바꿈으로써, 프레임워크는 측정·런타임 강제·학습에 쓰이는 하나의 일관된 산출물을 제공한다 — 에이전트가 무엇을 해야 하는지 명세하는 일과 실제로 그렇게 하게 만드는 일 사이의 루프를 닫는다.
Summary요약Write agent procedures as temporal-logic properties over execution traces, then reuse that one spec to measure, enforce, and train procedural compliance.에이전트 절차를 실행 트레이스에 대한 시간논리 속성으로 쓰고, 그 하나의 명세를 측정·강제·학습에 재사용한다.
