vLLM main — MiniMax-M3-MXFP4, a DeepSeek-V4 cudagraph rework (+26.8–27.9% TTFT), and new Rust-frontend endpoints vLLMJun 17

vLLM's main branch merged roughly 60 commits in the window, leaning into MoE quantization and disaggregation plumbing. Highlights include MiniMax-M3-MXFP4 support and FP8 sparse GQA for M3, a DeepSeek-V4 cudagraph optimization that reduces eager-break-during-capture for a reported 26.8–27.9% end-to-end TTFT improvement, a DSv4 FlashInfer sparse-index metadata cache (another ~2–4% TTFT), a Helion fused per-token-quant RMSNorm kernel, and FlashInfer non-gated MoE in bf16. The Rust frontend grew an /abort_requests endpoint, prompt-only completions, and hybrid/external DP load-balancing in the supervised bootstrap, while a KV-connector offloading fix stops the engine blocking to flush offloads when idle. The throughline is squeezing DeepSeek-V4/MiniMax-M3 kernels and maturing the Rust serving frontend.

vLLM의 main 브랜치는 이 구간에 약 60 커밋을 머지하며 MoE 양자화와 분리 서빙 배관에 기울었다. 핵심은 MiniMax-M3-MXFP4 지원과 M3용 FP8 희소 GQA, capture 중 eager-break를 줄여 종단 TTFT를 26.8~27.9% 개선했다고 보고된 DeepSeek-V4 cudagraph 최적화, DSv4 FlashInfer 희소 인덱스 메타데이터 캐시(추가 약 2~4% TTFT), Helion 융합 per-token 양자화 RMSNorm 커널, bf16의 FlashInfer 비게이트 MoE다. Rust 프런트엔드는 /abort_requests 엔드포인트, prompt-only completions, supervised bootstrap의 하이브리드/외부 DP 로드밸런싱을 얻었고, KV 커넥터 오프로딩 수정은 유휴 시 오프로드 flush로 엔진이 막히는 것을 방지한다. 관통 주제는 DeepSeek-V4·MiniMax-M3 커널을 짜내고 Rust 서빙 프런트엔드를 성숙시키는 것이다.

SGLang main — sgl-kernel 0.4.4, non-blocking spec-decode transfers, batched EAGLE replay, GLM-5.2 on Ascend SGLangJun 17

SGLang's main branch (~65 commits in the window) focused on speculative-decoding and decode-path performance. It bumped sgl-kernel/sglang-kernel to 0.4.4, made the spec-decode penalty host-to-device transfer non-blocking and shared the decode cumulate path, made latest_output_ids H2D non-blocking in prepare-for-decode, and batched EAGLE draft/draft-extend replay memcpys via a grouped foreach copy. It also added a cache-hit breakdown to HiCache bench_serving, fixed an EagleDraftExtendInput crash with triton/DP attention, added dflash Gemma-4 support, and landed a GLM-5.2 deployment path on Ascend NPUs. The throughline is shaving per-step host syncs and copy overhead out of the speculative-decoding hot path.

SGLang의 main(이 구간 ~65 커밋)은 추측 디코딩과 디코드 경로 성능에 집중했다. sgl-kernel·sglang-kernel을 0.4.4로 올리고, spec-decode 페널티의 호스트→디바이스 전송을 비차단으로 만들고 디코드 누적 경로를 공유했으며, prepare-for-decode에서 latest_output_ids H2D를 비차단으로 만들고 EAGLE draft·draft-extend 리플레이 memcpy를 grouped foreach copy로 배치화했다. 또한 HiCache bench_serving에 캐시 적중 분해를 추가하고, triton/DP 어텐션에서의 EagleDraftExtendInput 크래시를 고치고, dflash Gemma-4 지원을 더하고, Ascend NPU에 GLM-5.2 배포 경로를 안착시켰다. 관통 주제는 추측 디코딩 핫패스에서 스텝별 호스트 동기화와 복사 비용을 깎아내는 것이다.

SoftMoE — soft differentiable routing for Mixture-of-Experts in LLMsMoE2606.17952
SoftMoE: Soft Differentiable Routing for Mixture-of-Experts in LLMs (arXiv 2606.17952, submitted Jun 16) ↗SoftMoE: Soft Differentiable Routing for Mixture-of-Experts in LLMs (arXiv 2606.17952, 6/16 제출) ↗
Problem문제 정의Sparse MoE scales LLM parameters under a fixed inference budget by activating only a top-k subset of experts. But the discrete top-k operator is not differentiable, which forces a fixed number of active experts per input and wastes compute when some tokens need fewer experts than others.희소 MoE는 상위 k개 전문가만 활성화해 고정 추론 예산 안에서 LLM 파라미터를 키운다. 그러나 이산 top-k 연산자는 미분 불가능해 입력마다 활성 전문가 수가 고정되고, 어떤 토큰이 더 적은 전문가만 필요해도 연산이 낭비된다.
Method방법SoftMoE replaces discrete routing with a truncated soft top-k LapSum relaxation, making expert routing optimizable by gradients. It parameterizes the mean number of active experts per layer and imposes a global budget constraint, so the model learns how to allocate expert capacity across layers while staying fully compatible with autoregressive modeling.SoftMoE는 이산 라우팅을 잘린 소프트 top-k LapSum 완화로 바꿔 전문가 라우팅을 경사로 최적화한다. 레이어별 평균 활성 전문가 수를 파라미터화하고 전역 예산 제약을 부과해, 자기회귀 모델링과 완전히 호환되면서 레이어 간 전문가 용량 배분을 학습한다.
Results결과SoftMoE matches or beats sparse MoE on language modeling and downstream tasks while activating significantly fewer experts, and the learned per-layer allocation turns out to be highly non-uniform rather than the usual fixed top-k.SoftMoE는 훨씬 적은 전문가를 활성화하면서도 언어 모델링과 다운스트림에서 희소 MoE와 동등하거나 더 낫고, 학습된 레이어별 배분은 통상의 고정 top-k와 달리 매우 불균일하게 나타난다.
Summary요약Make routing differentiable and let the model decide how many experts each layer deserves under a global budget.라우팅을 미분 가능하게 만들고, 전역 예산 아래 각 레이어가 몇 개의 전문가를 받을지 모델이 정하게 하라.
Hard top-k vs learned soft budget하드 top-k vs 학습된 소프트 예산
A differentiable relaxation lets gradients tune how many experts each layer activates within one global budget.미분 가능한 완화로 경사가 하나의 전역 예산 안에서 레이어별 활성 전문가 수를 조정한다.
RouteBalance — fused model routing and load balancing for heterogeneous servingserving2606.17949
RouteBalance: Fused Model Routing and Load Balancing for Heterogeneous LLM Serving (arXiv 2606.17949, submitted Jun 16) ↗RouteBalance: Fused Model Routing and Load Balancing for Heterogeneous LLM Serving (arXiv 2606.17949, 6/16 제출) ↗
Problem문제 정의Heterogeneous serving stacks split scheduling into two layers that optimize in isolation: model routers pick a model from quality and cost signals while ignoring instance load, and load balancers optimize queues while ignoring quality. The two never agree, so neither hits the best quality–latency–cost trade-off.이질적 서빙 스택은 스케줄링을 따로 최적화되는 두 계층으로 쪼갠다 — 모델 라우터는 품질·비용 신호로 모델을 고르되 인스턴스 부하를 무시하고, 로드밸런서는 큐를 최적화하되 품질을 무시한다. 둘이 합의하지 못해 품질·지연·비용 절충 어디에도 최적이 못 된다.
Method방법RouteBalance is a serving-aware scheduling layer that fuses both into a single online assignment over concrete model instances, jointly trading off quality, latency, and cost.
