NVIDIA Dynamo Snapshot — CRIU-based fast startup, 21× faster cold start DynamoJun 5

On Jun 5 NVIDIA released Dynamo Snapshot, which uses CRIU and cuda-checkpoint to freeze and restore single-GPU inference workers on Kubernetes instead of cold-starting them. Unmapping the KV cache before checkpoint (cuMemUnmap/cuMemRelease) shrinks the Qwen3-0.6B artifact on a B200 from ~190 GiB to ~6 GiB, and a PoC over 8 striped NVMe SSDs cut gpt-oss-120b startup 21× to under 5s, which changes the economics of autoscaling and spot fleets.

NVIDIA가 6/5 Dynamo Snapshot을 공개했다. 쿠버네티스의 단일 GPU 추론 워커를 콜드스타트하지 않고 CRIU와 cuda-checkpoint로 동결했다가 복원한다. 체크포인트 전에 KV 캐시를 언맵(cuMemUnmap/cuMemRelease)해 B200의 Qwen3-0.6B 아티팩트를 ~190 GiB에서 ~6 GiB로 줄였고, NVMe SSD 8개를 스트라이프한 PoC에서 gpt-oss-120b 시작 시간을 21× 줄여 5초 미만으로 만들었다. 오토스케일링과 스팟 플릿의 비용 계산이 달라진다.

"KV cache unmap via cuMemUnmap and cuMemRelease reduces checkpoint artifact size from ~190 GiB to ~6 GiB for Qwen3-0.6B on a B200… gpt-oss-120b startup time is reduced by 21× to under 5 seconds."— NVIDIA Technical Blog, Jun 5, 2026

Method방법A lightweight "Forecast" projection runs during layer L and predicts which KV blocks layer L+1 needs, so they are prefetched from CPU to GPU while layer L is still computing.가벼운 "Forecast" 프로젝션이 레이어 L 연산 중에 L+1이 쓸 KV 블록을 예측하고, L이 아직 계산하는 동안 CPU에서 GPU로 미리 가져온다.

Problem문제 정의Reused context is rarely contiguous: some ranges are cached, others evicted and recomputed. Method방법Three parts: (1) a Multi-Segment Attention kernel that reads non-contiguous KV directly, (2) eviction that jointly weighs hit rate and position-aware recompute cost, (3) adaptive chunking sized to the latency budget.세 요소로 이뤄진다.
