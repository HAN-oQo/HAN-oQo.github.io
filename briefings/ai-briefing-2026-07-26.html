vLLM v0.26.0 — new Inkling model family stack and a DeepSeek-V4 performance push Jul 25

vLLM cut a v0.26.0 stable release built from 411 commits by 212 contributors. It adds a full support stack for the new Inkling model family (piecewise CUDA-graph support, Hopper FA4 relative attention, MTP-1 speculative decoding, LoRA, ModelOpt NVFP4), and a broad DeepSeek-V4 performance push — a specialized routing kernel (~2.94% E2E TPOT), a 1.5–2× fused_topk_bias kernel, redundant repeat/copy removal, and DSpark speculative decoding on AMD and XPU. It also ships fp32 lm_head via head_dtype for generation accuracy and per-KV-group selectable attention backends.

vLLM이 기여자 212명, 커밋 411개로 v0.26.0 안정판을 냈다. 새 Inkling 계열을 전면 지원하고(구간별 CUDA 그래프, Hopper FA4 상대 어텐션, MTP-1 투기 디코딩, LoRA, ModelOpt NVFP4), DeepSeek-V4 성능도 끌어올렸다. 전용 라우팅 커널(E2E TPOT 약 2.94%), 1.5~2배 빠른 fused_topk_bias, 중복 repeat/copy 제거, AMD·XPU의 DSpark가 들어갔다. head_dtype으로 fp32 lm_head를 쓸 수 있고, KV 그룹마다 어텐션 백엔드를 고를 수 있다.

SGLang v0.5.16 — DSpark confidence-driven speculative decoding and Inkling support Jul 25

SGLang cut v0.5.16 from 574 PRs by 169 contributors. Its headline is DSpark, a new speculative-decoding algorithm that drafts semi-autoregressively in blocks and then sizes each verify window from the draft's own confidence rather than a fixed draft length, reaching 383.7 tok/s at accept length ~5 on DeepSeek-V4-Pro (TP8, B300). It also adds full Inkling support — a 975B-parameter multimodal MoE with 1M-token context that mixes sliding-window, full and Mamba2 linear attention — verified on Blackwell TP4/TP8, H200 and AMD MI350X/MI355X.

SGLang이 기여자 169명, PR 574개로 v0.5.16을 냈다. 핵심인 DSpark는 블록 단위로 준자기회귀 초안을 만들고, 초안의 신뢰도에 따라 검증 윈도 크기를 정한다. DeepSeek-V4-Pro(TP8, B300)에서 수용 길이 약 5, 383.7 tok/s를 냈다. 975B 멀티모달 MoE Inkling(1M 토큰 문맥, 슬라이딩 윈도·풀·Mamba2 선형 어텐션 혼합)도 지원하며 Blackwell TP4/TP8·H200·AMD MI350X/MI355X에서 검증했다.

Windowed-MTP: Removing the Full-Context Draft-KV Tax at Million-Token Contextspeculative decodingMTP drafter2607.21535
Windowed-MTP (arXiv 2607.21535) ↗Windowed-MTP (arXiv 2607.21535) ↗
Problem문제 정의Frontier models increasingly ship a built-in Multi-Token-Prediction (MTP/NEXTN) draft head, assumed to be negligibly cheap. At million-token context this breaks: the MTP head runs full attention over the entire KV cache at every draft step, so its read grows linearly with context and comes to dominate the draft cost — exactly where speculation should help most. A deep native draft can even turn net-negative, slower than no speculation, and the effect sharpens under hybrid/linear-attention targets whose cheap verification leaves the draft's full read exposed.내장 MTP(NEXTN) 초안 헤드는 싸다고 여겨지지만, 백만 토큰 문맥에선 초안 스텝마다 전체 KV 캐시를 읽어 비용이 문맥에 비례해 커진다. 깊은 초안은 투기를 안 하느니만 못해지고, 검증이 싼 선형 어텐션 타깃에서 특히 심하다.
Method방법Apply a StreamingLLM-style sliding window plus an attention sink to the draft head so the draft reads only a bounded, recent slice of the KV cache instead of the full context, keeping the draft's per-step cost constant as context grows while leaving the target's verification exact and lossless.초안 헤드에 StreamingLLM식 슬라이딩 윈도와 어텐션 싱크를 달아 최근 구간만 읽게 한다. 타깃 검증은 그대로라 무손실이다.
Results결과Bounding the draft's KV read removes the exposed draft-KV tax, restoring speculative speedups at long context — including deeper drafts and linear-attention targets where a full-context MTP head had otherwise erased the gains.draft-KV 비용이 사라져 롱컨텍스트에서 투기 가속이 돌아온다. 깊은 초안과 선형 어텐션 타깃에서도 마찬가지다.
Summary요약Give the built-in MTP drafter a sliding window + sink so it no longer pays full-context attention every draft step, keeping speculation profitable at million-token context.MTP 드래프터의 읽기 범위를 윈도로 묶어 백만 토큰에서도 투기가 이득이 되게 한다.

Error Certificates for KV-Cache Eviction via Randomized DesignKV-cacheeviction theory2607.21475
Error Certificates for KV-Cache Eviction (arXiv 2607.21475) ↗Error Certificates for KV-Cache Eviction (arXiv 2607.21475) ↗
Problem문제 정의Deterministic KV-cache eviction keeps the top-k tokens by an importance score and deletes the rest. The authors prove such a design cannot know what it destroyed: evicted values can be altered so that everything the serving system retains is unchanged while the true attention-output error grows arbitrarily — so no serving-time estimator of that error can be consistent.상위 k 토큰만 남기는 결정적 축출은 무엇을 버렸는지 알 수 없다. 저자들은 남은 캐시가 같아도 실제 어텐션 오차가 얼마든지 커질 수 있어, 서빙 중 오차를 일관되게 추정할 방법이 없음을 증명한다.
Method방법Randomized eviction restores identifiability. With a Poisson-sampled tail at known inclusion probabilities, a single logit offset performs the Hájek correction inside the softmax, and a survey-sampling variance estimator over the retained set becomes a per-step error certificate — an auditable bound on the attention error the eviction introduces.꼬리를 알려진 확률로 푸아송 샘플링하면, 로짓 오프셋 하나로 소프트맥스 안에서 Hájek 보정을 할 수 있다. 표본조사 분산 추정기가 스텝별 오차 인증서(검증 가능한 오차 상한)가 된다.
Results결과The certificate reaches 0.97 empirical coverage at no accuracy cost. The team pre-registered seven claims on real workloads and reports losing three — a candid, falsifiable evaluation of where randomized certificates hold and where they do not.정확도 손실 없이 커버리지 0.97을 얻었다. 사전 등록한 주장 7개 중 3개는 실패했다고 솔직히 밝힌다.
Summary요약Replace deterministic top-k KV eviction with Poisson-randomized eviction so the retained set yields a consistent, per-step certificate bounding the attention error.상위 k 축출을 푸아송 무작위 축출로 바꿔 스텝별 오차 상한을 얻는다.

FlowBlock (arXiv 2607.17652) ↗FlowBlock (arXiv 2607.17652) ↗
Problem문제 정의Block-wise diffusion LLMs decode sequentially at the block level, enabling KV-cache reuse across blocks but making inter-block decoding strictly serial. Prior attempts to unlock inter-block parallelism via post-training achieve only modest speedups and often degrade accuracy.블록 단위 디퓨전 LLM은 KV 캐시를 재사용하는 대신 블록끼리는 직렬로 디코딩한다. 사후 학습으로 병렬화하려던 시도는 가속이 작고 정확도가 떨어졌다.
Method방법FlowBlock observes that self-correcting dLLMs offer a training-free alternative: token-to-token (T2T) editing can repair tokens drafted from a slightly stale upstream context, so a downstream block needs only an informative draft, not a finalized predecessor. Results결과Because it exploits an existing self-correction capability instead of post-training for parallelism, FlowBlock unlocks inter-block wavefront parallelism training-free while preserving generation quality, avoiding the accuracy loss of prior parallel-decoding schemes.추가 학습 없이 블록 간 병렬성을 얻으면서 생성 품질을 지킨다.
Summary요약Use a self-correcting dLLM's token-to-token editing to run consecutive blocks as a parallel wavefront on stale-but-informative drafts, gaining parallelism training-free without hurting quality.T2T 편집 덕분에 연속 블록을 병렬로 돌릴 수 있다. 학습이 필요 없고 품질도 유지된다.

Method방법The authors formulate attention recall as a spherical-packing problem and derive feature maps from first principles by certifying nonnegative attention weights through a self-dual homogeneous cone. Xiaomi's MiMo team, with TileRT, reports the first 1000-tokens/s decode on a trillion-parameter model using a single standard 8-GPU node rather than specialized hardware.
