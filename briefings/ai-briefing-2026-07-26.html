vLLM v0.26.0 — new Inkling model family stack and a DeepSeek-V4 performance push Jul 25

vLLM cut a v0.26.0 stable release built from 411 commits by 212 contributors. SGLang v0.5.16 — DSpark confidence-driven speculative decoding and Inkling support Jul 25

SGLang cut v0.5.16 from 574 PRs by 169 contributors. Its headline is DSpark, a new speculative-decoding algorithm that drafts semi-autoregressively in blocks and then sizes each verify window from the draft's own confidence rather than a fixed draft length, reaching 383.7 tok/s at accept length ~5 on DeepSeek-V4-Pro (TP8, B300). It also adds full Inkling support — a 975B-parameter multimodal MoE with 1M-token context that mixes sliding-window, full and Mamba2 linear attention — verified on Blackwell TP4/TP8, H200 and AMD MI350X/MI355X.

SGLang가 169명의 기여자가 낸 574개 PR로 v0.5.16을 냈다. 핵심은 DSpark — 블록 단위로 준자기회귀 초안을 만든 뒤 고정 초안 길이 대신 초안 자체의 신뢰도로 검증 윈도 크기를 정하는 새 투기 디코딩 알고리즘으로, DeepSeek-V4-Pro(TP8, B300)에서 수용 길이 약 5에 383.7 tok/s에 도달한다. 또한 슬라이딩 윈도·풀·Mamba2 선형 어텐션을 혼합한 1M 토큰 문맥의 975B 멀티모달 MoE인 Inkling을 완전 지원하며 Blackwell TP4/TP8·H200·AMD MI350X/MI355X에서 검증됐다.

Problem문제 정의Frontier models increasingly ship a built-in Multi-Token-Prediction (MTP/NEXTN) draft head, assumed to be negligibly cheap. At million-token context this breaks: the MTP head runs full attention over the entire KV cache at every draft step, so its read grows linearly with context and comes to dominate the draft cost — exactly where speculation should help most. A deep native draft can even turn net-negative, slower than no speculation, and the effect sharpens under hybrid/linear-attention targets whose cheap verification leaves the draft's full read exposed.프런티어 모델은 내장 MTP(NEXTN) 초안 헤드를 점점 탑재하며, 그 비용은 무시할 만하다고 가정된다. 백만 토큰 문맥에서는 이 가정이 깨진다 — MTP 헤드가 초안 스텝마다 전체 KV 캐시에 대해 풀 어텐션을 돌려, 읽기 비용이 문맥에 선형으로 커지며 초안 비용을 지배한다(투기가 가장 필요한 지점에서). 깊은 네이티브 초안은 오히려 손해(투기 없느니만 못함)가 될 수 있고, 검증이 저렴한 하이브리드·선형 어텐션 타깃에서 초안의 풀 읽기가 그대로 드러나 문제가 더 심해진다.
Method방법Apply a StreamingLLM-style sliding window plus an attention sink to the draft head so the draft reads only a bounded, recent slice of the KV cache instead of the full context, keeping the draft's per-step cost constant as context grows while leaving the target's verification exact and lossless.초안 헤드에 StreamingLLM 방식의 슬라이딩 윈도와 어텐션 싱크를 적용해, 초안이 전체 문맥 대신 최근의 유계 구간만 읽게 한다. 문맥이 커져도 초안의 스텝당 비용을 상수로 유지하면서, 타깃의 검증은 정확·무손실로 둔다.
Results결과Bounding the draft's KV read removes the exposed draft-KV tax, restoring speculative speedups at long context — including deeper drafts and linear-attention targets where a full-context MTP head had otherwise erased the gains.초안의 KV 읽기를 유계로 만들어 노출된 draft-KV 비용을 없애고, 롱컨텍스트에서 투기 가속을 회복한다 — 전체 문맥 MTP 헤드가 이득을 지워버렸던 더 깊은 초안과 선형 어텐션 타깃에서도 마찬가지다.
Summary요약Give the built-in MTP drafter a sliding window + sink so it no longer pays full-context attention every draft step, keeping speculation profitable at million-token context.내장 MTP 드래프터에 슬라이딩 윈도와 싱크를 주어 초안 스텝마다 전체 문맥 어텐션을 치르지 않게 함으로써, 백만 토큰 문맥에서도 투기를 이득으로 유지한다.

Problem문제 정의Deterministic KV-cache eviction keeps the top-k tokens by an importance score and deletes the rest. The authors prove such a design cannot know what it destroyed: evicted values can be altered so that everything the serving system retains is unchanged while the true attention-output error grows arbitrarily — so no serving-time estimator of that error can be consistent.결정적 KV 캐시 축출은 중요도 점수로 상위 k 토큰을 남기고 나머지를 지운다. 저자들은 이 설계가 자신이 무엇을 파괴했는지 알 수 없음을 증명한다 — 축출된 값을 바꿔도 서빙 시스템이 보존한 것은 그대로인 채 실제 어텐션 출력 오차는 임의로 커질 수 있어, 그 오차의 어떤 서빙 시점 추정기도 일관될 수 없다.
Method방법Randomized eviction restores identifiability. With a Poisson-sampled tail at known inclusion probabilities, a single logit offset performs the Hájek correction inside the softmax, and a survey-sampling variance estimator over the retained set becomes a per-step error certificate — an auditable bound on the attention error the eviction introduces.무작위화 축출이 식별 가능성을 되살린다. 알려진 포함 확률의 푸아송 샘플링 꼬리와 함께, 단일 로짓 오프셋이 소프트맥스 안에서 Hájek 보정을 수행하고, 보존 집합에 대한 표본조사 분산 추정기가 스텝별 오차 인증서 — 축출이 유발한 어텐션 오차의 감사 가능한 상한 — 가 된다.

Method방법GRADRAG introduces cross-component prompt adaptation: instead of tuning each agent's prompt alone, it adapts prompts across the pipeline so improvements in one component account for their effect on the others, coordinating the multi-agent RAG system as a whole rather than component-by-component.GRADRAG는 교차 구성요소 프롬프트 적응을 도입한다 — 각 에이전트의 프롬프트를 단독으로 조정하는 대신, 파이프라인 전반에서 프롬프트를 적응시켜 한 구성요소의 개선이 다른 구성요소에 미치는 효과를 반영하게 함으로써, 멀티에이전트 RAG 시스템을 구성요소별이 아니라 전체로 협응시킨다.
Results결과By coordinating prompt adaptation across components, GRADRAG targets the pipeline-level interactions that isolated per-component tuning misses, aiming for multi-agent RAG whose parts improve together instead of pulling in different directions.구성요소 전반에서 프롬프트 적응을 협응함으로써, GRADRAG는 개별 구성요소 튜닝이 놓치는 파이프라인 수준 상호작용을 겨냥하며, 부분들이 서로 다른 방향으로 당기지 않고 함께 개선되는 멀티에이전트 RAG를 지향한다.
Summary요약Adapt prompts across a multi-agent RAG pipeline jointly, so each component's change accounts for its effect on the others rather than being tuned in isolation.멀티에이전트 RAG 파이프라인 전반에서 프롬프트를 함께 적응시켜, 각 구성요소의 변경이 개별 튜닝이 아니라 다른 구성요소에 미치는 효과를 반영하게 한다.
