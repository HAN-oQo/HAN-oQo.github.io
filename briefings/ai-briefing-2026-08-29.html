NVIDIA Dynamo v1.4.2 — the Rust NIXL bindings had been talking to stubs Aug 29

A patch release on top of v1.4.1, and the headline fix is the kind that is worse than it sounds. In the Frontend and SGLang Runtime images the Rust NIXL bindings resolve the C API with a bare dlopen("libnixl_capi.so") and the runtime extension carries no RPATH — so Rust NIXL silently ran against non-functional stubs while the Python bindings in the same interpreter worked fine. Both images now install NIXL from PyPI at a target-scoped nixl_ref (v1.3.2) and register the wheel's library directory with the dynamic loader, and the agg_vision.sh workaround that used to export the directory by hand is gone. The release also removes the unused Nsight EFA metrics plugin from the shipped images, updates the AWS EFA installer to v1.50, and pins plotext below v6 in the Planner image because v6 drops the plot_size API that AIConfigurator profiler runs depend on. Backend runtime versions are unchanged from v1.4.1. Alongside the tag, 46 commits merged in this window: TLS/mTLS auto-injection through the operator's InfrastructureConfiguration, EPD image decoding in the vLLM path, an embeddings overhaul with tokenizer alignment and a multi-process pool, and generate metrics on the vLLM /inference/v1/generate endpoint. v1.4.2 also opens a -enterprise artifact suffix on NGC — same binaries, different support terms. v1.4.1 위의 패치 릴리스인데, 머리기사 수정이 들리는 것보다 나쁜 종류다. TwinKV: A Composable Repair Pass for KV Cache Eviction via Pairwise Key RedundancyKV cacheevictionarXiv:2608.27128
arxiv.org/abs/2608.27128 — submitted Aug 27 2026
Problem / 문제 정의 Long-context inference is bottlenecked by the KV cache's memory footprint, and every dominant eviction method scores tokens by attention magnitude — or, in attention-free variants, by each key's distance from a global reference point. The paper attacks that premise directly with a controlled leave-one-out probe: remove one token, measure how much the answer actually changes. The correlation between attention magnitude and a token's causal contribution comes out at Spearman ρ = −0.004, which is to say none. 장문맥 추론의 병목은 KV 캐시의 메모리 사용량이고, 지배적인 축출 기법은 모두 어텐션 크기로 — 또는 어텐션을 쓰지 않는 변형에서는 각 키와 전역 기준점 사이의 거리로 — 토큰에 점수를 매긴다. 논문은 그 전제를 통제된 leave-one-out 프로브로 정면 공격한다: 토큰 하나를 빼고 답이 실제로 얼마나 바뀌는지 잰다. 어텐션 크기와 토큰의 인과적 기여 사이 상관은 Spearman ρ = −0.004로 나온다. 즉 없다.
Method / 방법 TwinKV replaces importance with redundancy: a training-free, attention-free signal that asks whether a token's key has a near-duplicate elsewhere in the context. It does not replace an existing policy but runs as a composable repair pass on top of one. Given the policy's fixed retained set, it finds orphans — evicted tokens with no surviving duplicate — and redundant donors — retained tokens whose information is duplicated elsewhere — and swaps them, leaving the original budget and scoring rule untouched. TwinKV는 중요도를 중복성으로 대체한다: 학습이 필요 없고 어텐션도 쓰지 않는 신호로, 어떤 토큰의 키가 문맥 어딘가에 거의 같은 짝을 갖는지를 묻는다. 기존 정책을 대체하는 대신 그 위에 얹히는 합성 가능한 보수 패스로 동작한다. 정책이 정한 보존 집합을 받아, 살아남은 중복이 없는 축출 토큰인 고아(orphan)와 정보가 다른 곳에 중복된 보존 토큰인 잉여 기증자(redundant donor)를 찾아 둘을 맞바꾼다. 원래의 예산과 점수 규칙은 건드리지 않는다.
Results / 결과 Composed with four recent eviction policies on LongBench, LooGLE, RULER and a short-context MMLU-Pro no-harm control at compression ratios of 0.3, 0.5 and 0.7. Problem / 문제 정의 The standard recipe for a software-issue agent is to collect a large corpus of agent trajectories and fine-tune on the ones that succeeded. Problem / 문제 정의 If agents are going to act across email, files, payments and personal data, people without software backgrounds need some understandable, reusable way to control what those agents may do. Method / 방법 113 participants without professional software backgrounds were assigned to one of three conditions: per-action human-in-the-loop approval (HITL), automated per-action model review (AUTO), or the user-authored consequence policy (POLICY).
