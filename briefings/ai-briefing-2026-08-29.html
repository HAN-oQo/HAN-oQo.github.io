NVIDIA Dynamo v1.4.2 — the Rust NIXL bindings had been talking to stubs Aug 29

A patch release on top of v1.4.1 whose headline fix is worse than it sounds. In the Frontend and SGLang Runtime images the Rust NIXL bindings resolve the C API with a bare dlopen("libnixl_capi.so") and the runtime extension carries no RPATH, so Rust NIXL silently ran against non-functional stubs while the Python bindings in the same interpreter worked fine. Both images now install NIXL from PyPI at a target-scoped nixl_ref (v1.3.2) and register the wheel's library directory with the dynamic loader; the agg_vision.sh workaround is gone. The release also drops the unused Nsight EFA metrics plugin, updates the AWS EFA installer to v1.50, and pins plotext below v6 in the Planner image because v6 drops the plot_size API that AIConfigurator profiler runs need. SGLang — a persistent-CTA decode kernel for long context, and a KV pool that was being sized against stale memory Aug 29

125 commits, no new tag after v0.5.18. The biggest addition is AMD's Work-Centric ("Lean") Attention, a persistent-CTA decode kernel for long-context serving, where the usual one-block-per-query mapping leaves most CTAs idle. Two memory fixes matter more in production than in benchmarks: a KV cache pool sized far too small while weight-loading memory was still referenced, and a KeyError on batch requests whose state was freed before it was read. DCP1→DCP-N prefill/decode KV transfers are now packed into destination-contiguous RDMA blocks instead of per-fragment. HiCache: buffer mode decides a staged fetch against the live radix tree instead of a snapshot, load-back is fenced behind the forward stream, storage prefetch is keyed by request namespace, and an unnecessary all-reduce left the prefetch-progress check. A four-commit config refactor moved resolution out of the record and computed derived parallel widths from the leaves. Hardware coverage: Blackwell SM reservations for DeepGEMM MegaMoE grid barriers, SM90 FP8 GEMM routing, Kimi K3's EP-A2A/SP-MoE fast path for the Mooncake MoE all-to-all backend, a Qwen 3.8 rebase, and Ascend KDA causal conv1d. 커밋 125개, v0.5.18 이후 새 태그는 없다. 가장 큰 추가는 AMD가 기여한 Work-Centric("Lean") Attention이다. 장문맥 서빙용 persistent-CTA 디코드 커널로, 질의당 블록 하나를 배정하는 통상 방식에서 시퀀스가 길어지면 CTA 대부분이 노는 문제를 겨냥한다. 운영에서 더 중요한 메모리 수정도 두 건 있다. 가중치 로딩 메모리가 아직 참조 중일 때 KV 캐시 풀이 너무 작게 잡히던 문제와, 읽기 전에 상태가 해제된 배치 요청의 KeyError다. 분리(disaggregation) 경로에서는 DCP1→DCP-N 프리필·디코드 KV 전송을 조각별로 보내지 않고 목적지 연속 RDMA 블록으로 묶는다. TwinKV: A Composable Repair Pass for KV Cache Eviction via Pairwise Key RedundancyKV cacheevictionarXiv:2608.27128
arxiv.org/abs/2608.27128 — submitted Aug 27 2026
Problem / 문제 정의 Every dominant KV eviction method scores tokens by attention magnitude (or, attention-free, by distance from a global reference key). A leave-one-out probe that removes one token and measures the answer change finds Spearman ρ = −0.004 between attention magnitude and causal contribution: no correlation. 주류 KV 축출 기법은 모두 어텐션 크기(어텐션을 안 쓰는 변형은 전역 기준점과의 거리)로 토큰 점수를 매긴다. 토큰 하나를 빼고 답의 변화를 재는 leave-one-out 프로브로 보니, 어텐션 크기와 인과적 기여의 상관은 Spearman ρ = −0.004로 사실상 없었다.
Method / 방법 TwinKV uses redundancy instead: a training-free, attention-free check of whether a key has a near-duplicate elsewhere. Run as a repair pass on any policy's retained set, it swaps in orphans (evicted, no surviving duplicate) for redundant donors (retained, duplicated elsewhere), keeping the budget and scoring rule untouched. TwinKV는 중요도 대신 중복성을 본다. 학습도 어텐션도 필요 없이, 어떤 키에 거의 같은 짝이 문맥에 있는지만 확인한다. 기존 정책의 보존 집합 위에 보수 패스로 얹혀, 살아남은 짝이 없는 축출 토큰(고아, orphan)을 다른 곳에 중복된 보존 토큰(잉여 기증자, redundant donor)과 맞바꾼다. 예산과 점수 규칙은 그대로다.
Results / 결과 Composed with four recent policies on LongBench, LooGLE, RULER and an MMLU-Pro no-harm control at compression ratios 0.3, 0.5 and 0.7, it improves most configurations for two policies on Qwen3-4B, is near-even for a third, and helps only a minority for a fourth already near its ceiling (which improves in every cell on RULER with Llama-3.2-1B). Gains shrink at the loosest ratio, and few-shot classification exemplars are named as a case where it does not help. 최근 정책 네 가지와 조합해 LongBench·LooGLE·RULER와 MMLU-Pro 무해성 대조군에서 압축률 0.3·0.5·0.7로 평가했다. Qwen3-4B에서 두 정책은 대부분 설정이 좋아졌고, 세 번째는 반반, 이미 천장에 가까운 네 번째는 일부만 좋아졌다(Llama-3.2-1B RULER에서는 모든 칸이 개선). 압축률이 느슨할수록 이득이 작고, 소수샷 분류 예시에서는 효과가 없었다.
Summary / 요약 The ρ = −0.004 probe is the part worth arguing about: if attention magnitude carries no causal signal, years of eviction scores ranked on something else. ClusterAttention: A training-free speedup of bidirectional attentionsparse attentiontraining-freearXiv:2608.26965

Problem / 문제 정의 Sparse attention usually borrows structure from the input (word order, spatial proximity), which excludes unordered inputs like large tabular data. Clustering keys and queries by geometry has been too slow to pay off unless amortised over several forward passes. 희소 어텐션은 보통 어순이나 공간적 근접성 같은 입력 구조를 빌려 쓴다. 그래서 대규모 표 데이터처럼 순서가 없는 입력에는 못 쓰고, 키·질의를 기하로 군집화하는 방식은 여러 forward 패스에 비용을 나누지 않으면 너무 느렸다.
Method / 방법 ClusterAttention runs a fast recursive clustering per attention head and fixes every cluster to the same power-of-two size, so the block-sparse kernel runs at dense per-interaction latency. The centroid summarisation error is derived and compensated. ClusterAttention은 헤드마다 빠른 재귀 군집화를 하고, 모든 군집을 같은 2의 거듭제곱 크기로 맞춘다. 덕분에 블록 희소 커널이 dense와 같은 상호작용당 지연으로 돈다. 군집을 중심점으로 요약할 때 생기는 오차도 유도해 보정한다.
Results / 결과 On large tabular data it speeds up TabPFN-3 by two to six times while keeping at least 99% of dense accuracy. On Wan 2.1-14B T2V video it is closer to dense and faster than SVOO (1.8x vs 1.4x, both without offline calibration); the authors call it the first training-free method for unstructured input in a single forward pass. 대규모 표 데이터에서 TabPFN-3을 2~6배 빠르게 하면서 dense 정확도의 99% 이상을 유지했다.
