SGLang main — rejection sampling for MTP spec decode, host KV cache refactored into a pool_host package, AMD/ROCm fixes SGLangJun 19

SGLang's main branch (100+ commits in the window) leaned into speculative decoding, the memory-cache layer, and AMD support. It added rejection sampling for MTP speculative decoding, extracted the host KV-cache base layer into a dedicated pool_host package, and wired a window-aware leaf-lock release option onto the unified cache. AMD work fixed a no-op dtype cast in the dynamic top-k path on HIP, addressed garbled unquantized Qwen3-30B-A3B output on ROCm/aiter, and tuned o_proj GEMM and attention-output RoPE. The diffusion backend got token-shard optimizations and a resident FastHunyuan VAE on high-memory GPUs, and a cookbook gained a Laguna-M.1 PD-disaggregation section. The throughline is hardening MTP spec decode and the host-cache layer while broadening AMD and diffusion coverage.

SGLang의 main(이 구간 100+ 커밋)은 추측 디코딩·메모리 캐시 계층·AMD 지원에 기울었다. MTP 추측 디코딩용 거부 샘플링을 더하고, 호스트 KV 캐시 기반 계층을 전용 pool_host 패키지로 추출하고, 통합 캐시에 윈도 인식 리프 락 해제 옵션을 연결했다. Problem문제 정의Diffusion LLMs (dLLMs) decode multiple tokens per forward pass but their KV cache still grows linearly with context, capping throughput at long context. Offloading the cache to host DRAM eases memory pressure, but limited PCIe bandwidth means only a sparse subset of KV entries can be recalled — and accurate selection normally requires exact attention over the full cache, which is too expensive under offloading.디퓨전 LLM(dLLM)은 한 번의 순전파로 여러 토큰을 디코딩하지만 KV 캐시는 여전히 컨텍스트에 선형 증가해 롱컨텍스트 처리량을 제약한다. 캐시를 호스트 DRAM으로 오프로드하면 메모리 압박이 줄지만, 제한된 PCIe 대역폭 탓에 KV 항목의 희소 부분집합만 불러올 수 있고 — 정확한 선택은 보통 전체 캐시에 대한 정확 어텐션을 요구해 오프로딩에선 너무 비싸다.
Method방법HERALD exploits a property of block dLLMs: the relevant KV entries stay consistent across denoising steps within a block, so the top-k can be selected once and reused throughout the block. It uses a single center-query proxy to approximate the full B-query union for selection and offloads CPU-side attention, amortizing the selection cost across the whole block and reducing the required selection compute by roughly a factor of the block size.HERALD는 블록 dLLM의 성질을 활용한다 — 관련 KV 항목이 블록 내 디노이징 단계 전반에 일관되므로 top-k를 한 번 고르고 블록 내내 재사용한다. 단일 중심 쿼리 프록시로 선택 시 전체 B-쿼리 합집합을 근사하고 CPU 측 어텐션을 오프로드해, 선택 비용을 블록 전체에 분산하고 필요한 선택 연산을 대략 블록 크기 배수만큼 줄인다.
Results결과By selecting once per block and offloading the sparse-attention selection to the CPU, HERALD sustains high-accuracy KV retrieval under host-DRAM offloading and improves serving throughput for block dLLMs at long contexts over offloading baselines that recall the full cache.블록당 한 번 선택하고 희소 어텐션 선택을 CPU로 오프로드함으로써, HERALD는 호스트 DRAM 오프로딩 아래 고정확 KV 검색을 유지하고, 전체 캐시를 불러오는 오프로딩 베이스라인 대비 롱컨텍스트 블록 dLLM의 서빙 처리량을 높인다.
Summary요약Select top-k KV once per diffusion block and run the selection on the CPU — sparse offload without per-step recompute.디퓨전 블록당 top-k KV를 한 번만 고르고 선택을 CPU에서 — 단계별 재연산 없는 희소 오프로드.

Recency/Frequency Adaptive KV Caching for Large Language Model Serving (arXiv 2606.21238, submitted Jun 19) ↗Recency/Frequency Adaptive KV Caching for Large Language Model Serving (arXiv 2606.21238, 6/19 제출) ↗
Problem문제 정의KV caching accelerates LLM inference, but real workloads are large and diverse, making them hard to cache effectively. Existing managers evict cache blocks with a least-recently-used (LRU) policy, which lets multiple unrelated workloads flush each other's caches and depresses the hit rate.KV 캐싱은 LLM 추론을 가속하지만 실제 워크로드는 크고 다양해 효과적으로 캐시하기 어렵다. 기존 관리자는 LRU 정책으로 캐시 블록을 축출하는데, 이는 서로 무관한 여러 워크로드가 서로의 캐시를 밀어내게 해 적중률을 떨어뜨린다.
Method방법The authors integrate an adaptive caching policy that dynamically allocates cache space between recently occurring and frequently occurring KV blocks, rather than relying on recency alone. Splitting capacity by both recency and frequency keeps hot reusable blocks resident even when bursts of unrelated traffic arrive.저자들은 최근성에만 의존하는 대신, 최근 발생 KV 블록과 빈번 발생 KV 블록 사이에 캐시 공간을 동적으로 배분하는 적응형 캐싱 정책을 통합한다. 최근성과 빈도 모두로 용량을 나누면 무관한 트래픽이 몰려도 뜨거운 재사용 블록이 상주한다.
Results결과Evaluations show the adaptive policy improves the KV cache hit rate by up to 10.8% and reduces time-to-first-token, relative to the LRU baseline, on diverse multi-workload traces.평가에서 적응형 정책은 다양한 다중 워크로드 트레이스에서 LRU 베이스라인 대비 KV 캐시 적중률을 최대 10.8% 높이고 첫 토큰 지연(TTFT)을 줄인다.
