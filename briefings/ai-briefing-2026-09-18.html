SGLang — a worker can now change its mind about whether it is a prefill node or a decode node Sep 17

At least a hundred commits in the window, no new tag. The structural change is runtime role switching in prefill–decode disaggregation: until now a worker was launched as a prefill node or a decode node and stayed that way, so a fleet sized for one traffic mix had to be redeployed when the mix moved. Making the role switchable at runtime turns a deployment-time decision into a scheduling decision, which is the same direction the rest of the disaggregation ecosystem has been moving. Around it, the DeepSeek-V4-family work continued to deepen rather than broaden: attention metadata, sparse prefill and the KV pool were generalized over compression ratios so one code path serves several compressed-cache configurations, and a V4.1 branch gained an Engram module with request history. The unified radix cache picked up an agentic-aware tail-optimized LRU eviction policy — an eviction rule tuned for the long, tool-interrupted sessions agents produce — and HiCache batched its device-to-host submits per step for hybrid pools. The router side got two smaller things: a --min-load-choices flag that samples k random candidates for the min-load fallback instead of scanning all of them, and chat-prompt rendering through dynamo-render. Security hygiene landed too, restricting which standard-library globals the SafeUnpickler will resolve. 구간 내 커밋 최소 100개, 새 태그는 없다. 핵심은 프리필–디코드 분리에서의 런타임 역할 전환이다. 지금까지 워커는 띄울 때 정한 역할을 바꿀 수 없어서, 트래픽 구성이 바뀌면 다시 배포해야 했다. 이제 배포 시점의 결정이 스케줄링 결정이 된다. DeepSeek-V4 계열은 어텐션 메타데이터·희소 프리필·KV 풀을 압축 비율 전반으로 일반화했고, V4.1 갈래에 요청 이력을 담는 Engram 모듈이 붙었다. 통합 radix 캐시에는 도구 호출로 끊기는 긴 에이전트 세션에 맞춘 tail-optimized LRU 축출이 들어갔고, HiCache는 하이브리드 풀의 D2H 제출을 스텝 단위로 묶었다. 라우터에는 최소 부하 대체 경로에서 k개 후보만 무작위로 뽑는 --min-load-choices 플래그와 dynamo-render 기반 채팅 프롬프트 렌더링이 들어왔다. vLLM — a running engine can now hand its KV cache memory back Sep 17

At least a hundred commits in the window, no new tag. The headline addition is a release_kv_cache_memory() API: a live engine can release the KV arena it has reserved instead of holding it until the process exits. That matters for anyone co-locating inference with training or with a second model on the same device, because the KV arena is normally the largest single allocation an engine makes and it is normally permanent. Alongside it, the KV-cache metadata GET method used by external event consumers was restored, and a NIXL/HiSparse path was fixed so full blocks import without a tail prefill on the decode side. Two throughput bugs read like production reports: a max-load throughput cliff when max_num_seqs is not a multiple of eight, and stale FlashMLA workspace views that were not released after the workspace grew. The DeepSeek-V4.1 path integrated Mega-Gate from DeepGEMM and fixed FlashInfer DSpark non-causal attention; the ROCm side reverted the w4a4 ASM GEMM default back to off and added a missing hook that was crashing GLM-5.3-Flash at boot. A metrics nit worth noting: vLLM no longer logs a 0.0% prefix cache hit rate before any query has been served — the kind of zero that quietly poisons a dashboard's first minute. 구간 내 커밋 최소 100개, 새 태그는 없다. 핵심은 release_kv_cache_memory() API다. 살아 있는 엔진이 예약한 KV 아레나를 프로세스 종료 전에 반납할 수 있다. KV 아레나는 보통 엔진의 가장 큰 할당이고 한번 잡으면 놓지 않으므로, 학습이나 다른 모델과 장치를 나눠 쓸 때 의미가 크다. 외부 이벤트 소비자용 KV 캐시 메타데이터 GET 메서드가 복구됐고, NIXL/HiSparse 경로는 디코드 쪽 꼬리 프리필 없이 전체 블록을 들여오도록 고쳤다. 처리량 버그도 둘 고쳤다. max_num_seqs가 8의 배수가 아닐 때의 최대 부하 처리량 절벽과, 워크스페이스가 커진 뒤 반납되지 않던 FlashMLA 워크스페이스 뷰다. Ask the Tool, Don't Guess: Agent Tool Calls Hold Their Progress, and the Serving System Should Read ItKV cacheagentic servingarXiv:2609.18849
arxiv.org/abs/2609.18849 →
Problem문제 정의 An agentic request spends much of its wall-clock time waiting for a tool to return, and its KV cache occupies GPU memory for that entire wait. Serving systems decide whether to keep, evict or restore that cache by guessing how long the tool will take — from the tool's name, its history, a duration declared before the call, or the engine's own occupancy. The authors argue that no estimate fixed before a call starts can know its duration, and that such estimates may not even rank calls correctly against one another. 에이전트 요청은 도구 응답을 기다리는 데 많은 시간을 쓰고, 그동안 KV 캐시가 GPU 메모리를 차지한다. 서빙 시스템은 도구 이름, 이력, 사전 선언 시간, 엔진 점유율로 소요 시간을 추측해 캐시를 유지·축출·복원할지 정하는데, 저자들은 호출 전에 고정된 추정으로는 소요 시간을 알 수 없고 호출 간 순서조차 틀릴 수 있다고 본다.
Method방법 The proposal is to have tool calls report their own progress while they run, and the paper measures what that costs. A census of four public agent corpora finds a readable signal in most tool time once it is revealed, in two forms: a fraction of the work remaining, or an accurate signal that the end is near. A harness recovers that signal without changing what the agent sees, and it is fed to a production engine through a small number of hints at the points where a KV-cache decision is actually made. 도구 호출이 실행 중 스스로 진행률(남은 작업 비율 또는 종료 임박 신호)을 보고하게 한다. 공개 에이전트 말뭉치 네 개에서 대부분의 도구 시간에 이 신호를 읽을 수 있었고, 하네스가 에이전트 화면을 바꾸지 않고 회수해 KV 캐시 결정 지점에 힌트로 넘긴다.
Results결과 Recovering the signal costs no measurable drop in the agent's benchmark score. At the points where a KV-cache decision is made, the reported progress is between several times and an order of magnitude more accurate than the best published predictors, and it stays accurate when the environment changes. Plugged into a production engine, it cuts p90 time-to-first-token after a tool call by 20.7% with HBM only and 20.8% with HBM plus DRAM, measured against LRU and close to an oracle. 에이전트 벤치마크 점수 손실은 측정되지 않았고, 진행률은 기존 최고 예측기보다 수 배에서 10배까지 더 정확했다. 프로덕션 엔진에서 도구 호출 뒤 p90 TTFT를 LRU 대비 20.7%(HBM만), 20.8%(HBM+DRAM) 줄여 오라클에 가까웠다.
Summary요약 The paper's closing line is its thesis: a serving system should not guess what its tools can tell it. The interesting move is that the fix is a protocol change rather than a better model — the information already exists inside the running tool, and the agent stack is what silences it. 서빙 시스템은 도구가 말해 줄 수 있는 것을 추측하지 말아야 한다는 것이 논지다. 해법이 더 나은 예측 모델이 아니라 프로토콜 변경이라는 점이 흥미롭다.

Colla-Q: Toward Collaborative Experts in MoE Quantization via Minimax Precision BalancingquantizationMoEarXiv:2609.18131
arxiv.org/abs/2609.18131 →
Problem문제 정의 Quantization cuts memory and compute cost, but the damage is unusually pronounced in Mixture-of-Experts models. Each individual expert holds a small number of parameters, which makes it sensitive to low-bit representation, and because MoE behaves as an ensemble of routed contributions, one badly degraded expert can drag down the whole model's output rather than just the tokens routed to it. 양자화 피해는 MoE 모델에서 특히 크다. 전문가 하나하나는 파라미터가 적어 저비트에 민감하고, MoE는 앙상블처럼 동작하므로 크게 망가진 전문가 하나가 모델 전체 출력을 끌어내린다.
Method방법 Colla-Q is a bit-allocation framework that assigns bit-widths per expert using activation entropy, with the goal of keeping performance balanced across experts rather than minimizing average error. The framing is minimax: rather than letting a few experts take most of the damage, the allocation is chosen so that every expert stays good enough to contribute collaboratively in the quantized model. Colla-Q는 활성 엔트로피로 전문가별 비트 폭을 정한다. 평균 오차가 아니라 가장 약한 전문가를 기준으로 삼는 미니맥스 방식이라, 모든 전문가가 양자화 뒤에도 제 몫을 하도록 비트를 배분한다.
Results결과 The authors report two effects from the balanced allocation: better overall MoE performance, and reduced dependence on the calibration dataset. The second is the more practical of the two — uniformly adjusting each expert's performance is what makes the quantized model robust and stable, so the method generalizes more consistently across different calibration sets. The UN puts its global statistics behind an MCP endpoint Sep 17
