vLLM v0.29.0 — Model Runner V2 becomes the default for every model Sep 9

594 commits from 277 contributors, and the release's own first highlight is the one that matters most: Model Runner V2 is now the default for all models, completing a rollout that began with pooling models. MRV2 arrives with CUDA-graph memory profiling for KV-cache auto-sizing, batch-sharded sampling that cuts per-step logits memory by 1/TP, prompt embeds, padded FULL cudagraph dispatch for uniform decode under spec decode, and DP-sync skipping before EAGLE/MTP draft prefill; MRV1 survives only for a few ROCm models and features MRV2 has not caught up with. Three defaults changed underneath users: FlashInfer all-reduce is on for TP CUDA groups, the prefix-cache NONE_HASH is deterministic so distributed KV-cache deployments no longer need to pin PYTHONHASHSEED, and new --max-num-queued-reqs / --max-num-queued-tokens admission-control flags appear. Mamba prefix caching now takes internal prefill checkpoints for a reported 9–25% TTFT improvement. Kimi-K3 and DeepSeek V4 get a dense block of kernel work — fused MXFP4 top-k finalization in the K3 latent tail at about 5% end-to-end latency, K3 Mamba metadata preparation collapsed into one Triton launch for a 6.6–7.6x kernel speedup, tuned Hopper low-latency GEMM now also dispatched on SM100, the MLA gate merged into the QKV-A projection — and RL weight sync gains a sharded_rdt P2P backend where each worker pulls only its own TP/EP slice over NIXL or Ray Direct Transport. Breaking: ten deprecated architectures removed, the PyAV video decoder gone, and python -m vllm.entrypoints.openai.api_server deprecated in favour of vllm serve. 기여자 277명의 커밋 594개, 그리고 릴리스가 스스로 첫 항목으로 꼽은 것이 가장 중요하다. Model Runner V2가 이제 모든 모델의 기본값이며, 풀링 모델에서 시작한 전환이 마무리됐다. MRV2는 KV 캐시 자동 크기 조정을 위한 CUDA 그래프 메모리 프로파일링, 스텝별 logits 메모리를 1/TP로 줄이는 배치 샤딩 샘플링, prompt embeds, 스펙 디코드 하의 균일 디코드를 위한 패딩된 FULL cudagraph 디스패치, EAGLE/MTP 초안 프리필 전 DP 동기화 생략과 함께 왔다. MRV1은 일부 ROCm 모델과 MRV2가 아직 못 따라온 기능에만 남는다. 사용자 발밑에서 기본값 세 개가 바뀌었다. TP CUDA 그룹의 FlashInfer all-reduce가 켜지고, 프리픽스 캐시 NONE_HASH가 결정적이 되어 분산 KV 캐시 배포에서 PYTHONHASHSEED를 고정할 필요가 없어졌으며, --max-num-queued-reqs/--max-num-queued-tokens 수용 제어 플래그가 새로 생겼다. Mamba 프리픽스 캐싱은 내부 프리필 체크포인트를 남겨 TTFT를 9~25% 개선했다고 보고한다. Kimi-K3와 DeepSeek V4에는 커널 작업이 촘촘하게 들어왔다. K3 잠재 표현 말단의 fused MXFP4 top-k 마감으로 E2E 지연 약 5%, K3 Mamba 메타데이터 준비를 Triton 런치 하나로 접어 커널 6.6~7.6배, 튜닝된 Hopper 저지연 GEMM이 SM100에서도 디스패치되고, MLA 게이트가 QKV-A 프로젝션에 합쳐졌다. RL 가중치 동기화에는 각 워커가 NIXL 또는 Ray Direct Transport로 자기 TP/EP 슬라이스만 당겨오는 sharded_rdt P2P 백엔드가 생겼다. 파괴적 변경: 폐기된 아키텍처 열 개 제거, PyAV 비디오 디코더 삭제, python -m vllm.entrypoints.openai.api_server는 vllm serve로 대체 폐기.

SGLang — HiCache swaps a skip-list for a segment-lock protocol, and unified memory learns to evict full KV for Mamba Sep 9

Another full API page of 100 commits and no new tag. The cache-layer change is the one to read first: HiCache replaced skip_lock_node_ids with a segment lock protocol, trading an ad-hoc skip list for an explicit locking discipline over cache regions — the kind of change that only gets made when concurrent eviction and transfer start stepping on each other. Unified memory learned to evict full KV when Mamba runs short of bytes, and Mamba prefix-cache checkpoints are now stored at the configured SSM state dtype rather than a widened one. Attention got two sizing fixes: FlashInfer MLA indptr buffers are now sized to the padded max batch, and a shared MAX_LEN prefill CUDA-graph bucket is kept when the graph captures a DP gather. Model support moved on two fronts — GLM-5.3 Flash NVFP4 loading, and an optimized Domino rollout for DFlash V2 — while Kimi-K3's fused MoE finalize now accepts fp32 routing weights. AMD had a good window: ROCm 10 became the default for AMD PR and nightly tests. Two reversals are worth noting: the final multi-layer EAGLE shared-read event was reverted, and GSM8K thresholds were relaxed for the GLM-5.2 DSA-MTP variants. 여기도 API 한 페이지 100개 커밋에 새 태그는 없다. 먼저 읽을 것은 캐시 계층 변경이다. HiCache가 skip_lock_node_ids를 세그먼트 락 프로토콜로 교체했다. 임시 스킵 리스트를 캐시 리전에 대한 명시적 락 규율로 바꾼 것인데, 동시 축출과 전송이 서로를 밟기 시작할 때에야 하게 되는 종류의 변경이다. 통합 메모리는 Mamba가 바이트가 부족할 때 전체 KV를 축출하는 법을 배웠고, Mamba 프리픽스 캐시 체크포인트는 넓힌 타입이 아니라 설정된 SSM 상태 dtype으로 저장된다. 어텐션에는 크기 관련 수정 둘이 들어왔다. Sample-Guided Exact Top-K Selection for Long-Context Sparse Attentionsparse attentionGPU kernelarXiv:2609.08450
arxiv.org/abs/2609.08450 →
Problem문제 정의 Sparse attention keeps only a fixed-size subset of tokens, but the exact top-K stage that picks that subset still has to walk a score row whose length grows with context. Production radix selectors find their first usable rank boundary only after reading the whole row, so they pay a second row-scale pass before exact refinement can start. That double traversal is pure overhead on the critical path of every sparse-attention layer. 희소 어텐션은 고정 크기의 토큰 부분집합만 남기지만, 그 부분집합을 고르는 정확한 top-K 단계는 여전히 문맥 길이에 비례해 길어지는 점수 행을 훑어야 한다. 프로덕션 radix 선택기는 행 전체를 읽은 뒤에야 처음 쓸 만한 순위 경계를 찾으므로, 정확한 정제를 시작하기 전에 행 규모의 두 번째 패스를 더 낸다. 그 이중 순회는 모든 희소 어텐션 레이어의 임계 경로에 얹히는 순수 오버헤드다.
Method방법 The authors observe that locating a compact upper tail needs far less resolution than pinning the exact rank boundary, and that a fixed-stride partial view of the current row stays calibrated to the full-row rank across ragged lengths. HPC-Ops Top-K therefore lets that strided sample propose a row-local coarse boundary; the mandatory complete-row pass then certifies the proposal, forms the admitted candidate set, and initializes exact FP32 refinement over only the unresolved frontier. A nested secondary boundary handles underfilled proposals before anything is committed, so sampling controls common-path work but never correctness. 저자들은 조밀한 상위 꼬리를 찾는 데는 정확한 순위 경계를 못 박는 것보다 훨씬 낮은 해상도만 필요하고, 현재 행의 고정 간격 부분 뷰가 들쭉날쭉한 길이 전반에서 전체 행 순위에 대해 보정된 상태로 남는다는 것을 관찰한다. 그래서 HPC-Ops Top-K는 그 간격 표본이 행 국소 개략 경계를 제안하게 한다. 이후 의무적인 전체 행 패스가 그 제안을 인증하고, 채택 후보 집합을 만들고, 미해결 프런티어에 대해서만 정확한 FP32 정제를 초기화한다. 중첩된 2차 경계가 채워지지 않은 제안을 커밋 전에 처리하므로, 표본추출은 공통 경로의 작업량만 통제하고 정확성은 건드리지 않는다.
Results결과 Evaluated on indexer scores from Hy4-Preview, the selector beats the fastest verified external exact baseline by 1.29–1.75x across 20 operator configurations, with a 1.55x geometric-mean speedup. On two framework-derived sparse-attention traces it reaches 1.36x and 1.48x. The GPU implementation fuses complete-row certification with candidate formation and combines persistent, KV-split and direct-exact execution behind a graph-capturable ragged-row dispatch. Hy4-Preview의 인덱서 점수로 평가했을 때, 이 선택기는 연산자 구성 20종에서 검증된 가장 빠른 외부 정확 기준선을 1.29~1.75배 앞서고 기하평균 1.55배 속도를 낸다. 프레임워크에서 뽑은 희소 어텐션 트레이스 두 개에서는 1.36배와 1.48배에 이른다. GPU 구현은 전체 행 인증과 후보 구성을 융합하고, persistent·KV-split·direct-exact 실행을 그래프 캡처 가능한 들쭉날쭉 행 디스패치 뒤에 묶는다.
Summary요약 A sample first, then certify design for exact top-K: cheap strided peeking sets up the work, the one mandatory full pass proves the peek was enough, and exact refinement touches only the frontier. The implementation is in Tencent's open-source HPC-Ops operator library. 정확한 top-K를 위한 '먼저 표본, 다음 인증' 설계다. 값싼 간격 엿보기가 작업을 준비하고, 의무적인 한 번의 전체 패스가 그 엿보기로 충분했음을 증명하며, 정확한 정제는 프런티어만 건드린다. 구현은 Tencent의 오픈소스 HPC-Ops 연산자 라이브러리에 들어 있다.

Jacap: Robust KV Cache Eviction via Jacobian-Based Nonlinear Information Capacity PreservationKV evictiontheoryarXiv:2609.08131
arxiv.org/abs/2609.08131 →
Problem문제 정의 KV-cache eviction is what makes long-context inference affordable, but the policies in use are mostly empirical heuristics — keep the tokens with high attention weight, keep a sink, keep a recent window. None of them characterizes token utility under the nonlinearity that actually governs attention, the softmax. Without that, a policy can only be tuned, not reasoned about, and it breaks in exactly the high-compression regime where it matters. KV 캐시 축출은 긴 문맥 추론을 감당 가능하게 만드는 장치지만, 실제로 쓰이는 정책은 대부분 경험적 휴리스틱이다 — 어텐션 가중치가 높은 토큰을 남기고, 싱크를 남기고, 최근 윈도를 남긴다. 그중 어느 것도 어텐션을 실제로 지배하는 비선형성, 즉 softmax 아래에서 토큰의 효용을 규정하지 않는다. 그 규정이 없으면 정책은 튜닝만 가능하고 논증은 불가능하며, 정작 중요한 고압축 영역에서 무너진다.
Method방법 The paper rethinks eviction through local information geometry, modelling attention as a nonlinear Gaussian communication channel. A first-order Taylor expansion of the attention mapping yields the Jacobian Information Capacity, an objective that explicitly folds in query relevance, softmax sensitivity and structural diversity — three things existing heuristics each capture only one of. Jacap then implements that objective with softmax-aware importance weighting plus statistical leverage scores for subset selection, so the surviving set is chosen for how much channel capacity it preserves rather than for raw attention mass. 논문은 축출을 국소 정보 기하의 관점에서 다시 생각하며, 어텐션을 비선형 가우시안 통신 채널로 모형화한다. 어텐션 사상의 1차 테일러 전개에서 Jacobian Information Capacity가 나오는데, 이 목적함수는 질의 관련성, softmax 민감도, 구조적 다양성을 명시적으로 함께 담는다. 기존 휴리스틱은 이 셋 중 하나씩만 잡아낸다. Jacap은 그 목적을 softmax를 의식한 중요도 가중과 부분집합 선택용 통계적 레버리지 점수로 구현하므로, 살아남는 집합은 어텐션 총량이 아니라 얼마나 많은 채널 용량을 보존하는지로 선택된다.
Results결과 Across diverse architectures and benchmarks, Jacap delivers superior performance in most scenarios, and the authors single out high-compression regimes as where the advantage is clearest — consistent with the claim that heuristics degrade fastest exactly where the budget is tightest. 다양한 아키텍처와 벤치마크에서 Jacap은 대부분의 시나리오에서 더 나은 성능을 낸다. 저자들은 그 이점이 가장 분명한 곳으로 고압축 영역을 꼽는데, 휴리스틱이 예산이 가장 빡빡한 바로 그곳에서 가장 빠르게 나빠진다는 주장과 일치한다.
Summary요약 Plainly: instead of asking which tokens got the most attention, ask how much of attention's information-carrying capacity you lose by dropping them — and derive that loss from the softmax's own local sensitivity. It is a rare eviction paper that starts from an objective rather than an observation. 쉽게 말하면, 어느 토큰이 어텐션을 가장 많이 받았는지를 묻는 대신, 그 토큰을 버리면 어텐션의 정보 전달 용량이 얼마나 줄어드는지를 묻고, 그 손실을 softmax 자체의 국소 민감도에서 유도한다. 관찰이 아니라 목적함수에서 출발하는 드문 축출 논문이다.

Problem문제 정의 Every KV-cache compression method trades accuracy, latency and peak memory differently: quantization is cheap but lossy in a particular way, eviction is cheap in memory but throws information away, and low-rank schemes cost compute. Picking one configuration and freezing it means some prompts are compressed harder than they can bear while others waste headroom. A single fixed setting cannot be right across prompts and across resource constraints. KV 캐시 압축 기법은 모두 정확도·지연·최대 메모리를 서로 다르게 교환한다. 양자화는 값싸지만 특정한 방식으로 손실이 있고, 축출은 메모리에서는 값싸지만 정보를 버리며, 저랭크 기법은 연산을 먹는다. 설정 하나를 골라 고정하면 어떤 프롬프트는 견딜 수 없을 만큼 세게 압축되고 다른 프롬프트는 여유를 낭비한다. 고정된 단일 설정은 프롬프트 전반과 자원 제약 전반에서 옳을 수 없다.
Method방법 MetaKV turns the choice into a per-prompt decision under user-specified latency and peak-memory budgets. Lightweight predictors estimate three quantities for every candidate configuration — end-to-end latency, peak memory, and the probability that the answer will be correct — and the framework picks the configuration that satisfies both constraints while preserving accuracy. The candidate pool spans ten configurations drawn from three representative families (KVQuant, H₂O, RocketKV) plus an uncompressed FP16 option, so the selector can also decide not to compress at all. MetaKV는 그 선택을 사용자가 지정한 지연·최대 메모리 예산 아래에서 프롬프트별 결정으로 바꾼다. 가벼운 예측기가 모든 후보 설정에 대해 세 값을 추정한다 — 엔드투엔드 지연, 최대 메모리, 그리고 답이 맞을 확률 — 그리고 프레임워크는 두 제약을 만족시키면서 정확도를 지키는 설정을 고른다. 후보 풀은 대표 계열 세 곳(KVQuant, H₂O, RocketKV)에서 뽑은 설정 열 개에 압축하지 않는 FP16 옵션을 더한 것이어서, 선택기가 아예 압축하지 않기로 결정할 수도 있다.
Results결과 On four datasets covering mathematics, science, commonsense reasoning and reading comprehension, and across a wide range of latency and peak-memory constraints, MetaKV consistently beats the best static configuration. The metric is constrained success rate — the fraction of prompts answered correctly while satisfying both constraints — which improves by about 0.07 on average and by up to 0.135. 수학·과학·상식 추론·독해를 포괄하는 네 데이터셋에서, 그리고 넓은 범위의 지연·최대 메모리 제약에서 MetaKV는 최적 정적 설정을 일관되게 앞선다. 지표는 제약 성공률(constrained success rate), 즉 두 제약을 만족하면서 정답을 낸 프롬프트의 비율이고, 평균 약 0.07, 최대 0.135 개선된다.
Summary요약 Rather than proposing an eleventh compression method, MetaKV treats the existing ten as a menu and learns a per-request maître d'. The interesting metric choice is that a wrong answer and a blown latency budget count as the same kind of failure. 열한 번째 압축 기법을 제안하는 대신, MetaKV는 기존 열 개를 메뉴로 보고 요청별 안내인을 학습한다. 흥미로운 지표 선택은 틀린 답과 터진 지연 예산을 같은 종류의 실패로 센다는 점이다.

Problem문제 정의 Continuous batching raises throughput, but a long prompt's prefill sitting in the same iteration as other requests' decode steps delays those steps and blows inter-token latency targets. Chunked prefill exists to soften that interference, and in practice the chunk size is a fixed number someone tuned once. Small chunks protect decode latency but pay kernel-launch overhead again and again; large chunks are efficient but produce latency spikes. 연속 배칭은 처리량을 올리지만, 긴 프롬프트의 프리필이 다른 요청의 디코드 스텝과 같은 이터레이션에 앉으면 그 스텝들을 지연시키고 토큰 간 지연 목표를 터뜨린다. 청크 프리필은 그 간섭을 완화하려고 있는 장치이고, 실무에서 청크 크기는 누군가 한 번 튜닝해 둔 고정 숫자다. 작은 청크는 디코드 지연을 보호하지만 커널 런치 오버헤드를 반복해서 내고, 큰 청크는 효율적이지만 지연 스파이크를 만든다.
Method방법 SLOWeave is an online scheduler that, at each iteration, selects the largest prefill chunk predicted to finish before the earliest active decode deadline. No workload-specific chunk-size tuning is required: the decision is a logarithmic-time search over a monotone iteration-cost model. The paper also proves the policy optimal in a useful sense — whenever a decode-only iteration is feasible and the cost predictor is accurate, SLOWeave maximizes immediate prefill progress among all decisions that preserve every active request's next-token deadline. SLOWeave는 매 이터레이션에서 가장 이른 활성 디코드 기한 전에 끝날 것으로 예측되는 가장 큰 프리필 청크를 고르는 온라인 스케줄러다. 워크로드별 청크 크기 튜닝은 필요 없다. 결정은 단조 이터레이션 비용 모델에 대한 로그 시간 탐색이다. 논문은 이 정책이 쓸모 있는 의미에서 최적임도 증명한다. 디코드 전용 이터레이션이 가능하고 비용 예측기가 정확할 때, SLOWeave는 모든 활성 요청의 다음 토큰 기한을 지키는 결정들 가운데 즉각적인 프리필 진척을 최대화한다.
Results결과 Evaluated in a reproducible event-driven simulator and an iteration-level GPU runtime across chat, mixed-context, long-context and bursty workloads. Under a 25 ms time-per-output-token objective, goodput improves over the strongest fixed-chunk baseline by 39% on mixed requests and 38% on long-context requests; under a stricter 10 ms objective the gains rise to 3.3x and 2.4x respectively. The tighter the SLO, the more the fixed chunk size costs you. 재현 가능한 이벤트 기반 시뮬레이터와 이터레이션 수준 GPU 런타임에서 채팅·혼합 문맥·긴 문맥·버스트 워크로드로 평가했다. 출력 토큰당 25 ms 목표에서 굿풋이 최강 고정 청크 기준선 대비 혼합 요청 39%, 긴 문맥 요청 38% 개선되고, 더 엄격한 10 ms 목표에서는 각각 3.3배와 2.4배로 커진다. SLO가 빡빡할수록 고정 청크 크기가 비싸진다.
Summary요약 The primitive is small and implementation-ready: keep a monotone cost model of iteration time, read off the earliest decode deadline, and binary-search the biggest chunk that fits under it. Adaptive chunk sizing is isolated here as a serving primitive in its own right rather than a tuning knob. 프리미티브는 작고 바로 구현할 수 있다. 이터레이션 시간의 단조 비용 모델을 유지하고, 가장 이른 디코드 기한을 읽고, 그 아래 들어가는 최대 청크를 이진 탐색한다. 적응형 청크 크기 조정이 여기서는 튜닝 손잡이가 아니라 독립적인 서빙 프리미티브로 분리된다.

Analytical Resource Management for Fine-grained MoE Computation-Communication OverlapMoE servingSM residencyarXiv:2609.07536

Problem문제 정의 Fine-grained overlap in distributed MoE inference lets communication start as soon as partial compute results are ready. The catch is that the compute CTAs and the communication CTAs compete for the same finite residency capacity on each SM, and a resident CTA generally holds its resources until it finishes. CTAs that cannot become co-resident have to wait, which turns execution into waves. A fixed partition of SM resources cannot track changes in input size, routed expert load and kernel configuration, so it either backs up communication or starves expert compute parallelism. 분산 MoE 추론의 세밀한 오버랩은 부분 연산 결과가 준비되는 즉시 통신을 시작하게 해 준다. 문제는 연산 CTA와 통신 CTA가 각 SM의 동일한 유한 상주 용량을 두고 경쟁하고, 상주 CTA는 보통 끝날 때까지 자기 자원을 붙잡고 있다는 점이다. 공동 상주하지 못한 CTA는 기다려야 하고, 그래서 실행이 물결 모양이 된다. SM 자원의 고정 분할은 입력 크기, 라우팅된 전문가 부하, 커널 설정의 변화를 따라갈 수 없어 통신이 밀리거나 전문가 연산 병렬성이 굶는다.
Method방법 The paper presents a wave-quantized analytical model plus a launch-time resource manager for dependency-coupled overlap pipelines. Problem문제 정의 Multi-agent LLM systems solve a task by coordinating several policies in one shared environment. Terence Tao: AI is mining mathematics' open problems like a non-renewable resource Sep 9

Tao's argument, as summarized on GeekNews: you can generate infinitely many mathematical problems, but good open problems — the ones that yield insight — are different, and consuming them non-renewably can make productive research questions scarce. Choosing good problems requires knowing the difficulty landscape, which shows what existing techniques make easy, hard or impossible; powerful solvers flatten that landscape and make promising questions harder to spot. Current AI lowers difficulty across many areas without clearly marking the boundary between solvable and hard, and rapid technical change plus companies keeping failures and solution traces private deepens the effect. Because even a rumour that someone is working on a problem can trigger large-scale AI attempts at it, researchers gain an incentive to keep promising directions private — which he argues erodes the tradition of open science. GeekNews가 정리한 Tao의 논지는 이렇다. 수학 문제는 무한히 만들 수 있지만 통찰을 낳는 좋은 미해결 문제는 다르며, 그것을 재생 불가능한 방식으로 소모하면 유익한 연구 문제가 희소해질 수 있다. 좋은 문제를 고르려면 기존 기법으로 무엇이 쉽고 어렵고 불가능한지 보여주는 난이도 지형을 알아야 하는데, 강력한 해결 도구는 그 지형을 평탄하게 만들어 유망한 질문을 찾기 어렵게 한다. 현재 AI는 여러 분야의 난이도를 낮추면서도 풀 수 있는 문제와 어려운 문제의 경계를 분명히 드러내지 않고, 빠른 기술 변화에 기업이 실패 결과와 풀이 과정을 비공개로 두는 관행이 겹쳐 이를 심화한다. 누군가 연구 중이라는 소문만으로도 대규모 AI 풀이 시도가 촉발되므로 연구자에게는 유망한 방향을 비공개로 유지할 유인이 생기는데, 그것이 공개 과학의 전통을 훼손한다는 것이 그의 주장이다.
