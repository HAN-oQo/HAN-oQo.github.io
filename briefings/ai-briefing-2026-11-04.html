CISA: Retrofitting Dense Attention Models with Chunk-Indexed Sparse Attentionsparse attentionlong contextarXiv:2611.03200
arxiv.org/abs/2611.03200 →

Problem문제 정의Long-context LLM inference is costly because attention repeatedly reads a growing key-value history.긴 컨텍스트 LLM 추론은 어텐션이 계속 늘어나는 KV 기록을 반복해서 읽기 때문에 비싸다.

Method방법Chunk-Indexed Sparse Attention (CISA) retrofits pretrained dense models without gradient updates. It selects fixed-size KV chunks from compact summaries of existing keys, so there is no token-level index or separate full-length index cache. One indexing query per KV group is shared across the group, and QShare reuses selections across adjacent prefill queries.청크 인덱스 희소 어텐션(CISA)은 경사 업데이트 없이 사전학습된 밀집 모델을 개조한다. 기존 키의 압축 요약으로 고정 크기 KV 청크를 고르므로 토큰 단위 인덱스나 전체 길이 별도 인덱스 캐시가 필요 없다. KV 그룹당 인덱싱 쿼리 하나를 그룹이 공유하고, QShare는 인접한 프리필 쿼리 사이에서 선택을 재사용한다.

Results결과On NVIDIA Nemotron 3 Nano and Ultra and Inkling-Small, one-layer BF16 benchmarks at batch size 32 with Ultra’s per-device attention dimensions show core attention 11.7x faster for prefill queries near the end of a 1M-token prompt and 13.0x faster during decode.NVIDIA Nemotron 3 Nano·Ultra와 Inkling-Small에서, Ultra의 장치당 어텐션 차원으로 배치 크기 32의 단일 레이어 BF16 벤치마크를 돌리면 100만 토큰 프롬프트 끝부근 프리필 쿼리에서 핵심 어텐션이 11.7배, 디코드에서 13.0배 빠르다.

Summary요약Chunk summaries plus shared selection turn a dense checkpoint into a sparse-attention model with no training.청크 요약과 공유 선택만으로 학습 없이 밀집 체크포인트를 희소 어텐션 모델로 바꾼다.

AttentionIndex: Accelerating Learned Sparse Attention with a Causal Inverted-File Indexsparse attentionlong contextarXiv:2611.02508
arxiv.org/abs/2611.02508 →

Problem문제 정의Learned sparse attention, used in production models such as DeepSeek-V4 and GLM-5, lets each query attend to only k keys chosen by a lightweight indexer, but the indexer still scores every key in the prefix. At one million tokens, selection takes more than half of prefill time.DeepSeek-V4와 GLM-5 같은 상용 모델이 쓰는 학습형 희소 어텐션은 경량 인덱서가 고른 k개의 키만 쿼리가 보게 하지만, 인덱서는 여전히 프리픽스의 모든 키를 채점한다. 100만 토큰에서는 이 선택이 프리필 시간의 절반 넘게를 차지한다.

Method방법AttentionIndex routes each query over an inverted-file index that groups indexer keys by similarity, then refines candidates with the native indexer score. The index is built during prefill so new keys are searchable at once, previous clustering is reused to keep maintenance cheap, and each query sees only clusters built from its own prefix.AttentionIndex는 인덱서 키를 유사도로 묶은 역파일 인덱스 위에서 각 쿼리를 라우팅하고, 후보를 원래 인덱서 점수로 다듬는다. 인덱스는 프리필 중에 만들어 새 키를 바로 검색할 수 있고, 이전 군집을 재사용해 유지 비용을 낮추며, 각 쿼리는 자신의 프리픽스로 만든 군집만 본다.

Results결과The method is evaluated on GLM-5.3 and DeepSeek-V4-Flash at one million tokens; its blockwise two-stage baseline, HiSA, loses recall as context grows at a fixed candidate budget.방법은 100만 토큰의 GLM-5.3과 DeepSeek-V4-Flash에서 평가되었으며, 블록 단위 2단계 기준선인 HiSA는 후보 예산이 고정이면 컨텍스트가 늘수록 재현율이 떨어진다.

Summary요약A causal inverted-file index replaces the full-prefix indexer scan, so sparse-attention selection stops dominating long-prefill time.인과적 역파일 인덱스가 전체 프리픽스 인덱서 스캔을 대체해, 희소 어텐션 선택이 긴 프리필 시간을 지배하지 않게 한다.

Problem문제 정의LLM coding agents can increasingly automate model post-training, but whether they can act as forward-deployed engineer (FDE) agents, discovering customer requirements and turning them into deployment decisions, is unclear.LLM 코딩 에이전트는 모델 후속 학습을 점점 더 자동화할 수 있지만, 고객 요구사항을 발굴해 배포 결정으로 바꾸는 전방 배치 엔지니어(FDE) 에이전트로 일할 수 있는지는 불분명하다.

Method방법The study uses a real enterprise text-to-SQL engagement. A simulated customer grounded in the real requirements starts with an ambiguous request; in the discovery phase the agent must find acceptance criteria, data permissions and hardware constraints, then in the delivery phase plan and execute a post-training recipe.연구는 실제 기업 text-to-SQL 프로젝트를 사용한다. 실제 요구사항에 기반한 가상 고객이 모호한 요청으로 시작하고, 에이전트는 발굴 단계에서 수용 기준, 데이터 권한, 하드웨어 제약을 찾은 뒤 전달 단계에서 후속 학습 레시피를 계획하고 실행해야 한다.

Results결과Across 15 models, the strongest discover over 80% of withheld requirements while open-weight models discover 40-50%. In the delivery phase only 25% of runs across eight coding-agent configurations pass all acceptance criteria.15개 모델 중 가장 강한 모델은 숨겨진 요구사항의 80% 넘게 찾고 오픈 웨이트 모델은 40~50%를 찾는다. 전달 단계에서는 8개 코딩 에이전트 구성의 실행 중 25%만 모든 수용 기준을 통과한다.

Summary요약Agents find most hidden requirements but rarely carry a customer engagement through to a delivery that meets every criterion.에이전트는 숨겨진 요구사항 대부분을 찾지만 모든 기준을 충족하는 납품까지 고객 프로젝트를 끌고 가는 경우는 드물다.
