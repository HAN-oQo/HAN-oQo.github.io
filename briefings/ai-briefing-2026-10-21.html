TokenGate: Adapting LLMs for Fast and Memory-Efficient Prefill with Learned Token Pruningprefilltoken pruningarXiv:2610.26754
arxiv.org/abs/2610.26754 →

Problem문제 정의Language models push every input token through every layer, so long inputs such as code repositories or long documents are expensive to prefill. Skilled readers skim instead, and the paper asks a model to learn to do the same.언어 모델은 모든 입력 토큰을 모든 레이어에 통과시키므로 코드 저장소나 긴 문서 같은 긴 입력은 프리필 비용이 크다. 숙련된 독자는 훑어 읽는다는 점에서 착안해, 모델이 스스로 그렇게 하도록 학습시키는 것이 이 논문의 목표다.

Method방법TokenGate is a small component added to an already trained model that learns token pruning end to end. Because top-K selection is not differentiable, the authors introduce token-gated attention, inspired by Mixture-of-Experts, which reweights attention logits with per-token importance scores. Adaptation is lightweight and comparable to parameter-efficient fine-tuning.TokenGate는 이미 학습된 모델에 붙이는 작은 구성 요소로, 토큰 가지치기를 엔드투엔드로 학습한다. top-K 선택은 미분이 되지 않으므로 Mixture-of-Experts에서 착안한 토큰 게이트 어텐션을 도입해 토큰별 중요도 점수로 어텐션 로짓을 재가중한다. 적응 비용은 파라미터 효율적 미세조정과 비슷한 수준이다.

Results결과The paper reports 1.4–11.3x faster time-to-first-token and 1.5–3.4x lower peak memory with no accuracy degradation. Against the best prior token-pruning methods it reaches up to 6.4x faster prefill and 2x lower peak memory, on standard transformers such as Qwen3 and hybrid-attention models such as Qwen3.5.논문은 정확도 저하 없이 첫 토큰까지의 시간이 1.4~11.3배 빨라지고 최대 메모리가 1.5~3.4배 줄었다고 보고한다. 기존 최고 토큰 가지치기 기법 대비 프리필이 최대 6.4배 빠르고 최대 메모리는 2배 낮으며, Qwen3 같은 표준 트랜스포머와 Qwen3.5 같은 하이브리드 어텐션 모델 모두에 적용된다.

Summary요약A learned gate that decides which tokens survive each layer turns prefill pruning into a trainable, drop-in addition to existing models.레이어마다 어떤 토큰을 살릴지 정하는 학습형 게이트로, 프리필 가지치기를 기존 모델에 얹는 학습 가능한 추가 모듈로 만든다.

ReAnchor: Reusing Rejected Verifier States for Diffusion Draftingspeculative decodingdiffusion drafterarXiv:2610.26531
arxiv.org/abs/2610.26531 →

Problem문제 정의Block diffusion drafters speed up speculative decoding by drafting several tokens in one forward pass, but each pass yields only a fixed-length block from a single target-generated anchor. Verification also computes hidden states past the first rejected position, and those are usually thrown away.블록 확산 드래프터는 한 번의 순전파로 여러 토큰을 초안으로 만들어 추측 디코딩을 빠르게 하지만, 한 번에 타깃이 만든 단일 앵커에서 고정 길이 블록만 얻는다. 검증 과정은 첫 거절 위치 이후의 은닉 상태도 계산하는데, 이는 보통 버려진다.

Method방법ReAnchor is training-free: it re-anchors a pretrained drafter at shifted positions, feeding it the discarded verifier states to generate extra parallel draft blocks. These blocks improve predictions inside the original block and extend coverage beyond its endpoint.ReAnchor는 추가 학습이 필요 없다. 사전학습된 드래프터를 이동된 위치에 다시 앵커링하고, 버려지던 검증기 상태를 입력해 병렬 초안 블록을 더 만든다. 이 블록들이 원래 블록 내부의 예측을 개선하고 블록 끝 너머까지 범위를 넓힌다.

Results결과At temperature 0, the largest average gains are on Gemma 4-12B: acceptance length up 19.4% and decoding speed up 17.9% across eight benchmarks. Averaged over four target models and eight benchmarks with pretrained DFlash drafters, acceptance length improves 15.2% and decoding speed 13.4%.온도 0에서 가장 큰 평균 이득은 Gemma 4-12B로, 8개 벤치마크에서 수용 길이 19.4%, 디코딩 속도 17.9% 향상됐다. 사전학습된 DFlash 드래프터로 4개 타깃 모델과 8개 벤치마크를 평균하면 수용 길이 15.2%, 디코딩 속도 13.4% 개선이다.

Summary요약Recycling hidden states the verifier already computed gives diffusion drafters more reach at no training cost.검증기가 이미 계산한 은닉 상태를 재활용해 추가 학습 없이 확산 드래프터의 도달 범위를 넓힌다.

Understanding KV Residency in Production-Scale Agentic LLM WorkloadsKV cacheagentic tracesarXiv:2610.22863
arxiv.org/abs/2610.22863 →

Problem문제 정의Agentic LLM applications run chains of model and tool calls over a growing context. Keeping that context’s KV cache in GPU memory avoids recomputation, but at fleet scale it needs a large amount of memory.에이전트형 LLM 애플리케이션은 커지는 컨텍스트 위에서 모델 호출과 도구 호출을 이어 간다. 그 컨텍스트의 KV 캐시를 GPU 메모리에 두면 재계산을 피하지만, 플릿 규모에서는 막대한 메모리가 든다.

Method방법The authors analyze four production Microsoft M365 traces (Deep Research, Enterprise Assistant, Coding Agent, Enterprise Chat) covering more than 121 million model calls, using the public Llama-2-70B KV layout as a stand-in and trace-driven replay. They also propose multi-resolution retention (MRR), which demotes the least-recently-used session’s KV state to int4.저자들은 Microsoft M365의 실서비스 트레이스 4종(Deep Research, Enterprise Assistant, Coding Agent, Enterprise Chat)의 1억 2,100만 건이 넘는 모델 호출을 분석한다. 공개된 Llama-2-70B KV 구조를 대용으로 쓰고 트레이스 기반 재생을 수행하며, 가장 오래 쓰이지 않은 세션의 KV 상태를 int4로 강등하는 다중 해상도 보존(MRR)도 제안한다.

Results결과Deep Research issues 89% of model calls, and its median context grows from about 10K to 68K tokens by the 30th call. At one tenth of peak-hour demand, 63% of Deep Research calls recompute under LRU eviction versus 13.6% with MRR; when the next call lands on a different deployment, cached-context reuse drops from 89% to 29%.Deep Research가 모델 호출의 89%를 차지하며 중앙값 컨텍스트가 30번째 호출까지 약 10K에서 68K 토큰으로 커진다. 최대 시간대 수요의 10분의 1에서 LRU 제거 시 Deep Research 호출의 63%가 재계산하는 반면 MRR은 13.6%이고, 다음 호출이 다른 배포로 가면 캐시된 컨텍스트 재사용률이 89%에서 29%로 떨어진다.

Summary요약Eviction alone is not enough for agentic fleets; the authors argue for changing how KV state is represented while retained, together with deployment-aware routing or migration.에이전트형 플릿에서는 제거 정책만으로는 부족하다. 저자들은 보존 중인 KV 상태의 표현 방식을 바꾸고 배포를 인지하는 라우팅이나 마이그레이션을 함께 쓸 것을 주장한다.

Efficient KV Cache Migration for Geo-Distributed LLM Inference in Collaborative Edge ComputingKV migrationedgearXiv:2610.22172
arxiv.org/abs/2610.22172 →

Problem문제 정의Collaborative edge computing pools several geo-distributed, heterogeneous edge servers that jointly host model shards and their KV cache. Servers can disconnect or become overloaded, so KV cache must migrate, and cloud methods such as direct GPU-to-GPU transfer or recomputation from input tokens do not suit bandwidth-limited edge links.협업 엣지 컴퓨팅은 지리적으로 분산된 이기종 엣지 서버 여러 대를 묶어 모델 샤드와 KV 캐시를 함께 호스팅한다. 서버가 끊기거나 과부하가 걸리면 KV 캐시를 옮겨야 하는데, GPU 간 직접 전송이나 입력 토큰부터의 재계산 같은 클라우드 방식은 대역폭이 제한된 엣지에 맞지 않는다.

Method방법EdgeFlow is a hybrid scheme that combines direct KV cache transmission with activation-based recomputation, running computation and communication in parallel. Multi-node KV migration is formulated as an optimization problem and solved with a 2-approximation algorithm based on an improved linear-programming relaxation and bipartite-graph techniques.EdgeFlow는 KV 캐시 직접 전송과 활성값 기반 재계산을 결합하고 계산과 통신을 병렬로 수행하는 하이브리드 방식이다. 다중 노드 KV 마이그레이션을 최적화 문제로 정식화하고, 개선된 선형계획 완화와 이분 그래프 기법에 기반한 2-근사 알고리즘으로 푼다.

Results결과Experiments on a real-world distributed LLM inference platform show that EdgeFlow reduces migration time by up to 45%.실제 분산 LLM 추론 플랫폼에서의 실험에서 EdgeFlow는 마이그레이션 시간을 최대 45% 줄인다.

Summary요약Splitting migration between sending KV bytes and recomputing from activations, in parallel, makes failover cheaper on slow edge links.마이그레이션을 KV 바이트 전송과 활성값 재계산으로 나눠 병렬로 처리해, 느린 엣지 링크에서의 장애 전환 비용을 낮춘다.

Problem문제 정의LLM agents increasingly act as planners that call several expert models, each with its own weights, but serving systems assume all needed models fit in GPU memory. On memory-constrained GPUs, whole-model swapping stalls computation, and switching models without host-backed KV restoration discards session state.LLM 에이전트는 각자 가중치를 가진 여러 전문가 모델을 호출하는 플래너로 점점 쓰이지만, 서빙 시스템은 필요한 모델이 모두 GPU 메모리에 들어간다고 가정한다. 메모리가 제한된 GPU에서는 모델 전체 교체가 연산을 멈추게 하고, 호스트 기반 KV 복원 없이 모델을 바꾸면 세션 상태가 사라진다.

Method방법JointServe treats weight shards and KV-cache blocks as residency objects competing for one unified memory budget. It prefetches on an intent signal parsed from the caller’s output stream, loads only incremental layers on a switch via partial residency, and uses a preemptive transfer scheduler that guarantees live-session KV a bandwidth share, with a control step rebalancing the weight/KV split.JointServe는 가중치 샤드와 KV 캐시 블록을 하나의 통합 메모리 예산을 두고 경쟁하는 상주 객체로 다룬다. 호출자의 출력 스트림에서 파싱한 의도 신호로 미리 읽어 오고, 부분 상주로 전환 시 추가 레이어만 적재하며, 활성 세션 KV에 대역폭 몫을 보장하는 선점형 전송 스케줄러를 쓴다. 제어 단계가 가중치/KV 비율을 재조정한다.

Results결과Session completion time drops 21.7% versus the strongest whole-model-swap baseline, and by up to 49% on replayed SWE-bench, tau-bench and OSWorld traces. SLO attainment rises from 2.8–24.5% to 76.8–100%, and JointServe stays usable in a regime where every swap baseline fails to finish.가장 강한 모델 전체 교체 기준선 대비 세션 완료 시간이 21.7% 줄고, SWE-bench·tau-bench·OSWorld 트레이스 재생에서는 최대 49% 줄어든다. SLO 달성률은 2.8~24.5%에서 76.8~100%로 오르며, 모든 교체 기준선이 끝내지 못하는 구간에서도 JointServe는 동작한다.

Summary요약Managing weights and KV as one pool, and prefetching on the caller’s intent, lets multi-model agents run on GPUs that cannot hold every model at once.가중치와 KV를 하나의 풀로 관리하고 호출자의 의도에 맞춰 미리 읽어 와, 모든 모델을 한꺼번에 담지 못하는 GPU에서도 다중 모델 에이전트를 돌린다.

Same Simulation, Different Evidence: Where Retrieved Tool Output Costs LLM Agents Accuracytool useagent harnessarXiv:2610.26836
arxiv.org/abs/2610.26836 →

Problem문제 정의Agent harnesses often save long tool outputs to files that the agent must search or read on demand instead of keeping them in context. It is unclear where this costs accuracy even when the agent computes the right result.에이전트 하니스는 긴 도구 출력을 컨텍스트에 두지 않고 에이전트가 필요할 때 검색하거나 읽어야 하는 파일로 저장하는 경우가 많다. 에이전트가 올바른 결과를 계산하더라도 이것이 어디에서 정확도를 떨어뜨리는지는 분명하지 않았다.

Method방법The authors use PHREEQC, a USGS geochemistry simulator whose reports reach 846.8k characters, with 158 execution-verified multiple-choice questions. They compare reading reports through a section index against reading them in context, and re-run all 11,007 logged simulator calls to separate computation errors from evidence errors.저자들은 보고서가 최대 84만 6,800자에 이르는 USGS 지구화학 시뮬레이터 PHREEQC와 실행으로 검증된 객관식 158문항을 사용한다. 섹션 색인을 통해 보고서를 읽는 경우와 컨텍스트 안에서 읽는 경우를 비교하고, 기록된 시뮬레이터 호출 11,007건을 모두 재실행해 계산 오류와 증거 오류를 분리한다.

Results결과With section-index retrieval, GPT-5.1 and GPT-5.2 lose 11.3 and 7.9 accuracy points, while Claude Opus 4.6 and Claude Sonnet 4.6 show no detectable loss. The GPT models still compute the keyed value about as often; they answer from the wrong evidence, which the authors call evidence substitution. Naming the authoritative output raises accuracy by 6.3–7.9 points for the three GPT models.섹션 색인 검색에서는 GPT-5.1과 GPT-5.2가 정확도를 11.3점, 7.9점 잃지만 Claude Opus 4.6과 Claude Sonnet 4.6은 눈에 띄는 손실이 없다. GPT 모델들도 정답 값을 계산하는 빈도는 비슷하며, 잘못된 증거로 답하는 것이 문제이고 저자들은 이를 증거 대체라 부른다. 권위 있는 출력을 명시해 주면 GPT 모델 세 종에서 정확도가 6.3~7.9점 오른다.

Summary요약Where a harness puts tool output can change accuracy without changing the computation, so context-management choices should be judged by where accuracy is lost.하니스가 도구 출력을 어디에 두느냐가 계산은 그대로인 채 정확도를 바꿀 수 있으므로, 컨텍스트 관리 선택은 정확도가 어디서 손실되는지로 평가해야 한다.

Problem문제 정의Agent harnesses control what a model sees across turns by dropping old turns, summarizing them or replaying earlier reasoning. Method방법A pre-registered synthetic probe truncates the context window when a needed fact can or cannot be looked up again, with a replication on a second provider’s model.
