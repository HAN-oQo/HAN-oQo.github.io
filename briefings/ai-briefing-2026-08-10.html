Routing LLM Inference to the Cleanest Grid in Real Timeschedulingcarbon-aware routing2608.06188
Carbon-aware inference routing — steer requests to low-emission regions (arXiv 2608.06188) ↗탄소 인지 추론 라우팅: 배출이 적은 리전으로 요청 분배 (arXiv 2608.06188) ↗
Problem문제 정의LLM inference is a fast-growing electricity load whose marginal carbon intensity varies by more than an order of magnitude across grid regions and across the day. Request placement is an attractive lever because it needs no retraining and no hardware change, but prior work rarely validates it live against a real production router with per-request energy measured from telemetry.LLM 추론 전력의 한계 탄소 집약도는 리전과 시간대에 따라 10배 이상 차이 난다. 요청 배치는 재학습 없이 쓸 수 있는 수단이지만, 실제 프로덕션 라우터에서 요청별 실측 에너지로 검증한 사례는 드물었다.
Method방법The authors route inference across multi-region GPU testbeds using marginal operating emissions rate (MOER) signals, as a strict, reversible overlay on top of a production pressure-based router. Per-request energy is attributed from NVIDIA DCGM GPU telemetry via measured concurrency curves rather than nameplate TDP, and every request is carbon-settled against historical MOER, not just the forecast that drove the decision.기존 프로덕션 라우터 위에 되돌릴 수 있는 오버레이를 얹어 MOER(한계 운영 배출률) 신호로 리전을 고른다. 요청별 에너지는 NVIDIA DCGM 텔레메트리로 실측하고, 탄소는 실제 과거 MOER로 정산한다.
Results결과Live, a MOER signal steered inference across regions with no observed dispatch failures. Replaying a year of hourly MOER across a grid-diverse CONUS fleet, carbon-aware placement cut modeled GPU-attributable operational emissions by 50.9% versus round-robin (95% CI 48.5–53.3%); hourly lowest-MOER routing added about 22.4 percentage points, roughly 40% of the reduction, beyond a static annual-mean policy.라이브에서 디스패치 실패 없이 동작했다. 1년치 시간별 MOER 재생에서 배출이 라운드로빈 대비 50.9% 줄었고(95% CI 48.5–53.3%), 그중 약 22.4%p(감축량의 약 40%)는 시간별 최저 MOER 라우팅 몫이다.
Summary요약A practical, reversible carbon-aware layer over an existing router can roughly halve GPU-attributable inference emissions with no model or hardware changes — though the replay figure is an upper bound that forecast error would erode. A key operational tip: rank regions by absolute MOER, not the within-region percentile index.라우터 위 계층만으로 추론 배출을 대략 절반으로 줄일 수 있지만, 재생 수치는 예측 오차를 뺀 상한이다. 리전 순위는 리전 내 백분위가 아니라 절대 MOER로 매겨야 한다.

TensorCast: The Missing Tensor Management Layer in LLM InfrastructureKV-cacheserving infra2608.06007
Tensor-as-a-Service — one abstraction for weights, KV cache, checkpoints (arXiv 2608.06007) ↗Tensor-as-a-Service: 가중치·KV 캐시·체크포인트를 하나의 추상화로 (arXiv 2608.06007) ↗
Problem문제 정의Modern LLM infrastructure treats tensors not just as compute data but as persistent state shared across distributed components. Today each task — weight loading, KV cache management, checkpoint sync — is optimized by deeply fusing task-specific logic into engines, networks, or storage, creating isolated silos that block reuse and composition across evolving workloads.LLM 인프라에서 텐서는 여러 컴포넌트가 공유하는 지속 상태다. 그런데 가중치 로딩, KV 캐시 관리, 체크포인트 동기화는 저마다 전용 로직으로 박혀 있어 재사용이 어렵다.
Method방법The paper identifies tensor lifecycle management as a missing abstraction layer and proposes Tensor-as-a-Service (TaaS), decoupling tensor state management from computation logic. TensorCast provides first-class tensor abstractions, programmable lifecycle primitives, and a runtime that separates management policy from execution mechanism, so developers write tensor programs that transparently leverage distributed execution and data movement.텐서 상태 관리를 연산에서 떼어 내는 Tensor-as-a-Service(TaaS)를 제안한다. TensorCast는 텐서 추상화, 프로그래머블 생애주기 프리미티브, 정책과 메커니즘을 분리한 런타임을 제공한다.
Results결과Integrated with vLLM and SGLang and evaluated across weight materialization, weight synchronization, KV cache management, and programmable request routing, TensorCast matches specialized systems' performance while enabling new cross-component optimization policies. One programmable policy improves median time-to-first-token (TTFT) by up to 93.2% under highly concurrent multi-turn agent workloads.vLLM·SGLang에 통합해 전용 시스템과 대등한 성능을 냈다. 컴포넌트 간 정책 하나는 동시성 높은 멀티턴 에이전트 워크로드에서 중앙값 TTFT를 최대 93.2% 개선했다.
Summary요약TensorCast argues that the fix for tangled LLM serving stacks is a unifying tensor lifecycle layer rather than yet another point optimization. By making tensor state programmable and portable across engines, it enables cross-component policies (e.g., agent-aware KV routing) that specialized silos cannot express.얽힌 서빙 스택을 풀려면 국소 최적화를 하나 더 얹기보다 텐서 생애주기 계층을 통합해야 한다는 주장이다. 에이전트 인지 KV 라우팅처럼 사일로로는 표현할 수 없던 정책이 가능해진다.

PLoRA: An NDP-Enhanced Pooled-Memory System for Cost-Efficient Multi-LoRA Servingmulti-LoRA servingpooled memory2608.05483
Serve 1000+ LoRA adapters from CXL/NVLink pooled memory with near-data compute (arXiv 2608.05483) ↗CXL/NVLink 풀드 메모리와 근접 데이터 연산으로 1000+ LoRA 어댑터 서빙 (arXiv 2608.05483) ↗
Problem문제 정의Multi-LoRA serving turns one base model into thousands of per-user or per-agent variants, with deployments holding 1000-plus adapters. The workload inverts what GPUs offer — terabytes of memory demand against only tens of TFLOPS — and every published system stages adapters from CPU DRAM over PCIe, paying a kernel stop and host copy per access while capacity ends at the motherboard's DIMM slots.어댑터가 1000개를 넘는 멀티-LoRA 서빙에 필요한 건 연산보다 테라바이트급 메모리다. 기존 시스템은 어댑터를 CPU DRAM에서 PCIe로 옮기느라 커널 정지와 호스트 복사를 치르고, 용량은 DIMM 슬롯 수에 묶인다.
Method방법PLoRA keeps adapters and KV cache in memory-semantic pooled memory (CXL/NVLink) and returns only reduced results over the link, through a read-compute interface the GPU drives with its own loads and stores, with near-data processing (NDP) placed beside the pooled data. A GPU memory manager picks among four LoRA and two attention execution strategies per adapter and caches the most performance-critical bytes in GPU memory, guided by a link-parameterized cost model.어댑터와 KV 캐시를 풀드 메모리(CXL/NVLink)에 두고, 옆의 근접 데이터 처리(NDP)가 계산한 축약 결과만 GPU로 돌려준다. 비용 모델이 어댑터마다 LoRA 전략 4가지, 어텐션 전략 2가지 중 하나를 고른다.
Results결과On one H100 serving 1000 adapters, PLoRA achieves the lowest decode latency on every model and workload measured — averaging 6.6x below a real-machine S-LoRA — at under 3.4% added device area. Throughput saturates at just 32 GB/s on short contexts (a quarter of CXL 3.1), so the link stops mattering; per-GPU demand falls from 7B to a modeled 1.2T deployment once adapter traffic shards with tensor parallelism.어댑터 1000개를 올린 H100 한 장에서 디코드 지연이 실제 머신 S-LoRA보다 평균 6.6배 낮았다(추가 소자 면적 3.4% 미만). 처리량은 32 GB/s(CXL 3.1의 1/4)에서 포화해 링크는 병목이 아니고, 7B에서 1.2T 배포로 갈수록 GPU당 수요가 줄어든다.
Summary요약PLoRA reframes multi-LoRA serving as a memory-capacity problem best solved by pooled memory plus near-data compute, not by faster links. The same design runs unchanged from CXL-class to NVLink-class fabrics, and surplus bandwidth is spent buying pooled capacity rather than speed.멀티-LoRA 서빙을 빠른 링크가 아니라 풀드 메모리와 근접 연산으로 푸는 용량 문제로 다시 정의한다. 같은 설계가 CXL급부터 NVLink급 패브릭까지 그대로 돈다.

RAC: Reference-Aware Activation Compression for Communication-Efficient Split LLM Inferencesplit inferenceactivation compression2608.04991
Compress boundary hidden states with token-reference reuse for split inference (arXiv 2608.04991) ↗토큰 참조 재사용으로 경계 은닉상태를 압축하는 분할 추론 (arXiv 2608.04991) ↗
Problem문제 정의LLM agents repeatedly process long, privacy-sensitive contexts, yet cloud-only deployment exposes user data beyond the trusted endpoint and fully local deployment often needs costly hardware. Split inference runs the model head, tail, and tools locally and the middle layers in the cloud, but its local–cloud–local path transfers boundary hidden states on every invocation, creating a critical communication bottleneck.프라이버시에 민감한 긴 컨텍스트를 클라우드에 맡기면 노출되고, 완전 로컬은 비싸다. 분할 추론(split inference)은 head·tail을 로컬에, 중간 계층을 클라우드에 두지만 경계 은닉상태(boundary hidden states)가 오가며 통신 병목이 생긴다.
Method방법RAC is a reference-aware codec: it retrieves exact-token historical spans for prefill uplinks, reuses the reconstructed uplink state for same-round prefill downlinks, and generates boundary-specific decode references with lightweight causal predictors. It applies grouped affine alignment and calibrated residual quantization (with optional prefill outliers), while sender-side wire-format reconstruction keeps subsequent references synchronized and offline calibration accounts for quality and packed-representation cost.RAC는 프리필 업링크엔 토큰이 일치하는 과거 구간을, 같은 라운드 다운링크엔 복원한 업링크 상태를, 디코드엔 경량 인과 예측기의 참조를 쓰는 참조 인지 코덱이다. 여기에 그룹 아핀 정렬과 보정 잔차 양자화를 더한다.
Results결과Across three models and nine model–link pairs, Raw-to-RAC mean time-to-first-token (TTFT) ratios are 1.24–2.72x and time-per-output-token (TPOT) ratios are 1.01–2.79x, i.e. substantial speedups from cutting boundary traffic. Meanwhile the 12 non-perplexity task-score changes range from just -0.40 to +2.50 points, indicating near-lossless quality.3개 모델, 9개 모델–링크 조합에서 Raw 대비 평균 TTFT 비율은 1.24–2.72배, TPOT 비율은 1.01–2.79배였다. 12개 과제 점수 변화는 -0.40에서 +2.50점 사이로 거의 무손실이다.
Summary요약RAC shows that the boundary hidden states shuttled in split inference are highly compressible if you exploit token-level references from history and same-round reuse, plus calibrated residual quantization. The result is materially lower TTFT/TPOT with negligible task-quality loss, making privacy-preserving split deployments more practical.경계 은닉상태는 과거 토큰 참조와 보정 잔차 양자화로 크게 압축된다. 품질 손실 없이 지연이 줄어 프라이버시 보존형 분할 배포가 현실적이 된다.

Pruning-Aware Multi-Cluster Co-Inference for Large AI Models in AI-RANspruningdistributed inference2608.03026
Jointly tune pruning ratio, scheduling, and radio resources for edge co-inference (arXiv 2608.03026) ↗엣지 협업 추론을 위해 프루닝 비율·스케줄링·무선 자원을 공동 최적화 (arXiv 2608.03026) ↗
Problem문제 정의The growing scale and compute demand of large AI models (LAIMs) make efficient inference hard in resource-constrained distributed settings such as AI radio access networks. Running a full model on-device is infeasible, but naive pruning trades away accuracy, and there is no principled account of how pruning ratios and multi-device contributions jointly shape collaborative inference quality.대형 AI 모델(LAIM)은 AI 무선 접속망(AI-RAN) 같은 제약 환경에서 기기에 통째로 올릴 수 없고, 단순 프루닝은 정확도를 잃는다. 프루닝 비율과 여러 기기의 기여가 협업 추론 품질을 어떻게 함께 결정하는지 설명하는 이론도 없었다.
Method방법The authors propose a multi-cluster co-inference framework in which a multi-GPU edge server coordinates several user clusters. Within each cluster, devices capture data from diverse perspectives and run lightweight on-device LAIMs to extract local features, which are transmitted to the server for aggregation and fusion. A rate-distortion and partial-information-decomposition theory characterizes the pruning-versus-performance trade-off, driving a joint optimization of pruning ratio, task scheduling, bandwidth allocation, and transmit power.다중 GPU 엣지 서버가 여러 클러스터를 조율하고, 기기들은 경량 LAIM으로 뽑은 특징을 서버로 보낸다. 율-왜곡(rate-distortion) 이론과 부분 정보 분해로 프루닝 비율·태스크 스케줄링·대역폭·송신 전력을 함께 최적화한다.
Results결과The joint optimization minimizes inference distortion subject to latency, energy, and server-capacity constraints. Extensive simulations show the framework significantly outperforms benchmark schemes, delivering superior inference accuracy and resource efficiency across multi-cluster edge-intelligence networks.지연·에너지·서버 용량 제약 아래서 추론 왜곡을 최소화한다. 시뮬레이션에서 기존 기법보다 정확도와 자원 효율 모두 크게 앞섰다.
