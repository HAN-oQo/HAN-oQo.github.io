Routing LLM Inference to the Cleanest Grid in Real Timeschedulingcarbon-aware routing2608.06188
Carbon-aware inference routing — steer requests to low-emission regions (arXiv 2608.06188) ↗탄소 인지 추론 라우팅 — 배출이 적은 리전으로 요청 분배 (arXiv 2608.06188) ↗
Problem문제 정의LLM inference is a fast-growing electricity load whose marginal carbon intensity varies by more than an order of magnitude across grid regions and across the day. Request placement is an attractive lever because it needs no retraining and no hardware change, but prior work rarely validates it live against a real production router with per-request energy measured from telemetry.LLM 추론은 빠르게 늘어나는 전력 부하이며, 그 한계 탄소 집약도(marginal carbon intensity)는 전력망 리전마다, 그리고 하루 중 시간대마다 10배 이상 차이가 난다. 요청 배치는 재학습이나 하드웨어 변경 없이 쓸 수 있어 매력적이지만, 기존 연구는 실제 프로덕션 라우터를 상대로, 텔레메트리로 측정한 요청별 에너지를 써서 라이브 검증한 사례가 드물었다.
Method방법The authors route inference across multi-region GPU testbeds using marginal operating emissions rate (MOER) signals, as a strict, reversible overlay on top of a production pressure-based router. Per-request energy is attributed from NVIDIA DCGM GPU telemetry via measured concurrency curves rather than nameplate TDP, and every request is carbon-settled against historical MOER, not just the forecast that drove the decision.저자들은 한계 운영 배출률(MOER) 신호를 이용해 여러 리전의 GPU 테스트베드에 걸쳐 추론을 라우팅하며, 이를 기존 압력 기반 프로덕션 라우터 위에 얹는 엄격하고 되돌릴 수 있는 오버레이로 구현한다. 요청별 에너지는 명판 TDP가 아니라 측정된 동시성 곡선과 NVIDIA DCGM 텔레메트리로 산정하고, 모든 요청은 결정을 내린 예측치가 아니라 실제 과거 MOER에 대해 탄소 정산(settlement)한다.
Results결과Live, a MOER signal steered inference across regions with no observed dispatch failures. Replaying a year of hourly MOER across a grid-diverse CONUS fleet, carbon-aware placement cut modeled GPU-attributable operational emissions by 50.9% versus round-robin (95% CI 48.5–53.3%); hourly lowest-MOER routing added about 22.4 percentage points, roughly 40% of the reduction, beyond a static annual-mean policy.라이브 환경에서 MOER 신호는 관측된 디스패치 실패 없이 리전 간 추론을 유도했다. 전력망이 다양한 미국 본토(CONUS) 플릿에 1년치 시간별 MOER를 재생(replay)한 결과, 탄소 인지 배치는 라운드로빈 대비 모델링된 GPU 귀속 운영 배출을 50.9% 줄였다(95% CI 48.5–53.3%). 시간별 최저 MOER 라우팅은 정적 연평균 정책 대비 약 22.4%p, 즉 감축량의 약 40%를 추가로 기여했다.
Summary요약A practical, reversible carbon-aware layer over an existing router can roughly halve GPU-attributable inference emissions with no model or hardware changes — though the replay figure is an upper bound that forecast error would erode. A key operational tip: rank regions by absolute MOER, not the within-region percentile index.기존 라우터 위에 얹는 실용적이고 되돌릴 수 있는 탄소 인지 계층만으로, 모델·하드웨어 변경 없이 GPU 귀속 추론 배출을 대략 절반으로 줄일 수 있다(단, 재생 수치는 상한값이며 예측 오차가 이를 깎아낸다). 핵심 운영 팁: 리전은 리전 내부 백분위 지수가 아니라 절대 MOER로 순위를 매겨야 한다.

TensorCast: The Missing Tensor Management Layer in LLM InfrastructureKV-cacheserving infra2608.06007
Tensor-as-a-Service — one abstraction for weights, KV cache, checkpoints (arXiv 2608.06007) ↗Tensor-as-a-Service — 가중치·KV 캐시·체크포인트를 하나의 추상화로 (arXiv 2608.06007) ↗
Problem문제 정의Modern LLM infrastructure treats tensors not just as compute data but as persistent state shared across distributed components. Today each task — weight loading, KV cache management, checkpoint sync — is optimized by deeply fusing task-specific logic into engines, networks, or storage, creating isolated silos that block reuse and composition across evolving workloads.현대 LLM 인프라는 텐서를 단순 연산 데이터가 아니라 분산 컴포넌트 간에 공유되는 지속 상태(persistent state)로 다룬다. 하지만 지금은 가중치 로딩, KV 캐시 관리, 체크포인트 동기화 같은 각 작업이 실행 엔진·네트워크·스토리지에 작업별 로직을 깊게 융합해 최적화되어, 서로 고립된 사일로가 되고 변화하는 워크로드에서 재사용·조합을 막는다.
Method방법The paper identifies tensor lifecycle management as a missing abstraction layer and proposes Tensor-as-a-Service (TaaS), decoupling tensor state management from computation logic. TensorCast provides first-class tensor abstractions, programmable lifecycle primitives, and a runtime that separates management policy from execution mechanism, so developers write tensor programs that transparently leverage distributed execution and data movement.이 논문은 텐서 생애주기 관리를 인프라에 빠진 추상화 계층으로 규정하고, 텐서 상태 관리를 연산 로직에서 분리하는 Tensor-as-a-Service(TaaS)를 제안한다. TensorCast는 일급(first-class) 텐서 추상화, 프로그래머블 생애주기 프리미티브, 그리고 관리 정책을 실행 메커니즘에서 분리하는 런타임을 제공해, 개발자가 분산 실행과 데이터 이동을 투명하게 활용하는 텐서 프로그램을 작성하도록 한다.
Results결과Integrated with vLLM and SGLang and evaluated across weight materialization, weight synchronization, KV cache management, and programmable request routing, TensorCast matches specialized systems' performance while enabling new cross-component optimization policies. One programmable policy improves median time-to-first-token (TTFT) by up to 93.2% under highly concurrent multi-turn agent workloads.vLLM·SGLang과 통합해 가중치 구체화(materialization), 가중치 동기화, KV 캐시 관리, 프로그래머블 요청 라우팅에 걸쳐 평가한 결과, TensorCast는 전용 시스템과 대등한 성능을 내면서 새로운 컴포넌트 간 최적화 정책을 가능케 했다. 한 프로그래머블 정책은 고도로 동시적인 멀티턴 에이전트 워크로드에서 중앙값 TTFT를 최대 93.2% 개선했다.
Summary요약TensorCast argues that the fix for tangled LLM serving stacks is a unifying tensor lifecycle layer rather than yet another point optimization. By making tensor state programmable and portable across engines, it enables cross-component policies (e.g., agent-aware KV routing) that specialized silos cannot express.TensorCast는 얽힌 LLM 서빙 스택의 해법이 또 하나의 국소 최적화가 아니라 텐서 생애주기를 통합하는 계층이라고 주장한다. 텐서 상태를 엔진 간에 프로그래머블하고 이식 가능하게 만들어, 고립된 사일로로는 표현할 수 없는 컴포넌트 간 정책(예: 에이전트 인지 KV 라우팅)을 가능하게 한다.

PLoRA: An NDP-Enhanced Pooled-Memory System for Cost-Efficient Multi-LoRA Servingmulti-LoRA servingpooled memory2608.05483
Serve 1000+ LoRA adapters from CXL/NVLink pooled memory with near-data compute (arXiv 2608.05483) ↗CXL/NVLink 풀드 메모리 + 근접데이터 연산으로 1000+ LoRA 어댑터 서빙 (arXiv 2608.05483) ↗
Problem문제 정의Multi-LoRA serving turns one base model into thousands of per-user or per-agent variants, with deployments holding 1000-plus adapters. The workload inverts what GPUs offer — terabytes of memory demand against only tens of TFLOPS — and every published system stages adapters from CPU DRAM over PCIe, paying a kernel stop and host copy per access while capacity ends at the motherboard's DIMM slots.멀티-LoRA 서빙은 하나의 베이스 모델을 사용자별·에이전트별 수천 개 변형으로 바꾸며, 실제 배포는 1000개 이상의 어댑터를 담기도 한다. 이 워크로드는 GPU가 제공하는 것을 뒤집는다 — 수십 TFLOPS 대비 테라바이트급 메모리 수요 — 그리고 지금까지 발표된 모든 시스템은 어댑터를 CPU DRAM에서 PCIe로 스테이징하느라 접근마다 커널 정지와 호스트 복사를 치르고, 용량은 메인보드 DIMM 슬롯에서 끝나 버린다.
Method방법PLoRA keeps adapters and KV cache in memory-semantic pooled memory (CXL/NVLink) and returns only reduced results over the link, through a read-compute interface the GPU drives with its own loads and stores, with near-data processing (NDP) placed beside the pooled data. A GPU memory manager picks among four LoRA and two attention execution strategies per adapter and caches the most performance-critical bytes in GPU memory, guided by a link-parameterized cost model.PLoRA는 어댑터와 KV 캐시를 메모리 시맨틱 풀드 메모리(CXL/NVLink)에 두고, GPU가 자체 load/store로 구동하는 read-compute 인터페이스를 통해 링크로는 축약된 결과만 돌려보내며, 근접 데이터 처리(NDP)를 풀드 데이터 옆에 배치한다. GPU 메모리 관리자는 어댑터마다 4가지 LoRA 실행 전략과 2가지 어텐션 실행 전략 중에서 고르고, 링크 파라미터화 비용 모델의 안내에 따라 성능에 가장 중요한 바이트를 GPU 메모리에 캐싱한다.
Results결과On one H100 serving 1000 adapters, PLoRA achieves the lowest decode latency on every model and workload measured — averaging 6.6x below a real-machine S-LoRA — at under 3.4% added device area. Throughput saturates at just 32 GB/s on short contexts (a quarter of CXL 3.1), so the link stops mattering; per-GPU demand falls from 7B to a modeled 1.2T deployment once adapter traffic shards with tensor parallelism.1000개 어댑터를 서빙하는 H100 한 장에서 PLoRA는 측정한 모든 모델·워크로드에서 최저 디코드 지연을 달성했다 — 실제 머신 S-LoRA 대비 평균 6.6배 낮음 — 그것도 추가 소자 면적 3.4% 미만으로. 짧은 컨텍스트에서 처리량이 단 32 GB/s(CXL 3.1의 1/4)에서 포화되어 링크 대역폭이 더는 병목이 아니며, 어댑터 트래픽이 텐서 병렬화와 함께 샤딩되면 GPU당 수요가 7B에서 모델링된 1.2T 배포까지 낮아진다.
Summary요약PLoRA reframes multi-LoRA serving as a memory-capacity problem best solved by pooled memory plus near-data compute, not by faster links. The same design runs unchanged from CXL-class to NVLink-class fabrics, and surplus bandwidth is spent buying pooled capacity rather than speed.PLoRA는 멀티-LoRA 서빙을 더 빠른 링크가 아니라 풀드 메모리 + 근접 데이터 연산으로 푸는 게 최선인 메모리 용량 문제로 재정의한다. 동일 설계가 CXL급부터 NVLink급 패브릭까지 변경 없이 돌아가며, 남는 대역폭은 속도가 아니라 풀드 용량을 사는 데 쓰인다.
