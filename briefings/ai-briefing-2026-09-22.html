RheoSampling: Resolving the One-Hot Dilemma in Stochastic Dynamic-Tree Speculative Decodingspeculative decodingsamplingarXiv:2609.21827
arxiv.org/abs/2609.21827 →

ProblemDynamic-tree speculative decoding (e.g. EAGLE-3) builds the draft tree from the top-K children at each node with global pruning. That works under greedy decoding, but at any temperature above zero the draft distribution collapses to one-hot and acceptance falls sharply. Dynamic trees give up sampling to keep a context-aware shape; static trees keep sampling with a context-blind shape.EAGLE-3 같은 동적 트리 추측 디코딩은 노드마다 상위 K개 자식을 뽑고 전역으로 가지쳐 초안 트리를 만든다. 그리디에서는 잘 되지만 온도가 0보다 크면 초안 분포가 원-핫으로 무너져 수락률이 급락한다. 동적 트리는 문맥을 반영한 모양을 위해 샘플링을 버리고, 정적 트리는 샘플링을 지키는 대신 문맥을 무시한다.

MethodThe cause: one distribution is doing two conflicting jobs, building the tree and verifying tokens. RheoSampling separates them, building the tree from a context-aware signal while verification keeps the true sampling distribution, and adds a sparse draft mechanism and a verification strategy so the acceptance gain survives into wall-clock time.원인은 분포 하나가 트리 구성과 토큰 검증이라는 충돌하는 두 일을 맡는 데 있다. RheoSampling은 둘을 떼어, 트리는 문맥 인지 신호로 만들고 검증은 진짜 샘플링 분포를 그대로 쓴다. 희소 초안과 전용 검증 전략을 더해 수락률 이득이 실제 시간 단축으로 이어지게 한다.

ResultsAcross several LLMs and benchmarks, RheoSampling beats state-of-the-art dynamic-tree methods on both acceptance rate and end-to-end speedup under stochastic decoding.여러 LLM과 벤치마크의 확률적 디코딩에서 최신 동적 트리 방식보다 수락률과 종단 가속이 모두 높다.

SummaryRead it for the diagnosis. Many serving optimisations quietly assume greedy decoding, and this shows the cost once temperature goes up, which is where most production chat traffic runs.수치보다 진단이 볼 만하다. 많은 서빙 최적화가 그리디 디코딩을 은연중에 가정하는데, 실제 챗 트래픽 대부분이 도는 온도 설정에서 그 가정이 얼마나 비싼지 보여 준다.

SpecQuant: Speculative Decoding with Multi-Parent Quantization for Adaptive LLM Inferencespeculative decodingquantizationarXiv:2609.21704
arxiv.org/abs/2609.21704 →

ProblemLocal LLMs are bound by consumer compute and memory. Quantization, speculative decoding and adaptive inference all speed things up, but usually need retraining, per-architecture tuning, or a separate draft model kept compatible with the target.로컬 LLM은 소비자용 연산과 메모리에 묶인다. 양자화, 추측 디코딩, 적응형 추론은 모두 빨라지게 해 주지만 대개 재학습이나 아키텍처별 튜닝, 혹은 대상 모델과 호환되는 별도 초안 모델이 필요하다.

MethodTraining-free, with no separate draft model. From one base model SpecQuant derives INT4, FP8 and FP16 variants and uses the cheaper ones as drafters for the more accurate ones ("multi-parent": same weights, different precisions). Queries are routed dynamically among variants, so it adapts to the hardware without per-architecture tuning.학습이 필요 없고 별도 초안 모델도 없다. 베이스 모델 하나에서 INT4·FP8·FP16 변형을 만들고, 싼 변형을 더 정확한 변형의 초안기로 쓴다. "다중 부모(multi-parent)"는 정밀도만 다른 같은 가중치라는 뜻이다. 질의를 변형 사이에 동적으로 라우팅해 아키텍처별 튜닝 없이 하드웨어에 맞춘다.

ResultsOn Qwen2.5-based models over MMLU, AlpacaEval and GSM8K: 35–43% speedups with at most 2% accuracy loss, positioned as practical on-device deployment across diverse hardware.Qwen2.5 계열 모델의 MMLU·AlpacaEval·GSM8K에서 정확도 하락 2% 이내로 35~43% 가속을 보고한다. 저자들은 다양한 하드웨어에서 쓸 만한 온디바이스 배포 방법으로 내세운다.

SummaryThe win is operational: the hard part of speculative decoding is keeping a draft model aligned with the target, and deriving it from the target's own weights removes that. The catch is that the drafter is only as diverse as quantization noise.장점은 운영에 있다. 추측 디코딩에서 제일 번거로운 일은 대상 모델과 맞는 초안 모델을 유지하는 것인데, 대상 가중치에서 초안기를 뽑으면 그 문제가 없어진다. 대신 초안기의 다양성은 양자화 잡음 수준에 그친다.

ProblemOn a phone running long-context multimodal models, the KV cache is the binding constraint: it grows with sequence length and is read every step. Low-rank compression pays a reconstruction cost, eviction loses context for good, and flash offloading stalls on I/O. Each can cost more than it saves.휴대폰에서 긴 문맥 멀티모달 모델을 돌리면 KV 캐시가 병목이다. 시퀀스 길이만큼 자라고 매 스텝 읽힌다. 저랭크 압축은 복원 비용이 들고, 토큰 제거는 문맥을 영영 잃으며, 플래시 오프로딩은 I/O에서 멈춘다. 셋 다 아낀 메모리보다 비쌀 수 있다.

MethodA multi-tier cache (RAM-resident, compressed, flash-backed) with predictive placement: blocks move before the decoder asks, so I/O overlaps compute.
