Problem문제 정의Quantizing the KV cache cuts long-context memory but adds approximation error that is usually uncontrolled, noticed only when an answer goes wrong. Production wants the savings and a guarantee that no request silently degrades past a known bound.KV 캐시 양자화는 롱컨텍스트 메모리를 줄이지만 근사 오차가 생기고, 그 오차는 보통 답이 틀린 뒤에야 드러난다. 프로덕션은 메모리 절감과, 어떤 요청도 정해진 한계 이상 조용히 나빠지지 않는다는 보장을 함께 원한다.
Method방법A tiered KV cache keeps INT8 keys and INT4 values in GPU memory and the FP16 originals in system RAM. Error decomposition gives a per-step bound at runtime: if it is safe the step reads the quantized cache, otherwise it deterministically falls back to FP16.계층형 KV 캐시가 INT8 키와 INT4 값은 GPU 메모리에, FP16 원본은 시스템 RAM에 둔다. 오차 분해로 스텝마다 오차 한계를 계산해, 안전하면 양자화 캐시를 쓰고 아니면 FP16 원본으로 결정적으로 폴백한다.
Results결과Low-bit KV memory savings with a runtime-certified error guarantee and a deterministic fallback, so INT4/INT8 KV carries no uncontrolled accuracy risk on hard requests.런타임 인증 오차 보장과 결정적 폴백 덕분에, INT4/INT8 KV의 메모리 이득을 어려운 요청에서도 통제되지 않는 정확도 위험 없이 얻는다.
Summary요약Quantize the cache, certify the error each step, and keep an FP16 safety net in RAM for when the bound says "not safe."캐시는 양자화하되 스텝마다 오차를 인증하고, 한계가 "안전하지 않다"고 하면 RAM의 FP16으로 돌아간다.
Tiered KV: quantized in GPU, FP16 fallback in RAM, gated by a certified bound계층형 KV: GPU엔 양자화, RAM엔 FP16 폴백, 인증 한계로 선택
Each step checks a certified bound and reads either the quantized GPU cache or the FP16 copy in RAM.스텝마다 인증 한계를 보고 GPU 양자화 캐시와 RAM의 FP16 중 하나를 읽는다.

Summary요약When one expert shard dies, revive just that shard, not the whole model.전문가 샤드 하나가 죽으면 모델 전체가 아니라 그 샤드만 되살린다.

Problem문제 정의Speculative decoding drafts tokens cheaply and verifies them in one big-model pass. Method방법MoE-Spec introduces expert budgeting: it bounds how many experts the verify pass may activate and picks draft length and experts to stay within a compute/memory budget, keeping verify cost predictable.MoE-Spec은 검증이 활성화할 수 있는 전문가 수에 예산(expert budgeting)을 둔다. 초안 길이와 참여 전문가를 연산/메모리 예산 안에서 골라 검증 비용을 예측 가능하게 만든다.
