SpecGuard: Inference-Time Backdoor Detection For Freespeculative decodingruntime monitoringarXiv:2609.11799
arxiv.org/abs/2609.11799 →
Problem문제 정의 A model that was fine-tuned, shared, or downloaded from a third party may carry a backdoor: it behaves normally until a secret trigger appears, then switches to attacker-controlled behaviour. Pre-deployment auditing helps, but models that are updated often still need monitoring at runtime. The obstacle is cost — serving is latency-sensitive, and existing inference-time detectors either assume something about the shape of the trigger, which stealthy attacks break, or spend extra model computation on input perturbations or a second generation pass. 외부에서 받은 모델은 비밀 트리거에만 반응하는 백도어를 품을 수 있어 런타임 감시가 필요하다. 하지만 기존 탐지기는 트리거 형태를 가정하거나 추가 생성 패스 비용을 치른다.
Method방법 SpecGuard repurposes speculative decoding, which is already deployed for speed: a small draft model proposes tokens and the target model verifies them. The authors observe that the verification step already carries a usable signal — when a backdoor fires, the target model shifts toward the attacker's behaviour while the clean draft model does not predict that shift, so the draft-token acceptance rate changes. They formalize the conditions under which this signal appears, and argue it is not cheaply evaded: an attacker who suppresses the acceptance-rate shift must also weaken the backdoor itself. 스펙 디코딩의 검증 단계를 재활용한다. 백도어가 발화하면 타깃 모델은 바뀌지만 깨끗한 초안 모델은 그 변화를 예측하지 못해 초안 토큰 수용률이 달라진다. 이 신호를 억누르려면 백도어 자체를 약화시켜야 한다.
Results결과 Across a range of backdoor types and model families, SpecGuard reliably detects triggered behaviour, including stealthy cases where input-level filters see nothing. Because it reads a quantity the serving loop already computes, it avoids the extra generation cost that existing runtime detectors pay. The paper reports the detection as coming at zero added model-computation cost rather than at a measured latency penalty. 여러 백도어 유형과 모델 계열에서 입력 필터가 놓치는 은밀한 경우까지 안정적으로 탐지한다. 추가 모델 연산 비용은 0이다.
Summary요약 The appealing part is the reuse: a mechanism installed purely for throughput turns out to carry a security signal, so the monitor costs nothing extra to run. For anyone already running speculative decoding in production, this is closer to instrumentation than to a new subsystem — read the acceptance rate you were already computing, and watch it move. 처리량용 장치가 보안 신호를 공짜로 준다. 스펙 디코딩을 이미 쓰는 곳이라면 새 시스템이 아니라 계측 하나 추가에 가깝다.

Why Does Post-Training Quantization Work?quantizationanalysisarXiv:2609.11716
arxiv.org/abs/2609.11716 →
Problem문제 정의 Post-training quantization stores weights at reduced precision, and every quantized weight injects an error into the hidden state. Naively that error should grow layer by layer and wreck next-token prediction — and in a randomly initialized model it does. Pretrained models quantized after the fact accumulate far less hidden-state error and mostly keep their downstream accuracy, even though they never saw quantization noise during training. The paper asks the obvious follow-up: why? 양자화 오차는 층마다 쌓여 예측을 망가뜨려야 하고, 무작위 초기화 모델에서는 실제로 그렇다. 그런데 사전학습 모델은 사후 양자화 뒤에도 정확도를 대체로 유지한다. 논문은 그 이유를 묻는다.
Method방법 The authors compare full-precision and quantized forward passes directly and isolate two mechanisms. The first is error cancellation: the error a layer newly introduces tends to oppose the error it inherits from its input, so the two partially cancel and the full-precision-versus-quantized discrepancy stops compounding with depth. The second is a property of the output head: the LM-head geometry preferentially preserves the scores and probabilities of high-ranked tokens — the ones the model is most confident about. 두 기전을 분리한다. 첫째, 층이 새로 만든 오차가 물려받은 오차와 반대 방향으로 기울어 상쇄되므로 오차가 깊이에 따라 누적되지 않는다. 둘째, LM 헤드의 기하가 상위 순위 토큰의 점수를 우선 보존한다.
Results결과 The quantitative analysis identifies the opposing-error effect as a major factor slowing hidden-error growth, and attributes it to properties acquired during pretraining rather than to anything in the quantizer. Together the two mechanisms explain how error that passes through many layers still produces only small output changes. The authors verify the findings across models and quantization settings. 오차 상쇄가 은닉 오차 증가를 늦추는 주요인이며, 이는 양자화기가 아니라 사전학습에서 얻은 성질이다. 여러 모델과 양자화 설정에서 확인했다.
Summary요약 This is a why-paper rather than a method-paper, and that is its value: if the robustness comes from pretraining-acquired error cancellation plus head geometry, then those are the things a new architecture or a new quantizer can accidentally destroy. Put plainly, quantization works less because the rounding is clever and more because the network was already arranged to absorb it. 방법이 아니라 이유를 밝힌 논문이다. 양자화가 통하는 건 반올림이 영리해서가 아니라 신경망이 이미 오차를 흡수하도록 학습돼 있어서다. 새 아키텍처가 이 성질을 망가뜨릴 수도 있다.

Problem문제 정의 Open-weight models let you run inference without handing your prompts to a provider — but only if you own enough hardware. In practice many users fall back on a third party, which reopens two questions at once: is my input private, and did the server actually run the model it claimed? Existing answers tend to impose heavy server overhead or add trust assumptions that defeat the point. 하드웨어가 부족한 사용자는 오픈 웨이트 모델도 제3자에게 맡겨야 하고, 그러면 입력 비밀성과 "정말 그 모델을 돌렸는가"라는 문제가 생긴다. 기존 해법은 서버 부하가 크거나 신뢰 가정을 덧붙인다.
Method방법 Maverick narrows the problem to the operation that dominates LLM inference — matrix–vector multiplication — and delegates just that. At its core is what the authors describe as the first information-theoretically sound verification protocol for delegated matrix–vector multiplication, meaning the check does not rest on a computational hardness assumption. That primitive is combined with LPN-based pseudorandom masking to hide the client's input from the server. The authors implement the primitive and build an end-to-end prototype on top of it. LLM 추론을 지배하는 행렬–벡터 곱만 위임한다. 계산 난해성 가정 없는 정보이론적 검증 프로토콜을 LPN 기반 의사난수 마스킹과 결합해 입력을 서버에게서 가린다.

With four client threads the gains are 13x, 18x and 17x. Once the server is no longer the bottleneck, client-side microbenchmarks with simulated network delay show 12x–20x, 34x–135x and 38x–157x. Forward-Free LLM Depth Pruning via Weight Redundancypruningcalibration-freearXiv:2609.09883
arxiv.org/abs/2609.09883 →
Problem문제 정의 Depth pruning cuts inference cost by deleting whole Transformer blocks, and the hard part is choosing which. Activation-based methods do it well but need calibration data and forward passes to collect hidden states — an extra pipeline, and a dependency on data you may not be allowed to use. Existing forward-free methods avoid all that, but score each block in isolation and never ask whether two blocks are doing the same job. 깊이 가지치기에서 활성값 기반 방법은 정확하지만 교정 데이터와 순전파가 필요하다. 순전파 없는 기존 방법은 블록을 따로 평가할 뿐 블록 간 중복은 보지 않는다.
Method방법 Weight-Redundancy Pruning (WRP) estimates inter-layer redundancy straight from the checkpoint weights — no calibration data, no forward pass. It compares attention-output and MLP down-projection weights across layers and combines those pairwise similarities with relative projection-scale information. Problem문제 정의 Agent memory has proven itself in long-term dialogue, personalized assistants and video understanding, and that success is the problem: memory accumulates continuously, and the storage and retrieval cost it imposes shows up at inference time, on every request.
