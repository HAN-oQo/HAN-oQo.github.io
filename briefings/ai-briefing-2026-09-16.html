DeepSeek-V4-Flash on AMD gfx90a: Correctness Recovery and Inference Performance EngineeringAMD CDNA2FP4 MoEarXiv:2609.15627
arxiv.org/abs/2609.15627 →
Problem문제 정의 Porting a large sparse model to an older GPU is usually a performance story, but here the first obstacle was correctness: a fast path on MI250 (gfx90a/CDNA2) was numerically wrong because the routed-expert W2 weights were in the wrong permutation, which makes every later optimization measurement meaningless. 구형 GPU에 큰 희소 모델을 올리는 일은 보통 성능 문제로 다뤄지지만, 여기서는 정확성이 먼저 걸렸다. MI250(gfx90a/CDNA2)에서 빠르게 돌던 경로가 라우팅 전문가 W2 가중치 순열이 틀려 잘못된 값을 냈고, 그 위의 최적화 측정은 모두 무의미해진다.
Method방법 Inside SGLang the system combines safetensors loading, TP/EP, FP4 routed MoE, FP8 dense projections, sparse attention, HIP graphs and OpenAI-compatible serving; it repairs the W2 layout at load time and gates on fixed-token and hash checks before optimizing. Decode then uses packed FP4 weights, INT8 activations, CDNA2 dot-product instructions, peer-read all-reduce and topology-aware kernel geometry; prefill uses CDNA2 MFMA kernels, packed-weight reuse, less sparse-attention overhead, larger chunks and retuned expert sorting. SGLang 안에 safetensors 로딩, TP/EP, FP4 라우팅 MoE, FP8 밀집 투영, 희소 어텐션, HIP 그래프, OpenAI 호환 서빙을 묶고, 로드 시점에 W2 레이아웃을 고친 뒤 고정 토큰·해시 검사를 통과해야 최적화로 넘어간다. 디코드는 패킹 FP4 가중치, INT8 활성, CDNA2 내적 명령, peer-read 올리듀스로, 프리필은 CDNA2 MFMA 커널, 더 큰 청크, 재조정한 전문가 정렬로 빠르게 했다.
Results결과 On four MI250 GCDs with TP4/EP1, decode reaches about 74.5 tok/s and a 4,604-token prompt hits 2.061–2.062 s TTFT (about 2,234 input tok/s). The limits are memory bandwidth plus FP4 format mismatch, low-M utilization and per-layer synchronization. MI250 GCD 4개(TP4/EP1)에서 디코드는 약 74.5 tok/s, 4,604 토큰 프롬프트의 첫 토큰 시간은 2.061~2.062초(약 2,234 입력 tok/s)다. 병목은 메모리 대역폭에 더해 FP4 형식 불일치, 낮은 M 사용률, 층별 동기화다.
Summary요약 Worth reading for its ordering: correctness gates first, then optimization. The bottleneck list (format mismatch, low-M utilization, per-layer sync) transfers to any FP4 MoE port onto an older accelerator. 정확성 게이트를 먼저 세우고 최적화한 순서가 이 보고서의 가치다. 형식 불일치, 낮은 M 사용률, 층별 동기화라는 병목 목록은 FP4 MoE를 구형 가속기로 옮길 때 그대로 참고할 수 있다.

How Lossless Is Lossless Speculative Decoding? The Role of Numerical Precision in Orthrusspeculative decodingreproductionarXiv:2609.15504
arxiv.org/abs/2609.15504 →
Problem문제 정의 Orthrus is a hybrid autoregressive-diffusion model that emits several tokens in parallel over a frozen backbone and claims its acceleration is lossless, i.e. the same sequence the AR model would produce. This paper tests whether that claim survives real deployment numerics. Orthrus는 동결된 자기회귀 백본 위에서 여러 토큰을 병렬로 내는 자기회귀-확산 혼성 모델이고, 자기회귀 모델과 똑같은 출력을 낸다는 "무손실" 가속을 주장한다. 이 논문은 그 주장이 실제 배포의 수치 정밀도에서도 성립하는지 확인한다.
Method방법 The authors reproduce Orthrus (the original checkpoint and one they trained) and test exact trajectory matching under different precisions on 1,190 prompts from 12 domains. Matching is measured separately from benchmark scores, since average quality can hold while individual sequences change. 원 체크포인트와 직접 학습한 모델로 Orthrus를 재현하고, 12개 도메인 1,190개 프롬프트에서 정밀도별로 출력 시퀀스가 기준과 똑같은지 검사한다. 평균 품질은 같아도 개별 시퀀스는 달라질 수 있으므로 벤치마크 점수와 따로 본다.
Results결과 In BF16, exact matching holds in only 45% of cases for the authors' checkpoint and 43% for their own model, and divergence concentrates where the reference's response-conditional perplexity is high; benchmarks on lm-eval-harness show no systematic drop. In FP32 every prompt matches exactly. BF16에서 정확 일치율은 저자 체크포인트 45%, 직접 학습 모델 43%에 그치고, 기준 모델의 퍼플렉시티가 높은 곳에서 주로 갈라진다. lm-eval-harness 점수는 떨어지지 않았고, FP32에서는 모든 프롬프트가 정확히 일치했다.
Summary요약 The losslessness is real but lives in FP32; in BF16, which production runs, it becomes statistical. Evaluate exact trajectory equivalence separately rather than letting benchmark parity stand in for it. 무손실성은 FP32에서만 성립하고, 프로덕션이 쓰는 BF16에서는 통계적 보장으로 약해진다. 벤치마크가 같다고 넘어가지 말고 궤적 일치를 따로 평가해야 한다.

MAPS: Memory-Aware Predictive Scheduling Framework for Large Language Model ServingschedulingPD disaggregationarXiv:2609.15359
arxiv.org/abs/2609.15359 →
Problem문제 정의 Prefill-decode disaggregation still leaves memory-bound decode instances imbalanced, because output length is unknown when a request arrives. Bursty traffic from personal devices makes this worse. 프리필-디코드 분리를 해도 메모리 바운드인 디코드 인스턴스의 부하는 고르지 않다. 요청이 도착할 때 출력 길이를 모르기 때문이고, 개인 기기에서 오는 버스티한 트래픽이 이를 키운다.
Method방법 MAPS predicts output length on the device while the cloud prefills, so prediction adds almost no latency, then calibrates predictions into upper bounds with a target coverage rate. A hierarchical scheduler uses the bounds: the global level balances queues across decode instances, the local level fights head-of-line blocking. MAPS는 클라우드가 프리필하는 동안 기기에서 출력 길이를 예측해 지연을 거의 늘리지 않고, 이 예측을 목표 커버리지를 갖는 상한으로 보정한다. 계층형 스케줄러가 이 상한을 써서 전역에서는 디코드 인스턴스 간 큐를 고르게 하고, 지역에서는 헤드 오브 라인 블로킹을 줄인다.
Results결과 On two real workloads and two LLMs, MAPS beats three state-of-the-art systems, cutting average end-to-end latency by 42.6 and tail latency by up to 84.8 (as reported in the abstract).
