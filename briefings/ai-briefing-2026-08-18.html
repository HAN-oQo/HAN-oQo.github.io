DeaMoE: Efficient MoE Structure for Fast Small-Batch DecodingMoE servingdecoding2608.14385
Group experts into "departments" that share most parameters so small-batch decoding loads less weight (arXiv 2608.14385) ↗전문가를 대부분의 파라미터를 공유하는 "부서"로 묶어 소배치 디코딩의 가중치 로딩을 줄이기 (arXiv 2608.14385) ↗
Problem문제 정의MoE models are now standard in real-time interactive products — coding assistants, live audio-video systems — where response latency budgets force small-batch decoding. Under small batches MoE inference becomes memory-bound and is severely bottlenecked by expert weight loading, yet the paper argues this specific bottleneck has received limited attention. Existing answers either compress weights after training or design fine-grained experts during pre-training, which respectively hurt accuracy or add computation and communication overhead.실시간 대화형 MoE 제품은 지연 예산 때문에 소배치로 디코딩하고, 이때 전문가 가중치 로딩이 병목이 된다. 기존 해법인 학습 후 압축이나 세분화된 전문가 설계는 정확도를 떨어뜨리거나 연산·통신 오버헤드를 더한다.
Method방법DeaMoE is a decoding-efficient MoE architecture in which experts are grouped into departments. Experts in the same department come from the same professional field and therefore share most of their parameters, with each expert additionally holding a few private parameters that carry its individuality. A customized two-stage routing strategy is designed on top of this layout specifically to avoid redundant loading — the router first settles the department, so the shared bulk is fetched once and only the small private parts vary per expert.DeaMoE는 전문가를 부서(department)로 묶어 파라미터 대부분을 공유하게 하고, 전문가마다 작은 private 파라미터만 둔다. 2단계 라우팅이 먼저 부서를 고르므로 공유 덩어리는 한 번만 읽는다.
Results결과Against vanilla MoE, DeaMoE reduces per-step loaded weights by up to 50.9%. On a pre-trained 7B model on an A40 it delivers up to 1.33× end-to-end TPOT speedup, and in microbenchmarks on DeepSeek-V3 it reaches up to 2.00× peak speedup on A40 and 1.97× on H100.기본 MoE 대비 스텝당 로드 가중치를 최대 50.9% 줄인다. A40에서 7B 모델 기준 엔드투엔드 TPOT 최대 1.33×, DeepSeek-V3 마이크로벤치마크에서 A40 최대 2.00×, H100 최대 1.97× 가속이다.
Summary요약If small-batch MoE decoding is bottlenecked by how many distinct expert bytes you must pull per step, the fix can be structural: make the experts overlap on purpose, then route so you only pay for the difference.전문가를 일부러 겹치게 만들고 다른 부분만 읽게 해 소배치 MoE 디코딩의 가중치 로딩을 줄인다.

CoRun: Padding is Simple and Efficient for Deterministic LLM Inferencedeterminismscheduling2608.14376
Get bit-identical outputs by fixing batch shapes in the scheduler instead of rewriting kernels to be batch-invariant (arXiv 2608.14376) ↗커널을 batch-invariant로 다시 쓰는 대신 스케줄러에서 배치 모양을 고정해 비트 단위 동일 출력을 얻기 (arXiv 2608.14376) ↗
Problem문제 정의Even with sampling parameters and random seeds fixed, LLM inference still produces inconsistent outputs, which undermines model evaluation and reinforcement learning. A major source is batch-dependent GPU execution: dynamic input shapes change kernel tiling and the order of floating-point reductions, so the same prompt in a different batch takes a different arithmetic path. Existing systems fix this with batch-invariant kernels, but those kernels restrict optimization.시드와 샘플링 파라미터를 고정해도 LLM 출력이 달라져 평가와 RL이 흔들린다. 원인은 배치에 따라 바뀌는 커널 타일링과 리덕션 순서다. batch-invariant 커널은 이를 막지만 최적화 여지를 줄인다.
Method방법CoRun is a scheduling-based system that achieves deterministic inference without requiring batch invariance. It handles the two stages of LLM inference separately: prefill runs isolated, and decode runs as fixed-shape batches — padding to a fixed shape is the whole trick, hence the title. Fixed shapes let CoRun lean on CUDA graphs for efficient execution and a simpler implementation, since the shape a kernel sees no longer depends on which other requests happen to be in flight.CoRun은 batch invariance 없이 스케줄링으로 결정성을 얻는다. 프리필은 격리해서 돌리고 디코드는 고정 모양으로 패딩한 배치로 돌린다. 모양이 고정되니 CUDA 그래프를 그대로 쓸 수 있다.
Results결과Across LLMs with diverse architectures including Qwen and DeepSeek, CoRun ensures determinism while improving throughput by 15–324% over batch-invariant approaches. It also reduces time-to-first-token by 51.8% and time-per-output-token by 48.6% on average — so in these experiments determinism does not come with the usual latency tax.Qwen·DeepSeek 등 여러 구조에서 결정성을 보장하면서 batch-invariant 방식보다 처리량이 15~324% 높다. 평균 TTFT는 51.8%, TPOT는 48.6% 줄었다.
Summary요약Nondeterminism in serving is a scheduling property as much as a kernel property; if the scheduler guarantees the shape, the kernel is free to stay fast.스케줄러가 모양을 고정하면 커널을 느리게 만들지 않고도 결정성을 얻는다.

Graph 엔지니어링 vs Loop 엔지니어링: 실제로 달라진 것은 무엇인가 Aug 16

A deflation of the "loop engineering is dead, graph engineering is here" meme. Loops and graphs are not competing paradigms: a loop is one agent iterating toward a goal under an external verifier, and a graph is what you get when you connect several loops and handoffs. The graph structures themselves are old — chaining, routing, parallelization, orchestrator-workers, evaluator-optimizer, plus DAG schedulers and state machines. What is genuinely new is that each node is now a probabilistic agent that may decide differently on identical input, which forces orchestration to become explicit: what runs in parallel, what state passes between nodes, who can veto whom, where to roll back, where to cap cost. The post also warns that stacking more agents is not verification, since reviewers sharing a model and bad context produce correlated errors.

"loop 엔지니어링은 끝났고 이제 graph 엔지니어링"이라는 밈을 반박한다. 루프는 외부 검증자 아래 반복하는 에이전트 하나이고, 그래프는 여러 루프와 인계를 연결한 것이다. 체이닝, 라우팅, 병렬화, 오케스트레이터-워커, 평가자-최적화자, DAG 스케줄러, 상태 기계 같은 그래프 구조는 오래됐다. 새로운 점은 노드가 같은 입력에도 다르게 판단하는 확률적 에이전트라는 것이라, 병렬 실행, 상태 전달, 거부 권한, 롤백과 비용 차단 지점을 명시해야 한다. 같은 모델과 맥락을 공유하는 리뷰어는 상관된 오류를 내므로 에이전트를 더 쌓는 것은 검증이 아니다.
