Problem문제 정의Long-running assistants and agents consume interaction streams that eventually outgrow the context window. Context retention, summarization, and retrieval preserve access to selected history, but none provides a persistent computational state over the full lifecycle once the working context turns over.장시간 실행되는 어시스턴트·에이전트는 결국 컨텍스트 창을 넘어서는 상호작용 스트림을 소비한다. 컨텍스트 유지·요약·검색은 선택된 이력에 대한 접근을 보존하지만, 작업 컨텍스트가 교체된 뒤 전체 수명에 걸친 지속적 계산 상태를 주는 것은 없다.
Method방법The authors formulate the missing capability as "state continuity under context turnover" — carrying computation forward through a fixed-capacity memory whose lifetime is independent of the active context. LiveMem augments a pretrained full-attention LLM with an intrinsic memory state that preserves historical information across the whole lifecycle while the main attention path keeps a bounded KV window.저자들은 빠진 능력을 "컨텍스트 교체 하의 상태 연속성"으로 정식화한다 — 수명이 활성 컨텍스트와 독립적인 고정 용량 메모리를 통해 계산을 이어간다. LiveMem은 사전학습된 완전 어텐션 LLM에, 메인 어텐션 경로가 유계 KV 창을 유지하는 동안 전 수명에 걸쳐 이력 정보를 보존하는 내재 메모리 상태를 덧붙인다.
Results결과By decoupling the lifetime memory from the KV window, LiveMem lets a fixed-context model carry earlier interaction state forward instead of losing it when the window rolls, targeting the long-running assistant setting where history keeps growing past any fixed budget.수명 메모리를 KV 창에서 분리함으로써, LiveMem은 고정 컨텍스트 모델이 창이 밀릴 때 이전 상호작용 상태를 잃지 않고 이어가게 하며, 이력이 어떤 고정 예산도 넘어 계속 늘어나는 장시간 어시스턴트 상황을 겨냥한다.

Problem문제 정의In batched serving, heterogeneous requests that share a decode batch impose max-driven costs on one another: because a batch step's wall-clock cost is largely set by the largest active KV-cache footprint, a short request co-batched with a long one suffers latency and GPU consumption out of proportion to its own token workload.배치 서빙에서 디코드 배치를 공유하는 이질적 요청들은 서로에게 최대값 주도 비용을 강요한다 — 배치 스텝의 실시간 비용이 대체로 가장 큰 활성 KV 캐시 크기로 정해지므로, 긴 요청과 함께 배치된 짧은 요청은 자기 토큰 작업량에 비해 과도한 지연과 GPU 소비를 겪는다.
Method방법The paper formalizes this as a resource-fair scheduling problem and builds a mathematical model connecting within-batch fairness to system throughput. A fairness constraint bounds the disparity in decode progress — equivalently, KV-cache footprint — among co-batched requests, and an Insert-Short-Jobs scheduler is designed on top of that model.논문은 이를 자원 공정 스케줄링 문제로 정식화하고, 배치 내 공정성과 시스템 처리량을 잇는 수학 모델을 세운다. 공정성 제약은 함께 배치된 요청들 사이의 디코드 진행도 — 곧 KV 캐시 크기 — 격차를 제한하며, 그 모델 위에 Insert-Short-Jobs 스케줄러를 설계한다.
Results결과By bounding how far apart co-batched requests can drift in KV footprint, the scheduler aligns each request's resource consumption and cost with its own workload rather than the batch maximum, connecting fairness directly to throughput.함께 배치된 요청들이 KV 크기에서 얼마나 벌어질 수 있는지를 제한함으로써, 스케줄러는 각 요청의 자원 소비·비용을 배치 최대값이 아니라 자기 작업량에 맞추며 공정성을 처리량에 직접 연결한다.
Summary요약Bound the KV-footprint disparity among co-batched requests so a short request no longer pays the long request's max-driven cost — aligning per-request cost with its own token workload.함께 배치된 요청들의 KV 크기 격차를 제한해 짧은 요청이 더 이상 긴 요청의 최대값 주도 비용을 물지 않게 한다 — 요청별 비용을 자기 토큰 작업량에 맞춘다.

PCTree — parent-conditioned drafting trees for DSpark (arXiv 2608.02123) ↗PCTree — DSpark용 부모 조건부 드래프팅 트리 (arXiv 2608.02123) ↗
Problem문제 정의Speculative decoding only helps when drafted continuations survive target-model verification. Semi-autoregressive drafters such as DSpark predict a whole token block with one backbone forward and refine it with a lightweight Markov head, but DSpark decodes the block as a single chain, so an early mismatch invalidates the remaining suffix and caps the benefit of larger draft blocks.스펙 디코딩은 초안 연속이 타깃 모델 검증을 통과할 때만 도움이 된다. DSpark 같은 반자기회귀 드래프터는 한 번의 백본 순전파로 토큰 블록 전체를 예측하고 경량 마르코프 헤드로 다듬지만, DSpark는 블록을 단일 체인으로 디코딩해 초기 불일치가 남은 접미부를 무효화하고 큰 초안 블록의 이득을 제한한다.
