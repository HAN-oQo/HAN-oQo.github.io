Building py-kvcache: A Performance Characterization of External KV Caching for vLLM with NVMe SSDsKV offloadvLLM connectorarXiv:2609.11744

Problem문제 정의 Prefix caching cuts time-to-first-token by reusing previously computed KV states, but the reuse is not free: the cache has to be loaded from wherever it was stored. For short prefixes, or on a fast enough GPU, simply recomputing the prefix beats loading it. That break-even point is where the whole idea of an external cache tier lives or dies, and it is rarely measured directly. 프리픽스 캐시는 TTFT를 줄이지만 불러오는 비용이 있다. 프리픽스가 짧거나 GPU가 빠르면 다시 계산하는 편이 빠르고, 외부 캐시 계층의 가치는 이 손익분기점에 달려 있는데 직접 측정된 적이 드물다.
Method방법 The authors characterize the tradeoff in vLLM across GPU, CPU and NVMe tiers using synthetic workloads, long-context benchmarks and production traces, and find that cache performance depends on transfer granularity, intermediate memory use, and when transfers enter the request schedule — not only on device bandwidth. Those findings motivate py-kvcache, a vLLM KV Offload connector with asynchronous direct I/O, bounded shared staging, and scheduler-aware preloading that starts disk reads while requests are still waiting, overlapping the read with compute. vLLM의 GPU·CPU·NVMe 계층을 합성 워크로드, 롱컨텍스트 벤치마크, 프로덕션 트레이스로 특성화했더니 성능은 대역폭보다 전송 단위, 중간 메모리, 전송 시점에 좌우됐다. 이를 반영한 py-kvcache는 비동기 다이렉트 I/O, 공유 스테이징, 대기 중에 디스크 읽기를 시작하는 스케줄러 인지 프리로딩을 갖춘 vLLM KV Offload 커넥터다.
Results결과 At 80k tokens, loading from disk with py-kvcache is 2.0x faster than LMCache, with preloading alone contributing 1.34x. With GPU, CPU and disk caching all enabled it is 1.23x faster than LMCache and within about 4% of vLLM's native KV Offload implementation. LongBench and SCBench show the benefit extends to irregular prefix chains and multi-turn workloads. Bailian trace replays improve TTFT on a weaker GPU, but on an H100 the average request falls below the break-even point and GPU memory alone retains enough prefixes. 80k 토큰에서 디스크 로딩이 LMCache보다 2.0배 빠르고(프리로딩만으로 1.34배), 세 계층을 다 켜면 LMCache 대비 1.23배, vLLM 자체 구현과는 약 4% 이내다. Summary요약 The engineering contribution is a connector that hides disk latency behind the queue; the more durable contribution is the conclusion that external KV caching should be treated as a setup-specific admission decision rather than a default. Problem문제 정의 Omni-modal models take audio, video and text in the same context, so the KV cache grows faster than it does for text alone. KV cache quantization is the standard answer in text-only LLMs, but nobody had checked whether the assumptions it rests on survive a cache built from several modalities at once. 옴니모달 모델은 오디오·비디오·텍스트를 한 문맥에 받아 KV 캐시가 빨리 자란다. 텍스트 LLM용 KV 양자화의 가정이 여러 모달리티가 섞인 캐시에서도 성립하는지는 확인된 적이 없다.
