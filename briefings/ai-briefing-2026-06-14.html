vLLM v0.23.0 — 408 commits: DeepSeek-V4 hardening, Model Runner V2 default for Llama/Mistral vLLMJun 12

vLLM tagged v0.23.0, a large release of 408 commits from 200 contributors. DeepSeek-V4 got a second hardening-and-optimization pass across backends — its sparse-MLA metadata is decoupled from V3.2, it gained a TRTLLM-gen attention kernel, EPLB support for the Mega-MoE, and selective prefix-cache retention for sliding-window KV. The notes flag one caveat: MiniMax M3 is not yet in this tagged build — follow the vLLM recipe for it.

vLLM이 v0.23.0을 태깅했다 — 200명 기여자의 408개 커밋이 담긴 대형 릴리스다. DeepSeek-V4가 백엔드 전반에서 2차 하드닝·최적화를 받았다 — 희소 MLA 메타데이터를 V3.2에서 분리하고, TRTLLM-gen 어텐션 커널, Mega-MoE용 EPLB 지원, 슬라이딩윈도우 KV의 선택적 prefix-cache 보존을 추가했다. SGLang v0.5.13 — Spec V2 becomes the default speculative-decoding path SGLangJun 13

SGLang tagged v0.5.13, making Spec V2 the default speculative-decoding path: tree drafting with topk > 1 is now production-ready across the triton / FA3 / MLA / aiter backends — including page size 1 and Mamba/hybrid-linear models — while Spec V1 is deprecated and EAGLE/MTP now run on the unified V2 worker. Problem문제 정의Diffusion Transformers (DiTs) are now the dominant architecture for image and video generation, so efficient DiT serving matters. But existing systems pin each request to one fixed parallel configuration for its whole lifetime, while real DiT workloads vary a lot across requests, execution stages and system load — making any single static choice wasteful.디퓨전 트랜스포머(DiT)는 이제 이미지·비디오 생성의 지배적 아키텍처여서 효율적 DiT 서빙이 중요하다. 그러나 기존 시스템은 각 요청을 그 수명 내내 하나의 고정 병렬 설정에 묶어두는데, 실제 DiT 워크로드는 요청·실행 단계·시스템 부하에 따라 크게 달라져 어떤 단일 정적 선택도 낭비가 된다.
Method방법GF-DiT schedules parallelism dynamically — choosing and switching the parallel configuration per request and per stage as conditions change — and slashes the cost of reconfiguring a running deployment so the switch itself is nearly free.GF-DiT는 병렬화를 동적으로 스케줄한다 — 조건이 바뀌면 요청별·단계별로 병렬 설정을 선택·전환하고, 가동 중인 배포를 재구성하는 비용을 대폭 줄여 전환 자체를 거의 공짜로 만든다.
Results결과GF-DiT raises throughput by up to 6.01×, cuts mean latency by up to 95%, and lowers SLO-violation rates by up to 90%. Crucially, it drops communication-group setup overhead from 778 ms to roughly 60 µs — which is what makes switching configurations mid-flight practical.GF-DiT는 처리량을 최대 6.01× 높이고, 평균 지연을 최대 95% 줄이며, SLO 위반율을 최대 90% 낮춘다. 결정적으로 통신 그룹 설정 오버헤드를 778 ms에서 약 60 µs로 떨어뜨리는데, 이것이 가동 중 설정 전환을 실용적으로 만든다.
Summary요약Stop pinning a diffusion request to one parallel layout — let the server re-shape parallelism on the fly when reconfiguration costs microseconds, not seconds.디퓨전 요청을 하나의 병렬 배치에 묶지 말라 — 재구성이 초가 아니라 마이크로초면, 서버가 병렬화를 실시간으로 다시 빚게 하라.

ReSET — keeping NVFP4 reasoning accurate with step-aware temperature scalingquantization2606.13233

Problem문제 정의Large reasoning models generate long intermediate traces, which inflates inference cost. NVFP4 (a 4-bit format with hardware support) promises cheaper compute and memory, but applied to reasoning it backfires twice: accuracy drops under quantization, and existing NVFP4 kernels don't actually deliver speed in the small-batch autoregressive decoding that reasoning runs in.대형 추론 모델은 긴 중간 추론 흔적을 생성해 추론 비용을 키운다. NVFP4(하드웨어 지원 4비트 포맷)는 연산·메모리 절감을 약속하지만 추론에 적용하면 두 번 역효과가 난다 — 양자화로 정확도가 떨어지고, 기존 NVFP4 커널은 추론이 도는 소배치 자기회귀 디코딩에서 실제 속도를 내지 못한다.
Method방법The authors analyze token-level uncertainty and find quantization makes the model sample wrong at low-entropy "symbolic" tokens while over-concentrating on a few tokens at high-uncertainty reasoning steps. ReSET은 추론 단계별 엔트로피에 따라 표집 온도를 조정하고, 이를 지연 인지 NVFP4 디코딩 커널과 결합한다.
Results결과ReSET delivers up to a 2.5× kernel-level speedup over NVFP4 in vLLM and roughly a 2× end-to-end decoding speedup over BF16, while restoring reasoning accuracy that naïve NVFP4 loses. Code is released at github.com/aiha-lab/ReSET.ReSET은 vLLM의 NVFP4 대비 최대 2.5× 커널 가속과 BF16 대비 약 2× 엔드투엔드 디코딩 가속을 내면서, 단순 NVFP4가 잃는 추론 정확도를 회복한다. 코드는 github.com/aiha-lab/ReSET에 공개됐다.
Summary요약4-bit reasoning fails at the tokens that matter; fix it by tuning temperature to each step's uncertainty instead of abandoning low precision.4비트 추론은 중요한 토큰에서 무너진다 — 저정밀도를 포기하지 말고 단계별 불확실성에 맞춰 온도를 조정해 고치라.

Problem문제 정의Retrieval-augmented and agentic workloads keep re-prefilling the same predictable chunks — documents, code files, tool specs (the paper calls them "spans"). Yet prefix caching in engines like vLLM can only reuse a span's KV entries when it appears at the exact same position, so a document moved a few tokens over is recomputed from scratch.RAG·에이전트 워크로드는 동일하고 예측 가능한 덩어리 — 문서·코드 파일·툴 명세(논문은 'span'이라 부른다) — 를 계속 다시 prefill한다. 그러나 vLLM 같은 엔진의 prefix 캐싱은 span이 정확히 같은 위치에 나타날 때만 그 KV 항목을 재사용할 수 있어, 몇 토큰 밀린 문서는 처음부터 다시 계산된다.
Method방법MiniPIC makes caching position-independent: a span's KV can be reused wherever it lands in the prompt, not just at a fixed prefix. The striking claim is that it does this in under 100 lines of code, as a small, flexible addition rather than a rewrite of the cache.MiniPIC는 캐싱을 위치 독립적으로 만든다 — span의 KV를 고정 prefix뿐 아니라 프롬프트 어디에 놓이든 재사용한다. 인상적인 주장은 이를 100줄 미만 코드로, 캐시 재작성이 아니라 작고 유연한 추가로 해낸다는 점이다.
Results결과By reusing spans regardless of position, MiniPIC cuts redundant prefill by orders of magnitude, preserves the linear prefill scaling of genuinely new (uncached) spans, and adds only a 5.7% worst-case overhead — a large win for very small surface area.위치와 무관하게 span을 재사용함으로써 MiniPIC는 중복 prefill을 수십~수백 배 줄이고, 진짜 새로운(미캐시) span의 선형 prefill 스케일링을 보존하며, 최악의 경우에도 5.7% 오버헤드만 더한다 — 매우 작은 표면적 대비 큰 이득이다.
Summary요약If the same document keeps showing up at different offsets, cache it by content, not by position — 100 lines buys orders-of-magnitude less recompute.같은 문서가 다른 오프셋에서 계속 나타난다면 위치가 아니라 내용으로 캐시하라 — 100줄이 수십~수백 배의 재계산 절감을 산다.
