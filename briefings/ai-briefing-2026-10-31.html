arxiv.org/abs/2610.40305 →

Problem문제 정의Serving systems split weight and attention-state memory at fixed boundaries. Under heavy load the state region caps concurrency, under light load idle memory cannot be lent across, and tensors with different layouts and lifetimes make a shared pool hard.서빙 시스템은 가중치와 어텐션 상태 메모리를 고정 경계로 나눈다. 그래서 부하가 높으면 상태 영역이 동시성을 막고, 낮으면 남는 메모리를 빌려줄 수 없으며, 레이아웃과 수명이 다른 텐서가 섞여 공유 풀도 만들기 어렵다.

Method방법A shared page pool gives each tensor type its own view, page size and page table. A huge-page-aligned multi-level allocator, a page-table-aware fused MoE kernel that reads scattered expert weights without copies, and a workload-aware adjuster that moves pages via elastic expert offloading support it.텐서 종류마다 페이지 크기와 페이지 테이블이 다른 뷰를 둔 공유 페이지 풀을 만든다. 거대 페이지 정렬 다단계 할당기, 비연속 전문가 가중치를 복사 없이 읽는 융합 MoE 커널, 탄력적 전문가 오프로딩으로 페이지를 옮기는 워크로드 조정기가 이를 받친다.

Results결과Implemented on top of vLLM, Rimuru reaches up to 19.03x the baseline throughput and cuts TTFT by 98.1% on average.vLLM 위에 구현한 Rimuru는 기준선 대비 처리량이 최대 19.03배에 이르고 TTFT를 평균 98.1% 줄인다.

Summary요약Letting weights and attention state draw from one elastic page pool turns idle expert memory into request capacity.가중치와 어텐션 상태가 하나의 탄력적 페이지 풀을 쓰게 하면 유휴 전문가 메모리가 요청 처리 용량으로 바뀐다.

Problem문제 정의KV reuse systems use host DRAM as an intermediate cache in front of NVMe SSD.
