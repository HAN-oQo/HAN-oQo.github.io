Rimuru: Unified Memory Management for Modern LLM Serving via Elastic Expert OffloadingMoEmemory managementarXiv:2610.40305
arxiv.org/abs/2610.40305 →

Problem문제 정의Serving systems provision memory for model weights and attention states separately, with fixed boundaries. Under heavy load the state region caps concurrency, under light load idle memory in one region cannot be lent to the other, and heterogeneous tensors with different layouts and lifetimes make a shared pool hard to reuse.서빙 시스템은 모델 가중치와 어텐션 상태의 메모리를 고정된 경계로 따로 할당한다. 부하가 높으면 상태 영역이 동시성을 제한하고, 낮으면 한쪽의 유휴 메모리를 다른 쪽에 빌려줄 수 없으며, 레이아웃과 수명이 다른 이질적 텐서 때문에 공유 풀을 재사용하기도 어렵다.

Method방법Rimuru builds a shared page pool with per-tensor-type memory views, so each type uses its own page size and page table. A huge-page-aligned multi-level allocator splits and merges pages, a page-table-aware fused MoE kernel reads non-contiguous expert weights without copies, and a workload-aware adjuster moves pages between tensor types through elastic expert offloading.Rimuru는 텐서 종류별 메모리 뷰를 가진 공유 페이지 풀을 만들어 각 종류가 자체 페이지 크기와 페이지 테이블을 쓰게 한다. 거대 페이지에 정렬된 다단계 할당기가 페이지를 쪼개고 합치며, 페이지 테이블 인식 융합 MoE 커널이 비연속 전문가 가중치를 복사 없이 읽고, 워크로드 인식 조정기가 탄력적 전문가 오프로딩으로 텐서 종류 간에 페이지를 옮긴다.

Results결과Implemented on top of vLLM, Rimuru reaches up to 19.03x the baseline throughput and cuts TTFT by 98.1% on average.vLLM 위에 구현한 Rimuru는 기준선 대비 처리량이 최대 19.03배에 이르고 TTFT를 평균 98.1% 줄인다.

Summary요약Letting weights and attention state draw from one elastic page pool turns idle expert memory into request capacity.가중치와 어텐션 상태가 하나의 탄력적 페이지 풀을 쓰게 하면 유휴 전문가 메모리가 요청 처리 용량으로 바뀐다.

Method방법PDScope decouples the phases because expert routing is predictable in phase-specific ways.
