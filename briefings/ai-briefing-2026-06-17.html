vLLM main — GLM-5 ragged-MLA prefill, MiniMax-M3 mxfp8 MoE tuning, new streaming parser vLLMJun 16

Highlights include TRT-LLM ragged MLA-prefill support for GLM-5 dimensions, mxfp8 MoE/linear gfx950 tuning for MiniMax-M3 on AMD, a new Streaming Parser Engine with a MinimaxM2 parser, FA4 fp8 output for MLA prefill, and a Hierarchical Reasoning Model (HRM) text architecture. SGLang main — context-parallel abstractions, LPLB MoE load balancer, GLM-5.2 cookbooks SGLangJun 16

After v0.5.13, SGLang's main branch (~91 commits in the window) leaned into MoE expert parallelism and context parallelism. It introduced LPLB, a linear-programming load balancer for MoE expert parallelism, added context-parallel (CP) strategy abstractions as a first step toward fuller CP support, and extended DeepSeek-V4 prefill context-parallel on AMD's unified-KV attention. There were also GLM-5.2 deployment cookbooks with MTP tuning, an Amazon SageMaker deployment guide, a HiCache asymmetric-pool direct backend, and a perf fix avoiding a per-decode-step host sync in the min_new_tokens penalty. The throughline is scaling MoE/long-context serving across more parallelism dimensions while landing day-one GLM-5.2 recipes.

v0.5.13 이후 SGLang의 main(이 구간 ~91 커밋)은 MoE 전문가 병렬과 컨텍스트 병렬로 기울었다. MoE 전문가 병렬용 선형계획 로드밸런서 LPLB를 도입하고, 더 완전한 CP 지원을 향한 첫 단계로 컨텍스트 병렬(CP) 전략 추상화를 추가했으며, AMD 통합-KV 어텐션에서 DeepSeek-V4 prefill 컨텍스트 병렬을 확장했다. 또한 MTP 튜닝이 포함된 GLM-5.2 배포 쿡북, Amazon SageMaker 배포 가이드, HiCache 비대칭 풀 직접 백엔드, min_new_tokens 페널티의 디코드 스텝별 호스트 동기화를 없애는 perf 수정이 있었다. 관통 주제는 더 많은 병렬 차원으로 MoE·롱컨텍스트 서빙을 확장하면서 day-1 GLM-5.2 레시피를 안착시키는 것이다.

NVIDIA Dynamo main — unified prefill-admission lifecycle and goodput in planner replay DynamoJun 16

Dynamo's main branch (27 commits in the window) refactored its disaggregation internals. A routing refactor unified the prefill-admission lifecycle, and a separate fix wired an active-prefill-tokens threshold to gate prefill admission in disaggregated mode. The planner replay gained goodput and provisioned GPU-hours metrics, the KV router added a standalone selector peer-sync, and agent tracing was unified under a single DYN_REQUEST_TRACE env switch. Plumbing changes bumped the bundled vLLM to 0.23.0, cut the parser library over to a dedicated dynamo-parsers crate, and updated the aiconfigurator dependency. The week's theme is consolidating routing/admission and giving the planner better cost-aware signals.

Dynamo의 main 브랜치(이 구간 27 커밋)는 분산 내부 구조를 리팩터링했다. 라우팅 리팩터로 prefill 어드미션 라이프사이클을 통합했고, 별도 수정으로 분산 모드에서 active-prefill-tokens 임계값을 연결해 prefill 어드미션을 게이팅한다. 플래너 리플레이는 goodput과 프로비저닝된 GPU-시간 지표를 얻었고, KV 라우터는 독립 셀렉터 피어 동기화를 추가했으며, 에이전트 트레이싱은 단일 DYN_REQUEST_TRACE 환경 스위치로 통합됐다. 배관 변경으로 번들 vLLM을 0.23.0으로 올리고, 파서 라이브러리를 전용 dynamo-parsers 크레이트로 옮기고, aiconfigurator 의존성을 갱신했다. 이번 주 주제는 라우팅·어드미션 통합과 플래너에 더 나은 비용 인식 신호를 주는 것이다.

Problem문제 정의Coding agents are a fast-growing LLM workload — long-running closed-loop sessions where generations alternate with tool calls. Unlike chat, their serving behavior is understudied, and real sessions repeatedly reuse large prefixes that create sustained KVCache pressure conventional policies handle poorly.코딩 에이전트는 빠르게 늘어나는 LLM 워크로드로, 생성과 도구 호출이 번갈아 도는 장시간 폐루프 세션이다. 챗과 달리 서빙 거동이 덜 연구됐고, 실제 세션은 큰 prefix를 반복 재사용해 기존 정책이 잘 다루지 못하는 지속적 KVCache 압력을 만든다.
Method방법The authors collect real coding-assistant traces, then build CacheWise — a KVCache management layer that combines prefix-aware scheduling with reuse-aware eviction guided by lightweight predictions from tool-call metadata. It is implemented in vLLM and evaluated on the collected traces.저자들은 실제 코딩 어시스턴트 트레이스를 수집한 뒤 CacheWise를 만든다 — prefix 인식 스케줄링과, 도구 호출 메타데이터의 경량 예측이 이끄는 재사용 인식 축출을 결합한 KVCache 관리 계층이다. vLLM에 구현해 수집한 트레이스로 평가한다.
Results결과CacheWise reduces KVCache evictions by up to 2–2.6× and improves total agent session completion time by up to 3.5× on the collected traces.CacheWise는 수집 트레이스에서 KVCache 축출을 최대 2–2.6× 줄이고 전체 에이전트 세션 완료 시간을 최대 3.5× 개선한다.

VeriAttn — communication-efficient verifiable attention for LLM inferenceverifiable inference2606.16352
Communication-Efficient Verifiable Attention for LLM Inference (arXiv 2606.16352, submitted Jun 15) ↗Communication-Efficient Verifiable Attention for LLM Inference (arXiv 2606.16352, 6/15 제출) ↗
Problem문제 정의The computation integrity of remote LLM serving is hard to trust. The TEE-shielded partitioning (TSDP) approach uses a trusted enclave to compute non-linear parts and verify linear parts offloaded to an untrusted GPU — but applied directly to Transformers it incurs heavy TEE computation and TEE↔GPU communication.원격 LLM 서빙의 계산 무결성은 신뢰하기 어렵다. TEE 차폐 분할(TSDP)은 신뢰 엔클레이브가 비선형부를 계산하고 비신뢰 GPU에 오프로드된 선형부를 검증하지만, Transformer에 그대로 적용하면 TEE 계산과 TEE↔GPU 통신 비용이 크다.
Method방법VeriAttn offloads both the linear and non-linear parts of attention to the GPU while the TEE only verifies. For prefill it uses a two-level pipeline overlapping data movement, TEE pre-/post-processing, and GPU compute; for decode, when the KV cache exceeds GPU memory it partitions attention across TEE and GPU.VeriAttn은 어텐션의 선형·비선형부를 모두 GPU에 오프로드하고 TEE는 검증만 한다. prefill에서는 데이터 이동·TEE 전후처리·GPU 계산을 겹치는 2단 파이프라인을 쓰고, decode에서는 KV 캐시가 GPU 메모리를 초과하면 어텐션을 TEE와 GPU로 분할한다.
Results결과By verifying rather than recomputing on the enclave and overlapping the pipeline, VeriAttn accelerates verifiable LLM inference, cutting the TEE compute and TEE↔GPU communication overhead that naive TSDP suffers.엔클레이브에서 재계산 대신 검증하고 파이프라인을 겹침으로써, VeriAttn은 검증 가능한 LLM 추론을 가속해 단순 TSDP가 겪는 TEE 계산·TEE↔GPU 통신 비용을 줄인다.
Summary요약Let the GPU do attention and let the TEE just check it — verifiable inference without the TSDP communication tax.GPU가 어텐션을 하고 TEE는 검증만 하게 하라 — TSDP 통신 비용 없이 검증 가능한 추론.

SMEPilot — optimizing LLM inference with CPU scalable matrix extensionsCPU inference2606.16332
SMEPilot: Characterizing and Optimizing LLM Inference with Scalable Matrix Extensions (arXiv 2606.16332, submitted Jun 15) ↗SMEPilot: Characterizing and Optimizing LLM Inference with Scalable Matrix Extensions (arXiv 2606.16332, 6/15 제출) ↗
Problem문제 정의Modern CPUs integrate matrix extensions like Arm SME for high-throughput matrix math, but they are not a universal replacement for CPU cores: prefill, decode, attention, and KV-cache ops have different arithmetic intensities, vector behavior, and layout needs, while SME units and cores compete for shared memory bandwidth.현대 CPU는 고처리량 행렬 연산을 위해 Arm SME 같은 행렬확장을 통합하지만, CPU 코어의 만능 대체재는 아니다 — prefill·decode·어텐션·KV 캐시 연산은 산술강도·벡터 거동·레이아웃 요구가 다르고, SME 유닛과 코어는 공유 메모리 대역폭을 두고 경쟁한다.
