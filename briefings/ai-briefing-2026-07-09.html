Method방법FreqDepthKV factorizes adjacent-layer KV states into shared low-frequency depth components and sparse high-frequency residuals; a lightweight online probe assigns attention heads to shared-depth, residual-depth, or exact-cache modes by their contribution to reconstruction-sensitive attention logits, adapting to prompt structure without retraining.FreqDepthKV는 인접 계층 KV 상태를 공유 저주파 depth 성분과 희소 고주파 잔차로 인수분해한다. 경량 온라인 프로브가 재구성 민감 어텐션 로짓 기여도에 따라 헤드를 공유 depth·잔차 depth·정확 캐시 모드로 배정해, 재학습 없이 프롬프트 구조에 적응한다.
Results결과By preserving low-frequency shared structure while keeping only sparse high-frequency detail per head, it targets robust long-context question answering under compression.저주파 공유 구조를 보존하면서 헤드별 희소 고주파 세부만 유지함으로써, 압축 하에서도 견고한 장문맥 질의응답을 목표로 한다.

Kokoro — running high-quality text-to-speech locally on CPU alone Jul 9

Kokoro is an 82M-parameter TTS model that produces convincingly natural speech without a dedicated GPU, leaving the GPU free for LLM inference while the CPU handles voice. It supports multiple languages (English, Chinese, Hindi and more) with ~50 voices, ships an OpenAI-speech-API-compatible interface so existing voice apps can swap to local TTS, and synthesizes a short paragraph in ~1.5s on a Ryzen 7 / ~4.5s on an M2 Pro. The pitch is private, local, CPU-only speech generation that was impractical only a few years ago.

Kokoro는 8200만 파라미터 TTS 모델로, 전용 GPU 없이도 자연스러운 음성을 만들어 GPU는 LLM 추론에 남기고 CPU가 음성을 처리한다. 여러 언어(영어·중국어·힌디어 등)와 약 50개 음성을 지원하고, OpenAI 음성 API 호환 인터페이스를 제공해 기존 음성 앱을 로컬 TTS로 바꿀 수 있으며, 짧은 문단을 Ryzen 7에서 ~1.5초·M2 Pro에서 ~4.5초에 합성한다. 몇 년 전만 해도 비현실적이던 사적·로컬·CPU 전용 음성 생성을 내세운다.

A taxonomy of agent "loops" from the Claude Code team Jul 8

The Claude Code team describes a shift away from instructing a coding agent prompt-by-prompt toward an operating pattern where the agent repeats work cycles until a stop condition is met. They classify loops along four axes — how they are triggered, how they stop, which primitives they use, and which task types they fit — and name four main types: Turn-based, Goal-based, Time-based, and Proactive. The practical caution is that not every task needs a complex loop: start with the simplest solution, and remember that loop output quality depends on surrounding systems, so code quality and token-usage management matter.

Claude Code 팀은 코딩 에이전트를 프롬프트마다 지시하는 방식에서, 정지 조건이 충족될 때까지 작업 사이클을 반복하는 운영 패턴으로의 전환을 설명한다. 루프를 네 축 — 어떻게 트리거되는가, 어떻게 정지하는가, 어떤 primitive를 쓰는가, 어떤 작업 유형에 맞는가 — 으로 분류하고, Turn-based·Goal-based·Time-based·Proactive 네 가지 주요 유형을 제시한다. 실무 조언은 모든 작업에 복잡한 루프가 필요하진 않다는 것 — 가장 단순한 해법부터 시작하고, 루프 출력 품질은 주변 시스템에 좌우되므로 코드 품질·토큰 사용 관리가 중요하다.
