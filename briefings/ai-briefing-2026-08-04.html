Problem문제 정의Serving systems cache prompt KV state, but most front ends still re-tokenize the full request text on every call. The cost lands hardest on coding agents, which resubmit a long transcript after each small tool result, and reuse is hard because even a short append can change token boundaries near the end of the previous sequence.서빙 시스템은 프롬프트 KV 상태를 캐시하지만, 대부분의 프런트엔드는 매 호출마다 전체 요청 텍스트를 다시 토큰화한다. 비용은 코딩 에이전트에 가장 크게 떨어진다 — 작은 도구 결과마다 긴 트랜스크립트를 재제출하는데, 짧은 추가만으로도 직전 시퀀스 끝 근처의 토큰 경계가 바뀌어 재사용이 어렵다.
Method방법Measured across 153,951 calls from two agent ecosystems, the median call appends about 1.4K characters and only 1.0–3.6% of calls actually rebuild a sequence from scratch. TokTier makes tokenization exact and stateful: it keeps per-session tokenizer state so appended text is tokenized incrementally with correct boundaries, letting the cached prefix stay valid instead of being re-tokenized wholesale.두 에이전트 생태계의 153,951건 호출을 측정한 결과, 중앙값 호출은 약 1.4K자를 추가하고 실제로 시퀀스를 처음부터 재구성하는 호출은 1.0~3.6%에 불과하다. TokTier는 토큰화를 정확·상태 유지형으로 만든다 — 세션별 토크나이저 상태를 유지해 추가 텍스트를 올바른 경계로 증분 토큰화하고, 캐시된 프리픽스를 통째로 재토큰화하지 않고 유효하게 유지한다.
Results결과By matching tokenization to how agents actually append, TokTier keeps prefix caches reusable across the overwhelming majority of turns rather than invalidating them on every small edit, removing redundant re-tokenization from the agentic serving hot path.토큰화를 에이전트가 실제로 추가하는 방식에 맞춤으로써, TokTier는 매 작은 편집마다 캐시를 무효화하지 않고 압도적 다수 턴에서 프리픽스 캐시를 재사용 가능하게 유지해, 에이전트 서빙 핫패스에서 중복 재토큰화를 제거한다.

Problem문제 정의KV-cache compression is essential for efficient long-context inference, but existing eviction methods permanently discard unselected tokens and remove their aggregate contribution to attention. Merging-based alternatives preserve more information but can perturb the retained keys and values that should stay exact.KV 캐시 압축은 효율적 롱컨텍스트 추론에 필수지만, 기존 축출 방식은 선택되지 않은 토큰을 영구 폐기해 어텐션에 대한 그 총 기여를 없앤다. 병합 기반 대안은 더 많은 정보를 보존하지만, 정확히 유지돼야 할 잔류 키·값을 교란할 수 있다.
Method방법ResKV observes that the information dropped by eviction can be written as residual statistics in both the numerator and denominator of the softmax attention. Rather than keeping the evicted tokens, it reconstructs those aggregate residual contributions at attention time, so the fixed-budget cache approximates full attention without perturbing the exact keys and values it retains.ResKV는 축출이 버리는 정보가 소프트맥스 어텐션의 분자·분모 양쪽에서 잔차 통계로 표현될 수 있음을 관찰한다. 축출된 토큰을 유지하는 대신, 그 총 잔차 기여를 어텐션 시점에 재구성해, 고정 예산 캐시가 유지하는 정확한 키·값을 교란하지 않고도 완전 어텐션을 근사한다.
Results결과By restoring the omitted attention mass instead of throwing it away, ResKV closes much of the gap between hard eviction and full-cache attention at the same memory budget, targeting long-context settings where naïve eviction visibly degrades quality.빠뜨린 어텐션 질량을 버리지 않고 복원함으로써, ResKV는 같은 메모리 예산에서 강한 축출과 완전 캐시 어텐션 사이 격차의 상당 부분을 메우며, 소박한 축출이 눈에 띄게 품질을 떨어뜨리는 롱컨텍스트 상황을 겨냥한다.

Problem문제 정의LLM serving raises batch size to improve throughput, but performance eventually plateaus: beyond a deployment-dependent point, larger batches give marginal gains while inflating latency and GPU memory.
