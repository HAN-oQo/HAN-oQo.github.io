vLLM — the KV connector learns to share a cache between mismatched tensor-parallel layouts Sep 1

The day's centre of gravity was the KV-connector layer, and specifically the Mooncake store. One change lets a producer and a consumer with different tensor-parallel degrees share the same stored cache — the case that blocks you from prefilling on an 8-way instance and decoding on a 2-way one. Three bugfixes cluster around it: a wrong physical-block transfer length in Mooncake, producer partial tails that were never offloaded when a request finished, and a DecodeBench block-selection error under decode context parallelism. Away from the connector, a ModelOpt refactor rebuilt the LinearMethod classes on the generic QuantKey-driven method, and the Kimi-K3 work continued with router-weight prefetching for the M=1 case. 이날 무게중심은 KV 커넥터 계층, 그중에서도 Mooncake 스토어였다. 한 변경은 텐서 병렬 차수가 서로 다른 생산자와 소비자가 같은 저장 캐시를 공유하게 한다 — 8-way 인스턴스에서 프리필하고 2-way에서 디코드하는 구성을 막고 있던 지점이다. 그 주위로 버그 수정 세 건이 뭉쳐 있다. Mooncake의 물리 블록 전송 길이가 틀렸던 문제, 요청이 끝날 때 생산자 쪽 부분 꼬리가 오프로드되지 않던 문제, 디코드 컨텍스트 병렬에서 DecodeBench 블록 선택이 어긋나던 문제다. 커넥터 바깥에서는 ModelOpt 리팩터가 LinearMethod 클래스들을 범용 QuantKey 기반 방식 위에 다시 세웠고, Kimi-K3 작업은 M=1 경우의 라우터 가중치 프리페치로 이어졌다.

SGLang — deleting host–device syncs from the sliding-window path, and sizing the graph pool from measurements Sep 1

Two of the day's merges do the same unglamorous thing in different places: they remove a synchronisation point that forced the GPU to wait on the host. One drops the torch.unique sync from sliding-window page expansion in the memory cache; the other avoids a device-to-host sync for sliding-window lengths on the FlashInfer path. A third change in the same spirit stops allocating a zero bias in fused softmax routing. Separately, the CUDA graph pool stopped being sized by a static guess and now derives its size from warmup measurements, with a fix for graph-pool borrowing alongside. The cookbook grew DeepSeek-V4 recipes for DGX Spark and B200, and unified memory gained decode context parallelism for Kimi-Linear. 이날 머지된 것 중 두 건은 서로 다른 자리에서 같은 종류의 수수한 일을 한다. GPU가 호스트를 기다리게 만드는 동기화 지점을 없애는 것이다. 하나는 메모리 캐시의 슬라이딩 윈도우 페이지 확장에서 torch.unique 동기화를 걷어내고, 다른 하나는 FlashInfer 경로에서 슬라이딩 윈도우 길이의 디바이스→호스트 동기화를 피한다. 같은 결의 세 번째 변경은 fused softmax 라우팅에서 0 편향을 아예 할당하지 않게 한다. 별개로 CUDA 그래프 풀은 정적인 짐작 대신 워밍업 측정값에서 크기를 정하게 됐고, 그래프 풀 대여 문제 수정이 함께 들어왔다. 쿡북에는 DGX Spark와 B200용 DeepSeek-V4 레시피가 추가됐으며, 통합 메모리는 Kimi-Linear용 디코드 컨텍스트 병렬을 지원하게 됐다.

NVIDIA Dynamo — the router gains session affinity, and readiness becomes something you can scrape Sep 1

Dynamo's day was router work. Hard and soft session affinity landed, which is what you need when a multi-turn conversation should keep hitting the worker that already holds its prefix — hard when correctness demands it, soft when you would rather trade a cache miss than queue. Request-lifecycle cleanup was unified in one place, and a Rust/Python mismatch in kv-router environment-variable lookup was corrected. On the observability side, model readiness became an exposed metric and batch dispatch is now gated on it, so a worker that is up but not ready no longer receives a batch. Alongside: a GMS V1 refactor covering both vLLM and SGLang integration, and a per-request encode-buffer reuse in the bindings. Faithfulness Is Not Free: Auditing Offline KV-Cache Quantization in Retrieval-Augmented GenerationKV cachequantizationarXiv:2608.30996
arxiv.org/abs/2608.30996 →
Problem문제 정의A RAG system can precompute the KV cache of each retrieved document once and reuse it, so the context never has to be re-encoded per query. Quantizing those stored caches shrinks the storage bill further. The paper's point is that nobody has asked what compression does to faithfulness — whether the answer is still supported by the evidence the model was given — as opposed to accuracy.RAG 시스템은 검색된 문서의 KV 캐시를 한 번 미리 계산해 재사용할 수 있어, 질의마다 문맥을 다시 인코딩하지 않아도 된다. 그 저장된 캐시를 양자화하면 저장 비용은 더 줄어든다. 논문의 지적은, 압축이 충실성에 — 답이 모델에게 주어진 근거로 여전히 뒷받침되는지에 — 무슨 일을 하는지 아무도 묻지 않았다는 것이다. 정확도와는 다른 문제다.
Method방법They evaluate Qwen2.5-7B-Instruct with its offline caches quantized to INT8 and INT4, on RGB and HotpotQA. Accuracy is measured as usual; faithfulness is measured three separate ways — a hallucination detector, NLI entailment against the retrieved passages, and an LLM judge — so that a single flaky metric cannot carry the conclusion.저자들은 Qwen2.5-7B-Instruct의 오프라인 캐시를 INT8과 INT4로 양자화해 RGB와 HotpotQA에서 평가한다. 정확도는 통상대로 재고, 충실성은 세 가지 방법으로 따로 잰다 — 환각 탐지기, 검색된 지문에 대한 NLI 함의, 그리고 LLM 심판이다. 결론이 흔들리는 지표 하나에 얹히지 않게 하기 위해서다.
Results결과INT8 is near-lossless on both accuracy and faithfulness. INT4 lowers accuracy, and — the more interesting finding — among the answers that stay factually correct, over 90% of the faithfulness changes are negative. Accuracy metrics are simply blind to that regression. The harm grows under noisy retrieval and as more chunks are retrieved.INT8은 정확도와 충실성 양쪽에서 거의 무손실이다. INT4는 정확도를 떨어뜨리고, 더 흥미로운 발견으로, 사실관계가 그대로 맞은 답들 안에서도 충실성 변화의 90% 이상이 부정적이다. 정확도 지표는 그 퇴행을 아예 보지 못한다. 검색이 잡음 섞일수록, 그리고 청크를 더 많이 가져올수록 피해가 커진다.
Summary요약The practical rule the paper hands you is short: INT8 offline caches are safe, INT4 is not, and "accuracy held" is not evidence that compression was harmless. Faithfulness has to be audited separately before a compressed cache goes into production.논문이 건네는 실무 규칙은 짧다. INT8 오프라인 캐시는 안전하고 INT4는 아니며, "정확도가 유지됐다"는 것은 압축이 무해했다는 증거가 아니라는 것이다. 압축 캐시를 프로덕션에 올리기 전에 충실성은 따로 감사해야 한다.

A Universal Context-Reuse Layer for Cross-Model KV Sharingprefix cachingheterogeneous servingarXiv:2608.30963
arxiv.org/abs/2608.30963 →
Problem문제 정의Serving stacks reuse KV caches aggressively, but every existing mechanism assumes the producer and the consumer of a cache are the same model. In a fleet running several models over the same shared context — a document, a system prompt, a conversation history — each model still pays its own full prefill for text another model has already read.서빙 스택은 KV 캐시를 적극적으로 재사용하지만, 기존 메커니즘은 모두 캐시의 생산자와 소비자가 같은 모델이라고 전제한다. 같은 공유 문맥 — 문서, 시스템 프롬프트, 대화 기록 — 위에서 여러 모델을 돌리는 환경에서는, 다른 모델이 이미 읽은 텍스트에 대해서도 각 모델이 자기 몫의 전체 프리필을 그대로 낸다.
