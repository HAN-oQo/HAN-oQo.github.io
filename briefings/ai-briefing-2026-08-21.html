Pre-Compiled Pipeline Shards for Distributed LLM Inference on Intel AI PC Fleetspipeline paralleledge fleet2608.19147
Four idle laptops, pre-compiled per-layer shards, and a 70B model none of them can hold (arXiv 2608.19147) ↗유휴 노트북 4대, 레이어별 사전 컴파일 샤드, 그리고 어느 한 대도 못 담는 70B 모델 (arXiv 2608.19147) ↗
Problem문제 정의Modern Intel AI PCs ship integrated GPUs and NPUs with 16+ GB of unified memory and spend a lot of that capacity idle, but 16 GB is nowhere near enough for a 70B-parameter model. The obvious answer — split the model by layer across several machines over an ordinary network — normally loses so much speed that it stops being worth doing.요즘 Intel AI PC는 통합 GPU·NPU와 16GB 이상 통합 메모리를 갖추고도 그 용량을 놀리는 시간이 길지만, 16GB는 70B 파라미터 모델에는 턱없이 부족하다. 뻔한 해법 — 평범한 네트워크로 여러 대에 레이어 단위로 모델을 쪼개는 것 — 은 보통 속도를 너무 많이 잃어 할 이유가 사라진다.
Method방법Each per-stage shard is pre-compiled into an OpenVINO graph so one machine runs one shard and passes activations to the next. Three techniques close the speed gap. A naive per-stage export runs well below monolithic inference because it misses an OpenVINO GPU optimization; injecting a beam_idx Gather into each shard triggers the IndirectKVCache fusion and brings the shards back to parity. Speculative decoding is then applied on stateful OpenVINO models. Finally the pipeline serves several users at once by interleaving their requests across stages, each request carrying its own cache — micro-batching.각 스테이지 샤드를 OpenVINO 그래프로 미리 컴파일해, 한 대가 한 샤드를 실행하고 활성값을 다음으로 넘긴다. 속도 격차는 세 기법으로 메운다. 단순한 스테이지별 익스포트는 OpenVINO GPU 최적화를 놓쳐 단일체 추론보다 훨씬 느린데, 각 샤드에 beam_idx Gather를 넣으면 IndirectKVCache 융합이 발동해 원래 속도로 돌아온다. 그다음 스테이트풀 OpenVINO 모델 위에 추측 디코딩을 적용한다. 마지막으로 여러 사용자의 요청을 스테이지에 교차 배치하고 요청마다 자기 캐시를 들고 다니게 해(마이크로 배칭) 동시 서빙을 얻는다.
Results결과A two-node Llama 3.1 8B INT4 pipeline serves two concurrent users at 1.79× the single-user throughput of the unsplit model on the same hardware, and the gap widens under simulated wide-area latency. The design also scales to a 70B model no single fleet member can hold: four Lunar Lake AI PCs on Intel Tiber Cloud serve one user at interactive speed, with output token-for-token identical to the same four-node pipeline decoding without speculation. Code, raw benchmark logs and reproduction scripts are released.2노드 Llama 3.1 8B INT4 파이프라인은 같은 하드웨어에서 쪼개지 않은 모델의 단일 사용자 처리량 대비 1.79배로 두 사용자를 동시에 서비스하며, 광역 지연을 모사하면 격차가 더 벌어진다. 어느 한 대도 담을 수 없는 70B 모델까지 확장되어, Intel Tiber Cloud의 Lunar Lake AI PC 4대가 한 사용자를 대화 가능한 속도로 서비스하고, 출력은 추측 없이 디코딩한 동일 4노드 파이프라인과 토큰 단위로 일치한다. 코드·원시 벤치마크 로그·재현 스크립트가 공개됐다.
