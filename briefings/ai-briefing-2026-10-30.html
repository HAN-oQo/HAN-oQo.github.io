CRISP: Co-designing Pruning and Scheduling for Efficient MoE Inference on Edge ServersMoEedge servingarXiv:2610.37442
arxiv.org/abs/2610.37442 →

Problem문제 정의On memory-constrained edge platforms, MoE inference is dominated by moving expert weights rather than computing. Routing is input-dependent, so every expert must stay reachable, and uniform pruning or expert dropping ignores that expert combinations are highly skewed in frequency and that experts contribute unequally inside a combination.메모리가 제한된 엣지 환경에서 MoE 추론은 연산보다 전문가 가중치 이동이 지배한다. 라우팅이 입력에 따라 달라 모든 전문가에 접근 가능해야 하는데, 균일 가지치기나 전문가 제거는 전문가 조합의 빈도가 크게 치우쳐 있고 한 조합 안에서도 기여도가 다르다는 점을 무시한다.

Method방법CRISP reorders neurons by importance so that one stored expert can run at several execution widths. It assigns different execution to hot, warm and cold expert combinations based on frequency and expert role, and exploits the heterogeneous widths to overlap expert loading with computation.CRISP는 뉴런을 중요도 순으로 재정렬해 저장된 전문가 하나를 여러 실행 폭으로 돌릴 수 있게 한다. 빈도와 전문가 역할에 따라 뜨거운·따뜻한·차가운 전문가 조합에 서로 다른 실행 방식을 배정하고, 이 이질적 폭을 이용해 전문가 로딩과 연산을 겹친다.

Results결과On Mixtral-8x7B and DeepSeek-MoE-16B, CRISP improves throughput by up to 2.1x at the same memory budget while limiting accuracy loss to 3.6% relative to full-width inference.Mixtral-8x7B와 DeepSeek-MoE-16B에서 같은 메모리 예산으로 처리량을 최대 2.1배 높이면서, 전체 폭 추론 대비 정확도 손실을 3.6%로 제한한다.

Summary요약Efficient edge MoE serving needs to decide jointly which expert capacity to keep and how to schedule expert execution.효율적인 엣지 MoE 서빙은 어떤 전문가 용량을 남길지와 전문가 실행을 어떻게 스케줄할지를 함께 최적화해야 한다.

Problem문제 정의Existing agentic-serving systems ignore whether an external tool result is about to be ready, which wastes limited GPU resources, and they rely on heuristics to decide which waiting sessions to admit and where to place them.기존 에이전트 서빙 시스템은 외부 도구 결과가 곧 준비되는지를 무시해 한정된 GPU 자원을 낭비하고, 어떤 대기 세션을 받아들여 어디에 배치할지도 휴리스틱에 의존한다.

Method방법TAO combines a tool readiness score for near-term tool-return availability, a node cache credit with time-aware decay, and a token footprint for each session's memory cost. A joint dynamic program then selects and places waiting sessions under capacity constraints.TAO는 도구 반환이 임박했는지를 나타내는 준비도 점수, 시간에 따라 감쇠하는 노드별 캐시 크레딧, 세션별 메모리 비용인 토큰 풋프린트를 결합한다. 이어 결합 동적 계획법이 용량 제약 아래에서 대기 세션을 선택하고 배치한다.

Results결과Across 12 model-workload-concurrency settings, TAO cuts latency by up to 26.8%, mean time to first token by up to 36.3% and raises decode throughput by up to 29.5% versus the best evaluated baseline per metric.12가지 모델·워크로드·동시성 설정에서 지표별 최고 기준선 대비 지연을 최대 26.8%, 평균 첫 토큰 시간을 최대 36.3% 줄이고 디코드 처리량을 최대 29.5% 높인다.

arxiv.org/abs/2610.34721 →

Problem문제 정의When an MoE model exceeds GPU memory, batch-1 decoding slows from copying expert weights from host memory, and combining cache-aware routing with asynchronous prefetching makes outputs depend on transfer timing, so evaluations that ignore timing misdescribe the deployed model.MoE 모델이 GPU 메모리를 넘으면 배치 1 디코딩이 호스트 메모리의 전문가 가중치 복사로 느려진다. 캐시 인식 라우팅과 비동기 프리페치를 합치면 출력이 전송 타이밍에 좌우되어, 타이밍을 무시한 평가는 배포 모델을 제대로 반영하지 못한다.

Method방법Prefetch-steered routing keeps a deterministic per-layer logical cache of resident expert IDs.
