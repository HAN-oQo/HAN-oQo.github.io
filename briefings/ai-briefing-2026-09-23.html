Who Pays for the KV Cache? Attributing Shared AI Inference Spend Across Kubernetes and LLM Provider Billsserving costmulti-tenancyarXiv:2609.24991
arxiv.org/abs/2609.24991 →

ProblemOrganisations pay for AI through ledgers that do not talk to each other: Kubernetes allocations for self-hosted inference, gateway logs, and per-token bills from API providers. Where those systems meet, spend loses its owner — and inside a shared inference server, the rule used to meter tenants silently decides who pays for a KV cache everyone uses.조직은 서로 연결되지 않은 장부로 AI 비용을 낸다. 자체 호스팅 추론의 쿠버네티스 할당, 게이트웨이 로그, API 제공사의 토큰당 청구서다. 이 시스템들이 만나는 이음매에서 비용은 주인을 잃고, 공유 추론 서버 안에서는 테넌트를 계량하는 규칙이 모두가 쓰는 KV 캐시 비용을 누가 낼지를 조용히 결정한다.

MethodThe authors build unalloc, an open-source tool that joins OpenCost, LiteLLM, OpenAI and Anthropic cost data into one exact ledger and reports the share of spend with no owner. Five case studies run or simulate inference: a vLLM-style simulator with paged KV memory and prefix caching, a PyTorch transformer serving a multi-tenant trace with a real KV cache, tensor- and pipeline-parallel inference, the unmodified CLI against mock provider APIs, and four downstream use cases.저자들은 OpenCost, LiteLLM, OpenAI, Anthropic 비용 데이터를 하나의 정확한 장부로 합치고 주인 없는 비용의 비율을 보고하는 오픈소스 도구 unalloc을 만든다. 다섯 사례 연구가 추론을 실제로 돌리거나 시뮬레이션한다. paged KV 메모리와 프리픽스 캐싱을 갖춘 vLLM 방식 시뮬레이터, 실제 KV 캐시로 멀티테넌트 트레이스를 서빙하는 PyTorch 트랜스포머, 텐서·파이프라인 병렬 추론, 모의 제공사 API를 상대로 한 무수정 CLI, 그리고 하류 사용 사례 넷이다.

ResultsIn a constructed multi-pod scenario (one month of synthetic OpenCost allocations, not observed billing), owner labels set only on LeaderWorkerSet leader pods leave 66% of the GPU bill unowned; the natural fallback key assigns 61% of it to a Helm chart name while the headline unallocated share falls to 4%. SPECTRA: Adaptive Execution of Speculative Decoding on a Runtime-Reconfigurable Tiled Architecturespeculative decodinghardwarearXiv:2609.24847
arxiv.org/abs/2609.24847 →

ProblemOn edge devices, speculative decoding helps because a small drafter proposes tokens and the target verifies several at once. But verification sits in an awkward middle regime: decode is a memory-bound GEMV, prefill is a compute-bound GEMM, and verification's arithmetic intensity moves between them depending on speculation length and acceptance rate. Hardware fixed for either extreme is under-used for the other.엣지 기기에서 추측 디코딩이 도움이 되는 건 작은 초안기가 토큰을 제안하고 대상 모델이 여러 개를 한 번에 검증하기 때문이다. 그런데 검증은 어정쩡한 중간 영역에 있다. 디코드는 메모리 제약 GEMV, 프리필은 연산 제약 GEMM이고, 검증의 산술 강도는 추측 길이와 수락률에 따라 둘 사이를 오간다. 한쪽 극단에 고정된 하드웨어는 다른 쪽에서 놀게 된다.

MethodSPECTRA is a runtime-reconfigurable tiled architecture. Inside each tile, the compute engine switches between systolic execution for GEMMs and vector-lane execution for GEMVs. Across tiles, the system adapts parallelism by choosing tile count, kernel partitioning and communication pattern. Both levels of reconfiguration happen per kernel, so draft, verify and decode each get the shape that suits them.SPECTRA는 실행 중 재구성 가능한 타일 구조다. 각 타일 안에서 연산 엔진은 GEMM에는 시스톨릭 실행, GEMV에는 벡터 레인 실행으로 전환한다. 타일 사이에서는 타일 수, 커널 분할, 통신 패턴을 골라 병렬성을 맞춘다. 두 수준의 재구성 모두 커널 단위로 일어나므로, 초안·검증·디코드가 각자 맞는 모양을 얻는다.
