vLLM — Model Runner V2 learns to estimate acceptance, and quantization picks its own linear backend Sep 14

Sixty-nine commits, no new tag. The most forward-looking change is in Model Runner V2: acceptance estimation for adaptive verification. Speculative decoding usually verifies a fixed number of draft tokens per step; estimating the acceptance rate online is the prerequisite for deciding how many to verify, which is the difference between a speedup that holds on one workload and one that adapts to the traffic actually arriving. Alongside it, MRV2 learned to run pooling post-processing on non-final pipeline-parallel ranks, removing a needless serialization at the end of the pipeline. On the quantization side, linear backends are now selected per quantization scheme rather than globally — a small piece of plumbing that stops one scheme's best kernel from being imposed on another — and ReLU2 was fused with static FP8 activation quantization, collapsing an activation and its quantization into one pass. Metrics grew up too: MFU/MBU estimation now understands sliding-window attention and hybrid layers, so the utilization numbers stop silently assuming dense full attention. The ROCm DeepSeek-V4.1 lane stayed busy — the mHC post step was folded into the delayed pre-projection, the DSA decode candidate mask is strided over the live context rather than the full allocation, and CSA multi-stream overlap was enabled for DeepSeek-V4. Correctness and hygiene items: a padded-vocab d2t requirement was fixed for Qwen3 DSpark drafts, in-flight async lookup probes are reused in KV offload instead of being reissued, Qwen-VL video sampling knobs were capped, and credentials are now redacted from benchmark logs. 커밋 69개, 새 태그 없음. 핵심은 Model Runner V2의 적응형 검증용 수용률 추정이다. 스펙 디코딩은 보통 단계마다 정해진 수의 초안 토큰을 검증하는데, 수용률을 온라인으로 추정해야 검증 개수를 트래픽에 맞춰 조절할 수 있다. SGLang — a DCP double-free is closed at the page boundary, and gfx950 attention gets length-aware split-KV Sep 14

Forty-three commits, no new tag. The sharpest fix is a memory-safety one: adjacent KV-row frees are now merged so that a mid-page split under decode context parallelism cannot double-free. A page that is split across CP ranks can have its halves returned independently, and without coalescing the allocator sees the same page freed twice — the class of bug that surfaces as corrupted output long after the real fault. A second ordering fix makes DeepSeek-V4 K-cache reads wait for PDL, and prefetch cache state is now scoped to the request attempt rather than the request, so a retry does not inherit the state of the attempt that failed. AMD got the bulk of the performance work: gfx950 assembly attention gained length-aware split-KV for dynamic workloads, the chunked-prefill compute budget is now filled exactly rather than approximately, and an FP8 two-pool unified KV landed on gfx950; the GLM-5.2 MI355X MXFP4 image was bumped and TOPK_V2 enabled. On Ascend, CANN 9.1.0 and a5 nightly suites were added to CI and a SWA-mask device mismatch in DSpark verify graph capture was fixed. Prefill-decode work continued — speculative workers may now stage prefill shared reads, and the prefill rank is preserved across rebootstrap — and one batch of four changes was reverted, with one of them relanded in clamped form the same day. 커밋 43개, 새 태그 없음. 가장 중요한 수정은 메모리 안전이다. 디코드 컨텍스트 병렬(DCP)에서 페이지가 CP 랭크에 걸쳐 갈리면 두 절반이 따로 반환돼 같은 페이지가 두 번 해제될 수 있었다. 이제 인접한 KV 행 해제를 병합해 막는다. 이런 버그는 한참 뒤에 출력 손상으로 드러난다. Dynamo — a refused request stops looking like a server fault, and prompt tokens are shared across clones Sep 14

Twenty-eight commits, no new tag. The change with the longest operational tail is small: when a backend refuses a request it cannot serve, the runtime now returns 400 instead of 500. That single digit decides whether a client retries, whether a load balancer ejects the replica, and whether an on-call page fires — a refusal is the caller's problem, a 500 says the server broke. Dissecting GPU Utilization for LLM Inference on Nvidia HopperprofilingdecodearXiv:2609.12923
arxiv.org/abs/2609.12923 →
Problem문제 정의 A single SM-utilization percentage can make an inference workload look compute-saturated while hiding how much useful work is actually being done. The counter is not wrong; it collapses several distinct mechanisms into one number. The problem bites hardest during decode, where each request contributes only one new token and the dense projection GEMMs degenerate into small-row matrix multiplications. SM 사용률 숫자 하나는 워크로드를 연산 포화처럼 보이게 하지만 실제 유효 작업량은 가린다. 여러 기전을 한 숫자로 접기 때문이다. 요청마다 토큰 하나만 보태는 디코드에서 특히 심하다.
Method방법 The authors profile vLLM with FlashAttention-3 and cuBLASLt on an H100 NVL across cold prefill, warm prefill and decode, sweeping sequence length and batch size. They replace the usual single utilization number with eight counter-validated views derived from raw Nsight Compute reports, each pinned to a specific NCU counter or an explicit formula. The framing rests on a hardware detail: on Hopper the bfloat16 GMMA path executes in fixed 64-row matrix fragments, so small-batch decode can fill only a small fraction of each fragment with real token rows. H100 NVL에서 vLLM(FlashAttention-3, cuBLASLt)을 콜드·웜 프리필과 디코드로 나눠 프로파일링했다. 사용률 숫자 하나 대신 Nsight Compute 카운터나 명시적 수식에 묶인 여덟 가지 시각을 쓴다. Hopper의 bfloat16 GMMA는 64행 프래그먼트 단위로 돌기 때문에, 작은 배치 디코드는 프래그먼트의 일부만 실제 토큰으로 채운다.
Results결과 The eight views map utilization gaps onto concrete mechanisms — fragment fill, occupancy limits, stall signatures, wave quantization and kernel selection — across four production models and six per-layer kernel roles. The practical upshot is that a high SM-utilization reading during decode is frequently a fragment-fill artifact rather than evidence that the GPU is doing useful arithmetic. 여덟 시각은 사용률의 빈틈을 프래그먼트 채움, 점유율 한계, 정체 신호, 웨이브 양자화, 커널 선택으로 나눠 보여 준다(프로덕션 모델 넷, 커널 역할 여섯). 디코드에서 높은 SM 사용률은 유효 연산이 아니라 프래그먼트 채움의 부산물인 경우가 많다.
Summary요약 A measurement paper that argues the standard utilization metric is the wrong instrument for decode, and replaces it with eight views each traceable to a counter. For anyone sizing a decode fleet, the fragment-fill view is the one that changes decisions. 디코드에는 표준 사용률 지표가 맞지 않는다는 측정 논문이다. 디코드 설비 규모를 정할 때는 프래그먼트 채움 시각을 봐야 한다.

Problem문제 정의 AI is already contributing to LLM inference optimization, but almost all of it is profiling-based. Profiling-bound feedback confines the search to the capabilities and measured performance of an existing software stack, so a fundamentally better architecture can never be identified — the search cannot evaluate a design the current stack cannot run. AI 기반 추론 최적화는 대부분 프로파일링에 의존한다. 그러면 탐색이 지금 스택이 돌릴 수 있는 설계 안에 갇혀, 근본적으로 더 나은 아키텍처는 평가조차 못 한다.
