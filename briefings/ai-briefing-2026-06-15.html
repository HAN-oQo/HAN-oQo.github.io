SGLang main — ~70 commits since v0.5.13 harden the diffusion serving backend SGLangJun 14

After tagging v0.5.13, SGLang's main branch kept moving fast — roughly 70 commits merged in the window, with the diffusion-model backend the clear center of gravity. New work makes Diffusion Transformer (DiT) serving faster and more scalable: regional torch.compile (compile_repeated_blocks) for the diffusers DiT path, spatial-shard VAE decode spread across GPUs, VAE parallel decode combined with CFG-parallelism, and a --warmup-mode server argument plus broader warmup coverage. Outside diffusion it added a multi-GPU test/bench framework for custom all-reduce with tensor-parallel QK-Norm and reverted an AMD MXFP4 online-requantization change. The throughline: the engine is investing in image/video generation serving alongside its LLM core.

NVIDIA Dynamo main — worker-side request admission and a unified router log land after v1.2.1 DynamoJun 14

Dynamo's main branch added several routing- and runtime-level controls on top of the v1.2.1 patch. The headline is worker-side request admission — new --engine-request-limit and --dynamo-request-queue-limit flags let a worker shed or queue load before it overcommits — alongside a unified, structured "Selected-worker" INFO log across all router modes and a fix to log request rejections at warn rather than error level. There were also correctness touches (resolving EOS/BOS token ids from tokenizer config, normalizing the unified vLLM served-model name) and SGLang doc cleanup. Taken together it's about making the router's decisions observable and its admission behaviour controllable under pressure.

핵심은 워커측 요청 수용(request admission)이다. 새 --engine-request-limit·--dynamo-request-queue-limit 플래그로 워커가 과부하 전에 요청을 거절하거나 대기열에 넣는다. 모든 라우터 모드에 통합 "Selected-worker" INFO 로그가 생겼고, 요청 거부 로그는 error에서 warn으로 낮췄다. tokenizer config에서 EOS/BOS id 해석, vLLM served-model 이름 정규화 같은 보정도 있었다. 라우터 결정을 보이게 하고 부하 시 수용을 제어하려는 변경이다.

Can I Buy Your KV Cache? — a token-exact market for precomputed prefillKV cache2606.13361
Can I Buy Your KV Cache? (arXiv 2606.13361, submitted Jun 11) ↗Can I Buy Your KV Cache? (arXiv 2606.13361, 6/11 제출) ↗
Problem문제 정의Across the world, AI agents repeat the same absurd act: to read one document, each recomputes it from scratch. Every agent re-runs prefill — the most compute-intensive step a large model takes — over identical text, only to rebuild a KV cache identical to the one the agent before it just built. The same answer is computed a million times.AI 에이전트들은 같은 문서를 읽을 때마다 각자 prefill(가장 연산이 큰 단계)을 다시 돌려 똑같은 KV 캐시를 만든다. 같은 계산이 백만 번 반복되는 셈이다.
Method방법The proposal is "almost offensively simple": compute it once. Let a publisher precompute a document's KV cache, then let every other agent buy the right to load it and skip prefill entirely. The key technical claim is that this is token-exact — loading a precomputed KV and continuing matches prefilling from scratch.발행자가 문서의 KV 캐시를 한 번 계산하고, 다른 에이전트는 이를 로드할 권리를 사서 prefill을 건너뛴다. 로드 후 이어 가도 처음부터 prefill한 결과와 토큰 단위로 같다는 것이 핵심 주장이다.
Results결과Loading and continuing matches prefilling exactly (24/24 greedy tokens, and at the logits level) with no accuracy cost. On Qwen3-4B, reuse is 9–50× cheaper in compute than prefill, and the gap widens with length because prefill attention scales with L², so a single reuse already pays for itself.그리디 토큰 24/24, 로짓 수준까지 일치해 정확도 손실이 없다. Qwen3-4B에서 재사용은 prefill보다 9–50× 싸고, prefill 어텐션이 L²로 늘어 길수록 격차가 커지므로 한 번만 재사용해도 본전이다.
Summary요약If a million agents read the same document, prefill it once and let the rest load the KV — it's exact and 9–50× cheaper.같은 문서라면 prefill은 한 번만 하고 나머지는 KV를 로드한다. 결과는 같고 9–50× 싸다.

A document's KV cache is computed once by a publisher and loaded by every other agent, replacing repeated prefill with an exact, far cheaper load.한 번 계산한 KV를 여럿이 로드해 반복 prefill을 대체한다.
The Brain That Goes Quiet — 131 tok/s on an 8 GB laptop by taking the big model off the runtime pathon-device serving2606.12154
The Brain That Goes Quiet: Serving a Large Model's Knowledge at 131 Tokens per Second on an 8 GB Laptop by Removing the Large Model from the Runtime Path (arXiv 2606.12154, submitted Jun 10) ↗The Brain That Goes Quiet: Serving a Large Model's Knowledge at 131 Tokens per Second on an 8 GB Laptop by Removing the Large Model from the Runtime Path (arXiv 2606.12154, 6/10 제출) ↗
Problem문제 정의Earlier work showed a 35B-class Mixture-of-Experts model can be loaded and run on a consumer laptop with 8 GB of GPU memory. That solved placement but exposed a new problem: even correctly placed, the model took roughly four seconds to answer because it was still invoked at every query.앞선 연구로 35B급 MoE를 8 GB GPU 노트북에 올리는 데는 성공했다. 하지만 매 질의마다 모델을 호출해 답 하나에 약 4초가 걸렸다.
Method방법The author simply stopped invoking it at runtime. In an offline phase the large model reads source documents and writes verified answer entries into a structured knowledge store. At runtime only a lightweight router, a deterministic renderer, and a 1B-class model are active — the big model "goes quiet."오프라인에서 대형 모델이 문서를 읽어 검증된 답 항목을 지식 저장소에 써 둔다. 런타임에는 경량 라우터, 결정적 렌더러, 1B급 모델만 돌고 대형 모델은 "조용해진다".
Results결과On the same 8 GB laptop, end-to-end response time fell from ~4,465 ms to 518 ms and effective throughput rose from 15.7 to 131 tokens per second — by serving the precomputed knowledge instead of the model itself.같은 노트북에서 응답 시간이 약 4,465 ms에서 518 ms로, 실효 처리량이 15.7에서 131 tok/s로 개선됐다.
Summary요약Don't run the big model per query if you can precompute its answers — serve the verified knowledge store and keep a 1B model on the hot path.답을 미리 계산할 수 있으면 대형 모델은 오프라인에만 쓰고, 핫패스에는 지식 저장소와 1B 모델만 둔다.

The large model writes a verified knowledge store offline; at runtime a router, renderer and 1B model serve it, leaving the big model idle.오프라인 지식 저장소와 경량 런타임 구성.
FCGraft — functional cache grafting to cut repetitive prefill for code-policy agentsKV cache2606.13097
Functional Cache Grafting: Robust and Rapid Code-Policy Synthesis for Embodied Agents (arXiv 2606.13097, submitted Jun 11) ↗Functional Cache Grafting: Robust and Rapid Code-Policy Synthesis for Embodied Agents (arXiv 2606.13097, 6/11 제출) ↗
Problem문제 정의Code-writing LLMs turn natural-language goals into executable control programs for embodied agents. In open-domain settings this suffers twice: delayed decoding from repetitive prefill over long prompts, and limited robustness from fully generative decoding, which often yields API mismatches, missing safety guards, and unstable control logic.코드 LLM으로 체화 에이전트의 제어 프로그램을 만들 때, 긴 프롬프트의 반복 prefill이 느리고 전부 생성하다 보니 API 불일치나 안전 가드 누락이 잦다.
Method방법FCGraft maintains a library of function-level, validated code units and grafts their cached representations into generation instead of decoding everything from scratch. Reusing validated functions both skips repeated prefill computation and constrains output toward correct, guard-checked control logic.FCGraft는 검증된 함수 단위 코드 라이브러리를 두고, 그 캐시된 표현을 생성에 접붙인다(graft). 반복 prefill을 건너뛰면서 출력도 검증된 로직 쪽으로 묶인다.
Results결과By grafting cached, validated functions rather than regenerating them, FCGraft delivers faster code-policy synthesis and more robust programs — fewer API mismatches and missing safety checks — for embodied agents in open-domain environments.코드 정책 합성이 빨라지고 API 불일치와 안전검사 누락이 줄어든다.
Summary요약Don't regenerate the same function and re-prefill its prompt — graft a validated, cached unit and you gain both speed and safety.검증된 캐시 함수를 재사용하면 속도와 안전을 함께 얻는다.

TetherCache — training-free cache management for drift-resistant long video generationvideo gen2606.13035
TetherCache: Stabilizing Autoregressive Long-Form Video Generation with Gated Recall and Trusted Alignment (arXiv 2606.13035, submitted Jun 11) ↗TetherCache: Stabilizing Autoregressive Long-Form Video Generation with Gated Recall and Trusted Alignment (arXiv 2606.13035, 6/11 제출) ↗
Problem문제 정의Autoregressive video diffusion generates streaming, variable-length video by conditioning new frames on prior content. Extending it to minute-level clips is hard: a limited KV-cache budget prevents retaining the full history, while repeatedly conditioning on self-generated frames causes a context distribution shift that accumulates into artifacts, quality loss and temporal drift.자기회귀 비디오 디퓨전을 분 단위로 늘리면 KV 캐시 예산이 부족해 히스토리를 다 못 담는다. 자기 생성 프레임에 계속 조건화하면서 분포가 어긋나 아티팩트와 시간적 드리프트가 쌓인다.
Method방법TetherCache is a training-free, plug-and-play cache strategy. It organizes the KV cache into sink, memory and recent regions and adds two complementary mechanisms — gated recall and trusted alignment — to keep generation tethered to reliable context rather than drifting on its own outputs.TetherCache는 학습 없는 플러그앤플레이 캐시 전략이다. KV 캐시를 sink·memory·recent로 나누고 gated recall과 trusted alignment로 생성을 신뢰할 컨텍스트에 묶는다.
Results결과By managing what the limited cache keeps and trusts, TetherCache resists the distribution shift that degrades long videos, stabilizing quality over minute-level generation without retraining the base model.베이스 모델 재학습 없이 분 단위 생성의 품질을 안정화한다.
Summary요약Long video drifts because it trusts its own recent frames too much — partition the KV cache and gate what it recalls.롱비디오 드리프트는 최근 프레임 과신에서 온다. 캐시를 나누고 회상을 게이팅해 막는다.
