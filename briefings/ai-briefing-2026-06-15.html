NVIDIA Dynamo main — worker-side request admission and a unified router log land after v1.2.1 DynamoJun 14

Dynamo's main branch added several routing- and runtime-level controls on top of the v1.2.1 patch. The headline is worker-side request admission — new --engine-request-limit and --dynamo-request-queue-limit flags let a worker shed or queue load before it overcommits — alongside a unified, structured "Selected-worker" INFO log across all router modes and a fix to log request rejections at warn rather than error level. There were also correctness touches (resolving EOS/BOS token ids from tokenizer config, normalizing the unified vLLM served-model name) and SGLang doc cleanup. Taken together it's about making the router's decisions observable and its admission behaviour controllable under pressure.

Dynamo의 main 브랜치는 v1.2.1 패치 위에 라우팅·런타임 수준 제어를 여럿 추가했다. 핵심은 워커측 요청 수용(request admission)이다 — 새 --engine-request-limit·--dynamo-request-queue-limit 플래그로 워커가 과부하되기 전에 부하를 떨치거나 대기열에 넣을 수 있다. 더불어 모든 라우터 모드에서 통합·구조화된 "Selected-worker" INFO 로그와, 요청 거부를 error가 아니라 warn 수준으로 남기는 수정이 들어갔다. 정합성 보정(tokenizer config에서 EOS/BOS 토큰 id 해석, 통합 vLLM served-model 이름 정규화)과 SGLang 문서 정리도 있었다. 종합하면 라우터의 결정을 관측 가능하게, 수용 동작을 압박 상황에서 제어 가능하게 만드는 흐름이다.

Can I Buy Your KV Cache? — a token-exact market for precomputed prefillKV cache2606.13361
Can I Buy Your KV Cache? (arXiv 2606.13361, submitted Jun 11) ↗Can I Buy Your KV Cache? (arXiv 2606.13361, 6/11 제출) ↗
Problem문제 정의Across the world, AI agents repeat the same absurd act: to read one document, each recomputes it from scratch. Every agent re-runs prefill — the most compute-intensive step a large model takes — over identical text, only to rebuild a KV cache identical to the one the agent before it just built. The same answer is computed a million times.전 세계의 AI 에이전트가 같은 어이없는 짓을 반복한다 — 문서 하나를 읽으려고 저마다 처음부터 다시 계산한다. 모든 에이전트가 동일한 텍스트에 prefill(대형 모델이 하는 가장 연산 집약적 단계)을 다시 돌려, 바로 앞 에이전트가 막 만든 것과 똑같은 KV 캐시를 또 만든다. 같은 답이 백만 번 계산된다.
Method방법The proposal is "almost offensively simple": compute it once. Let a publisher precompute a document's KV cache, then let every other agent buy the right to load it and skip prefill entirely. The key technical claim is that this is token-exact — loading a precomputed KV and continuing matches prefilling from scratch.제안은 "거의 모욕적일 만큼 단순"하다 — 한 번만 계산하라. 발행자가 문서의 KV 캐시를 미리 계산하고, 다른 모든 에이전트는 그것을 로드해 prefill을 통째로 건너뛸 권리를 산다. 핵심 기술 주장은 이것이 토큰 단위로 정확하다는 것 — 미리 계산된 KV를 로드해 이어 가는 것이 처음부터 prefill하는 것과 일치한다.
Results결과Loading and continuing matches prefilling exactly (24/24 greedy tokens, and at the logits level) with no accuracy cost. On Qwen3-4B, reuse is 9–50× cheaper in compute than prefill, and the gap widens with length because prefill attention scales with L², so a single reuse already pays for itself.로드 후 이어 가기는 prefill과 정확히 일치하며(그리디 토큰 24/24, 로짓 수준까지) 정확도 손실이 없다. Qwen3-4B에서 재사용은 prefill보다 연산이 9–50× 싸고, prefill 어텐션이 L²로 늘어나므로 길이가 길수록 격차가 커진다 — 한 번의 재사용만으로 이미 본전을 뽑는다.
Summary요약If a million agents read the same document, prefill it once and let the rest load the KV — it's exact and 9–50× cheaper.백만 에이전트가 같은 문서를 읽는다면 prefill은 한 번만 하고 나머지는 KV를 로드하게 하라 — 정확하고 9–50× 싸다.

Problem문제 정의Earlier work showed a 35B-class Mixture-of-Experts model can be loaded and run on a consumer laptop with 8 GB of GPU memory. Method방법The author simply stopped invoking it at runtime. In an offline phase the large model reads source documents and writes verified answer entries into a structured knowledge store. Problem문제 정의Code-writing LLMs turn natural-language goals into executable control programs for embodied agents. In open-domain settings this suffers twice: delayed decoding from repetitive prefill over long prompts, and limited robustness from fully generative decoding, which often yields API mismatches, missing safety guards, and unstable control logic.코드 작성 LLM은 자연어 목표를 체화 에이전트의 실행 가능한 제어 프로그램으로 바꾼다. 개방 도메인에선 두 번 손해를 본다 — 긴 프롬프트에 대한 반복 prefill로 디코딩이 지연되고, 완전 생성형 디코딩의 낮은 견고성으로 API 불일치·누락된 안전 가드·불안정한 제어 로직이 자주 나온다.
Method방법FCGraft maintains a library of function-level, validated code units and grafts their cached representations into generation instead of decoding everything from scratch. Reusing validated functions both skips repeated prefill computation and constrains output toward correct, guard-checked control logic.FCGraft는 함수 단위로 검증된 코드 유닛 라이브러리를 유지하고, 모든 것을 처음부터 디코딩하는 대신 그들의 캐시된 표현을 생성에 접붙인다(graft). 검증된 함수를 재사용해 반복 prefill 연산을 건너뛰는 동시에 출력을 정확하고 가드가 검사된 제어 로직 쪽으로 제약한다.
Results결과By grafting cached, validated functions rather than regenerating them, FCGraft delivers faster code-policy synthesis and more robust programs — fewer API mismatches and missing safety checks — for embodied agents in open-domain environments.재생성 대신 캐시된 검증 함수를 접붙임으로써, FCGraft는 개방 도메인 체화 에이전트에 더 빠른 코드 정책 합성과 더 견고한 프로그램(API 불일치·누락 안전검사 감소)을 제공한다.
Summary요약Don't regenerate the same function and re-prefill its prompt — graft a validated, cached unit and you gain both speed and safety.같은 함수를 재생성하고 그 프롬프트를 다시 prefill하지 말라 — 검증된 캐시 유닛을 접붙이면 속도와 안전을 함께 얻는다.

Problem문제 정의Autoregressive video diffusion generates streaming, variable-length video by conditioning new frames on prior content. Extending it to minute-level clips is hard: a limited KV-cache budget prevents retaining the full history, while repeatedly conditioning on self-generated frames causes a context distribution shift that accumulates into artifacts, quality loss and temporal drift.자기회귀 비디오 디퓨전은 새 프레임을 이전 내용에 조건화해 스트리밍·가변 길이 영상을 만든다. 이를 분 단위로 늘리기는 어렵다 — 제한된 KV 캐시 예산이 전체 히스토리 보존을 막고, 자기 생성 프레임에 반복 조건화하면 컨텍스트 분포가 점차 어긋나 아티팩트·품질 저하·시간적 드리프트로 쌓인다.
