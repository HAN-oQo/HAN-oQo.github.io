Move the KV cache to the next base station before the handover, not after it (arXiv 2608.16477) ↗핸드오버 이후가 아니라 이전에 KV 캐시를 다음 기지국으로 옮기기 (arXiv 2608.16477) ↗
Problem문제 정의AI-RAN puts LLM serving next to mobile users, but a cellular handover can separate an in-flight request from its inference state: the user attaches to a target base station while the large, still-growing KV cache stays at the source. Keeping inference at the source preserves continuity but permanently raises inter-token latency; recovering the state at the target restores locality but requires transfer, recomputation, or both — and all of it happens only after the handover, directly extending service interruption time.AI-RAN은 LLM 서빙을 모바일 사용자 가까이 두지만, 셀룰러 핸드오버는 진행 중인 요청을 그 추론 상태로부터 떼어놓는다. 사용자는 타깃 기지국에 붙는데 크고 계속 자라는 KV 캐시는 소스에 남는다. 소스에서 계속 추론하면 연속성은 지켜지지만 토큰 간 지연이 영구적으로 올라가고, 타깃에서 상태를 복구하면 지역성은 회복되지만 전송·재계산 또는 둘 다가 필요하며 그 작업이 전부 핸드오버 이후에 일어나 서비스 중단 시간을 직접 늘린다.
Method방법Pallas prepares the inference state at the predicted target before the handover, in parallel with ongoing source-side inference and token delivery. At the preparation trigger it splits the token sequence into a stable historical prefix and an evolving suffix: the target reconstructs the prefix by local prefill, while the source streams the KV blocks generated for the suffix. At handover the target assembles both parts into an up-to-date cache and resumes decoding locally, so only unfinished preparation contributes to interruption. An online scheduler picks the prefetching window — how early preparation starts — from mobility predictions and runtime telemetry.Pallas는 예측된 타깃에서 핸드오버 전에 추론 상태를 준비하며, 이를 소스 측 추론·토큰 전달과 병렬로 수행한다. 준비 트리거 시점에 토큰 시퀀스를 안정적인 과거 프리픽스와 변화하는 서픽스로 나눠, 타깃은 프리픽스를 로컬 프리필로 재구성하고 소스는 서픽스에 대해 생성된 KV 블록을 스트리밍한다. 핸드오버 시 타깃이 두 부분을 최신 캐시로 조립하고 로컬에서 디코딩을 재개하므로, 끝내지 못한 준비분만 중단 시간에 기여한다. 온라인 스케줄러가 이동성 예측과 런타임 텔레메트리로부터 준비를 얼마나 일찍 시작할지(프리페칭 윈도)를 고른다.
