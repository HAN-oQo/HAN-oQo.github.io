DBLast: Dependent Block Drafting for Stochastic Speculative Decodingspeculative decodingstochastic sampling2608.05448
DBLast — dependent block drafting for non-greedy decoding (arXiv 2608.05448) ↗DBLast — 비탐욕 디코딩용 종속 블록 드래프팅 (arXiv 2608.05448) ↗
Problem문제 정의Speculative decoding proposes future tokens with a lightweight drafter that a target model verifies. Recent block or diffusion-style drafters predict several positions in one pass but assume those positions are conditionally independent — an assumption that breaks under non-greedy (stochastic) sampling, where multiple continuations are plausible and accepted draft length collapses as target entropy rises.스펙 디코딩은 가벼운 드래프터로 미래 토큰을 제안하고 타깃 모델이 검증한다. 최근 블록·확산형 드래프터는 여러 위치를 한 번에 예측하지만 그 위치들이 조건부 독립이라고 가정한다 — 이 가정은 여러 이어짐이 그럴듯한 비탐욕(확률적) 샘플링에서 깨지며, 타깃 엔트로피가 커질수록 수락 초안 길이가 무너진다.
Method방법DBLast builds a dependent block drafter on a low-rank latent mixture over token positions, so drafted positions are modeled jointly rather than independently. It is trained with an acceptance-oriented objective that directly optimizes the expected verified (accepted) length, aligning the drafter with what the target will actually accept.DBLast은 토큰 위치에 대한 저랭크 잠재 혼합 위에 종속 블록 드래프터를 세워, 초안 위치들을 독립이 아니라 결합으로 모델링한다. 수락 지향 목적함수로 학습해 기대 검증(수락) 길이를 직접 최적화하며, 드래프터를 타깃이 실제로 수락할 것에 정렬한다.
Results결과On Qwen3-4B and Qwen3-8B across GSM8K, MT-Bench, HumanEval, and creative-writing benchmarks, DBLast consistently improves accepted length over independent block sampling, restoring speculative speedups precisely in the non-greedy regime where prior block drafters degrade.Qwen3-4B·8B에서 GSM8K·MT-Bench·HumanEval·창작 벤치마크에 걸쳐 DBLast은 독립 블록 샘플링 대비 수락 길이를 꾸준히 개선해, 기존 블록 드래프터가 열화되는 비탐욕 구간에서 스펙 가속을 되살린다.
Summary요약A block drafter that models inter-position dependence and trains for acceptance, restoring speculative decoding under stochastic target sampling.위치 간 의존을 모델링하고 수락을 목표로 학습하는 블록 드래프터로, 확률적 타깃 샘플링에서 스펙 디코딩을 되살린다.

QEvict: Recoverable Quantized KV Eviction for Attention-Drift-Robust Long-Context DecodingKV-cachequantization2608.05326
QEvict — reversible three-tier KV eviction (arXiv 2608.05326) ↗QEvict — 되돌릴 수 있는 3계층 KV 축출 (arXiv 2608.05326) ↗
Problem문제 정의KV-cache eviction cuts memory by dropping tokens judged unimportant, but the decision is irreversible — once evicted, a token can never be reused. The authors show this is brittle: token and window importance drift as generated queries evolve, so standard policies permanently discard states that later receive heavy attention under the full-cache model.KV 캐시 축출은 덜 중요하다고 판단된 토큰을 버려 메모리를 줄이지만 그 결정은 되돌릴 수 없다 — 한번 축출되면 그 토큰은 다시 못 쓴다. 저자들은 이것이 취약함을 보인다 — 생성 질의가 진화하며 토큰·윈도의 중요도가 표류하므로, 표준 정책은 풀 캐시 모델에선 나중에 큰 어텐션을 받는 상태를 영구히 버린다.
Method방법QEvict is a three-tier KV scheme that replaces binary retain/delete with recoverable eviction: high-confidence windows stay full-precision, intermediate windows go to a quantized recoverable tier, and only the lowest-confidence windows are deleted. During decoding, cumulative attention updates each window's importance, and a quantized window that becomes important again is dequantized and promoted back to full precision. Two diagnostics (Future Missed Mass, Global LIR) measure attention lost to discarded states.QEvict은 이진 보존/삭제를 복구 가능한 축출로 바꾸는 3계층 KV 방식이다 — 고신뢰 윈도는 풀 정밀도로, 중간 윈도는 양자화 복구 계층으로, 최저 신뢰 윈도만 삭제한다. 디코딩 중 누적 어텐션이 각 윈도 중요도를 갱신하고, 다시 중요해진 양자화 윈도는 역양자화해 풀 정밀도로 승격한다. 두 진단(Future Missed Mass, Global LIR)이 버린 상태로 잃은 어텐션을 측정한다.
Results결과Across long-context understanding, retrieval, and reasoning benchmarks, QEvict consistently beats representative eviction and quantization baselines under a fixed memory budget, reducing missed attention and improving information retention as query-driven importance drifts.장문맥 이해·검색·추론 벤치마크 전반에서 QEvict은 고정 메모리 예산 하에 대표적 축출·양자화 기준선을 꾸준히 앞서, 질의 유발 중요도 표류에서 놓친 어텐션을 줄이고 정보 보존을 개선한다.
Summary요약Turn irreversible KV eviction into a reversible full / quantized / deleted hierarchy so drifting-importance tokens can be recovered instead of lost.되돌릴 수 없는 KV 축출을 풀·양자화·삭제의 되돌릴 수 있는 계층으로 바꿔, 중요도가 표류하는 토큰을 잃지 않고 복구한다.

Problem문제 정의On-device LLM deployment for personalized edge applications is bottlenecked by external memory access (EMA) in feed-forward network layers. Speculative decoding (many tokens per stage) and mixture-of-experts (sparse per-stage cost) each help, but the two techniques are mutually incompatible when naively combined on edge hardware.개인화 엣지 응용을 위한 온디바이스 LLM 배치는 FFN 계층의 외부 메모리 접근(EMA)이 병목이다. 스펙 디코딩(스테이지당 다수 토큰)과 MoE(스테이지당 희소 비용)는 각각 도움이 되지만, 엣지 하드웨어에서 순진하게 합치면 둘은 서로 양립하지 않는다.
Method방법EdgeXpert is a software–hardware co-designed accelerator that resolves this incompatibility. In prefill, "prompt-wise expert reuse" reformulates routing at the prompt level rather than per token: a lightweight encoder identifies important tokens, builds a shared expert set from them, and routes less-important tokens with a reduced expert budget — keeping shared experts resident to cut repeated expert EMA.EdgeXpert은 이 비양립을 해소하는 소프트웨어–하드웨어 공동 설계 가속기다. 프리필에서 "프롬프트 단위 전문가 재사용"은 라우팅을 토큰별이 아니라 프롬프트 수준으로 재구성한다 — 가벼운 인코더가 중요 토큰을 식별해 공유 전문가 집합을 만들고, 덜 중요한 토큰은 축소된 전문가 예산으로 라우팅해 공유 전문가를 상주시켜 반복 전문가 EMA를 줄인다.
Results결과By reducing FFN external-memory access on edge devices, EdgeXpert achieves up to 56.3% latency reduction and 44.1% energy reduction versus prior works.엣지 기기에서 FFN 외부 메모리 접근을 줄여, EdgeXpert은 기존 대비 최대 56.3% 지연 감소와 44.1% 에너지 감소를 달성한다.
Summary요약An edge accelerator that lets MoE and speculative decoding coexist by reusing experts at prompt granularity, sharply cutting memory-access latency and energy.전문가를 프롬프트 단위로 재사용해 MoE와 스펙 디코딩을 양립시키는 엣지 가속기로, 메모리 접근 지연과 에너지를 크게 줄인다.

Problem문제 정의Agentic, multi-turn, tool-calling inference makes prefill and decode behave very differently, so a single homogeneous GPU system struggles. The industry is shifting to heterogeneous disaggregated hardware (GPUs plus specialized accelerators), but the optimal hardware for each disaggregated component is underexplored.멀티턴·도구 호출의 에이전트 추론은 프리필과 디코드를 매우 다르게 만들어, 단일 동종 GPU 시스템이 버겁다. 업계는 이기종 분리 하드웨어(GPU + 특화 가속기)로 이동 중이나, 각 분리 구성요소에 최적인 하드웨어는 덜 탐구됐다.
Method방법HeteroPanacea is a system-level simulation framework spanning three axes: disaggregated quantization, automated intra-/inter-device parallelization scheduling, and PDAF (prefill–decode–attention–FFN) NPU architectural heterogeneity — a cross-stack simulator for future heterogeneous agentic serving.HeteroPanacea는 세 축을 아우르는 시스템 수준 시뮬레이션 프레임워크다 — 분리형 양자화, 자동 장치 내·간 병렬화 스케줄링, PDAF(프리필–디코드–어텐션–FFN) NPU 아키텍처 이기종성 — 미래의 이기종 에이전트 서빙을 위한 크로스 스택 시뮬레이터다.

Why LLMs can't "jump" Aug 7

This piece argues that today's generative AI is rapidly mechanizing induction (finding rules from data) and deduction (deriving results from given axioms), but not the "jump" — the abductive leap that invents new axioms or reframes a problem. The claim is that scaling pattern-completion sharpens the two mechanizable modes while leaving the genuinely generative step, coining the concepts a proof or theory rests on, largely untouched. It frames this gap as the current ceiling on machine discovery, not a bug to be patched by more data.

이 글은 오늘날의 생성형 AI가 귀납(데이터에서 규칙 찾기)과 연역(주어진 공리에서 결과 도출)은 빠르게 기계화하고 있지만, "점프" — 새 공리를 만들거나 문제를 재구성하는 가설적(귀추) 도약 — 는 못한다고 주장한다. 패턴 완성을 키우면 기계화 가능한 두 방식은 날카로워지지만, 증명이나 이론이 딛고 설 개념 자체를 지어내는 진짜 생성적 단계는 대체로 그대로 남는다는 것이다. 이 격차를 더 많은 데이터로 메울 버그가 아니라 기계 발견의 현재 상한으로 규정한다.
