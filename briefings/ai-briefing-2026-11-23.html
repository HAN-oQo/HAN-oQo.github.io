Contexture: Runtime Context Eviction for High-Throughput Agent ServingKV cacheagent servingarXiv:2611.26980
arxiv.org/abs/2611.26980 →

Problem문제 정의Agents such as Codex and OpenClaw resend ever-growing execution histories, so shared KV capacity in HBM caps agent-serving throughput. Context-reduction methods cannot see global cache state, while runtime KV managers cannot see which tool operations produced which tokens.Codex, OpenClaw 같은 에이전트는 길어지는 실행 이력을 매번 다시 보내므로 HBM의 공유 KV 용량이 처리량을 막는다. 문맥 축소 기법은 전역 캐시 상태를, 런타임 KV 관리자는 토큰이 어느 도구 작업에서 나왔는지를 모른다.

Method방법Contexture separates the harness's full conversation history from the model's execution context. It traces tokens to their originating tool operations, marks outputs that later operations supersede as removal candidates, and uses global KV pressure and prefix residency to decide when evicting them is worth losing cached computation; no harness changes, extra model calls or training are needed.하네스의 전체 이력과 모델의 실행 문맥을 분리하고, 토큰을 출처 도구 작업까지 추적해 나중 작업이 대체한 출력을 제거 후보로 둔다. 전역 KV 압력과 프리픽스 상주 상태를 보고 캐시된 계산을 버릴 가치가 있을 때만 퇴출하며, 하네스 수정·추가 모델 호출·학습은 필요 없다.

Results결과Tracing shows 64% of final-history tokens are removal candidates. Across two models, two harnesses and two benchmarks, throughput under SLO rises 20–73% over the best of no eviction, harness compaction, AgentDiet and Continuum, and 23% over LMCache alone on H100, with GPU energy per session down by up to 11%.최종 이력 토큰의 64%가 제거 후보였다. 두 모델·두 하네스·두 벤치마크에서 SLO 하 처리량이 무제거, 하네스 압축, AgentDiet, Continuum 중 최선보다 20–73%, H100에서 LMCache 단독보다 23% 높았고 세션당 GPU 에너지는 최대 11% 줄었다.

Summary요약Agent context should be evicted by the serving runtime using tool-level supersession, not trimmed blindly by the harness.에이전트 문맥은 하네스가 무작정 자르지 말고 서빙 런타임이 도구 단위 대체 관계를 보고 퇴출해야 한다.

TideCache: Efficient Hybrid LLM Serving with Transparent Cache Management and Layer-Wise Streaminghybrid modelsKV offloadarXiv:2611.26619
arxiv.org/abs/2611.26619 →

Problem문제 정의Hybrid open-weight models mix global-attention layers with bounded-state layers, so each request carries heterogeneous caches whose demand shifts with context length and concurrency. Static GPU memory splits leave capacity stranded on CPU–GPU superchips.하이브리드 개방 가중치 모델은 전역 어텐션 레이어와 고정 크기 상태 레이어를 섞어, 요청마다 문맥 길이와 동시성에 따라 수요가 바뀌는 이질적 캐시를 갖는다. 정적 GPU 메모리 분할로는 CPU–GPU 슈퍼칩의 용량이 논다.

Method방법A Transparent Cache Pool moves physical pages between cache components behind fixed virtual addresses, so layouts and backends stay unchanged. A Cache Streamer uses the compute time of bounded-state layers to prefetch the next global-attention layer's prefix into shared GPU slots, and a Request Scheduler picks resident or streamed execution per request.Transparent Cache Pool은 고정 가상 주소 뒤에서 물리 페이지를 캐시 사이로 옮겨 레이아웃과 백엔드를 그대로 둔다. Cache Streamer는 고정 상태 레이어가 계산하는 동안 다음 전역 어텐션 레이어의 프리픽스를 공유 GPU 슬롯으로 미리 가져오고, Request Scheduler가 요청마다 상주 실행과 스트리밍 실행을 고른다.

Results결과Implemented in SGLang and run on GB300 and GH200 across seven model/platform settings, TideCache completes up to 2.04x as many agent turns, cuts P50 per-token latency by 20–59% and improves agent P50 TTFT by 1.40–3.05x versus SGLang with HiCache.SGLang 구현을 GB300·GH200의 7개 모델·플랫폼 구성에서 SGLang+HiCache와 비교하니 에이전트 턴을 최대 2.04배 더 처리했고, P50 토큰당 지연은 20–59% 줄고 에이전트 P50 TTFT는 1.40–3.05배 좋아졌다.

Summary요약Streaming global-attention prefixes layer by layer frees HBM for the other caches of hybrid models.전역 어텐션 프리픽스를 레이어 단위로 스트리밍해 하이브리드 모델의 다른 캐시에 HBM을 돌려준다.

Aggron: Aggressive Compression of Agentic KV Caches during Head-of-Line Stalls in the Request QueueKV compressionschedulingarXiv:2611.26435
arxiv.org/abs/2611.26435 →

Problem문제 정의Agent programs grow context every turn, and serving is bounded by KV capacity. Existing compression waits for a large threshold, then summarizes big spans at once, and when that runs on the same engine it competes with live requests for compute and memory.에이전트 프로그램은 턴마다 문맥이 늘고 서빙은 KV 용량에 막힌다. 기존 압축은 큰 임계치를 넘어야 긴 구간을 한꺼번에 요약하고, 같은 엔진에서 돌면 실제 요청과 연산·메모리를 다툰다.

Method방법Aggron summarizes agentic requests at every turn and only compresses selected parts of the KV cache, keeping each summarization small. Summaries are issued from a separate Summarization Queue while the target request is stuck behind head-of-line stalls in the main queue, using leftover capacity, and only when the server predicts the summary will finish before the request runs.매 턴 KV 캐시의 선택된 부분만 작게 요약한다. 대상 요청이 메인 큐의 head-of-line 정체로 기다리는 동안 별도 Summarization Queue가 남는 용량으로 요약하되, 요청 실행 전에 끝날 것으로 예측될 때만 발행한다.

Results결과At high load and against state-of-the-art asynchronous summarization, Aggron lowers P99 program latency by 27–31% and raises throughput by 1.34–1.40x.고부하에서 최신 비동기 요약 방식보다 P99 프로그램 지연이 27–31% 줄고 처리량은 1.34–1.40배 늘었다.
