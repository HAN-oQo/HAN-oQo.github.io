Contexture: Runtime Context Eviction for High-Throughput Agent ServingKV cacheagent servingarXiv:2611.26980
arxiv.org/abs/2611.26980 →

Problem문제 정의Agents such as Codex and OpenClaw resend ever-growing execution histories, so shared KV capacity in HBM caps agent-serving throughput. Context-reduction methods cannot see global cache state, while runtime KV managers cannot see which tool operations produced which tokens.Codex, OpenClaw 같은 에이전트는 계속 길어지는 실행 이력을 매번 다시 보내므로 HBM의 공유 KV 용량이 에이전트 서빙 처리량을 제한한다. 문맥 축소 기법은 전역 캐시 상태를 보지 못하고, 런타임 KV 관리자는 어떤 토큰이 어떤 도구 작업에서 나왔는지 모른다.

Method방법Contexture separates the harness's full conversation history from the model's execution context. It traces tokens to their originating tool operations, marks outputs that later operations supersede as removal candidates, and uses global KV pressure and prefix residency to decide when evicting them is worth losing cached computation; no harness changes, extra model calls or training are needed.Contexture는 하네스가 가진 전체 대화 이력과 모델이 실행하는 문맥을 분리한다. 토큰을 생성한 도구 작업까지 추적해 이후 작업이 대체한 출력을 제거 후보로 표시하고, 전역 KV 압력과 프리픽스 상주 상태를 보고 캐시된 계산을 버릴 가치가 있을 때만 제거한다. 하네스 수정, 추가 모델 호출, 학습이 필요 없다.

Results결과Tracing shows 64% of final-history tokens are removal candidates. Across two models, two harnesses and two benchmarks, throughput under SLO rises 20–73% over the best of no eviction, harness compaction, AgentDiet and Continuum, and 23% over LMCache alone on H100, with GPU energy per session down by up to 11%.추적 결과 최종 이력 토큰의 64%가 제거 후보였다. 두 모델, 두 하네스, 두 벤치마크에서 SLO 하 처리량이 무제거, 하네스 압축, AgentDiet, Continuum 중 최선 대비 20–73% 높았고, H100에서 LMCache 단독 대비 23% 높았으며 세션당 GPU 에너지는 최대 11% 줄었다.

Summary요약Agent context should be evicted by the serving runtime using tool-level supersession, not trimmed blindly by the harness.에이전트 문맥은 하네스가 맹목적으로 자르기보다 서빙 런타임이 도구 단위 대체 관계를 근거로 퇴출해야 한다.

TideCache: Efficient Hybrid LLM Serving with Transparent Cache Management and Layer-Wise Streaminghybrid modelsKV offloadarXiv:2611.26619
arxiv.org/abs/2611.26619 →

Problem문제 정의Hybrid open-weight models mix global-attention layers with bounded-state layers, so each request carries heterogeneous caches whose demand shifts with context length and concurrency. Static GPU memory splits leave capacity stranded on CPU–GPU superchips.하이브리드 개방 가중치 모델은 전역 어텐션 레이어와 고정 크기 상태 레이어를 섞기 때문에, 요청마다 문맥 길이와 동시성에 따라 수요가 달라지는 이질적인 캐시를 갖는다. 정적인 GPU 메모리 분할은 CPU–GPU 슈퍼칩에서 용량을 놀린다.

Method방법A Transparent Cache Pool moves physical pages between cache components behind fixed virtual addresses, so layouts and backends stay unchanged. A Cache Streamer uses the compute time of bounded-state layers to prefetch the next global-attention layer's prefix into shared GPU slots, and a Request Scheduler picks resident or streamed execution per request.Transparent Cache Pool은 고정된 가상 주소 뒤에서 물리 페이지를 캐시 구성 요소 사이로 옮겨 레이아웃과 백엔드를 바꾸지 않는다. Cache Streamer는 고정 상태 레이어가 계산하는 시간 동안 다음 전역 어텐션 레이어의 프리픽스를 공유 GPU 슬롯으로 미리 가져오고, Request Scheduler는 요청마다 상주 실행과 스트리밍 실행 중 하나를 고른다.

Results결과Implemented in SGLang and run on GB300 and GH200 across seven model/platform settings, TideCache completes up to 2.04x as many agent turns, cuts P50 per-token latency by 20–59% and improves agent P50 TTFT by 1.40–3.05x versus SGLang with HiCache.SGLang에 구현해 GB300과 GH200의 7개 모델·플랫폼 구성에서 실험한 결과, SGLang+HiCache 대비 에이전트 턴을 최대 2.04배 더 처리하고 P50 토큰당 지연을 20–59% 줄였으며 에이전트 P50 TTFT를 1.40–3.05배 개선했다.

Summary요약Streaming global-attention prefixes layer by layer frees HBM for the other caches of hybrid models.전역 어텐션 프리픽스를 레이어 단위로 스트리밍해 하이브리드 모델의 다른 캐시에 HBM을 돌려준다.

arxiv.org/abs/2611.26435 →

Problem문제 정의Agent programs grow context every turn, and serving is bounded by KV capacity.
