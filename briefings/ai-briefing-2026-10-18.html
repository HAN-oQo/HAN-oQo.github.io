arxiv.org/abs/2610.22130 →

Problem문제 정의KV-cache memory grows linearly with context, and eviction must pick which tokens to drop. Minimizing output perturbation exactly is an NP-hard combinatorial problem, so current methods settle for heuristics or for designs that are hard to kernelize.KV 캐시 메모리는 컨텍스트에 비례해 늘어나며, 어떤 토큰을 버릴지 골라야 한다. 출력 섭동을 정확히 최소화하는 것은 NP-난해 조합 문제여서 기존 방법은 휴리스틱이나 커널화하기 어려운 설계에 머문다.

Method방법DropKV decouples the joint eviction decision into independent per-token scores based on residual-output perturbation, which avoids the combinatorial search. It admits a constant-factor approximation guarantee under a cone condition the authors check empirically on three long-context LLMs, and it ships as fused Triton kernels that never materialize the full attention matrix.DropKV는 결합 제거 결정을 잔차-출력 섭동에 기반한 토큰별 독립 점수로 분리해 조합 탐색을 피한다. 저자들이 세 개의 장문 LLM에서 경험적으로 확인한 원뿔 조건 아래 상수 배 근사 보장을 갖고, 전체 어텐션 행렬을 만들지 않는 융합 Triton 커널로 구현된다.

Results결과The scoring kernel is 19.8x faster, which translates to up to 9.9% matched-batch end-to-end prefill speedup. On RULER and LongBench it beats state-of-the-art eviction baselines at equal cache budgets with the lowest latency among eviction methods.점수 계산 커널은 19.8배 빨라 동일 배치 기준 종단 간 프리필이 최대 9.9% 빨라진다. RULER와 LongBench에서 같은 캐시 예산의 최신 제거 기법을 앞서며 제거 방식 중 지연이 가장 낮다.

Summary요약Independent per-token scoring with a provable guarantee and a fused kernel makes principled KV eviction cheap enough to use in prefill.보장이 있는 토큰별 독립 점수와 융합 커널로 원리적인 KV 제거를 프리필에서 쓸 만큼 싸게 만든다.

Problem문제 정의Device-cloud speculative decoding saves server computation, but growing a deep draft tree with a small language model needs repeated passes on a mobile NPU.기기-클라우드 추측 디코딩은 서버 연산을 줄이지만, 소형 언어 모델로 깊은 초안 트리를 키우려면 모바일 NPU에서 반복 패스가 필요하다.

Method방법HyCo gives depth to the server model's native multi-token prediction (MTP) head, executed on the device, and uses one SLM pass for alternative branches. Results결과On a Galaxy S26 Ultra over LTE/5G, HyCo cuts server GPU time per output token by 38.6% on Spec-Bench and 29.2% on 32K-token summarization versus server-side MTP self-speculation.
