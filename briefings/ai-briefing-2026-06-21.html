ASAP — asynchronous disaggregated inference for MoE prefillMoE servingprefill2606.22541
ASAP: A Disaggregated and Asynchronous Inference System for MoE Prefill (arXiv 2606.22541, submitted Jun 21) ↗ASAP: A Disaggregated and Asynchronous Inference System for MoE Prefill (arXiv 2606.22541, 6/21 제출) ↗
Problem문제 정의Modern MoE serving combines Data Parallelism (DP) for the attention stages with Expert Parallelism (EP) for the MoE stages, which forces frequent global synchronization barriers between the attention DP groups and the experts. In online serving, variance in request arrival rates and sequence lengths produces DP imbalance, so some DP ranks stall at the barrier — degrading time-to-first-token (TTFT) and overall throughput.현대 MoE 서빙은 어텐션 단계에 데이터 병렬(DP)을, MoE 단계에 전문가 병렬(EP)을 결합하는데, 이는 어텐션 DP 그룹과 전문가 사이에 잦은 전역 동기화 장벽을 강제한다. 온라인 서빙에선 요청 도착률·시퀀스 길이 편차가 DP 불균형을 낳아 일부 DP 랭크가 장벽에서 멈추고 — 첫 토큰 지연(TTFT)과 전체 처리량을 떨어뜨린다.
Method방법ASAP disaggregates the attention and MoE stages and runs them as a fully asynchronous execution pipeline, removing the global barrier between DP attention groups and the experts. Specialized asynchronous mechanisms let each stage proceed without waiting on the slowest DP rank, so imbalance no longer serializes the whole batch during the prefill phase.ASAP는 어텐션과 MoE 단계를 분리하고 완전 비동기 실행 파이프라인으로 돌려, DP 어텐션 그룹과 전문가 사이의 전역 장벽을 제거한다. 전용 비동기 메커니즘이 각 단계가 가장 느린 DP 랭크를 기다리지 않고 진행하게 해, prefill 단계에서 불균형이 더 이상 전체 배치를 직렬화하지 않는다.
Results결과By disaggregating attention from the MoE stage and overlapping them asynchronously, ASAP targets the synchronization stalls that DP imbalance causes during prefill, improving TTFT and throughput for online MoE serving relative to the barrier-synchronized hybrid-parallel baseline.어텐션을 MoE 단계에서 분리하고 비동기로 중첩함으로써, ASAP는 prefill 중 DP 불균형이 유발하는 동기화 정체를 겨냥해, 장벽 동기화 하이브리드 병렬 베이스라인 대비 온라인 MoE 서빙의 TTFT와 처리량을 높인다.
Summary요약Break the attention-vs-expert barrier: disaggregate MoE prefill into an async pipeline so DP imbalance stops stalling the batch.어텐션-전문가 장벽을 끊어라 — MoE prefill을 비동기 파이프라인으로 분리해 DP 불균형이 배치를 멈추지 못하게.

Smallest-Volume-First — geometry-aware online scheduling for LLM servingschedulingKV memory2606.22327
Geometry-Aware Online Scheduling for LLM Serving: From Theoretical Bound to System Practice (arXiv 2606.22327, submitted Jun 21) ↗Geometry-Aware Online Scheduling for LLM Serving: From Theoretical Bound to System Practice (arXiv 2606.22327, 6/21 제출) ↗
Problem문제 정의Managing the KV cache's dynamic memory footprint is now central to inference-engine performance, yet modern systems lean on time-centric heuristics such as Shortest Job First. Those heuristics are provably good only under traditional schedule models and fail to capture the highly dynamic, 2D spatio-temporal geometric growth specific to LLM decoding, where each running request grows its KV cache over time.KV 캐시의 동적 메모리 점유를 관리하는 것이 이제 추론 엔진 성능의 핵심이지만, 현대 시스템은 Shortest Job First 같은 시간 중심 휴리스틱에 의존한다. 그 휴리스틱은 전통적 스케줄 모델에서만 최적이 증명되며, 각 실행 요청이 시간에 따라 KV 캐시를 키우는 LLM 디코딩 특유의 매우 동적인 2D 시공간 기하 성장을 포착하지 못한다.
Method방법The authors propose geometry-aware online scheduling via a Smallest Volume First (SVF) algorithm and a lightweight 1-bit SVF variant, treating each request as a 2D spatio-temporal volume rather than a 1D job length. Using a new proof methodology they tighten the worst-case competitive ratio for SVF with known sizes from CR ≤ 48 down to CR ≤ 5, then realize the policy as a practical serving scheduler.저자들은 최소 부피 우선(SVF) 알고리즘과 경량 1-bit SVF 변형을 통한 기하 인식 온라인 스케줄링을 제안하며, 각 요청을 1D 작업 길이가 아니라 2D 시공간 부피로 다룬다. 새 증명 방법으로 크기를 아는 SVF의 최악 경쟁비를 CR ≤ 48에서 CR ≤ 5로 좁힌 뒤, 이 정책을 실용 서빙 스케줄러로 구현한다.
Results결과By scheduling on the geometric volume of KV growth rather than wall-clock job length, SVF achieves a much tighter competitive-ratio bound (≤ 5 vs ≤ 48) and translates the theory into a serving scheduler that better manages KV-cache memory pressure than time-centric SJF baselines.벽시계 작업 길이가 아니라 KV 성장의 기하 부피로 스케줄링함으로써, SVF는 훨씬 좁은 경쟁비 한계(≤ 5 대 ≤ 48)를 달성하고, 그 이론을 시간 중심 SJF 베이스라인보다 KV 캐시 메모리 압박을 잘 관리하는 서빙 스케줄러로 옮긴다.
Summary요약Schedule by the 2D "volume" of KV growth, not job length — Smallest Volume First tightens the competitive ratio from 48 to 5.작업 길이가 아니라 KV 성장의 2D "부피"로 스케줄링 — 최소 부피 우선이 경쟁비를 48에서 5로 좁힌다.

BatchGen: An Architecture for Scalable and Efficient Batch Inference (arXiv 2606.21712, submitted Jun 19) ↗BatchGen: An Architecture for Scalable and Efficient Batch Inference (arXiv 2606.21712, 6/19 제출) ↗
Problem문제 정의Batch inference is now a central mode of AI computation, but inference engines still use execution models designed for interactive serving.
