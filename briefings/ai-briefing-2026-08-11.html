HiSparse: Scaling Sparse-Attention Decoding with Hierarchical KV Cache ManagementKV-cachesparse attention2608.07009
Offload cold KV to a lower tier, swap only top-k blocks back into HBM (arXiv 2608.07009) ↗차가운 KV를 하위 계층으로 내리고 top-k 블록만 HBM으로 다시 스왑 (arXiv 2608.07009) ↗
Problem문제 정의Sparse-attention models only attend to a small subset of past tokens per step, yet serving systems still keep the entire KV cache resident in high-bandwidth GPU memory (HBM), so throughput is capped by HBM capacity rather than by the compute the sparse pattern actually needs. As concurrency grows, the resident cache crowds out batch size and token generation stalls.희소 어텐션 모델은 스텝마다 과거 토큰의 작은 일부에만 주의를 두지만, 서빙 시스템은 여전히 KV 캐시 전체를 고대역폭 GPU 메모리(HBM)에 상주시켜, 처리량이 희소 패턴이 실제로 필요로 하는 연산이 아니라 HBM 용량에 의해 제한된다. 동시성이 커지면 상주 캐시가 배치 크기를 밀어내 토큰 생성이 정체된다.
Method방법HiSparse manages the KV cache across a memory hierarchy: inactive entries are offloaded to a lower, larger memory tier while swap-in kernels dynamically load only the top-k blocks each decoding step actually attends to back into GPU memory for the attention computation. This decouples token generation from local HBM capacity, letting the batch grow well beyond what would fit if the full cache stayed resident. The design is built on the SGLang serving framework.HiSparse는 KV 캐시를 메모리 계층에 걸쳐 관리한다. 비활성 항목은 더 크고 낮은 메모리 계층으로 내리고, 스왑인 커널이 각 디코딩 스텝이 실제로 주의하는 top-k 블록만 GPU 메모리로 동적으로 불러와 어텐션을 계산한다. 이로써 토큰 생성이 로컬 HBM 용량과 분리되어, 전체 캐시를 상주시켰다면 담기 어려웠을 만큼 배치를 키울 수 있다. 설계는 SGLang 서빙 프레임워크 위에 구현됐다.
Results결과By decoupling generation from resident cache size, HiSparse achieves near-linear throughput scaling with concurrency: at 256 concurrent requests it reports over 3× the throughput of the baseline, precisely because the offload-plus-swap-in path spends HBM only on the blocks each step needs. The hierarchy turns a capacity ceiling into a bandwidth-managed pipeline.생성과 상주 캐시 크기를 분리함으로써 HiSparse는 동시성에 대해 거의 선형적인 처리량 확장을 달성한다. 256 동시 요청에서 베이스라인 대비 3배 이상의 처리량을 보고하는데, 이는 오프로드+스왑인 경로가 각 스텝이 필요로 하는 블록에만 HBM을 쓰기 때문이다. 계층 구조가 용량 상한을 대역폭으로 관리되는 파이프라인으로 바꾼다.
Summary요약HiSparse's lesson is that for sparse-attention decoding the bottleneck is where the KV cache lives, not how much is computed — so a hierarchical cache with top-k swap-in kernels lets a single GPU serve far more concurrent requests without changing the model.HiSparse의 교훈은 희소 어텐션 디코딩의 병목이 '얼마나 계산하느냐'가 아니라 'KV 캐시가 어디에 있느냐'라는 점이다 — 그래서 top-k 스왑인 커널을 갖춘 계층적 캐시만으로 모델 변경 없이 한 GPU가 훨씬 많은 동시 요청을 서빙할 수 있다.

Cascade: Exploiting SLO-Aware Latency Budget for Fair and High-Goodput LLM Inference Servingschedulingserving2608.06557
Schedule by a live "latency budget" = SLO − predicted remaining service time (arXiv 2608.06557) ↗지연 예산(= SLO − 예측 잔여 서비스 시간)으로 스케줄링 (arXiv 2608.06557) ↗
Problem문제 정의LLM serving platforms promise a response-latency service-level objective (SLO), but individual requests differ enormously in input length, generation length, and execution cost. Schedulers that ignore this heterogeneity either starve long requests or blow the SLO for short ones, and simple first-come or fixed-priority policies leave goodput (SLO-satisfying throughput) on the table.LLM 서빙 플랫폼은 응답 지연 SLO를 약속하지만, 개별 요청은 입력 길이·생성 길이·실행 비용이 크게 다르다. 이 이질성을 무시하는 스케줄러는 긴 요청을 굶기거나 짧은 요청의 SLO를 깨며, 단순 선착순·고정 우선순위 정책은 굿풋(SLO를 만족하는 처리량)을 놓친다.
Method방법Cascade defines a request's "latency budget" as the gap between its SLO and its predicted remaining service time, and estimates and continuously updates that budget from request characteristics, current KV-cache state, and system load. Requests with less slack are protected while those with room to spare yield, so scheduling decisions track how urgent each request truly is at every step rather than at admission only.Cascade는 요청의 "지연 예산"을 그 SLO와 예측된 잔여 서비스 시간의 차이로 정의하고, 요청 특성·현재 KV 캐시 상태·시스템 부하로부터 이 예산을 추정해 지속적으로 갱신한다. 여유가 적은 요청은 보호하고 여유가 있는 요청은 양보하게 해, 스케줄링 결정이 수락 시점이 아니라 매 스텝마다 각 요청의 실제 긴급도를 따라간다.
Results결과By steering the queue with the live latency-budget signal, Cascade improves both fairness across heterogeneous requests and overall goodput relative to budget-agnostic baselines, keeping more requests within their SLO under mixed input/output-length traffic. The budget abstraction gives the scheduler a single, continuously-refreshed notion of urgency to act on.라이브 지연 예산 신호로 큐를 조종함으로써, Cascade는 이질적 요청 간 공정성과 전체 굿풋을 예산 무관 베이스라인 대비 함께 개선하며, 혼합 입출력 길이 트래픽에서 더 많은 요청을 SLO 안에 유지한다. 예산 추상화는 스케줄러에 지속적으로 갱신되는 단일한 긴급도 개념을 제공한다.
Summary요약Cascade shows that a single derived quantity — how much SLO slack a request has right now — is a powerful scheduling primitive: continuously recomputing it from KV state and load lets one server be both fairer and higher-goodput without per-request priority tuning.Cascade는 단일 파생량 — 요청이 지금 얼마나 SLO 여유를 갖는지 — 이 강력한 스케줄링 프리미티브임을 보인다. KV 상태와 부하로부터 이를 지속 재계산하면 요청별 우선순위 튜닝 없이 한 서버가 더 공정하면서 더 높은 굿풋을 낼 수 있다.

CubicQuant: Parametric Non-Uniform Codebooks for High-Throughput LLM Inference with 1–8-Bit WeightsquantizationGPU throughput2608.06763
A cubic curve maps uniform codes to non-uniform levels, keeping a dense integer stream (arXiv 2608.06763) ↗3차 곡선으로 균일 코드를 비균일 레벨에 매핑하며 조밀한 정수 스트림 유지 (arXiv 2608.06763) ↗
Problem문제 정의Weight quantization for LLM inference has to balance two things that pull in opposite directions: reconstruction levels adaptive enough to match the weight distribution (which argues for irregular, per-value codebooks), and a representation regular enough for efficient GPU execution (which argues for uniform integer codes). Fully non-uniform codebooks improve accuracy but break the dense, predictable memory access GPUs want.LLM 추론용 가중치 양자화는 서로 반대로 당기는 두 가지를 균형 잡아야 한다. 가중치 분포에 맞출 만큼 적응적인 복원 레벨(불규칙한 값별 코드북을 요구)과, 효율적 GPU 실행을 위한 충분히 규칙적인 표현(균일 정수 코드를 요구)이다. 완전 비균일 코드북은 정확도를 높이지만 GPU가 원하는 조밀하고 예측 가능한 메모리 접근을 깨뜨린다.
Method방법CubicQuant is a parametric non-uniform scalar format that keeps a dense integer code stream while adapting reconstruction levels within each weight group. A monotonic cubic curve, specified by just two shape parameters and one scale per group, maps uniformly-spaced magnitude codes to non-uniform reconstruction levels — so the on-disk/on-wire bits stay a regular integer stream that GPU kernels decode cheaply, while the effective levels bend to fit the group's distribution. It targets weight-only 1–8-bit inference.CubicQuant은 그룹마다 조밀한 정수 코드 스트림을 유지하면서 복원 레벨을 적응시키는 파라메트릭 비균일 스칼라 포맷이다. 그룹당 단 두 개의 형상 파라미터와 하나의 스케일로 지정되는 단조 3차 곡선이 균일 간격의 크기 코드를 비균일 복원 레벨로 매핑한다 — 그래서 저장·전송 비트는 GPU 커널이 값싸게 디코드하는 규칙적 정수 스트림으로 남고, 실효 레벨은 그룹 분포에 맞춰 휜다. 가중치 전용 1–8비트 추론을 겨냥한다.
Results결과Because the code stream stays dense and integer, CubicQuant preserves the high-throughput decode path of uniform quantization while gaining the accuracy headroom of non-uniform reconstruction across the 1-to-8-bit range. The per-group cubic parameters are cheap to store and apply, so the extra flexibility costs almost nothing at decode time.코드 스트림이 조밀한 정수로 유지되므로 CubicQuant은 균일 양자화의 고처리량 디코드 경로를 지키면서, 1–8비트 범위에서 비균일 복원의 정확도 여유를 얻는다. 그룹별 3차 파라미터는 저장·적용 비용이 작아, 추가 유연성이 디코드 시점에 거의 비용을 들이지 않는다.
Summary요약CubicQuant reconciles the accuracy-vs-throughput tension in weight quantization by making non-uniformity a smooth, three-parameter cubic reshaping of a still-uniform integer code — you get adaptive levels without giving up the dense GPU-friendly stream.CubicQuant은 비균일성을 여전히 균일한 정수 코드의 매끈한 3-파라미터 3차 재형성으로 만들어 가중치 양자화의 정확도 대 처리량 긴장을 화해시킨다 — 조밀한 GPU 친화 스트림을 포기하지 않고 적응적 레벨을 얻는다.

Problem문제 정의Sparse computation is central to efficient LLM inference — pruned weights, sparse attention, block-sparse layouts — but each sparsity pattern needs a hand-tuned GPU kernel to actually run fast, and writing one per pattern is slow, expert-intensive work.
