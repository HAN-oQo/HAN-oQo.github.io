Problem문제 정의Sparse-attention models read only a few past tokens per step, yet servers keep the whole KV cache in GPU memory (HBM). Method방법HiSparse offloads inactive KV to a larger, lower memory tier, and swap-in kernels bring back only the top-k blocks each decode step attends to. It is built on SGLang.HiSparse는 비활성 KV를 더 큰 하위 메모리 계층으로 내리고, 스왑인 커널이 디코딩 스텝마다 실제로 보는 top-k 블록만 HBM으로 불러온다. SGLang 위에 구현했다.
Results결과Throughput scales almost linearly with concurrency, reaching over 3× the baseline at 256 concurrent requests, because HBM holds only the blocks each step needs.처리량이 동시성에 거의 선형으로 늘어 256 동시 요청에서 베이스라인의 3배를 넘는다. HBM에는 스텝마다 필요한 블록만 남기 때문이다.
Summary요약For sparse-attention decoding the bottleneck is where the KV cache lives, not how much is computed, so one GPU can serve far more requests without changing the model.희소 어텐션 디코딩의 병목은 계산량이 아니라 KV 캐시가 놓인 위치다. 모델을 바꾸지 않고도 GPU 한 장이 훨씬 많은 요청을 처리할 수 있다.

Problem문제 정의Serving platforms promise a latency SLO, but requests differ widely in input length, output length, and cost. Method방법Cascade defines a "latency budget" as SLO minus predicted remaining service time, and updates it every step from request traits, KV-cache state, and load.
