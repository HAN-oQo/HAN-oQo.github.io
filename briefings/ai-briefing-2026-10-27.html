Separating Thinking from Spelling for Efficient Generative Recommendationservinggenerative recsysarXiv:2610.32980
arxiv.org/abs/2610.32980 →

Problem문제 정의Generative recommenders write item semantic IDs code by code under trie-constrained beam search, so a history of T items costs TK backbone tokens and every beam step runs the full backbone. Returning B candidates costs O(BK) backbone decode tokens per user, and that cost dominates as the backbone, ID depth and candidate budget grow.생성형 추천기는 트라이 제약 빔 탐색으로 아이템 시맨틱 ID를 코드 단위로 쓰기 때문에, T개 이력은 TK개 백본 토큰이 되고 빔 스텝마다 전체 백본이 돈다. 후보 B개를 반환하는 데 사용자당 O(BK) 백본 디코드 토큰이 들며, 백본·ID 깊이·후보 수가 커질수록 이 비용이 지배적이 된다.

Method방법Deco separates reading the history from writing the identifier. The backbone reads each history item as one fused token and condenses the history once into a compact next-item concept; a light KV-cached decoder conditioned on that concept and the generated prefix then runs the whole beam search.Deco는 이력 읽기와 식별자 쓰기를 분리한다. 백본은 이력 아이템을 하나의 융합 토큰으로 읽어 이력을 한 번에 압축된 다음 아이템 개념으로 만들고, 그 개념과 생성된 접두를 조건으로 하는 가벼운 KV 캐시 디코더가 빔 탐색 전체를 수행한다.

Results결과On seven datasets from e-commerce, movies and music streaming, Deco matches or beats a standard generative recommender and the full-backbone teacher in accuracy while delivering 3.2–8.6x their throughput under a 50 ms p95 latency budget. It generates 1000 candidates faster than the teacher generates 100, and with a 1.5B-parameter LLM backbone it matches the 69M-parameter teacher’s throughput at higher accuracy.전자상거래·영화·음악 스트리밍 데이터셋 7개에서 Deco는 표준 생성형 추천기와 전체 백본 교사 모델 대비 정확도가 같거나 높으면서, p95 지연 50 ms 예산에서 처리량은 3.2~8.6배다. 후보 1000개를 교사가 100개를 만드는 시간보다 빨리 생성하며, 1.5B 백본에서는 69M 교사와 같은 처리량에 더 높은 정확도를 낸다.

Summary요약Moving beam search off the big backbone makes large candidate pools and larger models practical in a latency-bound serving pipeline.빔 탐색을 큰 백본에서 떼어내면 지연 제약이 있는 서빙 파이프라인에서도 큰 후보 풀과 큰 모델을 쓸 수 있다.

Problem문제 정의Sovereignty, compliance, latency and locality needs can make centralised cloud LLM serving unsuitable, and telco operators have geographically distributed compute and network capacity. Method방법InferSlice is a reference architecture for service-level-objective-driven inference over a telco infrastructure, integrating network slicing, GPU partitioning, elastic serving and observability. BT가 브리스톨 대학교·NVIDIA와 함께 주도했고 영국 전국 규모 WAN인 JOINER에서 구현했다.

Results결과The study reports that weight streaming shortens scale-out time, replication is placement-insensitive but memory-bound, and pipeline parallelism tolerates near and mid cross-site hops. Tensor parallelism and prefill-decode disaggregation fail beyond a single subnet hop.가중치 스트리밍이 스케일아웃 시간을 줄이고, 복제는 배치에 둔감하지만 메모리에 묶이며, 파이프라인 병렬화는 가깝거나 중간 거리의 사이트 간 홉을 견딘다고 보고한다. 텐서 병렬화와 프리필-디코드 분리는 단일 서브넷 홉을 넘으면 실패한다.

Problem문제 정의Applications have diverse inference budgets, and training a separate model for each is costly. Looped Transformers reuse parameters for flexible compute but struggle to stay strong across different budgets.애플리케이션마다 추론 예산이 다르고, 예산별로 모델을 따로 학습·유지하는 데 비용이 든다. 루프형 트랜스포머는 파라미터를 재사용해 유연한 연산을 제공하지만 여러 예산에서 성능을 유지하기가 어렵다.

Method방법Accordion is a mixture-of-experts model supporting five inference budgets through fixed-prefix layer looping; each budget follows a predefined execution path and the minimum budget is the unlooped model. Joint pretraining samples one budget per micro-batch, and SFT and RL preserve the budgets with parameter-group merging and budget-matched multi-teacher on-policy distillation.Accordion은 고정 접두 레이어 루핑으로 다섯 가지 추론 예산을 지원하는 MoE 모델이며, 각 예산은 미리 정한 실행 경로를 따르고 최소 예산은 루프 없는 모델이다. 공동 사전학습은 마이크로배치마다 예산 하나를 샘플링하고, SFT와 RL은 파라미터 그룹 병합과 예산별 다중 교사 온폴리시 증류로 예산을 유지한다.

Results결과The final model surpasses each domain expert on its task-and-budget average while keeping strong instruction following across all budgets. It retains depth-dependent gains in mathematical reasoning and code generation with additional layer executions.최종 모델은 과제·예산 평균에서 각 도메인 전문가를 넘고 모든 예산에서 강한 지시 따르기를 유지한다. 레이어 실행을 더 하면 수학 추론과 코드 생성에서 깊이에 따른 이득이 유지된다.

Summary요약One set of weights serves several latency and cost tiers by choosing how many times the prefix layers run.가중치 하나로 접두 레이어를 몇 번 돌리느냐에 따라 여러 지연·비용 등급을 서빙한다.

LazyFlash: Forward-Dense, Backward-Sparse Attention for Accelerated Long-Context Fine-Tuningsparse attentionlong contextarXiv:2610.31911
arxiv.org/abs/2610.31911 →

Problem문제 정의Attention is a major bottleneck for long sequences, and sparse attention mostly targets inference while many methods still train densely or cannot translate sparsity into wall-clock gains. Dense attention therefore stays the default in practice.긴 시퀀스에서는 어텐션이 주된 병목인데, 희소 어텐션은 대부분 추론을 겨냥하고 많은 방법이 여전히 dense로 학습하거나 희소성을 실제 시간 이득으로 바꾸지 못한다. 그래서 실무에서는 dense 어텐션이 계속 쓰인다.

Method방법LazyFlash keeps the forward pass exactly dense, so the trained model is a standard dense model that systems such as vLLM serve unchanged. In the backward pass it ranks query blocks by attention-output gradient norm and skips blocks that contribute negligibly, in a kernel where skipped blocks are never loaded or computed.LazyFlash는 순전파를 정확히 dense로 유지해 학습된 모델이 vLLM 같은 시스템이 그대로 서빙할 수 있는 표준 dense 모델이 되게 한다. 역전파에서는 어텐션 출력 기울기 노름으로 쿼리 블록을 순위 매기고 기여가 미미한 블록을 건너뛰며, 건너뛴 블록은 로드도 계산도 하지 않는 커널을 쓴다.

Results결과On long-context text and speech LLMs, LazyFlash maintains downstream performance while giving up to 5.7x attention-backward speedup over FlashAttention and 1.7x end-to-end training speedup.긴 문맥 텍스트·음성 LLM에서 다운스트림 성능을 유지하면서 FlashAttention 대비 어텐션 역전파 최대 5.7배, 종단간 학습 1.7배 가속을 낸다.

Summary요약Because attention training is dominated by the backward pass, sparsifying only that pass speeds up fine-tuning without changing what gets served.어텐션 학습은 역전파가 지배적이므로 그 부분만 희소화하면 서빙되는 모델은 바꾸지 않고 파인튜닝을 빠르게 할 수 있다.
