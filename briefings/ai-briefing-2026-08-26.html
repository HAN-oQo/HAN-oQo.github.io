48 commits, still no tag after v0.27.1. Problem / 문제 정의 Attention cost grows quadratically and KV-cache size linearly with sequence length, the core bottleneck for ultra-long-context and high-resolution generative models. The usual fix compresses the sequence once into summary states, but that step is irreversible: whatever the compressor drops is gone for every later layer. 어텐션 비용은 시퀀스 길이의 제곱으로, KV 캐시는 선형으로 늘어 초장문맥·고해상도 생성 모델의 핵심 병목이 된다. 흔한 해법은 시퀀스를 요약 상태로 한 번 압축하는 것인데, 이때 버린 정보는 이후 모든 레이어에서 되살릴 수 없다.
Method / 방법 Two streams run at every layer: local features are compressed bottom-up into a few proxy states, global interaction happens only among the proxies, and the result is decompressed and injected back top-down. Because the local stream persists, a later layer can recover what one compression step missed. Add-ons: factorized multi-level compression, layer-wise dynamic ratios, asymmetric dual embeddings, and a proxy-only KV cache. 모든 레이어에서 두 스트림을 돌린다. 로컬 특징을 소수의 프록시 상태로 압축하고, 전역 상호작용은 프록시끼리만 한 뒤, 결과를 복원해 로컬 스트림에 다시 주입한다. 로컬 스트림이 계속 남아 있어 한 단계가 놓친 정보를 다음 레이어가 다시 집을 수 있고, 여기에 다단 인수분해 압축·레이어별 동적 압축률·비대칭 이중 임베딩·프록시 전용 KV 캐시를 더했다.
Results / 결과 Needle-in-a-haystack retrieval was measured with 8K and 64K training windows and extrapolated to 256K tokens, made affordable by the proxy-only KV cache. Preliminary pixel- and latent-space flow-matching experiments show the idea is not text-specific. 8K·64K 학습 창에서 건초더미 속 바늘 검색을 측정하고 256K 토큰까지 외삽했으며, 프록시 전용 KV 캐시 덕분에 이 외삽이 감당할 만해진다. 픽셀·잠재 공간 flow matching 예비 실험으로 텍스트 전용 아이디어가 아님도 보였다.

Problem / 문제 정의 Large-scale rollouts (RL post-training, on-policy distillation, sampling-heavy evaluation) finish only when the slowest generation does, so a few long-tail generations dominate makespan. Yet rollout requests are routed uniformly, so an extremely long generation shares a high-concurrency decode batch with hundreds of short ones. RL 사후학습·온폴리시 증류·샘플링 위주 평가 같은 대규모 롤아웃은 가장 느린 생성이 끝나야 끝나므로 소수의 롱테일 생성이 makespan을 좌우한다. 그런데 요청은 레플리카에 균등 라우팅돼, 아주 긴 생성이 수백 개의 짧은 생성과 고동시성 디코드 배치를 나눠 쓴다.
Method / 방법 With known lengths, makespan-optimal routing combines tail isolation with load balancing. Since lengths are unknown, TailSieve uses partial rollouts as a training-free signal (prompts long-tailed on the last update tend to stay so), and a hierarchical controller sets the number of isolated groups and the tail/bulk replica split from response-work history and a measured concurrency–throughput model. Selected prompts are regenerated under the current policy, so generation stays on-policy with no accumulated length bias. 길이를 안다면 makespan 최적 라우팅은 꼬리 격리와 부하 분산의 결합이다. 길이를 모르므로 TailSieve는 부분 롤아웃을 학습 없는 신호로 쓰고(지난 갱신에서 롱테일이던 프롬프트는 계속 롱테일인 경향이 있다), 계층적 컨트롤러가 응답 작업량 이력과 측정한 동시성–처리량 모델로 격리 그룹 수와 꼬리·본체 레플리카 분할을 정한다. 선택된 프롬프트는 현재 정책으로 재생성해 온폴리시를 지키고 길이 편향이 쌓이지 않게 한다.
Results / 결과 Routing alone is up to 1.67× faster than uniform group routing. The tail pool is low-concurrency by construction, which makes route-specialized speculative decoding (MTP or DFlash) worthwhile there, for up to 2.59× total. 라우팅만으로 균등 그룹 라우팅 대비 최대 1.67배 빨라진다. 꼬리 풀은 구조상 동시성이 낮아 MTP나 DFlash 기반 추측 디코딩이 이득을 내고, 합치면 최대 2.59배가 된다.

Diamond Rapids, the next Xeon for enterprise orchestration: up to 256 cores, 1.28 GB of last-level cache, 16 memory channels at 12800 MT/s, 128 lanes of PCIe Gen6 / CXL 3.0, on Intel 18A-P with Foveros Direct 3D and UCIe-S. Crescent Island, a datacenter GPU for inference economics: 32 Xe cores and 256 XMX engines on Xe3P, up to 480GB of LPDDR5X, in a 350-watt air-cooled PCIe card. Wildcat Lake, shipping as Intel Core Series 3: a 2P+4E client and edge SoC on Intel 18A with Xe3 graphics, a 17-TOPS NPU, and Intel's first use of UCIe. Crescent Island is pitched on memory capacity and air cooling, for longer context and more concurrent agents in existing datacenters rather than peak FLOPs. Intel이 Hot Chips에서 세 아키텍처를 공개했다.
