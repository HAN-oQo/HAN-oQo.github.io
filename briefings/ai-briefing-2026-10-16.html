ReaDy: Recurrent States as Dynamic Context for Speculative Drafting in Hybrid Linear Attention Large Language Modelsspeculative decodinglinear attentionarXiv:2610.20503
arxiv.org/abs/2610.20503 →

Problem문제 정의Feature-based speculative drafters rely on the target model’s hidden features, which may not suit the later positions of a multi-token draft.특징 기반 추측 드래프터는 타깃 모델의 은닉 특징에 의존하는데, 이 특징은 여러 토큰 초안의 뒤쪽 위치에는 맞지 않을 수 있다.

Method방법ReaDy gives each draft position a learned query that retrieves supporting context from the committed recurrent states of a hybrid linear-attention target model. A lightweight state reader injects that context through residual updates, with low-rank reads and fused operators to keep overhead small. It builds on DSpark’s parallel backbone and sequential prediction head and is adapted in two stages.ReaDy는 각 초안 위치에 학습된 쿼리를 두어, 하이브리드 선형 어텐션 타깃 모델이 확정한 순환 상태에서 보조 문맥을 가져온다. 가벼운 상태 리더가 잔차 갱신으로 이 문맥을 주입하며, 저랭크 읽기와 융합 연산자로 오버헤드를 줄인다. DSpark의 병렬 백본과 순차 예측 헤드 위에 만들어졌고 두 단계로 적응시킨다.

Results결과Across seven benchmarks covering math, code generation and dialogue, it reports an average 3.16x decoding speedup over autoregressive decoding with Qwen3.8-27B on a single NVIDIA B200 GPU. It beats DSpark on every benchmark, with average gains of 7.97% in throughput and 8.50% in acceptance length.수학, 코드 생성, 대화를 다루는 7개 벤치마크에서 단일 NVIDIA B200 GPU의 Qwen3.8-27B로 자기회귀 디코딩 대비 평균 3.16배 디코딩 가속을 보고한다. 모든 벤치마크에서 DSpark를 앞서며 처리량은 평균 7.97%, 수용 길이는 평균 8.50% 개선된다.

Summary요약Reading the target’s recurrent states as draft context lets speculative drafting exploit what hybrid linear-attention models already compute.타깃의 순환 상태를 초안 문맥으로 읽으면 하이브리드 선형 어텐션 모델이 이미 계산한 정보를 추측 드래프팅에 활용할 수 있다.

Problem문제 정의Hybrid models mix attention KV caches, which grow with sequence length, with fixed-size recurrent and convolution states, and these differ in allocation granularity, reuse rules and lifetime, so one memory layout has to serve both under concurrent load.하이브리드 모델은 시퀀스 길이에 따라 커지는 어텐션 KV 캐시와 크기가 고정된 순환·합성곱 상태를 함께 쓰는데, 둘은 할당 단위, 재사용 규칙, 수명이 달라 동시 부하에서 하나의 메모리 배치로 둘을 모두 감당해야 한다.

Method방법The author builds four memory layouts in a modified vLLM runtime: a coarse shared-page baseline, recurrent-state paging, paging with convolution-slot packing, and separate native pools. Nine evaluation questions probe memory footprint and behavior under concurrent load.저자는 수정한 vLLM 런타임에 네 가지 메모리 배치를 구현한다: 거친 공유 페이지 기준선, 순환 상태 페이징, 합성곱 슬롯 패킹을 더한 페이징, 별도의 네이티브 풀. 아홉 가지 평가 질문으로 메모리 사용량과 동시 부하에서의 동작을 살핀다.

Results결과Refining the baseline up to packed paging improves output throughput and tail completion time at the main operating point, while the separate-pool design varies with memory budget, offered load and admission headroom. Recurrent-checkpoint availability is the bottleneck for joint reuse, and the retention interaction estimate is positive but its confidence interval includes zero.기준선에서 패킹된 페이징까지 단계적으로 개선하면 주 운영점에서 출력 처리량과 꼬리 완료 시간이 좋아지지만, 별도 풀 설계는 메모리 예산, 부하, 수용 여유에 따라 결과가 달라진다. 순환 체크포인트 가용성이 공동 재사용의 병목이며, 보존 상호작용 추정치는 양수이지만 신뢰구간이 0을 포함한다.

Problem문제 정의Multi-turn agentic requests build on earlier context. Prefix caching avoids repeated prefill, but routing every turn to the instance that holds its cache can create long local queues while other instances sit idle, and moving execution adds KV transfer overhead.다중 턴 에이전트 요청은 앞선 문맥 위에 쌓인다. 프리픽스 캐싱은 반복 프리필을 피하지만, 모든 턴을 캐시를 가진 인스턴스로 보내면 로컬 대기열이 길어지고 다른 인스턴스는 놀 수 있으며, 실행을 옮기면 KV 전송 오버헤드가 생긴다.

Method방법Vesta gives each session a stable holder for its KV cache and picks an executor for each request separately. Its objective weighs backlog, reusable prefixes, KV transfer cost and the queueing impact of added load, and it migrates reusable prefixes across length buckets to avoid cold starts.Vesta는 세션마다 KV 캐시를 보관할 안정적인 홀더를 두고 요청마다 실행기를 따로 고른다. 목적 함수는 대기 물량, 재사용 가능한 프리픽스, KV 전송 비용, 추가 부하의 대기열 영향을 함께 따지며, 콜드 스타트를 피하려고 재사용 가능한 프리픽스를 길이 구간 사이에서 이동시킨다.

Results결과On real-world agentic workloads in a PD-colocated deployment it improves throughput by 14.0% and cuts mean TTFT by 57.8% versus the state-of-the-art scheduler. In PD-disaggregated deployments it reduces mean TTFT by up to 18.1% and P99 TTFT by up to 29.0% at matched throughput.PD 동일 배치 환경의 실제 에이전트 워크로드에서 최신 스케줄러 대비 처리량이 14.0% 오르고 평균 TTFT가 57.8% 줄어든다. PD 분리 환경에서는 같은 처리량에서 평균 TTFT를 최대 18.1%, P99 TTFT를 최대 29.0% 줄인다.

Janas — an inference engine that runs MoE language models larger than RAM from an SSD Oct 13, 2026

Janas is a local inference engine that runs Mixture-of-Experts language models larger than RAM on ordinary PCs. It reads the weights each token needs from an NVMe SSD, keeps frequently used experts cached in memory, and runs without a GPU. The author reports about 24 tokens/s for a 48.4GB Qwen3-Next-80B-A3B model on a 32GB laptop versus 2.8 tokens/s for llama.cpp, but this is an early experimental release tested on a single machine.
