KVShareArena: KV-Cache Reuse Across Contexts and Model CheckpointsKV reusebenchmarkarXiv:2609.10266
arxiv.org/abs/2609.10266 →
Problem문제 정의 Serving systems already reuse KV caches, but only when the reused text sits at the very start of the prompt. Two growing workloads break that condition: a RAG server assembles a different set of retrieved chunks for every query, and a multi-agent coordinator reads reports written by other agents. Reused inside a new prompt, a cache carries the wrong positions and never attended to the other sources — and it may have been written by a different checkpoint of the same model family, which changes the stored values. 서빙 시스템의 KV 캐시 재사용은 재사용 텍스트가 프롬프트 맨 앞에 있을 때만 통한다. RAG 서버와 멀티 에이전트 조율자는 캐시를 프롬프트 중간에서 재사용하므로 위치가 틀어지고 다른 출처와의 상호작용이 빠지며, 캐시를 다른 체크포인트가 썼다면 값 자체도 다르다.
Method방법 Repair methods for such caches have appeared in three separate communities, each measured on its own terms, while existing benchmarks test only exact-prefix reuse where nothing is lost. KVShareArena benchmarks reuse across prompt contexts and across model checkpoints, on both retrieved chunks and agent reports. It scores every method by the fraction of the gap it recovers between no cache and full recomputation, and charges compute, memory and per-request latency with the cache in hand, reporting the one-time cost of building a cache separately. 기존 보수 방법들은 세 커뮤니티에서 따로 나와 서로 다른 기준으로 측정됐고, 기존 벤치마크는 정확한 프리픽스 재사용만 시험한다. KVShareArena는 문맥 간·체크포인트 간 재사용을 검색 청크와 에이전트 보고서에서 측정하고, '캐시 없음과 전체 재계산 사이 격차를 얼마나 회복하는가'와 연산·메모리·지연 비용으로 채점한다.
Results결과 Correcting positions, which needs no recomputation, is enough until a question needs several sources at once. There, only methods that pay — by re-encoding part of the cache or by training — recover half to two thirds of the gap, and unrepaired caches can be worse than no cache. Cache-compression methods that are harmless on a single prompt fall significantly behind position correction on freshly written agent reports. When a different checkpoint wrote the cache, training-free methods are barely affected while an adapter trained on one checkpoint's caches loses quality. The patterns hold across three model boards. 위치 보정만으로도 질문이 여러 출처를 한꺼번에 요구하기 전까지는 충분하다. 그 이후에는 재인코딩이나 학습에 비용을 쓰는 방법만 격차의 절반에서 3분의 2를 회복하고, 보수하지 않은 캐시는 캐시가 없는 것보다 나쁠 수 있다. 캐시 압축은 갓 쓰인 에이전트 보고서에서 크게 뒤지고, 다른 체크포인트의 캐시에서는 학습 없는 방법이 버티는 반면 학습한 어댑터는 품질을 잃는다.
Summary요약 The useful result is an ordering, not a winner: free position correction first, pay only when the query genuinely fuses sources, and be suspicious of compression on freshly written text. Harness, frozen querysets and cost accounting ship as a pip package with a public leaderboard. 순서가 핵심이다. 공짜 위치 보정을 먼저 쓰고, 출처를 정말 융합할 때만 비용을 내고, 갓 쓰인 텍스트의 압축은 의심한다. 하네스와 리더보드는 pip 패키지로 공개됐다.

Problem문제 정의 Autoregressive decoding re-reads a growing KV cache at every step, so long-context attention is bound by GPU memory bandwidth rather than by arithmetic. Block-sparse attention skips low-contribution KV blocks, but the two obvious ways to decide which blocks to skip each create a new dependency. A selector that decides after the current query-key product still has to read every K block, which is the cost you were trying to avoid. Method방법 CEDAR keeps the language model frozen and preserves global coverage by making omission cheap rather than absolute.
