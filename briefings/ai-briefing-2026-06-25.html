Execution-State Capsules — graph-bound checkpoint/restore for on-device servingruntimeon-device2606.20537
Execution-State Capsules: Graph-Bound Execution-State Checkpoint and Restore for Low-Latency, Small-Batch, On-Device Physical-AI Serving (arXiv 2606.20537, submitted Jun 18) ↗Execution-State Capsules: Graph-Bound Execution-State Checkpoint and Restore for Low-Latency, Small-Batch, On-Device Physical-AI Serving (arXiv 2606.20537, 6/18 제출) ↗
Problem문제 정의Mainstream serving reuses prefix work through paged or radix KV caches — but that manages only one positional fragment of execution state. In low-latency, small-batch, on-device serving (interactive agents, speech systems, robot policies) that repeatedly branch, reset, interrupt, and re-enter under tight responsiveness budgets, the rest of the live state has no first-class reuse mechanism.주류 서빙은 paged·radix KV 캐시로 접두사 작업을 재사용하지만, 이는 실행 상태의 위치 단편 하나만 관리한다. 빡빡한 응답 예산 아래 끊임없이 분기·리셋·중단·재진입하는 저지연·소배치 온디바이스 서빙(대화 에이전트·음성·로봇 정책)에서는 나머지 라이브 상태에 일급 재사용 메커니즘이 없다.
Method방법The paper introduces execution-state capsules, a graph-bound checkpoint/restore of the complete restorable state at a committed boundary. FlashRT, a white-box backend kernel runtime, runs captured graph plans over contiguous static buffers with no block-table indirection. Because the live state is a closed set of named buffers, a capsule can snapshot, restore, fork, or roll back the whole execution boundary — KV, recurrent state, convolution state, and more.논문은 커밋된 경계에서 복원 가능한 전체 상태를 그래프에 묶어 체크포인트/복원하는 execution-state capsule을 제안한다. 화이트박스 백엔드 커널 런타임 FlashRT는 블록 테이블 간접 없이 연속 정적 버퍼 위에서 캡처된 그래프 플랜을 실행한다. 라이브 상태가 이름붙은 버퍼의 닫힌 집합이므로, 캡슐은 실행 경계 전체(KV·순환 상태·합성곱 상태 등)를 스냅샷·복원·포크·롤백할 수 있다.
Results결과By treating the entire boundary as a closed set of static buffers, branch/reset/re-enter patterns become cheap state operations rather than recomputation, fitting the responsiveness budgets of physical-AI workloads. The capsule abstraction generalizes prefix reuse from "just the KV cache" to the full restorable execution state.경계 전체를 정적 버퍼의 닫힌 집합으로 다루면 분기·리셋·재진입이 재계산이 아니라 값싼 상태 연산이 되어, 물리-AI 워크로드의 응답 예산에 맞는다. 캡슐 추상화는 접두사 재사용을 "KV 캐시만"에서 복원 가능한 실행 상태 전체로 일반화한다.
Summary요약Checkpoint the whole on-device execution boundary as a capsule, so branching and re-entry cost a restore instead of a recompute.온디바이스 실행 경계 전체를 캡슐로 체크포인트해, 분기·재진입이 재계산이 아니라 복원 비용으로 끝나게 하라.

Prefill/Decode-Aware Evaluation of LLM Inference on Emerging AI Accelerators (arXiv 2606.17104, submitted Jun 14) ↗Prefill/Decode-Aware Evaluation of LLM Inference on Emerging AI Accelerators (arXiv 2606.17104, 6/14 제출) ↗
Problem문제 정의A growing number of AI accelerators claim advantages for LLM inference, yet it stays unclear under which conditions they actually beat GPUs. Aggregate throughput hides the fact that prefill and decode have very different computational profiles and latency metrics (TTFT vs. TPOT).점점 더 많은 AI 가속기가 LLM 추론 이점을 주장하지만, 어떤 조건에서 실제로 GPU를 이기는지는 불분명하다. 집계 처리량은 prefill과 decode의 연산 프로파일·지연 지표(TTFT vs TPOT)가 매우 다르다는 사실을 가린다.
