ReCache: Efficient KV Cache Reuse and Compression for Tool-Augmented LLM AgentsKV cachetool schemasarXiv:2608.19662
arxiv.org/abs/2608.19662 — Fang, Wei, Hu et al. (submitted Aug 20 2026)
Problem / 문제 정의 An agent's prompt is mostly boilerplate: the same tool and skill schemas, recurring across requests but in different combinations and different orders. Standard prefix caching only reuses a cache when the prefix matches byte-for-byte from position zero, so reordering two tools invalidates everything after them. The recurring text therefore gets re-encoded from scratch on almost every call. 에이전트 프롬프트의 대부분은 상투구다: 같은 도구·스킬 스키마가 요청마다 되풀이되지만 조합과 순서가 매번 다르다. 표준 프리픽스 캐싱은 0번 위치부터 바이트 단위로 일치할 때만 캐시를 재사용하므로, 도구 두 개의 순서만 바뀌어도 그 뒤 전체가 무효화된다. 결과적으로 되풀이되는 텍스트를 거의 매 호출마다 처음부터 다시 인코딩한다.
Method / 방법 ReCache caches each resource independently. Resource-wise attention deletes cross-resource interactions and gives every resource its own local positions, so its KV block becomes composition-invariant — valid no matter what sits beside it or in what order. On top of that, resource visibility is restricted to contribution-selected layer and KV-head-group routes, and structural plus semantic pruning keeps only the fields that matter for invocation. ReCache는 각 자원을 독립적으로 캐시한다. 자원별 어텐션이 자원 간 상호작용을 지우고 각 자원에 자기만의 지역 위치를 부여해, 그 KV 블록이 조합 불변이 된다 — 옆에 무엇이 어떤 순서로 오든 유효하다. 그 위에서 자원 가시성을 기여도로 선택된 레이어·KV 헤드 그룹 경로로 제한하고, 구조적·의미적 프루닝으로 호출에 필요한 필드만 남긴다.
Results / 결과 On a benchmark assembled from seven public tool- and skill-use datasets, including resource-disjoint tests, resource-wise attention matches dense invocation quality — 82.3% versus 82.4% Inv-F1 — while giving a 3.655× time-to-first-token speedup. The full framework cuts allocated KV-tensor memory by 92.43% and speeds attention up 1.423×. 공개 도구·스킬 사용 데이터셋 7종으로 구성한 벤치마크(자원 비중첩 테스트 포함)에서, 자원별 어텐션은 밀집 호출 품질과 맞먹으면서 — Inv-F1 82.3% 대 82.4% — 첫 토큰 시간을 3.655배 단축한다. 전체 프레임워크는 할당된 KV 텐서 메모리를 92.43% 줄이고 어텐션을 1.423배 가속한다.
Summary / 요약 The trick is giving up something the model was never really using: attention between one tool description and another. Once that is gone, the schema block is a self-contained cache entry, and the remaining question is only which layers need to see it at all. 요점은 모델이 실은 거의 쓰지 않던 것을 포기하는 데 있다: 도구 설명 사이의 어텐션. 그것을 없애면 스키마 블록이 자기완결적 캐시 항목이 되고, 남는 질문은 어느 레이어가 그것을 볼 필요가 있는가뿐이다.

A Thread-Register Decoupled GPU Execution Model for Efficient Tensor Computation (FIBER)GPU architecturemixed precisionarXiv:2608.19628
arxiv.org/abs/2608.19628 — Liu, Leng, Zhou et al. (submitted Aug 20 2026)
Problem / 문제 정의 Tensor Core throughput keeps climbing, and operand supply has already moved from register-based in Ampere to redundancy-free memory-based in Hopper and Blackwell. What has not moved is how work is assigned: parallelism is fixed and scheduling is coarse-grained. Modern LLM serving interleaves non-GEMM operations with GEMM constantly, and that interleaving is exactly what fixed parallelism handles badly. Tensor Core 처리량은 계속 오르고, 오퍼랜드 공급도 Ampere의 레지스터 기반에서 Hopper·Blackwell의 중복 없는 메모리 기반으로 이미 옮겨갔다. 옮겨가지 않은 것은 작업 할당 방식이다: 병렬성이 고정이고 스케줄링이 거칠다. 현대 LLM 서빙은 GEMM과 비-GEMM 연산을 끊임없이 섞는데, 고정 병렬성이 가장 못 다루는 것이 바로 그 섞임이다.
Method / 방법 FIBER extends the SIMT model with a new execution instance, the fiber, which owns no private registers. A fiber carries only minimal control state and reaches an SM's registers through a shared view, which allows parallelism to scale dynamically, dataflow to be scheduled at register granularity, and matrix operands to be supplied without duplication. The authors extend the ISA, the microarchitecture and the compiler together to provide shared-register addressing, conflict-free operand delivery, and fiber-based program mapping. FIBER는 SIMT 모델을 fiber라는 새 실행 단위로 확장한다. fiber는 전용 레지스터를 갖지 않고 최소한의 제어 상태만 들고 공유 뷰를 통해 SM 레지스터에 접근한다. 그래서 병렬성을 동적으로 조절하고, 데이터플로를 레지스터 단위로 스케줄링하며, 행렬 오퍼랜드를 중복 없이 공급할 수 있다. 저자들은 공유 레지스터 주소지정, 충돌 없는 오퍼랜드 전달, fiber 기반 프로그램 매핑을 위해 ISA·마이크로아키텍처·컴파일러를 함께 확장한다.
Results / 결과 Under a typical mixed-precision LLM serving scenario, FIBER reports a 2.25× end-to-end speedup on Ampere — 1.15× for the original FP16 computation alone — with 1.8× on Hopper and 2.09× on Blackwell, and kernel-level gains up to 2.49×. 전형적인 혼합 정밀도 LLM 서빙 시나리오에서 FIBER는 Ampere에서 종단 2.25배 가속을 보고한다 — 원래 FP16 연산만으로는 1.15배 — Hopper에서 1.8배, Blackwell에서 2.09배이며 커널 단위로는 최대 2.49배다.
Summary / 요약 The proposal is architectural rather than something you can enable in a serving engine today, but it names a real cost that shows up in every mixed-precision decode loop: threads that own registers they are not currently using, while the tensor pipeline waits for operands. 지금 서빙 엔진에서 켤 수 있는 기능이 아니라 아키텍처 제안이지만, 모든 혼합 정밀도 디코드 루프에서 드러나는 실제 비용을 지목한다: 텐서 파이프라인이 오퍼랜드를 기다리는 동안, 스레드는 당장 쓰지도 않는 레지스터를 점유하고 있다.

HYDRA: A Heterogeneous Chiplet DSE Framework for Serving Dynamic Hybrid LLM Workloadschiplet co-designTransformer–MambaarXiv:2608.19395
arxiv.org/abs/2608.19395 — Lin, Kanani, Lee et al. (submitted Aug 19 2026)
Problem / 문제 정의 Hybrid Transformer–Mamba models improve long-context efficiency, but they mix two very different computation and communication shapes in one forward pass, which makes them awkward to accelerate. Chiplet systems are a natural fit because you can put different compute and memory units on different dies — except that the design space then spans both static architecture choices and dynamic runtime policies, and is far too large to enumerate. 하이브리드 Transformer–Mamba 모델은 장문맥 효율을 높이지만, 한 번의 순전파에 성격이 크게 다른 두 연산·통신 형태를 섞어 가속이 까다롭다. 서로 다른 연산·메모리 단위를 서로 다른 다이에 올릴 수 있으니 칩렛 시스템이 잘 맞는데, 문제는 그 설계 공간이 정적 아키텍처 선택과 동적 런타임 정책에 모두 걸쳐 있어 전수 탐색이 불가능하다는 점이다.

Problem / 문제 정의 BrowseComp-Plus made agentic search measurable by swapping opaque web search for a fixed corpus, separating the agent's contribution from the retriever's. But that corpus holds only about 100K documents and was built from the supporting documents of its own queries plus mined hard negatives — meaning both the evidence and the distractors were selected per question, which flatters retrieval. BrowseComp-Plus는 불투명한 웹 검색을 고정 코퍼스로 바꿔 에이전트의 기여와 검색기의 기여를 분리하며 에이전트 검색을 측정 가능하게 만들었다. 그런데 그 코퍼스는 문서 약 10만 개뿐이고 자기 질의의 근거 문서에 채굴한 하드 네거티브를 더해 구성됐다 — 근거와 방해 문서가 모두 질문별로 선택됐다는 뜻이고, 이는 검색에 유리하게 작용한다.
Method / 방법 The authors keep the questions but relocate their evidence into ClimbMix, a 400B-token, 553M-document web-text mixture NVIDIA released for pre-training, built with no reference to any benchmark. The contribution is the projection pipeline: decompose each question into atomic reasoning hops, ground every hop in the new corpus, and keep a question only when automatic verification, an independent agent, and human review all agree that every hop is supported. The pipeline is dataset-agnostic and applies to any benchmark whose questions decompose into verifiable facts. 저자들은 질문은 그대로 두고 근거를 ClimbMix로 옮긴다. Summary / 요약 The accuracy drop is small and the recall collapse is not, which is the whole point: an agent can still answer while barely finding the right evidence. Problem / 문제 정의 Loading skill documents into a bounded context window is now the main way an agent acquires task-specific capability, which makes skill selection a first-order determinant of both success and token cost. Current agents score each skill independently on semantic relevance and then fill the budget by top-k or greedy packing — no guarantee about the selected set, no cost awareness. Redundant or badly chosen skills spend scarce context and can make performance worse. 제한된 컨텍스트 창에 스킬 문서를 올리는 것이 이제 에이전트가 과제별 능력을 얻는 주된 방법이고, 그래서 스킬 선택이 성공률과 토큰 비용을 함께 좌우한다. 현재 에이전트는 각 스킬을 의미 관련성으로 독립 채점하고 top-k나 탐욕적 채우기로 예산을 메운다 — 선택된 집합에 대한 보장도, 비용 인식도 없다. 중복되거나 잘못 고른 스킬은 귀한 컨텍스트를 소비하고 성능을 떨어뜨릴 수 있다.
Method / 방법 The paper first models how the selected set — not each skill in isolation — shapes execution outcomes, then casts selection as an optimization: pick a skill set under a hard token budget maximizing a monotone submodular benefit minus a context penalty. Best Prefix Selection (BPS) solves it in polynomial time with a bicriteria (1−1/e, 1) approximation whose benefit coefficient the authors argue is optimal in polynomial time. 논문은 먼저 개별 스킬이 아니라 선택된 집합이 실행 결과를 어떻게 형성하는지 모델링하고, 선택을 최적화 문제로 바꾼다: 엄격한 토큰 예산 아래 단조 서브모듈러 이득에서 컨텍스트 페널티를 뺀 값을 최대화하는 스킬 집합을 고른다. Best Prefix Selection(BPS)은 이를 다항 시간에 풀며, 저자들이 다항 시간 내 최적이라 주장하는 이득 계수를 갖는 (1−1/e, 1) 이중 기준 근사를 제공한다.
Results / 결과 On a contamination-controlled BigCodeBench variant, BPS beats every baseline, reaching 0.73 measured task success against 0.20–0.52 for released skill routers, text retrievers and the executor's own selection — and does it on 28% fewer tokens than the strongest released router. 오염을 통제한 BigCodeBench 변형에서 BPS는 모든 기준선을 앞서 과제 성공률 0.73을 기록하고, 공개된 스킬 라우터·텍스트 검색기·실행기 자체 선택은 0.20~0.52에 머문다 — 게다가 최강 공개 라우터보다 토큰을 28% 덜 쓴다.
Summary / 요약 The gap between 0.52 and 0.73 is large enough to suggest that a lot of what looks like agent capability is really selection quality. Submodularity is the load-bearing assumption: it is what makes "this skill adds less once you already have that one" tractable. 0.52와 0.73의 차이는 에이전트 능력처럼 보이는 것 상당 부분이 실은 선택 품질이라는 점을 시사할 만큼 크다. 핵심 가정은 서브모듈러성이다: "저 스킬이 이미 있으면 이 스킬의 추가 이득은 줄어든다"를 다룰 수 있게 만드는 것이 그 가정이다.
