Post-training study plan 포스트트레이닝 공부 계획

A survey → reproduce → scale ladder. Read the two surveys, then climb a hands-on ladder where each rung is a small runnable experiment — Docker-only on the shared GPU nodes (mi250 etc.), per our infra rules. Default tool: TRL until a run needs multi-node RL. 조사 → 재현 → 확장 사다리. 조사 2건을 읽고, 각 칸이 작은 실행형 실험인 실습 사다리를 오른다 — 인프라 규칙상 공유 GPU 노드(mi250 등)에서 Docker 전용. 기본 도구: TRL, 멀티노드 RL이 필요해질 때까지.

The plan계획

Phase단계 Goal목표 Read / do읽기 / 실습
0 Map the pipeline & the framework landscape파이프라인·프레임워크 지형 파악 Methodology survey + Frameworks survey방법론 조사 + 프레임워크 조사
1 SFT — get a base model following instructions; feel data-quality > quantitySFT — 베이스가 지시를 따르게; 품질 > 양 체감 TRL SFTTrainer on a small model (Qwen2.5-0.5B) + a curated set; compare 1k vs 50k examples작은 모델(Qwen2.5-0.5B)에 TRL SFTTrainer + 큐레이션 셋; 1k vs 50k 비교
2 Preference optimization — align without the RL loop선호 최적화 — RL 루프 없이 정렬 TRL DPOTrainer on a preference set; then SimPO/ORPO; eyeball length bias선호 셋에 TRL DPOTrainer; 이후 SimPO/ORPO; 길이 편향 관찰
3 RLVR — a critic-free RL loop on a verifiable taskRLVR — 검증 가능한 과제로 critic 없는 RL TRL GRPOTrainer on a math/code task with a programmatic reward; watch KL & reward curves수학/코드 과제 + 프로그램 보상으로 TRL GRPOTrainer; KL·보상 곡선 관찰
4 Reward modeling & distillation보상 모델링 · 증류 Train a small scalar RM; try a GenRM verifier; sequence-level distillation from a teacher's traces작은 스칼라 RM 학습; GenRM 검증기 시도; 교사 trace로 시퀀스 단위 증류
5 Scale & infra — when single-node stops being enough확장·인프라 — 단일 노드로 부족해질 때 Stand up veRL / OpenRLHF with a vLLM/SGLang rollout engine; reuse serving knowledge from inference notesveRL / OpenRLHF에 vLLM/SGLang 롤아웃 엔진; 추론 노트의 서빙 지식 재사용
ground rules기본 원칙 Shared GPU nodes → Docker only, no pip on the host. Clean up the server right after each run. Compare apples-to-apples (same model/data/seed) when judging a method. Log each run as a work-log entry, failures included. 공유 GPU 노드 → Docker 전용, 호스트 pip 금지. 실험 직후 서버 정리. 방법 비교는 동일 조건(같은 모델·데이터·시드)으로. 각 실험은 작업 로그로 남기고 실패도 기록.
editor's note — why this order편집자 주 — 이 순서인 이유 Each rung adds exactly one new idea over the last (reward signal → off-policy pref → on-policy RL → learned/teacher reward → distributed rollout), so a failure is easy to localize. The serving lens carries over: phase 5's rollout engine is vLLM/SGLang — the same engines the inference notes dissect. 각 칸이 직전 대비 새 개념을 정확히 하나씩만 더한다(보상 신호 → off-policy 선호 → on-policy RL → 학습/교사 보상 → 분산 롤아웃) — 그래서 실패 원인을 짚기 쉽다. 서빙 관점이 이어진다: 5단계 롤아웃 엔진이 vLLM/SGLang — 추론 노트가 해부한 바로 그 엔진들.
